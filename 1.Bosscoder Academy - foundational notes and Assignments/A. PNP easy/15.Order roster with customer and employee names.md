# 15. Order roster with customer and employee names

## Question and image

Using the Northwind database, build a roster that pairs every order with the customer who placed it and the employee who handled it. Join `Orders` to `Customers` (on `CustomerID`) and to `Employees` (on `EmployeeID`).

Return exactly these three columns:

- `OrderID`: the order's id.
- `CustomerName`: the customer's `CompanyName`.
- `EmployeeName`: the employee's first and last name joined by a single space, e.g. `Nancy Davolio`.

Return **one row per order**. Sort the result by `OrderID` **ascending**.

**Expected output:** `OrderID`, `CustomerName`, `EmployeeName` · 16282 rows · order matters.

## My solution — SQLite

```sql
select Orders. OrderID as OrderID , Customers. CompanyName as CustomerName , Employees.FirstName || ' ' || LastName as EmployeeName
from Customers
join Orders on Orders.CustomerID = Customers .CustomerID
join Employees on Orders.EmployeeID = Employees.EmployeeID
order by OrderID asc
```

**1. Match every order to the customer company**

Orders.CustomerID identifies the customer who placed an order. Joining it to Customers.CustomerID supplies CompanyName.

```sql
SELECT Orders.OrderID, Orders.CustomerID, Customers.CompanyName, Orders.EmployeeID
FROM Customers
JOIN Orders ON Orders.CustomerID = Customers.CustomerID
ORDER BY Orders.OrderID;
```

Result:

| OrderID | CustomerID | CompanyName | EmployeeID |
| --- | --- | --- | --- |
| 101 | BETA | Beta Stores | 1 |
| 102 | ALFA | Alpha Foods | 1 |
| 103 | ALFA | Alpha Foods | 2 |

Alpha Foods appears twice because it placed orders 102 and 103. That repetition is correct: the target is one row per order.

**2. Match each order to its handling employee**

Use Orders.EmployeeID to retrieve the employee attached to that order. This second join enriches the existing order rows.

```sql
SELECT Orders.OrderID, Customers.CompanyName AS CustomerName,
       Employees.FirstName, Employees.LastName
FROM Customers
JOIN Orders ON Orders.CustomerID = Customers.CustomerID
JOIN Employees ON Orders.EmployeeID = Employees.EmployeeID
ORDER BY Orders.OrderID;
```

Result:

| OrderID | CustomerName | FirstName | LastName |
| --- | --- | --- | --- |
| 101 | Beta Stores | Nancy | Davolio |
| 102 | Alpha Foods | Nancy | Davolio |
| 103 | Alpha Foods | Andrew | Fuller |

Orders 101 and 102 were handled by Nancy Davolio; order 103 by Andrew Fuller. The final SELECT joins each employee's first and last names with a space.

**3. Assemble the final query**

Combine the steps using the saved solution. The query below preserves the original logic.

```sql
select Orders. OrderID as OrderID , Customers. CompanyName as CustomerName , Employees.FirstName || ' ' || LastName as EmployeeName
from Customers
join Orders on Orders.CustomerID = Customers .CustomerID
join Employees on Orders.EmployeeID = Employees.EmployeeID

```

**Check the result:** The input has three orders and the result has those same three OrderID values, sorted 101, 102, 103. Each company and employee follows the corresponding order's keys.

## Official solution

```sql
SELECT
    o.OrderID AS OrderID,
    c.CompanyName AS CustomerName,
    e.FirstName || ' ' || e.LastName AS EmployeeName
FROM Orders o
JOIN Customers c ON o.CustomerID = c.CustomerID
JOIN Employees e ON o.EmployeeID = e.EmployeeID
ORDER BY o.OrderID ASC;
```

### What this tests

Joining three related tables, selecting and aliasing columns, and concatenating a full name.

### The approach

Start from Orders; join Customers on CustomerID and Employees on EmployeeID; return the order ID, customer company name, and employee full name; sort by OrderID.

### Why this way

Orders contains both foreign keys, so the joins attach the customer and employee details to each order.

### Common mistakes

Using incorrect aliases, returning first and last names separately, or selecting extra columns.
