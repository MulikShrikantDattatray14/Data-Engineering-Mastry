# 18. Vowel-initial companies with uppercased country

## Question and image

Marketing is building a feature segment for customers whose company name begins with a vowel, and wants the country name shown in upper case for a banner. From the **Customers** table, keep only rows where `CompanyName` starts with one of the letters **A, E, I, O, or U (case-insensitive)**.

Return the `CompanyName` and the `Country` converted to upper case as `CountryUpper`.

Output exactly two columns named `CompanyName` and `CountryUpper`. Sort by `CompanyName` **ascending (A to Z)**.

**Expected output:** `CompanyName`, `CountryUpper` · 12 rows · order matters.

## My solution — SQLite

```sql
select CompanyName, UPPER(Country) as CountryUpper
from Customers
where CompanyName like 'a%' OR CompanyName like 'A%' or
CompanyName like 'E%' OR CompanyName like 'e% ' or
CompanyName like 'i%' OR CompanyName like 'I%' or
CompanyName like 'O%' OR CompanyName like 'o%' or
CompanyName like 'u%' OR CompanyName like 'U% '
order by CompanyName asc
```

**1. Understand the prefix tests in the saved filter**

A pattern such as a% means a at the beginning followed by any sequence of characters. Under default SQLite LIKE behavior, ASCII letters match without case sensitivity.

```sql
SELECT CompanyName,
       CompanyName LIKE 'a%' AS StartsWithA,
       CompanyName LIKE 'E%' AS StartsWithE,
       CompanyName LIKE 'i%' AS StartsWithI,
       CompanyName LIKE 'O%' AS StartsWithO,
       CompanyName LIKE 'u%' AS StartsWithU
FROM Customers
ORDER BY CustomerID;
```

Result:

| CompanyName | StartsWithA | StartsWithE | StartsWithI | StartsWithO | StartsWithU |
| --- | --- | --- | --- | --- | --- |
| Acme | 1 | 0 | 0 | 0 | 0 |
| Beta | 0 | 0 | 0 | 0 | 0 |
| elm Works | 0 | 1 | 0 | 0 | 0 |
| Indigo | 0 | 0 | 1 | 0 | 0 |
| oak Shop | 0 | 0 | 0 | 1 | 0 |
| Union Goods | 0 | 0 | 0 | 0 | 1 |

A result of 1 means the test matched; 0 means it did not. Every vowel-initial company matches one of these tests, while Beta matches none.

**2. Keep rows matching any vowel branch**

The OR conditions keep a company when any one prefix test succeeds. This step uses the saved WHERE expression exactly, including its trailing spaces in two pattern literals.

```sql
SELECT CompanyName, Country
FROM Customers
WHERE CompanyName LIKE 'a%' OR CompanyName LIKE 'A%' OR
CompanyName LIKE 'E%' OR CompanyName LIKE 'e% ' OR
CompanyName LIKE 'i%' OR CompanyName LIKE 'I%' OR
CompanyName LIKE 'O%' OR CompanyName LIKE 'o%' OR
CompanyName LIKE 'u%' OR CompanyName LIKE 'U% ';
```

Result:

| CompanyName | Country |
| --- | --- |
| Acme | India |
| elm Works | France |
| Indigo | Brazil |
| oak Shop | Canada |
| Union Goods | Germany |

Beta is removed; the other five companies remain. The final query applies UPPER to Country and sorts CompanyName.

**3. Assemble the final query**

Combine the steps using the saved solution. The query below preserves the original logic.

```sql
select CompanyName, UPPER(Country) as CountryUpper
from Customers
where CompanyName like 'a%' OR CompanyName like 'A%' or
CompanyName like 'E%' OR CompanyName like 'e% ' or
CompanyName like 'i%' OR CompanyName like 'I%' or
CompanyName like 'O%' OR CompanyName like 'o%' or
CompanyName like 'u%' OR CompanyName like 'U% '
order by CompanyName asc
```

Final result for this example:

| CompanyName | CountryUpper |
| --- | --- |
| Acme | INDIA |
| Indigo | BRAZIL |
| Union Goods | GERMANY |
| elm Works | FRANCE |
| oak Shop | CANADA |

**Check the result:** The five vowel-initial companies remain, with countries INDIA, BRAZIL, GERMANY, FRANCE, and CANADA in the displayed name order. Filtering changes membership; UPPER changes only the country text.

The saved literals 'e% ' and 'U% ' include a final space, so those individual patterns require the company name to end in a space. Here the other E% and u% branches already cover those initials because SQLite LIKE is ASCII case-insensitive by default. The original query is preserved; it relies on that behavior. ORDER BY CompanyName uses the column's collation; this example uses SQLite's default binary ordering, so uppercase initials sort before lowercase initials.

## Official solution

```sql
SELECT CompanyName,
       UPPER(Country) AS CountryUpper
FROM Customers
WHERE UPPER(substr(CompanyName, 1, 1)) IN ('A', 'E', 'I', 'O', 'U')
ORDER BY CompanyName ASC;
```

### What this tests

Combining string extraction, case conversion, and filtering.

### The approach

Uppercase Country for the output; extract and uppercase the first character of CompanyName; keep vowels with IN; sort by company name.

### Why this way

Checking an uppercased initial against one vowel list is concise and avoids separate uppercase and lowercase conditions.

### Common mistakes

Using incorrect output aliases, missing or incomplete vowel filtering, or failing to handle letter case.
