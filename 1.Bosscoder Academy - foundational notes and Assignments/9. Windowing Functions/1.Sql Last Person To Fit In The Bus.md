# 1. SQL Last Person to Fit in the Bus

## Question and image

[**1204. Last Person to Fit in the Bus**](https://leetcode.com/problems/last-person-to-fit-in-the-bus/)

People board a bus one at a time, in `turn` order. The bus has a **1,000 kg weight limit**. Find the `person_name` of the last person who can board without the total weight exceeding that limit. The first person is guaranteed to fit.

**Example 1 — input:**

Queue:

| person_id | person_name | weight | turn |
|---:|---|---:|---:|
| 5 | Alice | 250 | 1 |
| 4 | Bob | 175 | 5 |
| 3 | Alex | 350 | 2 |
| 6 | John Cena | 400 | 3 |
| 1 | Winston | 500 | 6 |
| 2 | Marie | 200 | 4 |

**Output:**

| person_name |
|---|
| John Cena |

**Explanation:** Put the sample rows in `turn` order to see who boards:

| turn | person_id | person_name | weight (kg) | Total if this person boards (kg) | Result |
|---:|---:|---|---:|---:|---|
| 1 | 5 | Alice | 250 | 250 | Boards |
| 2 | 3 | Alex | 350 | 600 | Boards |
| 3 | 6 | John Cena | 400 | 1,000 | Boards; last person who fits |
| 4 | 2 | Marie | 200 | 1,200 | Cannot board |
| 5 | 4 | Bob | 175 | — | Cannot board after the queue stops |
| 6 | 1 | Winston | 500 | — | Cannot board after the queue stops |

The 1,200 kg value is what the total **would be** if Marie boarded; the actual bus remains at 1,000 kg.

## Schema

**Queue**

| Column Name | Type | Meaning |
|---|---|---|
| person_id | int | Unique person ID. |
| person_name | varchar | Person's name. |
| weight | int | Person's weight in kilograms. |
| turn | int | Boarding position. |

`person_id` and `turn` each contain every integer from 1 through the number of rows, without duplicates. `turn = 1` boards first.

## My solution — SQLite

Your final SQLite solution is below. The detailed walkthrough uses the same Queue example throughout.

```sql
WITH running_weights AS (
    SELECT
        turn,
        person_name,
        weight,
        SUM(weight) OVER (ORDER BY turn) AS total_weight
    FROM Queue
)
SELECT person_name
FROM running_weights
WHERE total_weight <= 1000
ORDER BY turn DESC
LIMIT 1;
```

### Step-by-step explanation with one example

**1. Put people in boarding order.** The `turn` column, not `person_id`, determines who boards first. Start by displaying the Queue rows in that order:

```sql
SELECT turn, person_name, weight
FROM Queue
ORDER BY turn;
```

| turn | person_name | weight |
| ---: | --- | ---: |
| 1 | Alice | 250 |
| 2 | Alex | 350 |
| 3 | John Cena | 400 |
| 4 | Marie | 200 |
| 5 | Bob | 175 |
| 6 | Winston | 500 |

**2. Calculate the weight through each turn.** `SUM(weight) OVER (ORDER BY turn)` keeps one row per person and adds weights from turn 1 through the current turn. The `ORDER BY` inside `OVER` sets the accumulation order. The outer `ORDER BY` below is optional: it displays the intermediate rows in turn order but does not change their running totals. Since each `turn` is unique, there are no ordering ties here.

```sql
SELECT
    turn,
    person_name,
    weight,
    SUM(weight) OVER (ORDER BY turn) AS total_weight
FROM Queue
ORDER BY turn;
```

| turn | person_name | weight | total_weight |
| ---: | --- | ---: | ---: |
| 1 | Alice | 250 | 250 |
| 2 | Alex | 350 | 600 |
| 3 | John Cena | 400 | 1000 |
| 4 | Marie | 200 | 1200 |
| 5 | Bob | 175 | 1375 |
| 6 | Winston | 500 | 1875 |

For example, Alex's total is `250 + 350 = 600`; John Cena's is `250 + 350 + 400 = 1000`. Marie would make it `1000 + 200 = 1200`, which exceeds the limit. The later totals are **hypothetical** cumulative weights of queue rows; those people do not actually board, and the bus remains at 1000 kg.

**3. Keep only turns that fit.** A window result cannot be filtered in the same query's `WHERE` clause. First name it `total_weight` in the CTE, then filter it in the outer query. `<= 1000` includes a person who brings the weight to exactly 1000 kg.

```sql
WITH running_weights AS (
    SELECT
        turn,
        person_name,
        weight,
        SUM(weight) OVER (ORDER BY turn) AS total_weight
    FROM Queue
)
SELECT turn, person_name, total_weight
FROM running_weights
WHERE total_weight <= 1000
ORDER BY turn;
```

| turn | person_name | total_weight |
| ---: | --- | ---: |
| 1 | Alice | 250 |
| 2 | Alex | 600 |
| 3 | John Cena | 1000 |

Marie, Bob, and Winston are excluded because their cumulative totals exceed 1000.

**4. Pick the last qualifying turn.** Among the remaining turns 1, 2, and 3, `ORDER BY turn DESC` puts turn 3 first. `LIMIT 1` keeps that row, and the final `SELECT` returns only the requested `person_name`. Ordering by `total_weight` without `DESC` would pick Alice; ordering by `turn` expresses the actual requirement.

The complete query is shown above. Its output is:

| person_name |
| --- |
| John Cena |

**Manual check:** `250 + 350 + 400 = 1000`, so John Cena fits. Adding the next person's 200 kg would make 1200, so no later turn can be the last person to board.

## My solution — SQL Server

The same CTE and running-total expression work in SQL Server. Replace SQLite's `LIMIT 1` with `TOP (1)` after `SELECT`.

```sql
WITH running_weights AS (
    SELECT
        turn,
        person_name,
        weight,
        SUM(weight) OVER (ORDER BY turn) AS total_weight
    FROM Queue
)
SELECT TOP (1) person_name
FROM running_weights
WHERE total_weight <= 1000
ORDER BY turn DESC;
```
