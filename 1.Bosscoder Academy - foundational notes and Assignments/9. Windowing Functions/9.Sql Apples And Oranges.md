# 9. SQL Apples & Oranges

## Question and image

**LeetCode 1445:** [Apples & Oranges](https://leetcode.com/problems/apples-oranges/)

For each `sale_date`, report `diff`: the number of apples sold minus the number of oranges sold.

Return the result table ordered by sale_date.

**Example 1:**

Input:

Sales table:

| sale_date | fruit | sold_num |
| --- | --- | --- |
| 2020-05-01 | apples | 10 |
| 2020-05-01 | oranges | 8 |
| 2020-05-02 | apples | 15 |
| 2020-05-02 | oranges | 15 |
| 2020-05-03 | apples | 20 |
| 2020-05-03 | oranges | 0 |
| 2020-05-04 | apples | 15 |
| 2020-05-04 | oranges | 16 |

Output:

| sale_date | diff |
| --- | --- |
| 2020-05-01 | 2 |
| 2020-05-02 | 0 |
| 2020-05-03 | 20 |
| 2020-05-04 | -1 |

**Example explanation:** Subtract oranges sold from apples sold for each date.

| sale_date | Apples | Oranges | Calculation |
|---|---:|---:|---|
| 2020-05-01 | 10 | 8 | 10 - 8 = 2 |
| 2020-05-02 | 15 | 15 | 15 - 15 = 0 |
| 2020-05-03 | 20 | 0 | 20 - 0 = 20 |
| 2020-05-04 | 15 | 16 | 15 - 16 = -1 |

## My solution — SQLite

```sql
WITH daily_fruit AS (
    SELECT sale_date, fruit, SUM(sold_num) AS total_sold
    FROM Sales
    GROUP BY sale_date, fruit
),
LEAD_CTE AS (
    SELECT
        sale_date,
        fruit,
        total_sold,
        LEAD(total_sold) OVER (
            PARTITION BY sale_date
            ORDER BY fruit
        ) AS next_total
    FROM daily_fruit
)
SELECT sale_date, total_sold - next_total AS diff
FROM LEAD_CTE
WHERE next_total IS NOT NULL
ORDER BY sale_date;
```

### Step-by-step explanation with one example

**1. Start with the sales for each date.** One output row must represent one `sale_date`, with `diff` equal to apples minus oranges. The input has one row per date and fruit because `(sale_date, fruit)` is the primary key.

```sql
SELECT sale_date, fruit, sold_num
FROM Sales
ORDER BY sale_date, fruit;
```

| sale_date | fruit | sold_num |
|---|---|---:|
| 2020-05-01 | apples | 10 |
| 2020-05-01 | oranges | 8 |
| 2020-05-02 | apples | 15 |
| 2020-05-02 | oranges | 15 |
| 2020-05-03 | apples | 20 |
| 2020-05-03 | oranges | 0 |
| 2020-05-04 | apples | 15 |
| 2020-05-04 | oranges | 16 |

**2. Calculate one total for each date and fruit.** The first CTE groups by both columns, so it keeps an apple group and an orange group for each date. `SUM(sold_num)` is the total for that group.

```sql
SELECT sale_date, fruit, SUM(sold_num) AS total_sold
FROM Sales
GROUP BY sale_date, fruit
ORDER BY sale_date, fruit;
```

| sale_date | fruit | total_sold |
|---|---|---:|
| 2020-05-01 | apples | 10 |
| 2020-05-01 | oranges | 8 |
| 2020-05-02 | apples | 15 |
| 2020-05-02 | oranges | 15 |
| 2020-05-03 | apples | 20 |
| 2020-05-03 | oranges | 0 |
| 2020-05-04 | apples | 15 |
| 2020-05-04 | oranges | 16 |

The numbers do not change in this sample because the primary key already allows only one row for each `(sale_date, fruit)` pair. Keeping the grouping follows the chosen calculation plan.

**3. Put the next fruit's total beside the current one.** `PARTITION BY sale_date` starts a separate window for each day. Inside each day's window, `ORDER BY fruit` puts `apples` before `oranges`. Therefore `LEAD(total_sold)` places that day's orange total on its apple row. The orange row has no following fruit, so its `next_total` is `NULL`.

```sql
WITH daily_fruit AS (
    SELECT sale_date, fruit, SUM(sold_num) AS total_sold
    FROM Sales
    GROUP BY sale_date, fruit
)
SELECT
    sale_date,
    fruit,
    total_sold,
    LEAD(total_sold) OVER (
        PARTITION BY sale_date
        ORDER BY fruit
    ) AS next_total
FROM daily_fruit
ORDER BY sale_date, fruit;
```

| sale_date | fruit | total_sold | next_total |
|---|---|---:|---:|
| 2020-05-01 | apples | 10 | 8 |
| 2020-05-01 | oranges | 8 | NULL |
| 2020-05-02 | apples | 15 | 15 |
| 2020-05-02 | oranges | 15 | NULL |
| 2020-05-03 | apples | 20 | 0 |
| 2020-05-03 | oranges | 0 | NULL |
| 2020-05-04 | apples | 15 | 16 |
| 2020-05-04 | oranges | 16 | NULL |

For example, the `2020-05-01` apple row now has `total_sold = 10` and `next_total = 8`. The window's `ORDER BY fruit` determines which row `LEAD` reads; it does not sort the final answer. The query's outer `ORDER BY sale_date, fruit` displays this intermediate table clearly.

**4. Keep the paired rows and subtract.** The second CTE is the result above. `WHERE next_total IS NOT NULL` removes its orange rows, leaving one apple row per date with both totals available. A zero orange total is a real value, so the `2020-05-03` apple row remains.

```sql
WITH daily_fruit AS (
    SELECT sale_date, fruit, SUM(sold_num) AS total_sold
    FROM Sales
    GROUP BY sale_date, fruit
),
LEAD_CTE AS (
    SELECT
        sale_date,
        fruit,
        total_sold,
        LEAD(total_sold) OVER (
            PARTITION BY sale_date
            ORDER BY fruit
        ) AS next_total
    FROM daily_fruit
)
SELECT sale_date, total_sold - next_total AS diff
FROM LEAD_CTE
WHERE next_total IS NOT NULL
ORDER BY sale_date;
```

| sale_date | diff |
|---|---:|
| 2020-05-01 | 2 |
| 2020-05-02 | 0 |
| 2020-05-03 | 20 |
| 2020-05-04 | -1 |

**5. Check the arithmetic.** The four retained rows calculate `10 - 8 = 2`, `15 - 15 = 0`, `20 - 0 = 20`, and `15 - 16 = -1`. These match the supplied output, and the final `ORDER BY sale_date` supplies the required date order. This pairing relies on each date having an apples row followed by an oranges row, as in the supplied data.
