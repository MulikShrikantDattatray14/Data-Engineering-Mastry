# 8. SQL Biggest Window Between Visits

## Question and image

**LeetCode 1709:** [Biggest Window Between Visits](https://leetcode.com/problems/biggest-window-between-visits/)

This assignment names the table `user_visits`. The linked LeetCode version calls it `UserVisits`; use the name provided by the platform where you run the query.

Assume today's date is '2021-01-01'.

Write a solution that will, for each user_id, find out the largest window of days between each visit and the one right after it (or today if you are considering the last visit).

Return the result table ordered by user_id.

**Example 1:**

Input:

user_visits table:

| user_id | visit_date |
| --- | --- |
| 1 | 2020-11-28 |
| 1 | 2020-10-20 |
| 1 | 2020-12-03 |
| 2 | 2020-10-05 |
| 2 | 2020-12-09 |
| 3 | 2020-11-11 |

Output:

| user_id | biggest_window |
| --- | --- |
| 1 | 39 |
| 2 | 65 |
| 3 | 51 |

**Example explanation:** For each user, compare each visit with the next visit; compare the last visit with 2021-01-01.

| user_id | From | To | Days between |
|---:|---|---|---:|
| 1 | 2020-10-20 | 2020-11-28 | 39 |
| 1 | 2020-11-28 | 2020-12-03 | 5 |
| 1 | 2020-12-03 | 2021-01-01 | 29 |
| 2 | 2020-10-05 | 2020-12-09 | 65 |
| 2 | 2020-12-09 | 2021-01-01 | 23 |
| 3 | 2020-11-11 | 2021-01-01 | 51 |

The largest gap for users 1, 2, and 3 is therefore 39, 65, and 51 days respectively.

## My solution — SQLite

Both approaches calculate the gap from each visit to the next visit by the same user, using `2021-01-01` after the last visit. The first follows your numbered-row self-join approach; the second uses `LEAD()` to fetch the next date directly.

**Approach 1 — `ROW_NUMBER()` and a left self-join**

```sql
WITH ranked_visits AS (
    SELECT
        user_id,
        visit_date,
        ROW_NUMBER() OVER (
            PARTITION BY user_id
            ORDER BY visit_date DESC
        ) AS rn
    FROM user_visits
)
SELECT
    older.user_id,
    CAST(MAX(
        JULIANDAY(COALESCE(newer.visit_date, '2021-01-01'))
        - JULIANDAY(older.visit_date)
    ) AS INTEGER) AS biggest_window
FROM ranked_visits AS older
LEFT JOIN ranked_visits AS newer
    ON older.user_id = newer.user_id
   AND newer.rn = older.rn - 1
GROUP BY older.user_id
ORDER BY older.user_id;
```

**Approach 2 — `LEAD()`**

```sql
WITH visit_gaps AS (
    SELECT
        user_id,
        visit_date,
        LEAD(visit_date, 1, '2021-01-01') OVER (
            PARTITION BY user_id
            ORDER BY visit_date
        ) AS next_visit
    FROM user_visits
)
SELECT
    user_id,
    MAX(CAST(
        JULIANDAY(next_visit) - JULIANDAY(visit_date)
        AS INTEGER
    )) AS biggest_window
FROM visit_gaps
GROUP BY user_id
ORDER BY user_id;
```

### Step-by-step explanation with one example

**1. Start with the supplied visits.** One output row is needed per user. For each visit, measure the days until that user's next visit; for their last visit, measure until `2021-01-01`. The answer is the largest of those gaps.

| user_id | visit_date |
|---:|---|
| 1 | 2020-11-28 |
| 1 | 2020-10-20 |
| 1 | 2020-12-03 |
| 2 | 2020-10-05 |
| 2 | 2020-12-09 |
| 3 | 2020-11-11 |

**2. Number visits separately for each user, newest first.** `PARTITION BY user_id` restarts the numbering for each user. `ORDER BY visit_date DESC` gives each user's latest visit `rn = 1`. The display order below is for inspection; the window's `ORDER BY` determines `rn`.

```sql
SELECT
    user_id,
    visit_date,
    ROW_NUMBER() OVER (
        PARTITION BY user_id
        ORDER BY visit_date DESC
    ) AS rn
FROM user_visits
ORDER BY user_id ASC, visit_date DESC;
```

| user_id | visit_date | rn |
|---:|---|---:|
| 1 | 2020-12-03 | 1 |
| 1 | 2020-11-28 | 2 |
| 1 | 2020-10-20 | 3 |
| 2 | 2020-12-09 | 1 |
| 2 | 2020-10-05 | 2 |
| 3 | 2020-11-11 | 1 |

**3. Pair each visit with the next newer visit.** Reference `ranked_visits` twice: `older` is the visit whose gap is measured, and `newer` has the same `user_id` and `rn = older.rn - 1`. The left join retains the `rn = 1` rows, which have no newer visit. `COALESCE` supplies `2021-01-01` for those rows.

```sql
WITH ranked_visits AS (
    SELECT
        user_id,
        visit_date,
        ROW_NUMBER() OVER (
            PARTITION BY user_id
            ORDER BY visit_date DESC
        ) AS rn
    FROM user_visits
)
SELECT
    older.user_id,
    older.visit_date,
    older.rn,
    newer.visit_date AS newer_visit,
    COALESCE(newer.visit_date, '2021-01-01') AS end_date
FROM ranked_visits AS older
LEFT JOIN ranked_visits AS newer
    ON older.user_id = newer.user_id
   AND newer.rn = older.rn - 1
ORDER BY older.user_id ASC, older.visit_date ASC;
```

| user_id | older.visit_date | rn | newer_visit | end_date |
|---:|---|---:|---|---|
| 1 | 2020-10-20 | 3 | 2020-11-28 | 2020-11-28 |
| 1 | 2020-11-28 | 2 | 2020-12-03 | 2020-12-03 |
| 1 | 2020-12-03 | 1 | NULL | 2021-01-01 |
| 2 | 2020-10-05 | 2 | 2020-12-09 | 2020-12-09 |
| 2 | 2020-12-09 | 1 | NULL | 2021-01-01 |
| 3 | 2020-11-11 | 1 | NULL | 2021-01-01 |

**4. Calculate each gap and take the largest per user.** In SQLite, subtracting date strings directly does not calculate elapsed days. `JULIANDAY(end_date) - JULIANDAY(older.visit_date)` gives the day difference. The direction matters: the later date comes first. `MAX` picks the largest gap within each `user_id` group, and `CAST(... AS INTEGER)` returns whole days.

| user_id | From | To | Gap in days |
|---:|---|---|---:|
| 1 | 2020-10-20 | 2020-11-28 | 39 |
| 1 | 2020-11-28 | 2020-12-03 | 5 |
| 1 | 2020-12-03 | 2021-01-01 | 29 |
| 2 | 2020-10-05 | 2020-12-09 | 65 |
| 2 | 2020-12-09 | 2021-01-01 | 23 |
| 3 | 2020-11-11 | 2021-01-01 | 51 |

`MAX` therefore gives 39 for user 1, 65 for user 2, and 51 for user 3. The final `ORDER BY user_id` produces:

| user_id | biggest_window |
|---:|---:|
| 1 | 39 |
| 2 | 65 |
| 3 | 51 |

**5. See how the `LEAD()` version reaches the same pairs.** With visits ordered **oldest first** inside `OVER`, `LEAD(visit_date, 1, '2021-01-01')` returns the next visit date. Its third argument supplies today's date for the final row, so no self-join is needed.

| user_id | visit_date | next_visit |
|---:|---|---|
| 1 | 2020-10-20 | 2020-11-28 |
| 1 | 2020-11-28 | 2020-12-03 |
| 1 | 2020-12-03 | 2021-01-01 |
| 2 | 2020-10-05 | 2020-12-09 |
| 2 | 2020-12-09 | 2021-01-01 |
| 3 | 2020-11-11 | 2021-01-01 |

The two queries produced the expected sample output in local SQLite. A single visit on `2020-12-01` also gives a 31-day window through `2021-01-01`. Duplicate visit dates can create zero-day intermediate gaps but do not change the largest gap.

## My solution — SQL Server

SQL Server uses `DATEDIFF(DAY, start_date, end_date)` in place of SQLite's `JULIANDAY` subtraction. The ranking, join, `LEAD()`, grouping, and output order stay the same.

**Approach 1 — `ROW_NUMBER()` and a left self-join**

```sql
WITH ranked_visits AS (
    SELECT
        user_id,
        visit_date,
        ROW_NUMBER() OVER (
            PARTITION BY user_id
            ORDER BY visit_date DESC
        ) AS rn
    FROM user_visits
)
SELECT
    older.user_id,
    MAX(DATEDIFF(
        DAY,
        older.visit_date,
        COALESCE(newer.visit_date, CAST('2021-01-01' AS date))
    )) AS biggest_window
FROM ranked_visits AS older
LEFT JOIN ranked_visits AS newer
    ON older.user_id = newer.user_id
   AND newer.rn = older.rn - 1
GROUP BY older.user_id
ORDER BY older.user_id;
```

**Approach 2 — `LEAD()`**

```sql
WITH visit_gaps AS (
    SELECT
        user_id,
        visit_date,
        LEAD(visit_date, 1, CAST('2021-01-01' AS date)) OVER (
            PARTITION BY user_id
            ORDER BY visit_date
        ) AS next_visit
    FROM user_visits
)
SELECT
    user_id,
    MAX(DATEDIFF(DAY, visit_date, next_visit)) AS biggest_window
FROM visit_gaps
GROUP BY user_id
ORDER BY user_id;
```
