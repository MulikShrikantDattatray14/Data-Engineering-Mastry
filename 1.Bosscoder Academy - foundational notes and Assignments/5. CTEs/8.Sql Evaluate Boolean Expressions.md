# 8. SQL Evaluate Boolean Expressions

## Question and image

**8. Sql Evaluate Boolean Expressions**

Table Variables:

| Column Name | Type |
|---|---|
| name | varchar |
| value | int |

In SQL, `name` is the primary key for this table.

This table contains the stored variables and their values.

Table Expressions:

| Column Name | Type |
|---|---|
| left_operand | varchar |
| operator | enum |
| right_operand | varchar |

In SQL, (`left_operand`, `operator`, `right_operand`) is the primary key for this table.

This table contains a boolean expression that should be evaluated.

`operator` is an enum that takes one of the values (`'<'`, `'>'`, `'='`).

The values of `left_operand` and `right_operand` are guaranteed to be in the Variables table.

Evaluate the boolean expressions in Expressions table.

**Example 1:**

Example:"

Input:

Variables table:

| name | value |
|---|---|
| x | 66 |
| y | 77 |

Expressions table:

| left_operand | operator | right_operand |
|---|---|---|
| x | > | y |
| x | < | y |
| x | = | y |
| y | > | x |
| y | < | x |
| x | = | x |

Output:

| left_operand | operator | right_operand | value |
|---|---|---|---|
| x | > | y | false |
| x | < | y | true |
| x | = | y | false |
| y | > | x | true |
| y | < | x | false |
| x | = | x | true |

*Explanation:*

As shown, you need to find the value of each boolean expression in the table using the variables table.

## Schema

**Variables**  
name, value

- `name` - varchar, primary key
- `value` - int

**Expressions**  
left_operand, operator, right_operand

- `left_operand` - varchar, guaranteed to exist in `Variables.name`
- `operator` - enum containing `'<'`, `'>'`, or `'='`
- `right_operand` - varchar, guaranteed to exist in `Variables.name`
- (`left_operand`, `operator`, `right_operand`) is the composite primary key.

## My solution — SQLite

```sql
SELECT
    E.left_operand,
    E.operator,
    E.right_operand,
    (
        CASE
            WHEN E.operator = '>'
                 AND L.value > R.value THEN 'true'
            WHEN E.operator = '<'
                 AND L.value < R.value THEN 'true'
            WHEN E.operator = '='
                 AND L.value = R.value THEN 'true'
            ELSE 'false'
        END
    ) AS value
FROM Expressions AS E
JOIN Variables AS L
    ON E.left_operand = L.name
JOIN Variables AS R
    ON E.right_operand = R.name;
```

### Step-by-step explanation with one example

Use the supplied example throughout. Each result below is produced from those same rows; the final query preserves your saved approach.

**Starting data**

`Variables`:

| name | value |
| --- | --- |
| x | 66 |
| y | 77 |

`Expressions`:

| left_operand | operator | right_operand |
| --- | --- | --- |
| x | > | y |
| x | < | y |
| x | = | y |
| y | > | x |
| y | < | x |
| x | = | x |

**1. Resolve the left operand to its stored value**

Expressions stores variable names, so attach the numeric value using a first alias of Variables.

```sql
SELECT E.left_operand, E.operator, E.right_operand,
       L.value AS left_value
FROM Expressions AS E
JOIN Variables AS L ON E.left_operand = L.name;
```

Result:

| left_operand | operator | right_operand | left_value |
| --- | --- | --- | --- |
| x | > | y | 66 |
| x | < | y | 66 |
| x | = | y | 66 |
| y | > | x | 77 |
| y | < | x | 77 |
| x | = | x | 66 |

Every expression whose left operand is x receives 66; those starting with y receive 77.

**2. Resolve the right operand independently**

Use a second alias of Variables because the right operand may name a different variable. Both values are needed on the same expression row.

```sql
SELECT E.left_operand, E.operator, E.right_operand,
       L.value AS left_value, R.value AS right_value
FROM Expressions AS E
JOIN Variables AS L ON E.left_operand = L.name
JOIN Variables AS R ON E.right_operand = R.name;
```

Result:

| left_operand | operator | right_operand | left_value | right_value |
| --- | --- | --- | --- | --- |
| x | > | y | 66 | 77 |
| x | < | y | 66 | 77 |
| x | = | y | 66 | 77 |
| y | > | x | 77 | 66 |
| y | < | x | 77 | 66 |
| x | = | x | 66 | 66 |

The x = x expression correctly gets 66 on both sides. Aliases L and R select two roles from the same table; they do not create new stored tables.

**3. Choose the comparison indicated by operator**

The operator column contains text, not executable SQL. CASE explicitly checks that text and performs the corresponding numeric comparison.

```sql
SELECT E.left_operand, E.operator, E.right_operand,
       L.value AS left_value, R.value AS right_value,
       CASE
           WHEN E.operator = '>' AND L.value > R.value THEN 'true'
           WHEN E.operator = '<' AND L.value < R.value THEN 'true'
           WHEN E.operator = '=' AND L.value = R.value THEN 'true'
           ELSE 'false'
       END AS value
FROM Expressions AS E
JOIN Variables AS L ON E.left_operand = L.name
JOIN Variables AS R ON E.right_operand = R.name;
```

Result:

| left_operand | operator | right_operand | left_value | right_value | value |
| --- | --- | --- | --- | --- | --- |
| x | > | y | 66 | 77 | false |
| x | < | y | 66 | 77 | true |
| x | = | y | 66 | 77 | false |
| y | > | x | 77 | 66 | true |
| y | < | x | 77 | 66 | false |
| x | = | x | 66 | 66 | true |

Each branch requires both the correct operator and a true comparison. For example, x > y is false because 66 is not greater than 77, even though x < y would be true.

**4. Assemble the final query**

Keep only the three original expression columns and the computed value, omitting the diagnostic numeric columns.

```sql
SELECT
    E.left_operand,
    E.operator,
    E.right_operand,
    (
        CASE
            WHEN E.operator = '>'
                 AND L.value > R.value THEN 'true'
            WHEN E.operator = '<'
                 AND L.value < R.value THEN 'true'
            WHEN E.operator = '='
                 AND L.value = R.value THEN 'true'
            ELSE 'false'
        END
    ) AS value
FROM Expressions AS E
JOIN Variables AS L
    ON E.left_operand = L.name
JOIN Variables AS R
    ON E.right_operand = R.name;
```

Final result for this example:

| left_operand | operator | right_operand | value |
| --- | --- | --- | --- |
| x | > | y | false |
| x | < | y | true |
| x | = | y | false |
| y | > | x | true |
| y | < | x | false |
| x | = | x | true |

**Check the result:** The true comparisons are 66 < 77, 77 > 66, and 66 = 66. The other three are false. This question does not require a particular row ordering.
