# 2. SQL Percentage Of Users Attended A Contest

## Question and image

**2. Sql Percentage Of Users Attended A Contest**

Table: Users

| Column Name | Type |
|---|---|
| user_id | int |
| user_name | varchar |

`user_id` is the primary key (column with unique values) for this table.

Each row of this table contains the name and the id of a user.

Table: Register

| Column Name | Type |
|---|---|
| contest_id | int |
| user_id | int |

(`contest_id`, `user_id`) is the primary key (combination of columns with unique values) for this table.

Each row of this table contains the id of a user and the contest they registered into.

Write a solution to find the percentage of the users registered in each contest rounded to two decimals.

Return the result table ordered by percentage in descending order. In case of a tie, order it by `contest_id` in ascending order.

*Explanation:*

All the users registered in contests 208, 209, and 210. The percentage is 100% and we sort them in the answer table by `contest_id` in ascending order.

## Schema

**Users**  
user_id, user_name

- `user_id` - int, primary key
- `user_name` - varchar

**Register**  
contest_id, user_id

- `contest_id` - int
- `user_id` - int
- (`contest_id`, `user_id`) is the composite primary key.

## My solution — SQLite

```sql
WITH total_users AS (
    SELECT
        COUNT(user_id) AS total_user_count
    FROM Users
)
SELECT
    R.contest_id,
    ROUND(
        COUNT(R.user_id) * 100.0 / T.total_user_count,
        2
    ) AS percentage
FROM Users AS U
JOIN Register AS R
    ON U.user_id = R.user_id
CROSS JOIN total_users AS T
GROUP BY R.contest_id, T.total_user_count
ORDER BY percentage DESC, R.contest_id ASC;
```

The denominator is every user in Users, not the number of registration rows or users in one contest.

```sql
WITH total_users AS (

SELECT * FROM total_users;
```

Alice, Bob, and Alex make three users. This single count is reused for every contest.

**2. Match each contest registration to its user**

Follow the saved join so every kept registration belongs to a user in Users.

```sql
SELECT R.contest_id, R.user_id, U.user_name
FROM Users AS U
JOIN Register AS R ON U.user_id = R.user_id
ORDER BY R.contest_id, R.user_id;
```

There are twelve registrations. One user may appear in several contests, but the composite key prevents that user appearing twice in the same contest.

**3. Attach the denominator and count each contest**

CROSS JOIN adds the one-row total to each registration. GROUP BY then reduces those rows to one count per contest.

```sql
WITH total_users AS (
    SELECT
        COUNT(user_id) AS total_user_count
    FROM Users
)
SELECT R.contest_id, COUNT(R.user_id) AS registered_users,
       T.total_user_count
FROM Users AS U
JOIN Register AS R ON U.user_id = R.user_id
CROSS JOIN total_users AS T
GROUP BY R.contest_id, T.total_user_count
ORDER BY R.contest_id;
```

Result:

| contest_id | registered_users | total_user_count |
| --- | --- | --- |
| 207 | 1 | 3 |
| 208 | 3 | 3 |
| 209 | 3 | 3 |
| 210 | 3 | 3 |
| 215 | 2 | 3 |

Contests 208, 209, and 210 each have all three users. Contest 215 has two, and 207 has one.

**4. Assemble the final query**

Calculate registered_users * 100.0 / total_user_count, round to two places, and apply percentage DESC then contest_id ASC for ties.

```sql
WITH total_users AS (
    SELECT
        COUNT(user_id) AS total_user_count
    FROM Users
)
SELECT
    R.contest_id,
    ROUND(
        COUNT(R.user_id) * 100.0 / T.total_user_count,
        2
    ) AS percentage
FROM Users AS U
JOIN Register AS R
    ON U.user_id = R.user_id
CROSS JOIN total_users AS T
GROUP BY R.contest_id, T.total_user_count
ORDER BY percentage DESC, R.contest_id ASC;
```
