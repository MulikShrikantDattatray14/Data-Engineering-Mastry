## My solution — SQLite

### Final solution

```sql
SELECT
    U.name,
    COALESCE(SUM(R.distance), 0) AS travelled_distance
FROM Users AS U
LEFT JOIN Rides AS R
    ON U.id = R.user_id
GROUP BY U.id, U.name
ORDER BY travelled_distance DESC, U.name ASC;
```

**1. Start with the users who must appear in the result.**

One output row represents one user. The result needs their name and total distance, including users with no rides. Therefore Users is the starting table; Rides supplies the distance records.

```sql
SELECT id, name
FROM Users
ORDER BY id;
```

Result:

| id | name |
| --- | --- |
| 1 | Alice |
| 2 | Bob |
| 3 | Alex |
| 4 | Donald |
| 7 | Lee |
| 13 | Jonathan |
| 19 | Elvis |

There are seven users, so this example needs seven final rows. Donald must remain even though none of the Rides rows belongs to him.

**2. Attach each user's rides while preserving unmatched users.**

Users.id identifies the user. Rides.user_id identifies who took a ride. Match these columns with LEFT JOIN so a missing ride does not remove its user.

```sql
SELECT
    U.id AS user_id,
    U.name,
    R.id AS ride_id,
    R.distance
FROM Users AS U
LEFT JOIN Rides AS R
    ON U.id = R.user_id
ORDER BY U.id, R.id;
```

Result:

| user_id | name | ride_id | distance |
| --- | --- | --- | --- |
| 1 | Alice | 1 | 120 |
| 2 | Bob | 2 | 317 |
| 3 | Alex | 3 | 222 |
| 4 | Donald | NULL | NULL |
| 7 | Lee | 4 | 100 |
| 7 | Lee | 7 | 120 |
| 7 | Lee | 9 | 230 |
| 13 | Jonathan | 5 | 312 |
| 19 | Elvis | 6 | 50 |
| 19 | Elvis | 8 | 400 |

Lee has three joined rows and Elvis has two because they took several rides. Donald has one placeholder row with NULL ride columns. The join produces ten rows: nine real rides plus Donald's placeholder. These repeated user names are expected at this stage.

**3. Group by each user's own ID and add their ride distances.**

GROUP BY U.id, U.name brings all rides for the same user into one group. The ID keeps different users separate even if their names are identical. Including U.name also makes this grouping valid in SQL Server.

```sql
SELECT
    U.id AS user_id,
    U.name,
    SUM(R.distance) AS total_before_zero_handling
FROM Users AS U
LEFT JOIN Rides AS R
    ON U.id = R.user_id
GROUP BY U.id, U.name
ORDER BY U.id;
```

Result:

| user_id | name | total_before_zero_handling |
| --- | --- | --- |
| 1 | Alice | 120 |
| 2 | Bob | 317 |
| 3 | Alex | 222 |
| 4 | Donald | NULL |
| 7 | Lee | 450 |
| 13 | Jonathan | 312 |
| 19 | Elvis | 450 |

Lee's group contains 100 + 120 + 230 = 450. Elvis's group contains 50 + 400 = 450. Donald's group contains only a NULL distance, so SUM returns NULL. Ten joined rows have now become seven user groups.

Do not define these groups using R.user_id: every user without a ride has NULL on that joined side, so multiple such users would collapse into a single group. U.id remains populated for each preserved user.

**4. Turn a missing total into zero.**

COALESCE takes the first non-NULL argument. Wrapping SUM(R.distance) means an existing total is kept, while a NULL total becomes 0.

```sql
SELECT
    U.id AS user_id,
    U.name,
    COALESCE(SUM(R.distance), 0) AS travelled_distance
FROM Users AS U
LEFT JOIN Rides AS R
    ON U.id = R.user_id
GROUP BY U.id, U.name
ORDER BY U.id;
```

Result:

| user_id | name | travelled_distance |
| --- | --- | --- |
| 1 | Alice | 120 |
| 2 | Bob | 317 |
| 3 | Alex | 222 |
| 4 | Donald | 0 |
| 7 | Lee | 450 |
| 13 | Jonathan | 312 |
| 19 | Elvis | 450 |

Only Donald's displayed total changes, from NULL to 0. Every user still has their own group. The user_id column is shown here only to make the group identity visible.

**5. Select the required columns and apply both sorting rules.**

Return name and travelled_distance. Sort distance descending so the largest total comes first. For equal totals, sort name ascending. The final query below combines all the steps and uses the corrected grouping.

```sql
SELECT
    U.name,
    COALESCE(SUM(R.distance), 0) AS travelled_distance
FROM Users AS U
LEFT JOIN Rides AS R
    ON U.id = R.user_id
GROUP BY U.id, U.name
ORDER BY travelled_distance DESC, U.name ASC;
```

Final result:

| name | travelled_distance |
| --- | --- |
| Elvis | 450 |
| Lee | 450 |
| Bob | 317 |
| Jonathan | 312 |
| Alex | 222 |
| Alice | 120 |
| Donald | 0 |

**Check the result:** Elvis and Lee both have 450, and Elvis comes first alphabetically. The remaining totals are Bob 317, Jonathan 312, Alex 222, Alice 120, and Donald 0. All seven users appear, and their totals sum to 1871, equal to the sum of the nine ride distances.

### Key learnings

- After a LEFT JOIN, group by the unique ID from the table whose rows you are preserving. Here that is U.id from Users.
- Grouping by R.user_id merges users without rides because their joined user IDs are all NULL. For example, if Donald and Sam both have no rides, they must still produce two separate rows with distance 0.
- Grouping by name alone can also merge different users with the same name. GROUP BY U.id, U.name preserves their identities and works in both SQLite and SQL Server.
- LEFT JOIN preserves a user without rides, but it does not automatically give that user a total of 0. Use COALESCE(SUM(R.distance), 0) for the required zero.
- Passing the supplied sample is not enough to check the grouping: this sample contains only one user without rides, so it does not expose the incorrect NULL group merge.
