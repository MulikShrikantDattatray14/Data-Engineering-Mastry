|---|---|

This table contains information about the transactions made during the visit_id.

Write a solution to find the IDs of the users who visited without making any transactions and the number of times they made these types of visits.

Return the result table sorted in **any order**.

The result format is in the following example.

**Example 1:**

**Input:**

Visits

| visit_id | customer_id |
|---|---|
| 1 | 23 |
| 2 | 9 |
| 4 | 30 |
| 5 | 54 |
| 6 | 96 |
| 7 | 54 |
| 8 | 54 |

Transactions

| transaction_id | visit_id | amount |
|---|---|---|
| 2 | 5 | 310 |
| 3 | 5 | 300 |
| 9 | 5 | 200 |
| 12 | 1 | 910 |
| 13 | 2 | 970 |

**Output:**

| customer_id | count_no_trans |
|---|---|
| 54 | 2 |
| 30 | 1 |
| 96 | 1 |

**Explanation:**

Customer with id = 23 visited the mall once and made one transaction during the visit with id = 12.

Customer with id = 9 visited the mall once and made one transaction during the visit with id = 13.

Customer with id = 30 visited the mall once and did not make any transactions.

Customer with id = 54 visited the mall three times. During 2 visits they did not make any transactions, and during one visit they made 3 transactions.

Customer with id = 96 visited the mall once and did not make any transactions.

As we can see, users with IDs 30 and 96 visited the mall one time without making any transactions. Also, user 54 visited the mall twice and did not make any transactions.

**Clarification of the supplied explanation:** The values `12` and `13` are transaction IDs; their corresponding visit IDs are `1` and `2`, respectively. The supplied explanation above is preserved as written.

## My solution — SQLite

```sql
SELECT
    V.customer_id,
    COUNT(*) AS count_no_trans
FROM Visits AS V
LEFT JOIN Transactions AS T
    ON V.visit_id = T.visit_id
WHERE T.transaction_id IS NULL
GROUP BY V.customer_id;
```

### Step-by-step explanation with one example

We need to **find visits with no transactions, then count those visits for each customer**. We follow the final query's `LEFT JOIN` approach using the same supplied example throughout.

**1. Understand what we are counting**

One customer can visit multiple times. Some visits may have transactions, while others may not.

For customer `54`:

- Visit `5` has transactions.
- Visit `7` has no transactions.
- Visit `8` has no transactions.

So customer `54` should appear with `count_no_trans = 2`.

We must examine **individual visits first**, then calculate a count for each customer.

**2. Start with the original tables**

`Visits`:

| visit_id | customer_id |
|---|---|
| 1 | 23 |
| 2 | 9 |
| 4 | 30 |
| 5 | 54 |
| 6 | 96 |
| 7 | 54 |
| 8 | 54 |

Each row represents **one visit**.

`Transactions`:

| transaction_id | visit_id | amount |
|---|---|---|
| 2 | 5 | 310 |
| 3 | 5 | 300 |
| 9 | 5 | 200 |
| 12 | 1 | 910 |
| 13 | 2 | 970 |

Each row represents **one transaction**.

Notice that visit `5` appears three times in `Transactions`. That means **one visit produced three transactions**.

The common column connecting these tables is `visit_id`.

**3. Attach transactions while keeping every visit**

Our thinking here is:

> For each visit, show its transactions. If there are none, still keep the visit.

That is why we use `LEFT JOIN`, with `Visits` on the left:

```sql
SELECT
    V.visit_id,
    V.customer_id,
    T.transaction_id,
    T.amount
FROM Visits AS V
LEFT JOIN Transactions AS T
    ON V.visit_id = T.visit_id;
```

The resulting rows are shown below, arranged by visit for readability:

| V.visit_id | V.customer_id | T.transaction_id | T.amount |
|---|---|---|---|
| 1 | 23 | 12 | 910 |
| 2 | 9 | 13 | 970 |
| 4 | 30 | NULL | NULL |
| 5 | 54 | 2 | 310 |
| 5 | 54 | 3 | 300 |
| 5 | 54 | 9 | 200 |
| 6 | 96 | NULL | NULL |
| 7 | 54 | NULL | NULL |
| 8 | 54 | NULL | NULL |

Two things happened:

- **Visit `5` became three joined rows** because it matched three transactions.
- **Visits `4`, `6`, `7`, and `8` were preserved**, with NULLs in the transaction columns because no matching transaction was found.

The seven original visits therefore became nine joined rows.

An ordinary `JOIN` would remove those unmatched visits, which are the visits we need to find.

**4. Keep only visits without a transaction**

Now our thinking is:

> Keep the rows where the join did not find a transaction.

Add:

```sql
WHERE T.transaction_id IS NULL
```

The query becomes:

```sql
SELECT
    V.visit_id,
    V.customer_id,
    T.transaction_id
FROM Visits AS V
LEFT JOIN Transactions AS T
    ON V.visit_id = T.visit_id
WHERE T.transaction_id IS NULL;
```

Result:

| visit_id | customer_id | transaction_id |
|---|---|---|
| 4 | 30 | NULL |
| 6 | 96 | NULL |
| 7 | 54 | NULL |
| 8 | 54 | NULL |

Why these rows remain:

- Visit `4`: no transaction.
- Visit `6`: no transaction.
- Visit `7`: no transaction.
- Visit `8`: no transaction.

Visits `1`, `2`, and all three joined rows for visit `5` are excluded.

**Every remaining row now represents one visit without a transaction.**

SQL checks for NULL using `IS NULL`. Writing `= NULL` does not perform this missing-value check.

**5. Group these visits by customer**

Now we have the correct visits, but customer `54` still appears twice.

Our thinking becomes:

> Put the qualifying visits belonging to the same customer into one group.

That is the purpose of:

```sql
GROUP BY V.customer_id
```

Using the four remaining rows, the groups are:

| customer_id | Qualifying visit IDs |
|---|---|
| 30 | 4 |
| 54 | 7, 8 |
| 96 | 6 |

We group by `customer_id` because the required output has **one row per customer**.

Grouping by `visit_id` would create one group per visit instead.

**6. Count the rows inside each customer's group**

Each remaining row is one qualifying visit, so we use:

```sql
COUNT(*) AS count_no_trans
```

`COUNT(*)` counts every row in the group. Compare the two counting expressions after filtering:

```sql
SELECT
    V.customer_id,
    COUNT(*),
    COUNT(T.transaction_id)
FROM Visits AS V
LEFT JOIN Transactions AS T
    ON V.visit_id = T.visit_id
WHERE T.transaction_id IS NULL
GROUP BY V.customer_id;
```

| customer_id | COUNT(*) | COUNT(T.transaction_id) |
|---|---|---|
| 30 | 1 | 0 |
| 54 | 2 | 0 |
| 96 | 1 | 0 |

`COUNT(T.transaction_id)` returns zero here because **every remaining transaction ID is NULL**, and `COUNT(column)` ignores NULL values.

For customer `54`, there are two rows to count, even though both have NULL transaction IDs.

**7. Assemble the final query**

```sql
SELECT
    V.customer_id,
    COUNT(*) AS count_no_trans
FROM Visits AS V
LEFT JOIN Transactions AS T
    ON V.visit_id = T.visit_id
WHERE T.transaction_id IS NULL
GROUP BY V.customer_id;
```

Read the query's logic in this order:

1. Start with the visits.
2. Attach matching transactions, preserving unmatched visits.
3. Keep only visits with no matching transaction.
4. Group those visits by customer.
5. Return each customer's ID and the number of visits in their group.

Final output:

| customer_id | count_no_trans |
|---|---|
| 30 | 1 |
| 54 | 2 |
| 96 | 1 |

No `ORDER BY` is required because the question accepts any order.

Manual check: customer `30` has visit `4`, customer `54` has visits `7` and `8`, and customer `96` has visit `6`. Customers `23` and `9` are excluded because their visits had transactions.

The join, filter, and final query were executed in SQLite; the intermediate results and final counts match this explanation.
