# 3. SQL Exchange Seats

## Question and image

**3. Sql Exchange Seats**

Table: Seat

| Column Name | Type |
|---|---|
| id | int |
| student | varchar |

id is the primary key (unique value) column for this table.

Each row of this table indicates the name and the ID of a student.

The ID sequence always starts from 1 and increments continuously.

Write a solution to swap the seat id of every two consecutive students. If the number of students is odd, the id of the last student is not swapped.

Return the result table ordered by id in ascending order.

**Example 1:**

Example:

Input:

Seat table:

| id | student |
|---|---|
| 1 | Abbot |
| 2 | Doris |
| 3 | Emerson |
| 4 | Green |
| 5 | Jeames |

Output:

| id | student |
|---|---|
| 1 | Doris |
| 2 | Abbot |
| 3 | Green |
| 4 | Emerson |
| 5 | Jeames |

Explanation:

Note that if the number of students is odd, there is no need to change the last one's seat.

## My solution — SQLite

```sql
SELECT
    CASE
        WHEN id % 2 = 0 THEN id - 1
        WHEN id % 2 = 1 AND (SELECT MAX(id) FROM Seat) > id THEN id + 1
        ELSE id
    END AS id,
    student
FROM Seat
ORDER BY id ASC;
```

### Step-by-step explanation with one example

We need the same students with new seat IDs: swap each consecutive pair and keep an unmatched final odd seat unchanged. Use the supplied Seat example throughout. The IDs start at 1 and are consecutive, so odd/even arithmetic identifies each pair.

**Starting data**

`Seat`:

| id | student |
| --- | --- |
| 1 | Abbot |
| 2 | Doris |
| 3 | Emerson |
| 4 | Green |
| 5 | Jeames |

**1. Find the last seat ID**

An odd seat can move forward only if the next seat exists. Because IDs are consecutive, comparing against MAX(id) tells us whether that odd seat is the last row.

```sql
SELECT MAX(id) AS last_id FROM Seat;
```

Result:

| last_id |
| --- |
| 5 |

The last ID is 5. It is odd, so its student must retain seat 5.

**2. Inspect which IDs are even or odd**

id % 2 is the remainder after division by 2: zero for even seats and one for odd seats. The CASE expression uses this to decide which direction to move.

```sql
SELECT id, student, id % 2 AS remainder
FROM Seat
ORDER BY id;
```

Result:

| id | student | remainder |
| --- | --- | --- |
| 1 | Abbot | 1 |
| 2 | Doris | 0 |
| 3 | Emerson | 1 |
| 4 | Green | 0 |
| 5 | Jeames | 1 |

Seats 2 and 4 will move back to 1 and 3. Seats 1 and 3 can move forward to 2 and 4. Seat 5 needs the final-seat exception.

**3. Calculate the new ID beside the original ID**

The first CASE branch moves even IDs back. The second moves odd IDs forward only when a later seat exists. ELSE keeps the unmatched final odd seat unchanged.

```sql
SELECT id AS original_id, student,
       CASE
           WHEN id % 2 = 0 THEN id - 1
           WHEN id % 2 = 1 AND (SELECT MAX(id) FROM Seat) > id THEN id + 1
           ELSE id
       END AS new_id
FROM Seat
ORDER BY original_id;
```

Result:

| original_id | student | new_id |
| --- | --- | --- |
| 1 | Abbot | 2 |
| 2 | Doris | 1 |
| 3 | Emerson | 4 |
| 4 | Green | 3 |
| 5 | Jeames | 5 |

The new IDs in original-row order are 2, 1, 4, 3, 5. No WHERE filter is needed: every student must remain.

**4. Assemble the final query**

Expose the calculated new_id under the required name id, keep student, and ORDER BY that output id. This sorts the exchanged seats into their final positions.

```sql
SELECT
    CASE
        WHEN id % 2 = 0 THEN id - 1
        WHEN id % 2 = 1 AND (SELECT MAX(id) FROM Seat) > id THEN id + 1
        ELSE id
    END AS id,
    student
FROM Seat
ORDER BY id ASC;
```

Final result for this example:

| id | student |
| --- | --- |
| 1 | Doris |
| 2 | Abbot |
| 3 | Green |
| 4 | Emerson |
| 5 | Jeames |

**Check the result:** Manual check: Abbot moves from 1 to 2 and Doris from 2 to 1; Emerson moves from 3 to 4 and Green from 4 to 3; Jeames stays at 5. There are still five students and five unique output seat IDs.
