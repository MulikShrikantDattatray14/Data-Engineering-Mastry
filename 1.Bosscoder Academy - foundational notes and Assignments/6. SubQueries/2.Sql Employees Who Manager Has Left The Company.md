# 2. SQL Employees Who Manager Has Left The Company

## Question and image

**2. Sql Employees Who Manager Has Left The Company**

Table: Employees

| Column Name | Type |
|---|---|
| employee_id | int |
| name | varchar |
| manager_id | int |
| salary | int |

In SQL, employee_id is the primary key for this table.

This table contains information about the employees, their salary, and the ID of their manager. Some employees do not have a manager (manager_id is null).

Find the IDs of the employees whose salary is strictly less than $30000 and whose manager left the company. When a manager leaves the company, their information is deleted from the Employees table, but the reports still have their manager_id set to the manager that left.

Return the result table ordered by employee_id.

**Example 1:**

Example:

Input:

Employees table:

| employee_id | name | manager_id | salary |
|---|---|---|---|
| 3 | Mila | 9 | 60301 |
| 12 | Antonella | null | 31000 |
| 13 | Emery | null | 67084 |
| 1 | Kalel | 11 | 21241 |
| 9 | Mikaela | null | 50937 |
| 11 | Joziah | 6 | 28485 |

Output:

| employee_id |
|---|
| 11 |

*Explanation:*

The employees with a salary less than $30000 are 1 (Kalel) and 11 (Joziah).

Kalel's manager is employee 11, who is still in the company (Joziah).

Joziah's manager is employee 6, who left the company because there is no row for employee 6 as it was deleted.

## Schema

**Employees**

| Column Name | Type |
|---|---|
| employee_id | int |
| name | varchar |
| manager_id | int |
| salary | int |

- `employee_id` is the primary key.
- `manager_id` is null for employees who do not have a manager.
- When a manager leaves, their row is deleted, while their reports retain that manager's ID in `manager_id`.

## My solution — SQLite

```sql
SELECT employee_id
FROM Employees
WHERE manager_id NOT IN (
    SELECT employee_id
    FROM Employees
)
  AND salary < 30000
ORDER BY employee_id;
```

### Step-by-step explanation with one example

We need employees earning strictly less than 30000 whose non-NULL manager ID no longer exists as an employee ID. Use the supplied Employees rows for every step. The same table is used once for candidate employees and once as the full list of people still employed.

**Starting data**

`Employees`:

| employee_id | name | manager_id | salary |
| --- | --- | --- | --- |
| 3 | Mila | 9 | 60301 |
| 12 | Antonella | NULL | 31000 |
| 13 | Emery | NULL | 67084 |
| 1 | Kalel | 11 | 21241 |
| 9 | Mikaela | NULL | 50937 |
| 11 | Joziah | 6 | 28485 |

**1. List all employees still in the company**

A manager is still present if their ID exists anywhere in Employees.employee_id. The subquery must include all employees, regardless of salary.

```sql
SELECT employee_id FROM Employees ORDER BY employee_id;
```

Result:

| employee_id |
| --- |
| 1 |
| 3 |
| 9 |
| 11 |
| 12 |
| 13 |

IDs 1, 3, 9, 11, 12, and 13 exist. ID 6 does not. Filtering this list by salary would wrongly treat some still-employed managers as missing.

**2. Identify employees below the salary threshold**

Salary is a condition on the employee whose ID we may return. It is strictly less than 30000, not less than or equal.

```sql
SELECT employee_id, name, manager_id, salary
FROM Employees
WHERE salary < 30000
ORDER BY employee_id;
```

Result:

| employee_id | name | manager_id | salary |
| --- | --- | --- | --- |
| 1 | Kalel | 11 | 21241 |
| 11 | Joziah | 6 | 28485 |

Kalel and Joziah are the candidates. Kalel's manager_id is 11; Joziah's is 6.

**3. Apply the missing-manager test to those candidates**

The outer manager_id is compared with the complete inner employee_id list. Both the missing-manager condition and salary condition must hold.

```sql
SELECT employee_id, name, manager_id, salary
FROM Employees
WHERE manager_id NOT IN (SELECT employee_id FROM Employees)
  AND salary < 30000
ORDER BY employee_id;
```

Result:

| employee_id | name | manager_id | salary |
| --- | --- | --- | --- |
| 11 | Joziah | 6 | 28485 |

Joziah remains because manager 6 is absent. Kalel is excluded because manager 11 is still employed. NULL manager_id means no manager; NOT IN evaluates to unknown for it and WHERE does not keep that row.

**4. Assemble the final query**

Return only employee_id and sort by it. The saved query keeps the same two independent filters.

```sql
SELECT employee_id
FROM Employees
WHERE manager_id NOT IN (
    SELECT employee_id
    FROM Employees
)
  AND salary < 30000
ORDER BY employee_id;
```

Final result for this example:

| employee_id |
| --- |
| 11 |

**Check the result:** Manual check: employee 1 earns 21241 but reports to existing employee 11, so fails. Employee 11 earns 28485 and reports to missing ID 6, so qualifies.
