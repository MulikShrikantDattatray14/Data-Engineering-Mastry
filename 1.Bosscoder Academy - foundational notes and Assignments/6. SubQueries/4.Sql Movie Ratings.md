## My solution — SQLite

```sql
SELECT name AS results
FROM (
    SELECT U.name
    FROM Users AS U
    JOIN MovieRating AS M ON U.user_id = M.user_id
    GROUP BY M.user_id
    ORDER BY COUNT(M.movie_id) DESC, U.name ASC
    LIMIT 1
) AS top_user

UNION ALL

SELECT title AS results
FROM (
    SELECT M1.title
    FROM Movies AS M1
    JOIN MovieRating AS M2 ON M1.movie_id = M2.movie_id
    WHERE M2.created_at > '2020-01-31'
      AND M2.created_at < '2020-03-01'
    GROUP BY M2.movie_id
    ORDER BY AVG(M2.rating) DESC, M1.title ASC
    LIMIT 1
) AS top_movie;
```

### Step-by-step explanation with one example

The output has one column named results and two rows: first the user who rated the most movies, then the movie with the highest February 2020 average. Use the supplied Users, Movies, and MovieRating rows throughout. Each half has its own grouping, tie-break, and one-row selection.

**Starting data**

`Movies`:

| movie_id | title |
| --- | --- |
| 1 | Avengers |
| 2 | Frozen 2 |
| 3 | Joker |

`Users`:

| user_id | name |
| --- | --- |
| 1 | Daniel |
| 2 | Monica |
| 3 | Maria |
| 4 | James |

`MovieRating`:

| movie_id | user_id | rating | created_at |
| --- | --- | --- | --- |
| 1 | 1 | 3 | 2020-01-12 |
| 1 | 2 | 4 | 2020-02-11 |
| 1 | 3 | 2 | 2020-02-12 |
| 1 | 4 | 1 | 2020-01-01 |
| 2 | 1 | 5 | 2020-02-17 |
| 2 | 2 | 2 | 2020-02-01 |
| 2 | 3 | 2 | 2020-03-01 |
| 3 | 1 | 3 | 2020-02-22 |
| 3 | 2 | 4 | 2020-02-25 |

**1. Attach user names to rating rows**

MovieRating contains user_id but the answer needs a user name. Join Users on user_id. Do not restrict dates here: the user question counts all rated movies.

```sql
SELECT U.user_id, U.name, M.movie_id, M.created_at
FROM Users AS U
JOIN MovieRating AS M ON U.user_id = M.user_id
ORDER BY U.user_id, M.movie_id;
```

Result:

| user_id | name | movie_id | created_at |
| --- | --- | --- | --- |
| 1 | Daniel | 1 | 2020-01-12 |
| 1 | Daniel | 2 | 2020-02-17 |
| 1 | Daniel | 3 | 2020-02-22 |
| 2 | Monica | 1 | 2020-02-11 |
| 2 | Monica | 2 | 2020-02-01 |
| 2 | Monica | 3 | 2020-02-25 |
| 3 | Maria | 1 | 2020-02-12 |
| 3 | Maria | 2 | 2020-03-01 |
| 4 | James | 1 | 2020-01-01 |

Daniel and Monica each have three rating rows, Maria has two, and James has one. The unique (movie_id, user_id) key means a user has at most one rating row for each movie.

**2. Count movies per user and resolve ties**

GROUP BY M.user_id creates one group per user. Sort the count descending to prefer the largest count, then the name ascending to prefer the lexicographically smaller name when counts tie.

```sql
SELECT U.name, COUNT(M.movie_id) AS movies_rated
FROM Users AS U
JOIN MovieRating AS M ON U.user_id = M.user_id
GROUP BY M.user_id
ORDER BY COUNT(M.movie_id) DESC, U.name ASC;
```

Result:

| name | movies_rated |
| --- | --- |
| Daniel | 3 |
| Monica | 3 |
| Maria | 2 |
| James | 1 |

Daniel comes before Monica because both counts are 3 and Daniel sorts before Monica. The unique Users.user_id ensures one user name per group in this SQLite query.

**3. Select the winning user**

LIMIT 1 is applied after the count and name sorting, so it selects exactly the first ranked user.

```sql
SELECT U.name
FROM Users AS U
JOIN MovieRating AS M ON U.user_id = M.user_id
GROUP BY M.user_id
ORDER BY COUNT(M.movie_id) DESC, U.name ASC
LIMIT 1;
```

Result:

| name |
| --- |
| Daniel |

The first output value will be Daniel.

**4. Attach titles and keep February ratings**

The movie half needs titles from Movies and ratings from MovieRating. Its date filter applies only to this half. For the supplied date-only values, dates after January 31 and before March 1 are exactly February 2020.

```sql
SELECT M1.title, M2.user_id, M2.rating, M2.created_at
FROM Movies AS M1
JOIN MovieRating AS M2 ON M1.movie_id = M2.movie_id
WHERE M2.created_at > '2020-01-31'
  AND M2.created_at < '2020-03-01'
ORDER BY M1.movie_id, M2.user_id;
```

Result:

| title | user_id | rating | created_at |
| --- | --- | --- | --- |
| Avengers | 2 | 4 | 2020-02-11 |
| Avengers | 3 | 2 | 2020-02-12 |
| Frozen 2 | 1 | 5 | 2020-02-17 |
| Frozen 2 | 2 | 2 | 2020-02-01 |
| Joker | 1 | 3 | 2020-02-22 |
| Joker | 2 | 4 | 2020-02-25 |

January ratings and Maria's March 1 rating are excluded before averaging. Each of the three movies has two February ratings.

**5. Compute the February average per movie and resolve ties**

Group the filtered rows by movie_id, calculate AVG(rating), then sort average descending and title ascending. Averaging before filtering would include ratings from the wrong months.

```sql
SELECT M1.title, AVG(M2.rating) AS average_rating
FROM Movies AS M1
JOIN MovieRating AS M2 ON M1.movie_id = M2.movie_id
WHERE M2.created_at > '2020-01-31'
  AND M2.created_at < '2020-03-01'
GROUP BY M2.movie_id
ORDER BY AVG(M2.rating) DESC, M1.title ASC;
```

Result:

| title | average_rating |
| --- | --- |
| Frozen 2 | 3.5 |
| Joker | 3.5 |
| Avengers | 3 |

Frozen 2 and Joker both average 3.5; Frozen 2 sorts first by title. Avengers averages 3.

**6. Select the winning movie**

Apply LIMIT 1 after both sorting rules, just as for the winning user.

```sql
SELECT M1.title
FROM Movies AS M1
JOIN MovieRating AS M2 ON M1.movie_id = M2.movie_id
WHERE M2.created_at > '2020-01-31'
  AND M2.created_at < '2020-03-01'
GROUP BY M2.movie_id
ORDER BY AVG(M2.rating) DESC, M1.title ASC
LIMIT 1;
```

Result:

| title |
| --- |
| Frozen 2 |

The second output value will be Frozen 2.

**7. Assemble the final query**

Wrap each ranked LIMIT 1 query as a derived table so its ORDER BY and LIMIT apply independently, then stack their values with UNION ALL. Both branches expose the same output label results. UNION ALL preserves two rows even if the winning user name equals the winning movie title.

```sql
SELECT name AS results
FROM (
    SELECT U.name
    FROM Users AS U
    JOIN MovieRating AS M ON U.user_id = M.user_id
    GROUP BY M.user_id
    ORDER BY COUNT(M.movie_id) DESC, U.name ASC
    LIMIT 1
) AS top_user

UNION ALL

SELECT title AS results
FROM (
    SELECT M1.title
    FROM Movies AS M1
    JOIN MovieRating AS M2 ON M1.movie_id = M2.movie_id
    WHERE M2.created_at > '2020-01-31'
      AND M2.created_at < '2020-03-01'
    GROUP BY M2.movie_id
    ORDER BY AVG(M2.rating) DESC, M1.title ASC
    LIMIT 1
) AS top_movie;
```

Final result for this example:

| results |
| --- |
| Daniel |
| Frozen 2 |

**Check the result:** Manual check: Daniel and Monica each rated three movies; Daniel wins alphabetically. February averages are Avengers = (4 + 2) / 2 = 3; Frozen 2 = (5 + 2) / 2 = 3.5; Joker = (3 + 4) / 2 = 3.5. Frozen 2 wins that title tie. The saved SQLite query produces Daniel and Frozen 2 as the two rows.

The date condition is explained against the schema's date-only values. The saved query has no outer ORDER BY for the compound result; the displayed row sequence is the observed local SQLite result. The original query is preserved.

## My solution — SQL Server

```sql
SELECT name AS results
FROM (
    SELECT TOP (1) U.name
    FROM Users AS U
    JOIN MovieRating AS M ON U.user_id = M.user_id
    GROUP BY M.user_id, U.name
    ORDER BY COUNT(M.movie_id) DESC, U.name ASC
) AS top_user

UNION ALL

SELECT title AS results
FROM (
    SELECT TOP (1) M1.title
    FROM Movies AS M1
    JOIN MovieRating AS M2 ON M1.movie_id = M2.movie_id
    WHERE M2.created_at > '2020-01-31'
      AND M2.created_at < '2020-03-01'
    GROUP BY M2.movie_id, M1.title
    ORDER BY AVG(CAST(M2.rating AS DECIMAL(18, 6))) DESC, M1.title ASC
) AS top_movie;
```
