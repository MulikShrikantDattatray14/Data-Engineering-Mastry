# 1. SQL Students With Invalid Departments

## Question and image

**1. Sql Students With Invalid Departments**

Table: Departments

| Column Name | Type |
|---|---|
| id | int |
| name | varchar |

In SQL, id is the primary key of this table.

The table has information about the id of each department of a university.

Table: Students

| Column Name | Type |
|---|---|
| id | int |
| name | varchar |
| department_id | int |

In SQL, id is the primary key of this table.

The table has information about the id of each student at a university and the id of the department he/she studies at.

Find the id and the name of all students who are enrolled in departments that no longer exist.

Return the result table ordered by id in ascending order

**Example 1:**

Example:

Input:

Departments table:

| id | name |
|---|---|
| 1 | Electrical Engineering |
| 7 | Computer Engineering |
| 13 | Bussiness Administration |

Students table:

| id | name | department_id |
|---|---|---|
| 23 | Alice | 1 |
| 1 | Bob | 7 |
| 5 | Jennifer | 13 |
| 2 | John | 14 |
| 4 | Jasmine | 77 |
| 3 | Steve | 74 |
| 6 | Luis | 1 |
| 8 | Jonathan | 7 |
| 7 | Daiana | 33 |
| 11 | Madelynn | 1 |

Output:

| id | name |
|---|---|
| 2 | John |
| 7 | Daiana |
| 4 | Jasmine |
| 3 | Steve |

*Explanation:*

John, Daiana, Steve, and Jasmine are enrolled in departments 14, 33, 74, and 77 respectively. department 14, 33, 74, and 77 do not exist in the Departments table.

## My solution — SQLite

```sql
SELECT
    id,
    name
FROM Students
WHERE department_id NOT IN (
    SELECT id
    FROM Departments
)
ORDER BY id ASC;
```

### Step-by-step explanation with one example

We need each student whose department_id does not refer to an existing Departments.id, with student IDs sorted ascending. Use the supplied Students and Departments examples throughout. A student's own id and their department_id have different meanings.

**Starting data**

`Departments`:

| id | name |
| --- | --- |
| 1 | Electrical Engineering |
| 7 | Computer Engineering |
| 13 | Bussiness Administration |

`Students`:

| id | name | department_id |
| --- | --- | --- |
| 23 | Alice | 1 |
| 1 | Bob | 7 |
| 5 | Jennifer | 13 |
| 2 | John | 14 |
| 4 | Jasmine | 77 |
| 3 | Steve | 74 |
| 6 | Luis | 1 |
| 8 | Jonathan | 7 |
| 7 | Daiana | 33 |
| 11 | Madelynn | 1 |

**1. Build the list of existing department IDs**

The subquery returns IDs of departments that still exist. It must read Departments.id, because this is the reference list against which the student's department_id is checked.

```sql
SELECT id FROM Departments ORDER BY id;
```

Result:

| id |
| --- |
| 1 |
| 7 |
| 13 |

The valid departments are 1, 7, and 13. These are department IDs, not student IDs.

**2. Keep students whose department is missing**

Test department_id NOT IN the complete existing-department list. Keep department_id in this diagnostic output so each exclusion is easy to verify.

```sql
SELECT id, name, department_id
FROM Students
WHERE department_id NOT IN (
    SELECT id FROM Departments
)
ORDER BY id ASC;
```

Result:

| id | name | department_id |
| --- | --- | --- |
| 2 | John | 14 |
| 3 | Steve | 74 |
| 4 | Jasmine | 77 |
| 7 | Daiana | 33 |

John refers to 14, Steve to 74, Jasmine to 77, and Daiana to 33. None of those department IDs appear in {1, 7, 13}. The other students reference existing departments.

**3. Assemble the final query**

Project only id and name, and retain ORDER BY id ASC. This preserves the saved NOT IN approach.

```sql
SELECT
    id,
    name
FROM Students
WHERE department_id NOT IN (
    SELECT id
    FROM Departments
)
ORDER BY id ASC;
```

Final result for this example:

| id | name |
| --- | --- |
| 2 | John |
| 3 | Steve |
| 4 | Jasmine |
| 7 | Daiana |

**Check the result:** Manual check: the missing departments are 14, 74, 77, and 33. Their students have IDs 2, 3, 4, and 7, respectively. The final query returns that ascending order.

The supplied sample output lists the same four students in a different order. The walkthrough output follows the explicit ascending-id requirement and the saved ORDER BY. Departments.id is a primary key, so the subquery does not introduce NULL IDs; a NULL student department_id would not pass NOT IN.
