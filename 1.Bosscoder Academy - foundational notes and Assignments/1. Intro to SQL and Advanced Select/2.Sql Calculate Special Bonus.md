# 2. SQL Calculate Special Bonus

## Question and image

Calculate a bonus for every employee. An employee receives 100% of their salary when their `employee_id` is odd **and** their name does not start with `M`. The bonus is `0` otherwise. Return `employee_id` and `bonus`, ordered by `employee_id`.

**Example 1**

Input — `Employees`:

| employee_id | name | salary |
|---:|---|---:|
| 2 | Meir | 3000 |
| 3 | Michael | 3800 |
| 7 | Addilyn | 7400 |
| 8 | Juan | 6100 |
| 9 | Kannon | 7700 |

Expected output:

| employee_id | bonus |
|---:|---:|
| 2 | 0 |
| 3 | 0 |
| 7 | 7400 |
| 8 | 0 |
| 9 | 7700 |

Employees 2 and 8 have even IDs. Employee 3 has an odd ID, but the name starts with `M`. Employees 7 and 9 meet both requirements and receive their full salaries.

## Schema

`Employees`:

| Column Name | Type |
|---|---|
| employee_id | int |
| name | varchar |
| salary | int |

`employee_id` is the primary key. Each row holds one employee's ID, name, and salary.

## My solution — SQLite

### Solution 1 — IIF

```sql
SELECT employee_id,
       IIF(employee_id % 2 = 1 AND name NOT LIKE 'M%', salary, 0) AS bonus
FROM Employees
ORDER BY employee_id;
```

`IIF(condition, value_if_true, value_if_false)` returns the salary only when both tests pass.

### Solution 2 — CASE

```sql
SELECT employee_id,
       CASE
           WHEN employee_id % 2 = 1 AND name NOT LIKE 'M%' THEN salary
           ELSE 0
       END AS bonus
FROM Employees
ORDER BY employee_id;
```

`CASE` spells out the two possible bonus values. The `ELSE 0` covers everyone who does not meet both conditions.

### Solution 3 — Boolean multiplication (my final query)

```sql
SELECT employee_id,
       salary * (employee_id % 2 = 1 AND name NOT LIKE 'M%') AS bonus
FROM Employees
ORDER BY employee_id;
```

In SQLite, a true condition acts like `1` and a false condition acts like `0` in arithmetic. This is concise for the given sample. If an odd-ID employee's `name` is `NULL`, the expression can produce a `NULL` bonus rather than the requested zero; Solution 2 handles that case explicitly.

### Step-by-step explanation with one example

**Starting data.** Each employee must remain in the result, even if their bonus is zero.

| employee_id | name | salary |
|---:|---|---:|
| 2 | Meir | 3000 |
| 3 | Michael | 3800 |
| 7 | Addilyn | 7400 |
| 8 | Juan | 6100 |
| 9 | Kannon | 7700 |

**1. Check whether each ID is odd.** `% 2` gives the remainder after division by two. An odd ID has remainder `1`.

```sql
SELECT employee_id, name, salary,
       employee_id % 2 AS remainder
FROM Employees
ORDER BY employee_id;
```

| employee_id | name | salary | remainder |
|---:|---|---:|---:|
| 2 | Meir | 3000 | 0 |
| 3 | Michael | 3800 | 1 |
| 7 | Addilyn | 7400 | 1 |
| 8 | Juan | 6100 | 0 |
| 9 | Kannon | 7700 | 1 |

Only employees 3, 7, and 9 pass the odd-ID test. Employees 2 and 8 must receive zero.

**2. Check the name.** `LIKE 'M%'` finds a name starting with `M`; `NOT LIKE` reverses that test. For this sample, SQLite displays `1` for true and `0` for false.

```sql
SELECT employee_id, name,
       name NOT LIKE 'M%' AS name_allowed
FROM Employees
ORDER BY employee_id;
```

| employee_id | name | name_allowed |
|---:|---|---:|
| 2 | Meir | 0 |
| 3 | Michael | 0 |
| 7 | Addilyn | 1 |
| 8 | Juan | 1 |
| 9 | Kannon | 1 |

Michael has an odd ID, but his name fails this test. Juan passes the name test, but his ID is even. Both requirements must be satisfied by the **same employee**.

**3. Combine the tests with AND.** Both tests true gives `1`; any failed test gives `0` for these non-NULL sample names.

```sql
SELECT employee_id, name, salary,
       (employee_id % 2 = 1 AND name NOT LIKE 'M%') AS eligible
FROM Employees
ORDER BY employee_id;
```

| employee_id | name | salary | eligible |
|---:|---|---:|---:|
| 2 | Meir | 3000 | 0 |
| 3 | Michael | 3800 | 0 |
| 7 | Addilyn | 7400 | 1 |
| 8 | Juan | 6100 | 0 |
| 9 | Kannon | 7700 | 1 |

**4. Calculate and order the bonus.** Multiply `salary` by `eligible`: `7400 × 1 = 7400`, while `3800 × 0 = 0`. Return only the requested ID and bonus.

```sql
SELECT employee_id,
       salary * (employee_id % 2 = 1 AND name NOT LIKE 'M%') AS bonus
FROM Employees
ORDER BY employee_id;
```

| employee_id | bonus |
|---:|---:|
| 2 | 0 |
| 3 | 0 |
| 7 | 7400 |
| 8 | 0 |
| 9 | 7700 |

`ORDER BY employee_id` gives the required ascending ID order. There are five input employees and five output rows; none are filtered away.

## My solution — SQL Server

Solutions 1 and 2 use the same `IIF` and `CASE` syntax in SQL Server:

```sql
-- Solution 1: IIF
SELECT employee_id,
       IIF(employee_id % 2 = 1 AND name NOT LIKE 'M%', salary, 0) AS bonus
FROM Employees
ORDER BY employee_id;
```

```sql
-- Solution 2: CASE
SELECT employee_id,
       CASE
           WHEN employee_id % 2 = 1 AND name NOT LIKE 'M%' THEN salary
           ELSE 0
       END AS bonus
FROM Employees
ORDER BY employee_id;
```

SQL Server does not use a Boolean condition as a numeric `0` or `1`, so Solution 3's multiplication cannot be copied directly. Its SQL Server equivalent keeps the same eligibility test and chooses the bonus with `CASE`:

```sql
-- SQL Server adaptation of Solution 3
SELECT employee_id,
       CASE
           WHEN employee_id % 2 = 1 AND name NOT LIKE 'M%' THEN salary
           ELSE 0
       END AS bonus
FROM Employees
ORDER BY employee_id;
```

This also gives zero when a name does not pass the test. Text case matching in SQL Server depends on the column's collation; SQLite's default `LIKE` ignores ASCII letter case.

## Official solution

The supplied handout uses Boolean multiplication, matching Solution 3:

```sql
SELECT employee_id,
       salary * (employee_id % 2 = 1 AND name NOT LIKE 'M%') AS bonus
FROM Employees
ORDER BY employee_id;
```

**What this tests:** `AND`, modulo `%`, text pattern filtering with `NOT LIKE`, and a calculated output column.

**The approach:** An odd ID and a name without the `M` prefix make the SQLite condition `1`; multiplying salary by it keeps the full salary. Otherwise the condition is `0` for the supplied sample and the bonus is zero.

**Why this way:** Every employee stays in the output, including employees with zero bonus. The calculation happens in `SELECT`, then the rows are ordered by ID.

**Common mistakes:** Using `OR` instead of `AND`, omitting `ORDER BY employee_id`, assuming Boolean multiplication works in SQL Server, or overlooking that a `NULL` name may yield a `NULL` bonus in SQLite.
