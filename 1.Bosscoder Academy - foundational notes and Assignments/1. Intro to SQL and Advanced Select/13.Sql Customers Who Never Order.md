# 13. SQL Customers Who Never Order

## Question and image

Find the names of all customers who have never placed an order. Return one column named `Customers`. No output order is specified.

**Example 1**

Input — `Customers`:

| id | name |
|---:|---|
| 1 | Joe |
| 2 | Henry |
| 3 | Sam |
| 4 | Max |

Input — `Orders`:

| id | customerId |
|---:|---:|
| 1 | 3 |
| 2 | 1 |

Expected output:

| Customers |
|---|
| Henry |
| Max |

Joe and Sam have orders; Henry and Max do not.

## Schema

`Customers`:

| Column Name | Type |
|---|---|
| id | int |
| name | varchar |

`id` is the primary key. Each row holds a customer ID and name.

`Orders`:

| Column Name | Type |
|---|---|
| id | int |
| customerId | int |

`id` is the primary key. `customerId` is a foreign key referencing `Customers.id`. Each row records an order and the customer who placed it.

## My solution — SQLite

```sql
SELECT name AS Customers
FROM Customers
WHERE id NOT IN (SELECT customerId FROM Orders);
```

### Step-by-step explanation with one example

**Starting data.** We need the names of customers whose IDs do not appear in `Orders.customerId`.

| Customers.id | Customers.name |
|---:|---|
| 1 | Joe |
| 2 | Henry |
| 3 | Sam |
| 4 | Max |

| Orders.id | Orders.customerId |
|---:|---:|
| 1 | 3 |
| 2 | 1 |

**1. Collect IDs that have ordered.** The subquery reads only `customerId` from `Orders`:

```sql
SELECT customerId
FROM Orders;
```

| customerId |
|---:|
| 3 |
| 1 |

These IDs belong to Sam and Joe. There is no need to join to `Orders` to get the final names; `Customers` already has them.

**2. Check each customer against those IDs.** For this example, `id NOT IN (3, 1)` is true only for IDs 2 and 4. The following SQLite query makes that comparison visible:

```sql
SELECT id, name,
       id NOT IN (SELECT customerId FROM Orders) AS never_ordered
FROM Customers;
```

| id | name | never_ordered |
|---:|---|---:|
| 1 | Joe | 0 |
| 2 | Henry | 1 |
| 3 | Sam | 0 |
| 4 | Max | 1 |

SQLite shows false as `0` and true as `1` here. Joe and Sam are excluded because their IDs appear in the subquery. Henry and Max remain.

**3. Return the requested column.** The final query keeps the true rows and renames `name` to `Customers`:

```sql
SELECT name AS Customers
FROM Customers
WHERE id NOT IN (SELECT customerId FROM Orders);
```

| Customers |
|---|
| Henry |
| Max |

The sample has no `NULL` in `Orders.customerId`. If that column can contain `NULL`, `NOT IN` can fail to return customers with no orders because the comparison becomes unknown. The prompt calls it a foreign key but does not explicitly say it is non-`NULL`. Filtering `NULL` values inside the subquery or using `NOT EXISTS` handles that case. This note does not change the saved final query.
