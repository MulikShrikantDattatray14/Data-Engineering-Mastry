# 5. SQL Game Play Analysis

## Question and image

**5. Sql Game Play Analysis**

Table: Activity

| Column Name | Type |
|---|---|
| player_id | int |
| device_id | int |
| event_date | date |
| games_played | int |

`(player_id, event_date)` is the primary key (combination of columns with unique values) of this table.

This table shows the activity of players of some games.

Each row is a record of a player who logged in and played a number of games (possibly 0) before logging out on someday using some device.

Write a solution to report the fraction of players that logged in again on the day after the day they first logged in, rounded to 2 decimal places. In other words, you need to determine the number of players who logged in on the day immediately following their initial login, and divide it by the number of total players.

The result format is in the following example.

**Example 1:**

Input:

Activity table:

| player_id | device_id | event_date | games_played |
|---|---|---|---|
| 1 | 2 | 2016-03-01 | 5 |
| 1 | 2 | 2016-03-02 | 6 |
| 2 | 3 | 2017-06-25 | 1 |
| 3 | 1 | 2016-03-02 | 0 |
| 3 | 4 | 2018-07-03 | 5 |

Output:

| fraction |
|---|
| 0.33 |

Explanation:

Only the player with id 1 logged back in after the first day he had logged in so the answer is 1/3 = 0.33

## My solution — SQLite

```sql
WITH total_players AS (
    SELECT
        COUNT(DISTINCT player_id) AS total_no_of_players
    FROM Activity
),
first_login AS (
    SELECT
        player_id,
        MIN(event_date) AS first_login_date
    FROM Activity
    GROUP BY player_id
),
logged_in_again AS (
    SELECT
        COUNT(A.player_id) AS count_of_returned
    FROM first_login AS F
    JOIN Activity AS A
        ON A.player_id = F.player_id
       AND A.event_date = DATE(F.first_login_date, '+1 day')
)
SELECT
    ROUND(
        count_of_returned * 1.0 / total_no_of_players,
        2
    ) AS fraction
FROM total_players
CROSS JOIN logged_in_again;
```

### Key learnings

- `COUNT(DISTINCT player_id)` calculates the denominator: the total number of players.
- `MIN(event_date)` grouped by `player_id` finds each player's first login before checking for a return.
- Looking for any two consecutive activity dates would be incorrect because the question specifically asks about the day after the first login.
- `A.player_id = F.player_id` ensures the next-day activity belongs to the same player.
- `A.event_date = DATE(F.first_login_date, '+1 day')` checks for activity exactly one calendar day after that player's first login in SQLite.
- Both join conditions are required: matching only the date could match a different player's activity.
- `logged_in_again` returns one count row, and `total_players` also returns one count row, so `CROSS JOIN` combines the two values into one row for division.
- Multiplying by `1.0` forces decimal division while keeping the result as a fraction. Multiplying by `100.0` would incorrectly produce a percentage.
- `ROUND(..., 2) AS fraction` produces the required output format.

### Step-by-step explanation with one example

Use the supplied example throughout. Each query below runs against these same starting rows; intermediate SELECT statements do not modify the tables.

**Starting data**

`Activity`:

| player_id | device_id | event_date | games_played |
| --- | --- | --- | --- |
| 1 | 2 | 2016-03-01 | 5 |
| 1 | 2 | 2016-03-02 | 6 |
| 2 | 3 | 2017-06-25 | 1 |
| 3 | 1 | 2016-03-02 | 0 |
| 3 | 4 | 2018-07-03 | 5 |

**1. Count all players**

The denominator is the number of different players, not the number of activity rows.

```sql
SELECT COUNT(DISTINCT player_id) AS total_no_of_players
FROM Activity;
```

Result:

| total_no_of_players |
| --- |
| 3 |

Five activity rows belong to 3 players. Even a login with games_played = 0 still counts as a login.

**2. Find each first login and the required return date**

MIN finds the first login within each player group. DATE adds exactly one calendar day to that date.

```sql
SELECT player_id, MIN(event_date) AS first_login_date,
       DATE(MIN(event_date), '+1 day') AS required_return_date
FROM Activity
GROUP BY player_id;
```

Result:

| player_id | first_login_date | required_return_date |
| --- | --- | --- |
| 1 | 2016-03-01 | 2016-03-02 |
| 2 | 2017-06-25 | 2017-06-26 |
| 3 | 2016-03-02 | 2016-03-03 |

The required return dates are March 2 for player 1, June 26 for player 2, and March 3 for player 3.

**3. Match a return to the same player and exact next day**

Both join conditions are necessary: the same player must have an activity row on their required return date.

```sql
WITH first_login AS (
    SELECT player_id, MIN(event_date) AS first_login_date
    FROM Activity
    GROUP BY player_id
)
SELECT F.player_id, F.first_login_date, A.event_date AS return_date
FROM first_login AS F
JOIN Activity AS A
    ON A.player_id = F.player_id
   AND A.event_date = DATE(F.first_login_date, '+1 day');
```

Result:

| player_id | first_login_date | return_date |
| --- | --- | --- |
| 1 | 2016-03-01 | 2016-03-02 |

Only player 1 has a matching return. Player 3 has later activity, but it is not the day after their first login.

**4. Count qualifying players**

The primary key allows at most one row per player on the required date, so counting the matched player rows counts qualifying players once.

```sql
WITH first_login AS (
    SELECT player_id, MIN(event_date) AS first_login_date
    FROM Activity
    GROUP BY player_id
)
SELECT COUNT(A.player_id) AS count_of_returned
FROM first_login AS F
JOIN Activity AS A
    ON A.player_id = F.player_id
   AND A.event_date = DATE(F.first_login_date, '+1 day');
```

Result:

| count_of_returned |
| --- |
| 1 |

The numerator is 1. The final CROSS JOIN puts it alongside the denominator of 3.

**5. Assemble the final query**

Combine the steps using the saved solution. The query below preserves the original logic.

```sql
WITH total_players AS (
    SELECT
        COUNT(DISTINCT player_id) AS total_no_of_players

        COUNT(A.player_id) AS count_of_returned
    FROM first_login AS F
    JOIN Activity AS A
        ON A.player_id = F.player_id

)
```

## My solution — SQL Server

```sql
WITH total_players AS (
    SELECT
        COUNT(DISTINCT player_id) AS total_no_of_players
    FROM Activity
),
first_login AS (
    SELECT
        player_id,
        MIN(event_date) AS first_login_date
    FROM Activity
    GROUP BY player_id
),
logged_in_again AS (
    SELECT
        COUNT(A.player_id) AS count_of_returned
    FROM first_login AS F
    JOIN Activity AS A
        ON A.player_id = F.player_id
       AND A.event_date = DATEADD(day, 1, F.first_login_date)
)
SELECT
    ROUND(
        count_of_returned * 1.0 / total_no_of_players,
        2
    ) AS fraction
FROM total_players
CROSS JOIN logged_in_again;
```

SQL Server uses `DATEADD(day, 1, date)` instead of SQLite's `DATE(date, '+1 day')`.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
