# 6. SQL Monthly Transactions I

## Question and image

**6. Sql Monthly Transactions I**

Table: Transactions

| Column Name | Type |
|---|---|
| id | int |
| country | varchar |
| state | enum |
| amount | int |
| trans_date | date |

`id` is the primary key of this table.

The table has information about incoming transactions.

The `state` column is an enum of type ["approved", "declined"].

Write an SQL query to find for each month and country, the number of transactions and their total amount, the number of approved transactions and their total amount.

The query result format is in the following example.

**Example 1:**

Input:

Transactions table:

| id | country | state | amount | trans_date |
|---|---|---|---|---|
| 121 | US | approved | 1000 | 2018-12-18 |
| 122 | US | declined | 2000 | 2018-12-19 |
| 123 | US | approved | 2000 | 2019-01-01 |
| 124 | DE | approved | 2000 | 2019-01-07 |

Output:

| month | country | trans_count | approved_count | trans_total_amount | approved_total_amount |
|---|---|---|---|---|---|
| 2018-12 | US | 2 | 1 | 3000 | 1000 |
| 2019-01 | DE | 1 | 1 | 2000 | 2000 |
| 2019-01 | US | 1 | 1 | 2000 | 2000 |

## Schema

## My solution — SQLite

```sql
WITH first_half AS (
    SELECT
        STRFTIME('%Y-%m', trans_date) AS month,
        country,
        COUNT(*) AS trans_count,
        SUM(amount) AS trans_total_amount
    FROM Transactions
    GROUP BY STRFTIME('%Y-%m', trans_date), country
),
second_half AS (
    SELECT
        STRFTIME('%Y-%m', trans_date) AS month,
        country,
        COUNT(*) AS approved_count,
        SUM(amount) AS approved_total_amount
    FROM Transactions
    WHERE state = 'approved'
    GROUP BY STRFTIME('%Y-%m', trans_date), country
)
SELECT
    first_half.month,
    first_half.country,
    first_half.trans_count,
    COALESCE(second_half.approved_count, 0) AS approved_count,
    first_half.trans_total_amount,
    COALESCE(second_half.approved_total_amount, 0)
        AS approved_total_amount
FROM first_half
LEFT JOIN second_half
    ON first_half.month = second_half.month
   AND first_half.country = second_half.country;
```

### Key learnings

- `STRFTIME('%Y-%m', trans_date)` creates a year-month value in SQLite. Including the year prevents the same month from different years from being merged.
- Grouping by the formatted month and `country` creates one summary for each exact month-country combination.
- `COUNT(*)` counts every transaction row. Unlike `COUNT(column)`, it does not skip rows because a selected column is `NULL`.
- `SUM(amount)` in `first_half` calculates the total amount of all approved and declined transactions in each group.
- `WHERE state = 'approved'` filters individual rows before grouping, so every aggregate in `second_half` represents approved transactions only.
- `WHERE` is correct for the state condition because it filters rows. `HAVING` is used when filtering groups based on an aggregate result.
- The join must match both `month` and `country`. Matching only one would combine summaries belonging to different countries or months.
- `first_half` contains every month-country group. `second_half` contains only groups with approved transactions.
- A `LEFT JOIN` preserves groups that contain only declined transactions. An inner join would remove those groups because they have no match in `second_half`.
- When no approved group exists, the joined approved values are `NULL`. `COALESCE(value, 0)` converts those missing values to zero.
- The final query selects `first_half.month` because `trans_date` is not exposed by either CTE.
- Qualifying columns with `first_half.` and `second_half.` prevents ambiguity when both CTEs contain columns with the same names.

### Step-by-step explanation with one example

Use the supplied example throughout. Each query below runs against these same starting rows; intermediate SELECT statements do not modify the tables.

**Starting data**

`Transactions`:

| id | country | state | amount | trans_date |
| --- | --- | --- | --- | --- |
| 121 | US | approved | 1000 | 2018-12-18 |
| 122 | US | declined | 2000 | 2018-12-19 |
| 123 | US | approved | 2000 | 2019-01-01 |
| 124 | DE | approved | 2000 | 2019-01-07 |

**1. Identify each transaction month**

The result needs one group per year-month and country. STRFTIME keeps the year as well as the month.

```sql
SELECT id, STRFTIME('%Y-%m', trans_date) AS month, country, state, amount
FROM Transactions;
```

Result:

| id | month | country | state | amount |
| --- | --- | --- | --- | --- |
| 121 | 2018-12 | US | approved | 1000 |
| 122 | 2018-12 | US | declined | 2000 |
| 123 | 2019-01 | US | approved | 2000 |
| 124 | 2019-01 | DE | approved | 2000 |

IDs 121 and 122 share December 2018 and US. The two January transactions belong to different country groups.

**2. Summarize all transactions**

The first_half CTE supplies every month-country group, including declined transactions.

```sql
SELECT STRFTIME('%Y-%m', trans_date) AS month, country,
       COUNT(*) AS trans_count, SUM(amount) AS trans_total_amount
FROM Transactions
GROUP BY STRFTIME('%Y-%m', trans_date), country;
```

Result:

| month | country | trans_count | trans_total_amount |
| --- | --- | --- | --- |
| 2018-12 | US | 2 | 3000 |
| 2019-01 | DE | 1 | 2000 |
| 2019-01 | US | 1 | 2000 |

For December US, two transactions sum to 3000. This full summary will be the left side of the join.

**3. Summarize approved transactions separately**

Filter rows with WHERE before grouping so both aggregates count only approved rows.

```sql
SELECT STRFTIME('%Y-%m', trans_date) AS month, country,
       COUNT(*) AS approved_count, SUM(amount) AS approved_total_amount
FROM Transactions
WHERE state = 'approved'
GROUP BY STRFTIME('%Y-%m', trans_date), country;
```

Result:

| month | country | approved_count | approved_total_amount |
| --- | --- | --- | --- |
| 2018-12 | US | 1 | 1000 |
| 2019-01 | DE | 1 | 2000 |
| 2019-01 | US | 1 | 2000 |

For December US, ID 122 is excluded, so the approved count is 1 and approved total is 1000. The January groups each have one approved row.

**4. Assemble the final query**

Combine the steps using the saved solution. The query below preserves the original logic.

```sql
WITH first_half AS (
    SELECT
        STRFTIME('%Y-%m', trans_date) AS month,
        country,
        COUNT(*) AS trans_count,
        SUM(amount) AS trans_total_amount
    FROM Transactions
    GROUP BY STRFTIME('%Y-%m', trans_date), country
),
second_half AS (
    SELECT
        STRFTIME('%Y-%m', trans_date) AS month,
        country,
        COUNT(*) AS approved_count,
        SUM(amount) AS approved_total_amount
    FROM Transactions
    WHERE state = 'approved'
    GROUP BY STRFTIME('%Y-%m', trans_date), country
)
SELECT
    first_half.month,
    first_half.country,
    first_half.trans_count,
    COALESCE(second_half.approved_count, 0) AS approved_count,
    first_half.trans_total_amount,
    COALESCE(second_half.approved_total_amount, 0)
        AS approved_total_amount
FROM first_half
LEFT JOIN second_half
    ON first_half.month = second_half.month
   AND first_half.country = second_half.country;
```

Final result for this example:

| month | country | trans_count | approved_count | trans_total_amount | approved_total_amount |
| --- | --- | --- | --- | --- | --- |
| 2018-12 | US | 2 | 1 | 3000 | 1000 |
| 2019-01 | DE | 1 | 1 | 2000 | 2000 |
| 2019-01 | US | 1 | 1 | 2000 | 2000 |

**Check the result:** The final LEFT JOIN matches both month and country. December US therefore returns 2 total transactions, 1 approved, 3000 total amount, and 1000 approved amount. COALESCE converts missing approved summaries to zero while preserving the full summary.

Limitation of the saved solution: the supplied sample has no NULL country. If country is NULL, first_half.country = second_half.country does not match the two NULL groups, so approved metrics become zero even when approved transactions exist for that month. The query is preserved as saved; this walkthrough confirms the supplied sample, not correctness for nullable countries.

## My solution — SQL Server

```sql
WITH first_half AS (
    SELECT
        CONVERT(CHAR(7), trans_date, 126) AS month,
        country,
        COUNT(*) AS trans_count,
        SUM(amount) AS trans_total_amount
    FROM Transactions
    GROUP BY CONVERT(CHAR(7), trans_date, 126), country
),
second_half AS (
    SELECT
        CONVERT(CHAR(7), trans_date, 126) AS month,
        country,
        COUNT(*) AS approved_count,
        SUM(amount) AS approved_total_amount
    FROM Transactions
    WHERE state = 'approved'
    GROUP BY CONVERT(CHAR(7), trans_date, 126), country
)
SELECT
    first_half.month,
    first_half.country,
    first_half.trans_count,
    COALESCE(second_half.approved_count, 0) AS approved_count,
    first_half.trans_total_amount,
    COALESCE(second_half.approved_total_amount, 0)
        AS approved_total_amount
FROM first_half
LEFT JOIN second_half
    ON first_half.month = second_half.month
   AND first_half.country = second_half.country;
```

SQL Server uses `CONVERT(CHAR(7), trans_date, 126)` to produce the `YYYY-MM` value instead of SQLite's `STRFTIME()`.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
