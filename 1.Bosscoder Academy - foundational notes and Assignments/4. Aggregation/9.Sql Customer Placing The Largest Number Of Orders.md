# 9. SQL Customer Placing The Largest Number Of Orders

## Question and image

**9. Sql Customer Placing The Largest Number Of Orders**

Table: Orders

| Column Name | Type |
|---|---|
| order_number | int |
| customer_number | int |

`order_number` is the primary key (column with unique values) for this table.

This table contains information about the order ID and the customer ID.

Write a solution to find the `customer_number` for the customer who has placed the largest number of orders.

The test cases are generated so that exactly one customer will have placed more orders than any other customer.

The result format is in the following example.

**Example 1:**

Input:

Orders table:

| order_number | customer_number |
|---|---|
| 1 | 1 |
| 2 | 2 |
| 3 | 3 |
| 4 | 3 |

Output:

| customer_number |
|---|
| 3 |

*Explanation:*

The customer with number 3 has two orders, which is greater than either customer 1 or 2 because each of them only has one order.

So the result is customer_number 3.

## Schema

**Orders**  
order_number, customer_number

- `order_number` — integer; primary key
- `customer_number` — integer
- Exactly one customer has the largest number of orders.

## My solution — SQLite

```sql
SELECT
    customer_number
FROM Orders
GROUP BY customer_number
ORDER BY COUNT(order_number) DESC
LIMIT 1;
```

### Key learnings

- `GROUP BY customer_number` creates one group containing all orders placed by each customer.
- `COUNT(order_number)` calculates the number of orders in each customer group.
- Aggregate functions cannot be directly nested as `MAX(COUNT(order_number))` in the same query level.
- `ORDER BY COUNT(order_number) DESC` sorts the customer groups from the highest order count to the lowest.
- The query selects `customer_number` because the required output is the customer's ID, not their order count.
- `LIMIT 1` keeps the first customer after sorting.
- The question guarantees one unique winner, so returning one row does not discard a tied customer.

### Step-by-step explanation with one example

Use the supplied example throughout. Each query below runs against these same starting rows; intermediate SELECT statements do not modify the tables.

**Starting data**

`Orders`:

| order_number | customer_number |
| --- | --- |
| 1 | 1 |
| 2 | 2 |
| 3 | 3 |
| 4 | 3 |

**1. Count orders per customer**

The output is a customer ID, but choosing that ID requires a count for every customer first.

```sql
SELECT customer_number, COUNT(order_number) AS order_count
FROM Orders
GROUP BY customer_number;
```

Result:

| customer_number | order_count |
| --- | --- |
| 1 | 1 |
| 2 | 1 |
| 3 | 2 |

Customers 1 and 2 each have one order. Customer 3 has two.

**2. Put the largest count first**

Sort grouped counts in descending order before taking a single row. The secondary sort below only makes the diagnostic ties easy to read.

```sql
SELECT customer_number, COUNT(order_number) AS order_count
FROM Orders
GROUP BY customer_number
ORDER BY COUNT(order_number) DESC, customer_number ASC;
```

Result:

| customer_number | order_count |
| --- | --- |
| 3 | 2 |
| 1 | 1 |
| 2 | 1 |

Customer 3 moves to the first row. There is no tie for the winner, as guaranteed by the prompt.

**3. Assemble the final query**

Combine the steps using the saved solution. The query below preserves the original logic.

```sql
SELECT
    customer_number
FROM Orders
GROUP BY customer_number
ORDER BY COUNT(order_number) DESC
LIMIT 1;
```

Final result for this example:

| customer_number |
| --- |
| 3 |

**Check the result:** LIMIT 1 keeps customer 3, and SELECT returns only customer_number as required. The count is used for sorting but does not have to appear in the final projection.

## My solution — SQL Server

```sql
SELECT TOP 1
    customer_number
FROM Orders
GROUP BY customer_number
ORDER BY COUNT(order_number) DESC;
```

SQL Server uses `TOP 1` in the `SELECT` clause instead of SQLite's trailing `LIMIT 1`.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
