# 7. SQL Game Play Analysis II

## Question and image

**7. Sql Game Play Analysis Ii**

Table: Activity

| Column Name | Type |
|---|---|
| player_id | int |
| device_id | int |
| event_date | date |
| games_played | int |

`(player_id, event_date)` is the primary key (combination of columns with unique values) of this table.

This table shows the activity of players of some games.

Each row is a record of a player who logged in and played a number of games (possibly 0) before logging out on someday using some device.

Write a solution to find the first login date for each player.

The result format is in the following example.

**Example 1:**

Input:

Activity table:

| player_id | device_id | event_date | games_played |
|---|---|---|---|
| 1 | 2 | 2016-03-01 | 5 |
| 1 | 2 | 2016-05-02 | 6 |
| 2 | 3 | 2017-06-25 | 1 |
| 3 | 1 | 2016-03-02 | 0 |
| 3 | 4 | 2018-07-03 | 5 |

| player_id | first_login |
|---|---|
| 1 | 2016-03-01 |
| 2 | 2017-06-25 |
| 3 | 2016-03-02 |

## Schema

**Activity**  
player_id, device_id, event_date, games_played

- `player_id` — integer
- `device_id` — integer
- `event_date` — date
- `games_played` — integer
- (`player_id`, `event_date`) is the primary key.

## My solution — SQLite

```sql
SELECT
    player_id,
    MIN(event_date) AS first_login
FROM Activity
GROUP BY player_id;
```

### Key learnings

- `GROUP BY player_id` creates a separate group, or bucket, for every player.
- `MIN(event_date)` calculates the earliest login date within each player's group.
- Without `GROUP BY player_id`, `MIN(event_date)` would return only one earliest date from the entire `Activity` table.
- `MIN()` returns the smallest value; it does not remove that value.
- `AS first_login` provides the exact output column name required by the question.
- No `ORDER BY` is needed because the question does not specify an output order.

### Step-by-step explanation with one example

Use the supplied example throughout. Each query below runs against these same starting rows; intermediate SELECT statements do not modify the tables.

**Starting data**

`Activity`:

| player_id | device_id | event_date | games_played |
| --- | --- | --- | --- |
| 1 | 2 | 2016-03-01 | 5 |
| 1 | 2 | 2016-05-02 | 6 |
| 2 | 3 | 2017-06-25 | 1 |
| 3 | 1 | 2016-03-02 | 0 |
| 3 | 4 | 2018-07-03 | 5 |

**1. Inspect only player and login date**

The first login depends on event_date; device_id and games_played do not decide which row is earliest.

```sql
SELECT player_id, event_date
FROM Activity
ORDER BY player_id, event_date;
```

Result:

| player_id | event_date |
| --- | --- |
| 1 | 2016-03-01 |
| 1 | 2016-05-02 |
| 2 | 2017-06-25 |
| 3 | 2016-03-02 |
| 3 | 2018-07-03 |

Player 1 has two dates, player 2 has one, and player 3 has two. Playing zero games does not remove a login.

**2. Take a minimum inside each player group**

Grouping by player keeps one player from influencing another player's earliest date. The diagnostic count makes the group sizes visible.

```sql
SELECT player_id, COUNT(*) AS login_count, MIN(event_date) AS first_login
FROM Activity
GROUP BY player_id;
```

Result:

| player_id | login_count | first_login |
| --- | --- | --- |
| 1 | 2 | 2016-03-01 |
| 2 | 1 | 2017-06-25 |
| 3 | 2 | 2016-03-02 |

The five source rows become three player rows. Each minimum is chosen only from that player's dates.

**3. Assemble the final query**

Combine the steps using the saved solution. The query below preserves the original logic.

```sql
SELECT
    player_id,
    MIN(event_date) AS first_login
FROM Activity
GROUP BY player_id;
```

Final result for this example:

| player_id | first_login |
| --- | --- |
| 1 | 2016-03-01 |
| 2 | 2017-06-25 |
| 3 | 2016-03-02 |

**Check the result:** Player 1 first logged in on 2016-03-01, player 2 on 2017-06-25, and player 3 on 2016-03-02. The final query removes the diagnostic count. A global MIN without GROUP BY would incorrectly return just one date for everyone.

## My solution — SQL Server

```sql
SELECT
    player_id,
    MIN(event_date) AS first_login
FROM Activity
GROUP BY player_id;
```

The same query works in SQLite and SQL Server.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
