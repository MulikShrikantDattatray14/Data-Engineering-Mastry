# 4. SQL Find Immediate Delivery II

## Question and image

**4. Sql Find Immediate Delivery Ii**

Table: Delivery

| Column Name | Type |
|---|---|
| delivery_id | int |
| customer_id | int |
| order_date | date |
| customer_pref_delivery_date | date |

`delivery_id` is the column of unique values of this table.

The table holds information about food delivery to customers that make orders at some date and specify a preferred delivery date (on the same order date or after it).

If the customer's preferred delivery date is the same as the order date, then the order is called immediate; otherwise, it is called scheduled.

The first order of a customer is the order with the earliest order date that the customer made. It is guaranteed that a customer has precisely one first order.

Write a solution to find the percentage of immediate orders in the first orders of all customers rounded to 2 decimals.

The result format is in the following example.

**Example 1:**

Input:

Delivery table:

| delivery_id | customer_id | order_date | customer_pref_delivery_date |
|---|---|---|---|
| 1 | 1 | 2019-08-01 | 2019-08-02 |
| 2 | 2 | 2019-08-02 | 2019-08-02 |
| 3 | 1 | 2019-08-11 | 2019-08-12 |
| 4 | 3 | 2019-08-24 | 2019-08-24 |
| 5 | 3 | 2019-08-21 | 2019-08-22 |
| 6 | 2 | 2019-08-11 | 2019-08-13 |
| 7 | 4 | 2019-08-09 | 2019-08-09 |

Output:

| immediate_percentage |
|---|
| 50.00 |

*Explanation:*

The customer id 1 has a first order with delivery id 1 and it is scheduled.
The customer id 2 has a first order with delivery id 2 and it is immediate.

The customer id 3 has a first order with delivery id 5 and it is scheduled.

The customer id 4 has a first order with delivery id 7 and it is immediate.

Hence, half the customers have immediate first orders.

## Schema

**Delivery**  
delivery_id, customer_id, order_date, customer_pref_delivery_date

- `delivery_id` — integer; unique
- `customer_id` — integer
- `order_date` — date
- `customer_pref_delivery_date` — date on or after `order_date`
- Every customer has exactly one earliest order.

## My solution — SQLite

```sql
WITH customer_count AS (
    SELECT
        COUNT(DISTINCT customer_id) AS total_customers
    FROM Delivery
),
first_order_of_each_customer AS (
    SELECT
        customer_id,
        MIN(order_date) AS first_order_date
    FROM Delivery
    GROUP BY customer_id
),
immediate_orders AS (
    SELECT
        COUNT(*) AS immediate_first_orders
    FROM Delivery AS D
    JOIN first_order_of_each_customer AS F
        ON D.customer_id = F.customer_id
       AND D.order_date = F.first_order_date
    WHERE D.order_date = D.customer_pref_delivery_date
)
SELECT
    ROUND(
        immediate_first_orders * 100.0 / total_customers,
        2
    ) AS immediate_percentage
FROM customer_count
CROSS JOIN immediate_orders;
```

### Key learnings

- The denominator is the number of customers because every customer has exactly one first order.
- The first-order CTE must find `MIN(order_date)` for each `customer_id` before testing whether an order is immediate.
- Filtering for immediate orders before finding the minimum date would find the earliest immediate order, which may not be the customer's actual first order.
- `D.customer_id = F.customer_id` connects each earliest-date result to the correct customer. By itself, it would still match all orders made by that customer.
- `D.order_date = F.first_order_date` removes the later orders and keeps only the row whose date equals that customer's earliest order date.
- Together, both join conditions recover the exact first-order row for each customer.
- After recovering those rows, `D.order_date = D.customer_pref_delivery_date` identifies which first orders were immediate.
- Both `customer_count` and `immediate_orders` return one row, so their `CROSS JOIN` places the two counts together for the percentage calculation.
- `100.0` forces decimal division, and `ROUND(..., 2)` rounds the result to two decimal places.

### Step-by-step explanation with one example

Use the supplied example throughout. Each query below runs against these same starting rows; intermediate SELECT statements do not modify the tables.

**Starting data**

`Delivery`:

| delivery_id | customer_id | order_date | customer_pref_delivery_date |
| --- | --- | --- | --- |
| 1 | 1 | 2019-08-01 | 2019-08-02 |
| 2 | 2 | 2019-08-02 | 2019-08-02 |
| 3 | 1 | 2019-08-11 | 2019-08-12 |
| 4 | 3 | 2019-08-24 | 2019-08-24 |
| 5 | 3 | 2019-08-21 | 2019-08-22 |
| 6 | 2 | 2019-08-11 | 2019-08-13 |
| 7 | 4 | 2019-08-09 | 2019-08-09 |

**1. Count customers for the denominator**

There is exactly one first order per customer, so count customers rather than all seven deliveries.

```sql
SELECT COUNT(DISTINCT customer_id) AS total_customers
FROM Delivery;
```

Result:

| total_customers |
| --- |
| 4 |

The denominator is 4. Later orders do not add another customer.

**2. Find the first order date for each customer**

Find the earliest order before testing whether it was immediate. Filtering for immediate orders first would change what first means.

```sql
SELECT customer_id, MIN(order_date) AS first_order_date
FROM Delivery
GROUP BY customer_id;
```

Result:

| customer_id | first_order_date |
| --- | --- |
| 1 | 2019-08-01 |
| 2 | 2019-08-02 |
| 3 | 2019-08-21 |
| 4 | 2019-08-09 |

Customer 3 first ordered on August 21, even though their August 24 order is immediate.

**3. Recover the exact first-order rows**

Join each earliest date back to Delivery using both customer and date so later orders are excluded.

```sql
WITH first_order_of_each_customer AS (
    SELECT customer_id, MIN(order_date) AS first_order_date
    FROM Delivery
    GROUP BY customer_id
)
SELECT D.delivery_id, D.customer_id, D.order_date, D.customer_pref_delivery_date
FROM Delivery AS D
JOIN first_order_of_each_customer AS F
    ON D.customer_id = F.customer_id
   AND D.order_date = F.first_order_date
ORDER BY D.customer_id;
```

Result:

| delivery_id | customer_id | order_date | customer_pref_delivery_date |
| --- | --- | --- | --- |
| 1 | 1 | 2019-08-01 | 2019-08-02 |
| 2 | 2 | 2019-08-02 | 2019-08-02 |
| 5 | 3 | 2019-08-21 | 2019-08-22 |
| 7 | 4 | 2019-08-09 | 2019-08-09 |

Delivery IDs 1, 2, 5, and 7 are the four first orders. ID 4 is correctly excluded despite being immediate.

**4. Count immediate first orders**

Apply the equality test only to those recovered first orders. This is the numerator CTE in the saved solution.

```sql
WITH first_order_of_each_customer AS (
    SELECT customer_id, MIN(order_date) AS first_order_date
    FROM Delivery
    GROUP BY customer_id
)
SELECT COUNT(*) AS immediate_first_orders
FROM Delivery AS D
JOIN first_order_of_each_customer AS F
    ON D.customer_id = F.customer_id
   AND D.order_date = F.first_order_date
WHERE D.order_date = D.customer_pref_delivery_date;
```

Result:

| immediate_first_orders |
| --- |
| 2 |

Only IDs 2 and 7 meet the date equality, giving 2 immediate first orders.

**5. Assemble the final query**

Combine the steps using the saved solution. The query below preserves the original logic.

```sql
WITH customer_count AS (
    SELECT
        COUNT(DISTINCT customer_id) AS total_customers
    FROM Delivery
),
first_order_of_each_customer AS (
    SELECT
        customer_id,
        MIN(order_date) AS first_order_date
    FROM Delivery
    GROUP BY customer_id
),
immediate_orders AS (
    SELECT
        COUNT(*) AS immediate_first_orders
    FROM Delivery AS D
    JOIN first_order_of_each_customer AS F
        ON D.customer_id = F.customer_id
       AND D.order_date = F.first_order_date
    WHERE D.order_date = D.customer_pref_delivery_date
)
SELECT
    ROUND(
        immediate_first_orders * 100.0 / total_customers,
        2
    ) AS immediate_percentage
FROM customer_count
CROSS JOIN immediate_orders;
```

Final result for this example:

| immediate_percentage |
| --- |
| 50 |

**Check the result:** The final CROSS JOIN combines the one-row counts: 2 immediate first orders / 4 customers * 100 = 50%. ROUND preserves two-decimal precision; a SQLite client can display the numeric result as 50 rather than 50.00.

> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation.
