## 1. Clean and inspect text

A function in `SELECT` calculates an output value; it does not update stored text. Single quotes delimit text: `'Mira''s account'` contains one apostrophe inside the value.

Use one running value: `'  mIRA.PATEL@example.com  '`, with two spaces at each end.

```sql
SELECT TRIM('  mIRA.PATEL@example.com  ') AS trimmed,
       LOWER(TRIM('  mIRA.PATEL@example.com  ')) AS cleaned,
       UPPER('mira') AS uppercase;
```

| trimmed | cleaned | uppercase |
|---|---|---|
| mIRA.PATEL@example.com | mira.patel@example.com | MIRA |

Read nested functions from inside out: trim first, then lowercase. `LTRIM` removes leading spaces, `RTRIM` trailing spaces, and `TRIM` both. Internal spaces remain.

| SQLite expression | Result | Meaning |
|---|---|---|
| `TRIM('  Mira  Patel  ')` | `Mira  Patel` | Internal double space remains |
| `REPLACE('Mira.Patel', '.', ' ')` | `Mira Patel` | Replace matching substrings |
| `REPLACE('ID-ID-7', 'ID-', '')` | `7` | Empty replacement removes matches |
| `RTRIM('codexyx', 'xy')` | `code` | Remove any trailing x or y |
| `LENGTH('')` | 0 | Empty text has known length zero |
| `LENGTH(NULL)` | NULL | Unknown text has unknown length |

SQLite's optional trim argument is a **character set**, not an exact word. Default trimming removes ordinary spaces, not every whitespace character. Built-in `LOWER`/`UPPER` handle ASCII case; do not assume complete international case conversion. [SQLite core functions](https://www.sqlite.org/lang_corefunc.html)

SQL Server `TRIM(text)` is available from 2017; earlier versions use `LTRIM(RTRIM(text))`. Its custom form is `TRIM('xy' FROM text)`. SQL Server 2022's directional trim and optional characters for `LTRIM`/`RTRIM` require compatibility level 160. [SQL Server TRIM](https://learn.microsoft.com/en-us/sql/t-sql/functions/trim-transact-sql), [RTRIM](https://learn.microsoft.com/en-us/sql/t-sql/functions/rtrim-transact-sql)

```sql
SELECT LENGTH('  mIRA.PATEL@example.com  ') AS raw_length,
       LENGTH(TRIM('  mIRA.PATEL@example.com  ')) AS clean_length,
       INSTR('mira.patel@example.com', '@') AS at_position,
       INSTR('mira.patel@example.com', '#') AS missing_position;
```

| raw_length | clean_length | at_position | missing_position |
|---:|---:|---:|---:|
| 26 | 22 | 11 | 0 |

Positions start at **1**; a missing separator gives 0. Clean first when boundary spaces are not meaningful.

| Need | SQLite | SQL Server | MySQL |
|---|---|---|---|
| Character length | `LENGTH(text)` | `LEN(text)`, excluding trailing spaces | `CHAR_LENGTH(text)` |
| Byte length | `LENGTH(CAST(text AS BLOB))` | `DATALENGTH(text)` | `LENGTH(text)` |
| Locate `@` | `INSTR(text, '@')` | `CHARINDEX('@', text)` | `LOCATE('@', text)` |

`LENGTH('A ')` is 2 in SQLite, but `LEN('A ')` is 1 in SQL Server. Bytes are not characters; a Unicode code point is not always a whole visible symbol either. Notice the argument order changes for searching. [SQL Server LEN](https://learn.microsoft.com/en-us/sql/t-sql/functions/len-transact-sql), [MySQL string functions](https://dev.mysql.com/doc/refman/8.4/en/string-functions.html)

## 2. Extract and combine text

`SUBSTR(text, start, length)` means “take this many characters beginning here.” The final argument is a length, not an ending position.

```sql
SELECT SUBSTR('mira.patel@example.com', 1, 10) AS local_part,
       SUBSTR('mira.patel@example.com', 12) AS domain,
       SUBSTR('mira.patel@example.com', -3) AS ending;
```

| local_part | domain | ending |
|---|---|---|
| mira.patel | example.com | com |

SQLite permits an omitted length and a negative start counted from the right. SQL Server's broadly supported form is `SUBSTRING(text, start, length)`; `LEFT(text,n)` and `RIGHT(text,n)` handle ends. SQLite also accepts `SUBSTRING` as an alias from 3.34 onward. [SQLite SUBSTR](https://www.sqlite.org/lang_corefunc.html#substr)

For a variable separator, calculate its position:

```sql
WITH cleaned AS (
    SELECT LOWER(TRIM('  mIRA.PATEL@example.com  ')) AS email
), located AS (
    SELECT email, INSTR(email, '@') AS at_position FROM cleaned
)
SELECT SUBSTR(email, 1, at_position - 1) AS local_part,
       SUBSTR(email, at_position + 1) AS domain
FROM located
WHERE at_position > 0;
```

Output: `mira.patel | example.com`. Subtract 1 to exclude `@` from the left piece; add 1 to skip it for the right piece. This is extraction, not complete email validation.

SQLite `||` combines values within one row:

```sql
SELECT 'Mira' || ' ' || 'Patel' AS full_name,
       'Mira' || NULL AS unknown_join,
       'Mira' || COALESCE(NULL, '') AS handled_join,
       COALESCE('', 'unknown') AS empty_is_not_null;
```

| full_name | unknown_join | handled_join | empty_is_not_null |
|---|---|---|---|
| Mira Patel | NULL | Mira | empty string |

`COALESCE` chooses the first non-NULL expression; it does not replace `''`. Decide how missing components should appear rather than inserting replacements automatically.

SQLite 3.44+ and SQL Server support `CONCAT` treating NULL arguments as empty text; MySQL `CONCAT` instead returns NULL if an argument is NULL. `CONCAT_WS('-', 'Mira', NULL, 'Patel')` skips the NULL and gives `Mira-Patel` in these engines. An empty string is retained, so replacing NULL with `''` gives `Mira--Patel`. SQL Server has `CONCAT_WS` from 2017. [SQLite 3.44](https://www.sqlite.org/releaselog/3_44_0.html), [SQL Server CONCAT_WS](https://learn.microsoft.com/en-us/sql/t-sql/functions/concat-ws-transact-sql)

## 3. LIKE and GLOB

Use `=` for an exact comparison. `LIKE` describes simple wildcard patterns; SQLite `GLOB` adds case-sensitive Unix-style patterns and character groups. **GLOB is not regex.**

| Need | SQLite LIKE | SQLite GLOB |
|---|---|---|
| Starts with A | `'A%'` | `'A*'` |
| Ends with n | `'%n'` | `'*n'` |
| Contains ost | `'%ost%'` | `'*ost*'` |
| One character between A and C | `'A_C'` | `'A?C'` |
| Starts with a listed letter | No bracket-set syntax | `'[ABC]*'` |

`%` and `*` match any-length text, including empty text. `_` and `?` match exactly one character. Both operators match the whole value; surrounding wildcards permit surrounding text.

```sql
SELECT 'ABC' LIKE 'A_C' AS like_one,
       'ABC' GLOB 'A?C' AS glob_one,
       'AC' LIKE 'A_C' AS too_short,
       'ABBC' GLOB 'A?C' AS too_long;
```

| like_one | glob_one | too_short | too_long |
|---:|---:|---:|---:|
| 1 | 1 | 0 | 0 |

```sql
SELECT 'AUSTIN' LIKE '[AEIOU]%' AS like_brackets,
       'AUSTIN' GLOB '[AEIOU]*' AS glob_brackets,
       'austin' LIKE 'A%' AS like_case,
       'austin' GLOB 'A*' AS glob_case;
```

| like_brackets | glob_brackets | like_case | glob_case |
|---:|---:|---:|---:|
| 0 | 1 | 1 | 0 |

SQLite LIKE treats brackets literally and normally ignores ASCII case. GLOB is case-sensitive: `[AEIOUaeiou]` includes both vowel cases. A bracket group consumes one character; the following `*` allows **any** remaining text, not just more vowels. Ranges such as `[A-Z]` and negated groups such as `[^0-9]` are supported. [SQLite pattern operators](https://www.sqlite.org/lang_expr.html#like)

```sql
SELECT '50%' LIKE '50!%' ESCAPE '!' AS literal_percent,
       'A*' GLOB 'A[*]' AS literal_star;
```

Both results are 1. LIKE has an `ESCAPE` clause; GLOB uses bracket quoting for this literal asterisk. Backslash is not a universal escape character. `%` and `_` are ordinary characters in GLOB.

SQL Server LIKE supports `%`, `_`, bracket groups and negated groups. Its case/range behavior depends on collation. For explicit ASCII-style comparisons, an appropriate binary collation can help:

```sqlserver
SELECT CASE WHEN N'austin' COLLATE Latin1_General_100_BIN2
                      LIKE N'[AEIOUaeiou]%'
            THEN 1 ELSE 0 END AS starts_with_vowel;
```

Expected result: 1. Apply the intended collation to displayed values too when `DISTINCT` must use the same case distinctions. Trailing spaces and Unicode/non-Unicode matching can affect suffix checks; test the actual column type. [SQL Server LIKE](https://learn.microsoft.com/en-us/sql/t-sql/language-elements/like-transact-sql)

## 4. Combine boundary conditions

Define A = “does not start with a vowel” and B = “does not end with a vowel.”

| City | A | B | A OR B | A AND B |
|---|---|---|---|---|
| Austin | False | True | True | False |
| Chicago | True | False | True | False |
| Boston | True | True | True | True |
| Oslo | False | False | False | False |

`OR` permits either condition; `AND` requires both. Do not replace one with the other because the sample happens to look similar. Parenthesize alternatives when adding another condition because `AND` binds more tightly than `OR`.

SQLite initial-vowel test: `city GLOB '[AEIOUaeiou]*'`. Final-vowel test: `city GLOB '*[AEIOUaeiou]'`. `NOT GLOB` reverses each complete match. `[^AEIOUaeiou]*` requires a first nonvowel character, whereas negating the initial-vowel pattern also accepts empty text; those forms differ for `''`. NULL produces unknown and does not pass WHERE.

`SELECT DISTINCT city` removes repeated selected city names. `SELECT DISTINCT *` compares complete rows, so two stations with different IDs can still display the same city twice. Pattern matching and duplicate removal are separate decisions.

## 5. Regular expressions

A regex describes character types, repetition and alternatives. Verify engine support before copying one:

| Engine | Support |
|---|---|
| SQLite core | No default `regexp()` implementation; an application or extension must supply it |
| MySQL 8 | Native regex functions using ICU |
| SQL Server 2022 and earlier | No native functions shown below; LIKE/PATINDEX are wildcard patterns |
| SQL Server 2025 | Native RE2-based regex; REGEXP_LIKE needs compatibility 170+ |

Other SQL Server scalar regex functions are available at all compatibility levels on supported engine versions. [SQLite REGEXP](https://www.sqlite.org/lang_expr.html#regexp), [MySQL regex](https://dev.mysql.com/doc/refman/8.4/en/regexp.html), [SQL Server support](https://learn.microsoft.com/en-us/sql/t-sql/functions/regexp-like-transact-sql#platform-support)

### Build the rule in pieces

For ordinary single-line ASCII text:

| Regex piece | Meaning | Example |
|---|---|---|
| `^` and `$` | Start and end anchors | `^AB$` accepts only AB |
| `[A-Z]`, `[0-9]` | One character from a range | `Q`, `7` |
| `[^0-9]` | One character outside that set | A or !, not 7 |
| `.` | One character, normally not newline | `h.t` matches hat |
| `[.]` | Literal dot | `a[.]b` matches a.b |
| `*`, `+`, `?` | Zero or more; one or more; optional | `ab*` accepts a; `ab+` does not |
| `{3}`, `{2,}`, `{2,4}` | Exactly 3; at least 2; between 2 and 4 | `[0-9]{3}` matches 007 |
| `(ab)+` | Repeat a grouped sequence | ab, abab |
| `cat\|dog` | Either alternative | cat or dog |

A quantifier repeats the preceding item: regex `A*` repeats A; GLOB `A*` means A followed by arbitrary text. Regex matching can find a substring unless anchored. Group alternatives as `^(cat|dog)$`; `^cat|dog$` has different start/end requirements. The backslash before a pipe in the table is only Markdown escaping.

Rule: **two uppercase letters, a hyphen, then three digits** becomes `^[A-Z]{2}-[0-9]{3}$`.

| Input | Matches? |
|---|---|
| AB-007 | Yes |
| XY-900 | Yes |
| ab-007 | No: wrong case |
| A-007 | No: missing letter |
| AB-07 | No: missing digit |
| AB-007X | No: extra suffix |

```mysql
SELECT REGEXP_LIKE('AB-007', '^[A-Z]{2}-[0-9]{3}$', 'c') AS matches;
```

Expected result: 1. For SQL Server 2025, use its Boolean condition inside CASE:

```sqlserver
SELECT CASE WHEN REGEXP_LIKE('AB-007', '^[A-Z]{2}-[0-9]{3}$', 'c')
            THEN 1 ELSE 0 END AS matches;
```

`c` requests case-sensitive matching; `i` requests case-insensitive matching. SQL Server regex defaults to case-sensitive matching, independently of the ordinary LIKE collation behavior. Other flags control multiline anchors and whether a dot matches a newline.

### Replace, extract and escape

These expressions are for **MySQL 8 or SQL Server 2025**, not unextended SQLite:

| Expression | Expected output |
|---|---|
| `REGEXP_REPLACE('+91 (20) 555-0100', '[^0-9]', '')` | 91205550100 |
| `REGEXP_REPLACE('Box 12, Shelf 34', '[0-9]+', '#')` | Box #, Shelf # |
| `REGEXP_SUBSTR('Box 12, Shelf 34', '[0-9]+')` | 12 |
| `REGEXP_SUBSTR('Box 12, Shelf 34', '[0-9]+', 1, 2)` | 34 |
| `REGEXP_SUBSTR('Box', '[0-9]+')` | NULL |

In the fourth row, 1 is the starting position and 2 is the occurrence. Replacement defaults to all matches in these forms. [SQL Server replacement](https://learn.microsoft.com/en-us/sql/t-sql/functions/regexp-replace-transact-sql), [extraction](https://learn.microsoft.com/en-us/sql/t-sql/functions/regexp-substr-transact-sql)

SQL strings and regex each have parsing rules. A literal dot can be `[.]` in both engines. To use regex `\.`, ordinary MySQL string syntax needs `'\\.'`; SQL Server uses `'\.'`. MySQL's `NO_BACKSLASH_ESCAPES` mode changes that extra layer. [MySQL string escaping](https://dev.mysql.com/doc/refman/8.4/en/string-literals.html)

`\bcat\b` matches a complete word such as `a cat!`, not `scatter`; `\Bcat` matches the embedded `cat` in `scatter`. A boundary is a position, not necessarily a space. MySQL SQL literals normally double these backslashes. Pattern `(ab)\1` means repeat the captured text in engines supporting matching backreferences, but SQL Server's RE2 lacks backreferences and lookaround. Replacement capture references are a separate feature. [RE2 syntax](https://github.com/google/re2/wiki/Syntax), [ICU syntax](https://unicode-org.github.io/icu/userguide/strings/regexp.html)

A simplified email shape is:

```text
^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+[.][A-Za-z]{2,}$
```

It accepts `sam.lee@example.com` and rejects `sam@example`, but also accepts `a..b@example.com`. It proves only the stated shape, not full real-world validity. Follow the exact classroom rule when solving a question.

For an already well-formed single-@ address, regex `[^@]+$` extracts `example.com` from `sam@example.com`. The source's `@[^.]+` extracts only `@example`. Likewise `https?://[^ ]+` extracts `https://docs.example.com/help` from a space-delimited sentence, but can include tabs or trailing punctuation. `^[^.]+` on that URL gives `https://docs`, not a clean subdomain. Extraction and validation are different jobs.

## 6. Combine text across rows

Concatenation combines values within a row. A text aggregate combines many rows into one list. Decide duplicates and order separately.

Input `Places`: Pune, Delhi, Pune. Distinct alphabetical output should be `Delhi, Pune`.

```sql
-- SQLite 3.44+
SELECT GROUP_CONCAT(city, ', ' ORDER BY city) AS cities
FROM (SELECT DISTINCT city FROM Places) AS unique_cities;
```

For older SQLite syntax, supply an ordered derived input directly:

```sql
SELECT GROUP_CONCAT(city, ', ') AS cities
FROM (SELECT DISTINCT city FROM Places ORDER BY city) AS ordered_cities;
```

Prefer explicit aggregate ordering on 3.44+; it states the requirement directly. The fallback query was checked on the current local SQLite runtime, not on an older installed version. An outer `ORDER BY` sorts output rows, not items inside a list. [SQLite aggregation](https://www.sqlite.org/lang_aggfunc.html), [3.44 ordering support](https://www.sqlite.org/releaselog/3_44_0.html)

```sqlserver
-- SQL Server 2017+; ordered clause needs compatibility 110+
SELECT STRING_AGG(city, ', ') WITHIN GROUP (ORDER BY city) AS cities
FROM (SELECT DISTINCT city FROM Places) AS unique_cities;
```

SQL Server has no `STRING_AGG(DISTINCT ...)`; deduplicate first. Cast to `varchar(max)`/`nvarchar(max)` when large output requires it. These aggregates skip NULL input values. [STRING_AGG](https://learn.microsoft.com/en-us/sql/t-sql/functions/string-agg-transact-sql)

MySQL equivalent: `GROUP_CONCAT(DISTINCT city ORDER BY city SEPARATOR ', ')`.

## 7. Clauses: build a result in stages

Functions calculate values. Clauses arrange query stages. `LIKE`, `AND` and `OR` are operators, not standalone clauses.

Our Sales fixture contains:

| sale_id | region | amount | sold_on |
|---|---|---:|---|
| 1 | East | 40 | 2026-01-05 |
| 2 | East | 60 | 2026-01-06 |
| 3 | West | 20 | 2026-01-07 |
| 4 | West | 180 | 2026-01-08 |
| 5 | East | 20 | 2026-02-01 |
| 6 | North | 20 | 2026-01-10 |

```sql
SELECT region, SUM(amount) AS total_amount
FROM Sales
WHERE sold_on >= '2026-01-01' AND sold_on < '2026-02-01'
GROUP BY region
HAVING SUM(amount) >= 100
ORDER BY total_amount DESC, region ASC
LIMIT 1;
```

| Stage | What remains |
|---|---|
| FROM | Six sales |
| WHERE | January sales 1, 2, 3, 4, 6 |
| GROUP BY | East 100; North 20; West 200 |
| HAVING | East 100; West 200 |
| ORDER BY | West first, then East |
| LIMIT | West, 200 |

Think **FROM/JOIN -> WHERE -> GROUP BY -> HAVING -> SELECT -> DISTINCT -> ORDER BY -> LIMIT/TOP**. This is a reasoning order, not a promise about the physical execution plan. In SQL Server write `SELECT TOP (1) ...` and omit LIMIT. [Logical SELECT order](https://learn.microsoft.com/en-us/sql/t-sql/queries/select-transact-sql#logical-processing-order-of-the-select-statement)

`WHERE amount >= 100` would keep only sale 4 before grouping, producing West 180; it is not equivalent to `HAVING SUM(amount) >= 100`. Grouping changes one row from a sale to a region. Avoid selecting an ungrouped sale ID alongside the group total.

Use SELECT aliases in ORDER BY for portability; avoid relying on them in WHERE. Required sorting belongs in final ORDER BY, with a tie-breaker when needed. `LIMIT 1` means one row, not every row tied for first.

## 8. Supporting numbers and dates

`COUNT(*)` counts rows; `COUNT(column)` counts non-NULL values; `COUNT(DISTINCT column)` counts different non-NULL values. `SUM` and `AVG` ignore NULL inputs. On all six Sales rows, sum = 340 and average = 56.67 after rounding.

```sql
SELECT ROUND(AVG(1.0 * amount), 2) AS average_sale,
       ROUND(100.0 * SUM(CASE WHEN amount >= 100 THEN 1 ELSE 0 END)
             / COUNT(*), 2) AS large_sale_percentage
FROM Sales;
```

| average_sale | large_sale_percentage |
|---:|---:|
| 56.67 | 16.67 |

Only one of six sales reaches 100. Use decimals before division; consider `NULLIF(denominator,0)` for empty populations. `ROUND` gives a number, while `PRINTF('%.2f%%',98.1)` gives display text `98.10%`. Keep numeric values numeric while calculating and sorting.

| Task | SQLite | SQL Server | Expected value |
|---|---|---|---|
| Add five days | `DATE('2026-01-28','+5 days')` | `CAST(DATEADD(day,5,'20260128') AS date)` | 2026-02-02 |
| Date-only difference | `JULIANDAY('2026-02-02')-JULIANDAY('2026-01-28')` | `DATEDIFF(day,'20260128','20260202')` | 5 |
| Year/month/day | `STRFTIME('%Y-%m-%d','2026-02-03')` | `YEAR`, `MONTH`, `DAY` separately | Text parts versus integers |
| Current timestamp | `DATETIME('now')` | `GETDATE()` | Depends on execution time |

SQLite `now` uses UTC. SQL Server GETDATE uses its system clock without a time-zone offset. DATEDIFF counts date-part boundaries: crossing midnight by two minutes can count as one day, so it is not universally elapsed-duration arithmetic. [SQLite dates](https://www.sqlite.org/lang_datefunc.html), [SQL Server DATEDIFF](https://learn.microsoft.com/en-us/sql/t-sql/functions/datediff-transact-sql)

For a full month, prefer an inclusive first day and exclusive next-month start. SQLite text comparisons need consistent sortable ISO dates/timestamps. `BETWEEN` includes both endpoints. Always quote date literals; unquoted `2026-02-01` is arithmetic. Use `IS NULL`, not `= NULL`.

## 9. Extra class-function reference

These are **MySQL** expressions from the class-function family, not SQLite built-ins:

| Expression | Output | Other-engine direction |
|---|---|---|
| `LCASE('MIRA')` | mira | LOWER in both engines |
| `MID('bosscoder',6,3)` | ode | SUBSTR / SUBSTRING |

MySQL custom `TRIM('xy' FROM text)` removes repeated exact pieces, unlike SQLite's character-set argument. `SPACE(3)` produces three spaces in MySQL/SQL Server; SQLite can use `PRINTF('%3s','')`.
