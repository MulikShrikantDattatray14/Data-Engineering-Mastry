## My solution — SQLite

```sql
SELECT
    user_id,
    (UPPER(SUBSTR(name, 1, 1)) || LOWER(SUBSTR(name, 2, LENGTH(name)))) AS name
FROM Users
ORDER BY user_id;
```

### Step-by-step explanation with one example

**1. Understand the required result and the starting data**

Return one row for each user, with `user_id` and the corrected `name`. Only the first character should be uppercase; every remaining character should be lowercase. Sort the final rows by `user_id` ascending.

Use the same supplied `Users` example throughout:

| user_id | name |
|---|---|
| 1 | aLice |
| 2 | bOB |

The names need two different transformations, so split each name into its first character and its remaining characters. This is a calculation on each row; no join, grouping, or aggregation is needed.

**2. Extract the first character and make it uppercase**

`SUBSTR(name, 1, 1)` starts at position 1 and takes one character. Wrapping it in `UPPER(...)` changes that character to uppercase.

```sql
SELECT
    user_id,
    name,
    SUBSTR(name, 1, 1) AS first_character,
    UPPER(SUBSTR(name, 1, 1)) AS uppercase_first
FROM Users
ORDER BY user_id;
```

| user_id | name | first_character | uppercase_first |
|---|---|---|---|
| 1 | aLice | a | A |
| 2 | bOB | b | B |

Each user still has one row. We have prepared `A` and `B`, but we still need the rest of each name.

**3. Extract the remaining characters and make them lowercase**

`SUBSTR(name, 2, LENGTH(name))` starts at the second character. `LENGTH(name)` asks for enough characters to reach the end. SQLite returns the available characters; it does not add extra characters when the requested length extends beyond the string.

For `aLice`, the length is 5, and extracting from position 2 returns `Lice`. For `bOB`, the length is 3, and extracting from position 2 returns `OB`.

```sql
SELECT
    user_id,
    name,
    LENGTH(name) AS name_length,
    SUBSTR(name, 2, LENGTH(name)) AS remaining_characters,
    LOWER(SUBSTR(name, 2, LENGTH(name))) AS lowercase_rest
FROM Users
ORDER BY user_id;
```

| user_id | name | name_length | remaining_characters | lowercase_rest |
|---|---|---|---|---|
| 1 | aLice | 5 | Lice | lice |
| 2 | bOB | 3 | OB | ob |

Now the two pieces are ready: `A` and `lice` for user 1; `B` and `ob` for user 2.

**4. Join the two pieces and give the result its required name**

SQLite's `||` operator joins text. The expression below combines the uppercase first character with the lowercase remainder:

```sql
SELECT
    user_id,
    UPPER(SUBSTR(name, 1, 1)) AS uppercase_first,
    LOWER(SUBSTR(name, 2, LENGTH(name))) AS lowercase_rest,
    (UPPER(SUBSTR(name, 1, 1)) || LOWER(SUBSTR(name, 2, LENGTH(name)))) AS name
FROM Users
ORDER BY user_id;
```

| user_id | uppercase_first | lowercase_rest | name |
|---|---|---|---|
| 1 | A | lice | Alice |
| 2 | B | ob | Bob |

`AS name` sets the calculated column's heading to `name`. This `SELECT` displays corrected values; it does not update the stored names in `Users`.

**5. Assemble the final query and return only the requested columns**

The intermediate columns helped us inspect the calculation. The final output needs only `user_id` and `name`. `ORDER BY user_id` sorts ascending by default.

```sql
SELECT
    user_id,
    (UPPER(SUBSTR(name, 1, 1)) || LOWER(SUBSTR(name, 2, LENGTH(name)))) AS name
FROM Users
ORDER BY user_id;
```

| user_id | name |
|---|---|
| 1 | Alice |
| 2 | Bob |

**6. Check the result manually**

- User 1: `aLice` becomes `UPPER('a') || LOWER('Lice')`, which is `'A' || 'lice'`, giving `Alice`.
- User 2: `bOB` becomes `UPPER('b') || LOWER('OB')`, which is `'B' || 'ob'`, giving `Bob`.
- Both input rows remain, and user 1 appears before user 2.
- The same expression also handles a one-character name: the remainder is an empty string, so only the uppercase first character is returned.

### Saved MySQL solution

This is the user's confirmed version for the MySQL editor. It preserves the same split, case conversion, and ordering, using `CONCAT(...)` to join the pieces.

```sql
SELECT
    user_id,
    CONCAT(
        UPPER(SUBSTR(name, 1, 1)),
        LOWER(SUBSTR(name, 2, LENGTH(name)))
    ) AS name
FROM Users
ORDER BY user_id;
```

Write `SUBSTR(...)` without a space between the function name and its opening parenthesis. MySQL's default parsing treats some built-in function names differently when a space is present. [MySQL function parsing documentation](https://dev.mysql.com/doc/refman/26.10/en/function-resolution.html)

In MySQL, `||` normally means logical OR unless the `PIPES_AS_CONCAT` SQL mode is enabled. `CONCAT(...)` expresses the intended text joining directly. [MySQL operator documentation](https://dev.mysql.com/doc/refman/8.4/en/logical-operators.html)

## My solution — SQL Server

```sql
SELECT
    user_id,
    (UPPER(SUBSTRING(name, 1, 1)) + LOWER(SUBSTRING(name, 2, LEN(name)))) AS name
FROM Users
ORDER BY user_id;
```

This keeps the same logic as the SQLite solution. SQL Server uses `SUBSTRING` for extraction, `LEN` for the name length, and `+` to join these text expressions. `UPPER`, `LOWER`, the `name` alias, and the ordering stay the same.

### What this tests

Extracting parts of a name, changing their case, and joining them into a formatted name.

### The approach

Take the first character with `SUBSTR(name, 1, 1)` and apply `UPPER`. Take the remaining characters from position 2 and apply `LOWER`. Join the pieces with `CONCAT` and order by `user_id`.

### Why this way

The first character and the remaining characters need different case transformations. The expression preserves one result row for each user.

### Common mistakes

- Applying the same case function to the entire name.
- Starting the remaining substring at the wrong position.
- Omitting the requested order.
- Assuming these function names and argument forms work in every SQL engine. This is the class-provided syntax; the saved SQLite, MySQL, and SQL Server versions are shown above.
