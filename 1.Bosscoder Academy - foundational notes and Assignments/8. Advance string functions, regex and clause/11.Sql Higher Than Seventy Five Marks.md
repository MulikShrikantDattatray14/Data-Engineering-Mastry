# 11. SQL Higher Than Seventy Five Marks

## Question and image

**5. Sql Higher Than Seventy Five Marks**

Query the Name of any student in STUDENTS who scored higher than Marks. Order your output by the last three characters of each name.

If two or more students both have names ending in the same last three characters (i.e.: Bobby, Robby, etc.), secondary sort them by ascending ID.

| Column | Type |
|---|---|
| ID | Integer |
| Name | String |
| Marks | Integer |

The Name only contains uppercase and lowercase letters.

**Example 1:**

**Input:**

| ID | Name | Marks |
|---|---|---|
| 1 | Ashley | 81 |
| 2 | Samantha | 75 |
| 4 | Julia | 76 |
| 3 | Belvet | 84 |

**Output:**

| Name |
|---|
| Ashley |
| Julia |
| Belvet |

**Explanation:**

Only Ashley, Julia, and Belvet have Marks > . If you look at the last three characters of each of their names, there are no duplicates and 'ley' < 'lia' < 'vet'.

**Source note:** The supplied statement and explanation omit the numeric cutoff. The title, together with the example excluding Samantha at 75 and including Julia at 76, indicates an intended cutoff of 75. The original wording is preserved above.

## My solution — SQLite

### Final solution

```sql
SELECT Name
FROM STUDENTS
WHERE Marks > 75
ORDER BY SUBSTR(Name, -3) ASC, ID ASC;
```

### Step-by-step explanation with one example

**1. Define the output and inspect the input**

The result contains one column, `Name`, for each student whose marks are strictly greater than 75. We use the last three characters of the name to decide the order; the displayed value remains the full name. If those characters match, the smaller `ID` comes first.

Use the same supplied example throughout:

```sql
SELECT ID, Name, Marks
FROM STUDENTS;
```

| ID | Name | Marks |
|---|---|---|
| 1 | Ashley | 81 |
| 2 | Samantha | 75 |
| 4 | Julia | 76 |
| 3 | Belvet | 84 |

These are the input rows, shown in the sample order. No result ordering has been requested in this inspection query. All required information is in `STUDENTS`, so no join is needed.

**2. Keep students who scored more than 75**

```sql
SELECT ID, Name, Marks
FROM STUDENTS
WHERE Marks > 75;
```

| ID | Name | Marks |
|---|---|---|
| 1 | Ashley | 81 |
| 4 | Julia | 76 |
| 3 | Belvet | 84 |

`WHERE` checks each student independently. Ashley, Julia, and Belvet pass. Samantha has exactly 75, so she is excluded: “higher than” means `>`, not `>=`. The question text omits the cutoff, but its title and example identify 75, as recorded in the source note.

**3. Extract the characters used for sorting**

```sql
SELECT
    ID,
    Name,
    SUBSTR(Name, -3) AS last_three
FROM STUDENTS
WHERE Marks > 75;
```

| ID | Name | last_three |
|---|---|---|
| 1 | Ashley | ley |
| 4 | Julia | lia |
| 3 | Belvet | vet |

In SQLite, a negative starting position counts from the end: `-1` means the last character and `-3` means the third-last character. Omitting the length argument returns the substring from that position through the end. For names shorter than three characters, `SUBSTR(Name, -3)` returns the whole name.

`last_three` is an inspection column to help us see the sorting value. The final result still needs only `Name`.

**4. Sort the remaining students**

```sql
SELECT
    ID,
    Name,
    SUBSTR(Name, -3) AS last_three
FROM STUDENTS
WHERE Marks > 75
ORDER BY SUBSTR(Name, -3) ASC, ID ASC;
```

| ID | Name | last_three |
|---|---|---|
| 1 | Ashley | ley |
| 4 | Julia | lia |
| 3 | Belvet | vet |

Compare the three-character strings from left to right. For `ley` and `lia`, the first `l` matches; then `e` comes before `i`. Both strings come before `vet`. Therefore the names appear as Ashley, Julia, and Belvet.

`ID ASC` is used only when the complete sorting substrings are equal. The sample has no such tie, so its IDs do not change the name order. We do not sort all rows by ID first.

**5. Assemble the final query and return only Name**

```sql
SELECT Name
FROM STUDENTS
WHERE Marks > 75
ORDER BY SUBSTR(Name, -3) ASC, ID ASC;
```

| Name |
|---|
| Ashley |
| Julia |
| Belvet |

Manual check: four students enter, Samantha is excluded at the 75 boundary, and the other three appear in suffix order: `ley`, `lia`, `vet`. `ORDER BY` may use the name expression and `ID` without displaying them as additional result columns in this query. There is no aggregation or `GROUP BY` because each retained student remains a separate result row.

### Earlier saved version — short-name limitation

```sql
SELECT Name
FROM STUDENTS
WHERE Marks > 75
ORDER BY (SUBSTR(Name, LENGTH(Name) - 2, LENGTH(Name))) ASC, ID ASC;
```

This version produces the supplied sample output. For names of at least three characters, `LENGTH(Name) - 2` locates the third-last character. The third argument is the maximum number of characters to take; asking for more than remain simply returns the available suffix.

However, it is not a complete solution when two-character names are allowed. For those names, `LENGTH(Name) - 2` is 0. In SQLite, `SUBSTR(Name, 0, 2)` returns only the first character.

| ID | Name | Marks | Earlier expression | Final SUBSTR(Name, -3) |
|---|---|---|---|---|
| 1 | Al | 80 | A | Al |
| 2 | Ab | 80 | A | Ab |

Both students qualify. The earlier expression creates an artificial tie on `A`, so `ID ASC` produces Al, Ab. The final expression retains the full short names and correctly produces Ab, Al. Use the final solution above for the unrestricted question.

## My solution — SQL Server

```sql
SELECT Name
FROM STUDENTS
WHERE Marks > 75
ORDER BY RIGHT(Name, 3) ASC, ID ASC;
```

`RIGHT(Name, 3)` is the SQL Server expression for the final three characters; it returns the full name when fewer than three characters are present. The selected column, strict marks filter, suffix sorting, and ID tie-breaker preserve the final SQLite approach. Only the substring syntax changes.
