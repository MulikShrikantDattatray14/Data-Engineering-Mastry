# 8. SQL Duplicate Emails

## Question and image

**8. Sql Duplicate Emails**

Table: Person

| Column Name | Type |
|---|---|
| id | int |
| email | varchar |

`id` is the primary key (column with unique values) for this table.

Each row of this table contains an email. The emails will not contain uppercase letters.

Write a solution to report all the duplicate emails. Note that it's guaranteed that the email field is not NULL.

Return the result table ordered by Email.

**Example 1:**

Input:

Person table:

| id | email |
|---|---|
| 1 | a@b.com |
| 2 | c@d.com |
| 3 | a@b.com |

Output:

| Email |
|---|
| a@b.com |

Explanation: a@b.com is repeated two times.

## Schema

**Person**  
id, email

- `email` — varchar; not `NULL` and contains no uppercase letters

## My solution — SQLite

```sql
SELECT DISTINCT p1.email AS Email
FROM Person AS p1
WHERE p1.email IN (
    SELECT DISTINCT p2.email
    FROM Person AS p2
    GROUP BY p2.email
    HAVING COUNT(p2.email) >= 2
)
ORDER BY p1.email;
```

### Key learnings

- `GROUP BY p2.email` creates one group for each email, and `HAVING COUNT(p2.email) >= 2` keeps only email groups that occur at least twice.
- `=` compares against exactly one value. The subquery can return several different duplicate emails, so `IN` is required to test whether an outer email matches any returned value.
- The outer `DISTINCT` ensures that each duplicate email appears only once in the result.
- The inner `DISTINCT` is redundant because `GROUP BY p2.email` already returns one row per email, but it does not make the query incorrect.
- `AS Email` is required because the expected output column name uses a capital `E`.
- `ORDER BY p1.email` satisfies the required alphabetical ordering.

### Step-by-step explanation with one example

We need each repeated email address once, ordered alphabetically. Use the supplied Person rows throughout. The saved solution first identifies duplicate email values, then selects matching Person rows and removes repeated output values.

**Starting data**

`Person`:

| id | email |
| --- | --- |
| 1 | a@b.com |
| 2 | c@d.com |
| 3 | a@b.com |

**1. Count rows for each email**

Different Person IDs can share an email. Group by email, not id, to bring those repeated email values together.

```sql
SELECT p2.email, COUNT(p2.email) AS email_count
FROM Person AS p2
GROUP BY p2.email
ORDER BY p2.email;
```

Result:

| email | email_count |
| --- | --- |
| a@b.com | 2 |
| c@d.com | 1 |

a@b.com occurs twice; c@d.com occurs once. email is guaranteed non-NULL, so each row contributes to COUNT(email).

**2. Build the duplicate-email list**

HAVING keeps email groups with at least two rows. IN is appropriate later because this list could contain several email addresses.

```sql
SELECT DISTINCT p2.email
FROM Person AS p2
GROUP BY p2.email
HAVING COUNT(p2.email) >= 2;
```

Result:

| email |
| --- |
| a@b.com |

The list contains only a@b.com for this sample. DISTINCT inside the grouped subquery is redundant but retained from the saved logic.

**3. Inspect matching Person rows before final DISTINCT**

The outer IN condition keeps any Person row whose email belongs to the duplicate list. Multiple people can still produce repeated output email values at this point.

```sql
SELECT p1.id, p1.email
FROM Person AS p1
WHERE p1.email IN (
    SELECT DISTINCT p2.email
    FROM Person AS p2
    GROUP BY p2.email
    HAVING COUNT(p2.email) >= 2
)
ORDER BY p1.id;
```

Result:

| id | email |
| --- | --- |
| 1 | a@b.com |
| 3 | a@b.com |

IDs 1 and 3 both remain, and both contain a@b.com. The final outer DISTINCT will merge the repeated output email into one row.

**4. Assemble the final query**

Return DISTINCT p1.email using the requested Email column label and sort by email.

```sql
SELECT DISTINCT p1.email AS Email
FROM Person AS p1
WHERE p1.email IN (
    SELECT DISTINCT p2.email
    FROM Person AS p2
    GROUP BY p2.email
    HAVING COUNT(p2.email) >= 2
)
ORDER BY p1.email;
```

Final result for this example:

| Email |
| --- |
| a@b.com |

**Check the result:** Manual check: a@b.com appears in rows 1 and 3, so it is reported once. c@d.com appears only in row 2 and is excluded.

## My solution — SQL Server

```sql
SELECT DISTINCT p1.email AS Email
FROM Person AS p1
WHERE p1.email IN (
    SELECT DISTINCT p2.email
    FROM Person AS p2
    GROUP BY p2.email
    HAVING COUNT(p2.email) >= 2
)
ORDER BY p1.email;
```

The same query works in SQLite and SQL Server.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
