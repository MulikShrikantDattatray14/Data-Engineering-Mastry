# SQL NULL and Full-Price Products — Foundation Notes

## Why this matters

An e-commerce promotion team needs products sold without a discount. A **known zero discount** is different from an **unknown discount** caused by missing prices. Mixing them produces incorrect business reports.

## What does NULL mean?

`NULL` indicates an unknown or missing value; it is not the text `'NULL'` and not the number 0. Use `IS NULL` or `IS NOT NULL` to check it.

| Market_Price | Sale_Price | Difference | Meaning |
|---:|---:|---:|---|
| 100 | 100 | 0 | Known full price |
| 100 | 90 | 10 | Known discount |
| 100 | NULL | NULL | Unknown; **not** verified full price |

```sql
SELECT ProductID, Sale_Price, Market_Price
FROM Products
WHERE Market_Price IS NOT NULL
  AND Sale_Price IS NOT NULL
  AND Market_Price = Sale_Price;
```

**Explanation:** Both prices must exist, then equality proves no discount.

## CASE displays; WHERE filters

```sql
SELECT ProductID,
       CASE WHEN Market_Price = Sale_Price
            THEN 'Full price'
       END AS discount_display
FROM Products
WHERE Market_Price IS NOT NULL
  AND Sale_Price IS NOT NULL
  AND Market_Price = Sale_Price;
```

- `CASE` labels the row.
- `WHERE` decides whether the row appears.
- `'NULL'` is a string. Actual SQL `NULL` is unquoted.

## Revision

- Remember three-valued logic: conditions involving `NULL` may evaluate to UNKNOWN.
- Compare prices only when both are known.
- SQLite accepts `==` for equality, but standard `=` is more portable.
- `ORDER BY Sale_Price DESC, ProductID ASC` makes tied prices deterministic.
