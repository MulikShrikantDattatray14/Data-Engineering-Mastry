# PNP P006 — Most Expensive Products Never Discounted

**Source ID:** P006 · **Difficulty:** Easy · **Topics:** NULL, arithmetic, CASE, filtering, sorting, LIMIT  
**Verification:** Independently revised and SQLite-verified in Study Mode. This is a **reattempt** of a previously solved PNP question, **not** a newly solved source ID.

## A. Business question

A promotions team wants up to ten of its most expensive items currently sold at the printed market price. Find products with **known equal market and sale prices**, not products with missing prices. Show the text `Full price` in `discount_display`. Sort by Sale_Price descending, then ProductID ascending.

## B. Sample input

**Products** (one row represents one product):

| ProductID | Product | Brand | Sale_Price | Market_Price |
|---:|---|---|---:|---:|
| 1 | Mug | Home | 100 | 100 |
| 2 | Lamp | Home | 150 | 150 |
| 3 | Mystery | Home | NULL | 100 |
| 4 | Bottle | Home | 90 | 100 |

## C. Expected output

| ProductID | Product | Brand | Sale_Price | Market_Price | discount_display |
|---:|---|---|---:|---:|---|
| 2 | Lamp | Home | 150 | 150 | Full price |
| 1 | Mug | Home | 100 | 100 | Full price |

**Why:** Lamp and Mug have known equal prices. Mystery's missing sale price is unknown; Bottle has a real discount.

## D. Learner's final SQLite solution (verbatim)

```sql
SELECT ProductID, Product, Brand, Sale_Price, Market_Price,
    CASE
        WHEN Market_Price = Sale_Price THEN 'Full price'
    END AS discount_display
FROM Products
WHERE Market_Price IS NOT NULL
  AND Sale_Price IS NOT NULL and Market_Price - Sale_Price ==0
ORDER BY Sale_Price DESC, ProductID ASC
LIMIT 10;
```

**Review:** Accepted after correcting earlier `CASE` branches, alias punctuation, comparison and missing filter. `==` is supported in SQLite, while `=` is more portable. The query directly tests zero difference rather than constructing an intermediate nullable discount column.

## E. SQL Server version (assistant conversion; not learner-authored)

```sql
SELECT TOP (10)
    ProductID, Product, Brand, Sale_Price, Market_Price,
    CASE WHEN Market_Price = Sale_Price
         THEN 'Full price' END AS discount_display
FROM Products
WHERE Market_Price IS NOT NULL
  AND Sale_Price IS NOT NULL
  AND Market_Price - Sale_Price = 0
ORDER BY Sale_Price DESC, ProductID ASC;
```

No SQL Server execution is claimed. T-SQL uses `TOP (10)` rather than SQLite's `LIMIT 10`.

## G. Progressive worked example

### Step 1 — Inspect known price columns

```sql
SELECT ProductID, Product, Sale_Price, Market_Price
FROM Products ORDER BY ProductID;
```

| ProductID | Product | Sale_Price | Market_Price |
|---:|---|---:|---:|
| 1 | Mug | 100 | 100 |
| 2 | Lamp | 150 | 150 |
| 3 | Mystery | NULL | 100 |
| 4 | Bottle | 90 | 100 |

### Step 2 — Remove missing prices

```sql
SELECT ProductID, Product, Sale_Price, Market_Price
FROM Products
WHERE Market_Price IS NOT NULL AND Sale_Price IS NOT NULL
ORDER BY ProductID;
```

| ProductID | Product | Sale_Price | Market_Price |
|---:|---|---:|---:|
| 1 | Mug | 100 | 100 |
| 2 | Lamp | 150 | 150 |
| 4 | Bottle | 90 | 100 |

Mystery is removed, because missing price does not mean zero discount.

### Step 3 — Keep only zero difference

```sql
SELECT ProductID, Product, Market_Price - Sale_Price AS discount
FROM Products
WHERE Market_Price IS NOT NULL AND Sale_Price IS NOT NULL
  AND Market_Price - Sale_Price = 0
ORDER BY ProductID;
```

| ProductID | Product | discount |
|---:|---|---:|
| 1 | Mug | 0 |
| 2 | Lamp | 0 |

Bottle is removed because its discount equals 10.

### Step 4 — Display a friendly label

```sql
CASE WHEN Market_Price = Sale_Price THEN 'Full price' END AS discount_display
```

Each remaining row shows `Full price`. **CASE labels**; it does not independently remove Bottle unless WHERE filters it.

### Step 5 — Sort and keep at most ten

```sql
ORDER BY Sale_Price DESC, ProductID ASC LIMIT 10;
```

The higher-priced Lamp comes before Mug. With ties, ProductID breaks the tie. Only two qualify here, so the query returns two.

## H. Edge cases and revision

- NULL price: excluded even though arithmetic with NULL yields NULL.
- Discounted products: excluded even if their sale price is very high.
- Equal prices: included and labeled Full price.
- Identical sale prices: tie broken using ProductID.
- More than ten qualifying rows: `LIMIT 10` returns ten.
- **Rule:** `CASE` controls display; `WHERE` controls membership.
