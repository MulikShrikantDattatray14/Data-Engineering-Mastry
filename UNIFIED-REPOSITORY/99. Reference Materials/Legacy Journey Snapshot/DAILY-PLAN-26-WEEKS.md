# 26-Week Daily SQL + Python Learning Plan

**Start:** Saturday, 2026-11-07 (Asia/Kolkata)
**Cadence:** Saturday–Thursday study; Friday rest/light optional review. Six days/week for 26 weeks.
**Daily target:** SQL 2 focused hours + Python 2 focused hours. 25 minutes concept + 75 minutes practice + 20 minutes review/notes per subject.
**Career goal:** Compete for strong product-company Data Engineer / Data Platform interviews (~2 years software experience), aspirational ₹30–40 LPA total compensation. Preparation does not guarantee an offer.

## Daily practice targets by phase

| Weeks | SQL daily target | Python daily target |
|---|---|---|
| 1–4 | 5–7 short queries (mix easy/medium as appropriate) | 4–6 small coding exercises |
| 5–8 | 4–6 increasingly multi-concept queries | 3–5 exercises or 1 tested mini-script |
| 9–16 | 3–5 medium/advanced SQL problems | 2–4 tasks, or one end-to-end coding assignment |
| 17–22 | 2–4 engineering scenarios or one significant design exercise | 1–2 substantial PySpark/pipeline tasks, with tests |
| 23–26 | 1 timed SQL case/mocks + corrections | 1 timed coding/ETL case + corrections |

**Quality rule:** Accuracy and understanding matter more than counts. If tasks are large, complete fewer but deeper exercises. Day 6 is mixed revision, debugging or an applied exercise rather than blindly opening new topics.

## Daily tracking checklist

For each day: record time spent, number of independent attempts, concepts confidently explained, mistakes, GitHub links, and one spaced-revision action. Do not mark anything completed ahead of studying.

## Public documentation standards

- Theory notes include clear explanations, real-world examples, edge cases and runnable code.
- Separate first attempts from reviewed solutions; never pretend draft answers were correct.
- Keep revision index and progress tracker current after actual study.
- Use only synthetic/publicly licensed data and do not expose secrets or employer code.
- Every week revise the next week's workload if problem difficulty or real job demands change.

## Beyond foundation

SQL and Python retain equal daily time budgets. As skills mature, SQL time covers warehouse and performance concepts; Python time covers ETL, PySpark, cloud and project implementation. Interviews also require design decisions, project credibility and communication.
