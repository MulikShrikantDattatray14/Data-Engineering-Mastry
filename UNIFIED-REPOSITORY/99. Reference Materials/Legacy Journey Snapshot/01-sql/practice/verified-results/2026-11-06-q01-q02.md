## Q1 — Paid Maharashtra orders amount > 1000

**Student first attempt (preserved exactly):**

```sql
SELECT order_id , amount
FROM orders
WHERE status = 'paid' and  state = 'Maharashtra' and amount > 1000
order by amount desc
```

**Expected output**

| order_id | amount |
|---:|---:|
| 105 | 1800 |
| 101 | 1200 |

**Actual output — executed original SQLite query**

| order_id | amount |
|---:|---:|
| 105 | 1800 |
| 101 | 1200 |

**Comparison:** Match; no missing or extra rows.

**SQLite reference solution — assistant-verified**

```sql
SELECT order_id, amount
FROM orders
WHERE status = 'paid'
  AND state = 'Maharashtra'
  AND amount > 1000
ORDER BY amount DESC;
```

**SQL Server / T-SQL reference — assistant-converted, not executed**

```sql
SELECT order_id, amount
FROM orders
WHERE status = 'paid'
  AND state = 'Maharashtra'
  AND amount > 1000
ORDER BY amount DESC;
```

**Why:** The `amount > 1000` predicate excludes NULL because `NULL > 1000` is UNKNOWN and `WHERE` only retains TRUE. No additional `IS NOT NULL` is required for this conjunctive filter.

## Q2 — Paid Maharashtra OR amount > 2000, excluding NULL

**Original first attempt (preserved exactly):**

```sql
SELECT order_id, status, state, amount
FROM orders
WHERE  (status ='paid' and state='Maharashtra') or  amount > 2000 
order by order_id
```

**Expected output**

| order_id | status | state | amount |
|---:|---|---|---:|
| 101 | paid | Maharashtra | 1200 |
| 103 | cancelled | Maharashtra | 2200 |
| 105 | paid | Maharashtra | 1800 |
| 106 | pending | Maharashtra | 2600 |

**Actual output — executed original SQLite query**

| order_id | status | state | amount |
|---:|---|---|---:|
| 101 | paid | Maharashtra | 1200 |
| 103 | cancelled | Maharashtra | 2200 |
| **104** | **paid** | **Maharashtra** | **NULL** |
| 105 | paid | Maharashtra | 1800 |
| 106 | pending | Maharashtra | 2600 |

**Comparison:** Extra row 104. The `paid AND Maharashtra` branch is TRUE even though `amount > 2000` is UNKNOWN, so the overall OR is TRUE.

**Student's corrected SQLite attempt (preserved exactly):**

```sql
SELECT order_id, status, state, amount
FROM orders
WHERE  (status ='paid' and state='Maharashtra' and amount is not null ) or  (amount > 2000 and amount is not null)
order by order_id
```

**Actual output — executed revised SQLite query**

| order_id | status | state | amount |
|---:|---|---|---:|
| 101 | paid | Maharashtra | 1200 |
| 103 | cancelled | Maharashtra | 2200 |
| 105 | paid | Maharashtra | 1800 |
| 106 | pending | Maharashtra | 2600 |

**Comparison:** Correct; matches expected. The student's redundant `amount IS NOT NULL` in the second branch does not affect correctness.

**SQLite reference solution — assistant-verified**

```sql
SELECT order_id, status, state, amount
FROM orders
WHERE ((status = 'paid' AND state = 'Maharashtra')
       OR amount > 2000)
  AND amount IS NOT NULL
ORDER BY order_id ASC;
```

**SQL Server / T-SQL reference — assistant-converted, not executed**

```sql
SELECT order_id, status, state, amount
FROM orders
WHERE ((status = 'paid' AND state = 'Maharashtra')
       OR amount > 2000)
  AND amount IS NOT NULL
ORDER BY order_id ASC;
```

**Why:** The global `AND amount IS NOT NULL` guarantees NULL exclusion across **both** alternatives. This is a more compact equivalent of the student's correctly revised expression.
