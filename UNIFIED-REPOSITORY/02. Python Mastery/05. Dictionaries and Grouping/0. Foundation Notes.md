# Dictionaries and Grouping — Foundation Notes

## Why learn this?

A CSV or API may contain thousands of orders. If you need to find one customer quickly, count statuses, or total revenue by city, a **dictionary** lets you map a **key to a value** instead of repeatedly searching a list. Think of the key as an address and the value as the information stored there.

**JavaScript connection:** Python `dict` is closest to a plain JS object for JSON-like string keys, or `Map` for general hashable keys.

## 1. Create, read and update

```python
customer = {"id": 101, "city": "Pune"}
print(customer["city"])       # Pune
customer["city"] = "Mumbai"  # update
customer["tier"] = "gold"    # add
print(customer.get("phone", "unknown")) # unknown
```

- Dictionary keys are unique. Reassigning a key updates its value.
- `customer["phone"]` raises `KeyError` if missing.
- `get("phone", "unknown")` supplies a fallback **only if the key is absent**; an existing `None` is still returned.
- Modern Python dictionaries retain insertion order, but use `sorted(...)` for reports requiring a specific order.

| JavaScript | Python |
|---|---|
| `customer.city` | `customer["city"]` |
| `customer?.phone ?? "unknown"` | `customer.get("phone") if customer.get("phone") is not None else "unknown"` |
| `Object.entries(customer)` | `customer.items()` |

## 2. Count events by status

```python
statuses = ["paid", "failed", "paid", "paid"]
counts = {}
for status in statuses:
    counts[status] = counts.get(status, 0) + 1
print(counts)  # {'paid': 3, 'failed': 1}
```

**Visualize the changing dictionary:**

| Incoming event | Previous value | Updated value |
|---|---:|---:|
| paid | 0 | `{"paid": 1}` |
| failed | 0 | `{"paid": 1, "failed": 1}` |
| paid | 1 | `{"paid": 2, "failed": 1}` |
| paid | 2 | `{"paid": 3, "failed": 1}` |

Each iteration updates only its matching key. This resembles SQL's `GROUP BY status, COUNT(*)`.

## 3. Group sales by city

```python
orders = [
    {"city": "Pune", "amount": 100},
    {"city": "Delhi", "amount": 200},
    {"city": "Pune", "amount": 300},
]
totals = {}
for order in orders:
    city = order["city"]
    totals[city] = totals.get(city, 0) + order["amount"]
print(totals)  # {'Pune': 400, 'Delhi': 200}
```

**Progressive result:** Pune 100 → Delhi 200 → Pune 100 + 300 = 400. Dictionary grouping avoids needing a separate accumulator variable for every city.

## 4. Useful standard-library helpers

```python
from collections import Counter, defaultdict
print(Counter(statuses))   # Counter({'paid': 3, 'failed': 1})
by_city = defaultdict(list)
by_city["Pune"].append(101)
print(dict(by_city))        # {'Pune': [101]}
```

`Counter` counts automatically. `defaultdict(list)` starts a new empty list for a previously unseen key.

## 5. How to choose a collection

| Need | Python type |
|---|---|
| An editable ordered sequence | `list` |
| An ordered fixed record | `tuple` |
| Unique IDs / membership | `set` |
| Lookup, grouping or counts by key | `dict` |

## Key revision points

- `in my_dict` checks **keys**, not values.
- A missing key via `[]` causes `KeyError`; `.get()` can use a fallback.
- Dict keys must be hashable; list objects cannot be keys.
- Hash-based lookups are **average-case** constant time, not guaranteed worst-case.
- Beware of conflating `None`, `0`, and absent keys.
