# 8. SQL Revising The Select Query

## Question and image

Return **all columns** for every city in `CITY` whose `COUNTRYCODE` is `USA` and whose `POPULATION` is **larger than 100000**. No output order is specified.

**Example 1**

Input — `CITY`:

| ID | NAME | COUNTRYCODE | DISTRICT | POPULATION |
|---:|---|---|---|---:|
| 1 | New York | USA | New York | 8008278 |
| 2 | Los Angeles | USA | California | 3694820 |
| 3 | Chicago | USA | Illinois | 2896016 |
| 4 | Toronto | CAN | Ontario | 3000000 |
| 5 | Houston | USA | Texas | 1953631 |

Expected output:

| ID | NAME | COUNTRYCODE | DISTRICT | POPULATION |
|---:|---|---|---|---:|
| 1 | New York | USA | New York | 8008278 |
| 2 | Los Angeles | USA | California | 3694820 |
| 3 | Chicago | USA | Illinois | 2896016 |
| 5 | Houston | USA | Texas | 1953631 |

Toronto has enough population but is in Canada, so it is excluded. All four `USA` rows in this sample also have populations above 100000.

## Schema

`CITY`:

| Column Name | Type |
|---|---|
| ID | NUMBER |
| NAME | VARCHAR2(17) |
| COUNTRYCODE | VARCHAR2(3) |
| DISTRICT | VARCHAR2(20) |
| POPULATION | NUMBER |

The example and the query use `COUNTRYCODE`; the space in `COUNTRY CODE` in the prose table is formatting.

## My solution — SQLite

```sql
SELECT *
FROM CITY
WHERE COUNTRYCODE = 'USA' AND POPULATION > 100000;
```

### Step-by-step explanation with one example

**Starting data.** Each row is one city. The output needs every column of cities that pass **both** tests.

| ID | NAME | COUNTRYCODE | DISTRICT | POPULATION |
|---:|---|---|---|---:|
| 1 | New York | USA | New York | 8008278 |
| 2 | Los Angeles | USA | California | 3694820 |
| 3 | Chicago | USA | Illinois | 2896016 |
| 4 | Toronto | CAN | Ontario | 3000000 |
| 5 | Houston | USA | Texas | 1953631 |

**1. Keep American cities.** `COUNTRYCODE = 'USA'` removes Toronto even though it has a large population.

```sql
SELECT ID, NAME, COUNTRYCODE, POPULATION
FROM CITY
WHERE COUNTRYCODE = 'USA';
```

| ID | NAME | COUNTRYCODE | POPULATION |
|---:|---|---|---:|
| 1 | New York | USA | 8008278 |
| 2 | Los Angeles | USA | 3694820 |
| 3 | Chicago | USA | 2896016 |
| 5 | Houston | USA | 1953631 |

**2. Also require population above 100000.** `AND` means a city must pass the country and population checks **on the same row**.

```sql
SELECT ID, NAME, COUNTRYCODE, POPULATION
FROM CITY
WHERE COUNTRYCODE = 'USA' AND POPULATION > 100000;
```

| ID | NAME | COUNTRYCODE | POPULATION |
|---:|---|---|---:|
| 1 | New York | USA | 8008278 |
| 2 | Los Angeles | USA | 3694820 |
| 3 | Chicago | USA | 2896016 |
| 5 | Houston | USA | 1953631 |

All four American cities in this sample exceed 100000, so this second filter removes no additional sample rows. It is still required: an American city with a population of **exactly** 100000 would fail `> 100000`.

**3. Return all columns.** `SELECT *` returns the five attributes in the supplied `CITY` table:

```sql
SELECT *
FROM CITY
WHERE COUNTRYCODE = 'USA' AND POPULATION > 100000;
```

| ID | NAME | COUNTRYCODE | DISTRICT | POPULATION |
|---:|---|---|---|---:|
| 1 | New York | USA | New York | 8008278 |
| 2 | Los Angeles | USA | California | 3694820 |
| 3 | Chicago | USA | Illinois | 2896016 |
| 5 | Houston | USA | Texas | 1953631 |

The table is shown in sample input order to match the example. The prompt does not require ordering, and SQL does not guarantee this row order without `ORDER BY`.
