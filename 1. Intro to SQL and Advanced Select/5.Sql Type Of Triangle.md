# 5. SQL Type Of Triangle

## Question and image

For each row of `TRIANGLES`, use side lengths `A`, `B`, and `C` to return one `TriangleType`:

- `Equilateral`: all three sides have equal length.
- `Isosceles`: two sides have equal length.
- `Scalene`: all three sides have different lengths.
- `Not A Triangle`: the three lengths cannot form a triangle.

The prompt does not specify an output order.

**Example 1**

Input — `TRIANGLES`:

| A | B | C |
|---:|---:|---:|
| 20 | 20 | 23 |
| 20 | 20 | 20 |
| 20 | 21 | 22 |
| 13 | 14 | 30 |

Expected output, shown in the sample's input-row order:

| TriangleType |
|---|
| Isosceles |
| Equilateral |
| Scalene |
| Not A Triangle |

`(20, 20, 23)` has two equal sides; `(20, 20, 20)` has three. `(20, 21, 22)` has three different sides. `(13, 14, 30)` is invalid because `13 + 14` is not greater than `30`.

## My solution — SQLite

```sql
SELECT
    CASE
        WHEN A + B <= C
          OR A + C <= B
          OR B + C <= A THEN 'Not A Triangle'
        WHEN A = B AND B = C THEN 'Equilateral'
        WHEN A = B OR B = C OR C = A THEN 'Isosceles'
        ELSE 'Scalene'
    END AS TriangleType
FROM TRIANGLES;
```

### Step-by-step explanation with one example

**Starting data.** Every input row describes one set of three side lengths. `CASE` will produce one `TriangleType` for each row.

| A | B | C |
|---:|---:|---:|
| 20 | 20 | 23 |
| 20 | 20 | 20 |
| 20 | 21 | 22 |
| 13 | 14 | 30 |

The tables below follow the sample's input-row order only to make the calculations easy to trace. The prompt does not require a particular SQL output order.

**1. Reject lengths that cannot form a triangle.** For a valid triangle, each pair's sum must be **strictly greater** than the remaining side. If any sum is `<=` the remaining side, the shape is invalid.

```sql
SELECT A, B, C,
       (A + B <= C OR A + C <= B OR B + C <= A) AS invalid_shape
FROM TRIANGLES;
```

| A | B | C | A+B vs C | A+C vs B | B+C vs A | invalid_shape |
|---:|---:|---:|---|---|---|---:|
| 20 | 20 | 23 | 40 > 23 | 43 > 20 | 43 > 20 | 0 |
| 20 | 20 | 20 | 40 > 20 | 40 > 20 | 40 > 20 | 0 |
| 20 | 21 | 22 | 41 > 22 | 42 > 21 | 43 > 20 | 0 |
| 13 | 14 | 30 | 27 <= 30 | 43 > 14 | 44 > 13 | 1 |

SQLite displays false as `0` and true as `1`. The last row fails because `13 + 14 = 27`, which is less than `30`. The first `WHEN` returns `Not A Triangle` for that row, so later equal-side checks cannot relabel it. Checking invalidity first also classifies `(0, 0, 0)` correctly as invalid rather than Equilateral.

**2. Check whether all sides are equal.** A valid row is Equilateral when `A = B` **and** `B = C`.

```sql
SELECT A, B, C,
       (A = B AND B = C) AS all_equal
FROM TRIANGLES;
```

| A | B | C | all_equal |
|---:|---:|---:|---:|
| 20 | 20 | 23 | 0 |
| 20 | 20 | 20 | 1 |
| 20 | 21 | 22 | 0 |
| 13 | 14 | 30 | 0 |

Only `(20, 20, 20)` is Equilateral. It also has equal pairs, so the Equilateral branch must come **before** the Isosceles branch.

**3. Check whether any pair is equal.** For a remaining valid row, one equal pair makes it Isosceles.

```sql
SELECT A, B, C,
       (A = B OR B = C OR C = A) AS any_pair_equal
FROM TRIANGLES;
```

| A | B | C | any_pair_equal |
|---:|---:|---:|---:|
| 20 | 20 | 23 | 1 |
| 20 | 20 | 20 | 1 |
| 20 | 21 | 22 | 0 |
| 13 | 14 | 30 | 0 |

`(20, 20, 23)` reaches the Isosceles branch. `(20, 20, 20)` does **not** reach it because its earlier Equilateral branch already matched. The invalid row was also handled earlier. The only remaining row, `(20, 21, 22)`, has three different sides and reaches `ELSE 'Scalene'`.

**4. Assemble the CASE.** Each row takes the first true branch:

```sql
SELECT
    CASE
        WHEN A + B <= C
          OR A + C <= B
          OR B + C <= A THEN 'Not A Triangle'
        WHEN A = B AND B = C THEN 'Equilateral'
        WHEN A = B OR B = C OR C = A THEN 'Isosceles'
        ELSE 'Scalene'
    END AS TriangleType
FROM TRIANGLES;
```

| Input sides | TriangleType |
|---|---|
| (20, 20, 23) | Isosceles |
| (20, 20, 20) | Equilateral |
| (20, 21, 22) | Scalene |
| (13, 14, 30) | Not A Triangle |

The actual query returns only `TriangleType`; the input-sides column above is shown to match each result with its sample row. There is no requested `ORDER BY`. The solution assumes the columns contain side lengths; if `NULL` values were allowed, the desired label for those rows would need to be specified.

## Official solution

The supplied handout uses the same branch order:

```sql
SELECT
    CASE
        WHEN A + B <= C OR A + C <= B OR B + C <= A THEN 'Not A Triangle'
        WHEN A = B AND B = C THEN 'Equilateral'
        WHEN A = B OR A = C OR B = C THEN 'Isosceles'
        ELSE 'Scalene'
    END AS TriangleType
FROM TRIANGLES;
```

**What this tests:** Conditional classification with `CASE`, comparisons, `AND`, and `OR`.

**The approach:** Reject invalid side combinations, then test all-equal, then any equal pair; the remaining valid combinations are Scalene.

**Why this way:** `CASE` returns its first matching branch. Testing invalid shapes before equality and Equilateral before Isosceles prevents incorrect labels.

**Common mistakes:** Using `<` instead of `<=` for an invalid equality boundary, checking Isosceles before Equilateral, or testing only `A + B` while forgetting the other two side pairs.
