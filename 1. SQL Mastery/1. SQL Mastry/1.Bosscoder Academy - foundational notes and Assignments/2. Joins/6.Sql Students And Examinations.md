## Question and image

Find **how many times each student attended each subject's exam**. Include every student–subject combination, even when its attendance count is zero. Return the result ordered by `student_id` and then `subject_name`.

**Example 1**

Input — `Students`:

| student_id | student_name |
|---:|---|
| 1 | Alice |
| 2 | Bob |
| 13 | John |
| 6 | Alex |

Input — `Subjects`:

| subject_name |
|---|
| Math |
| Physics |
| Programming |

Input — `Examinations`:

| student_id | subject_name |
|---:|---|
| 1 | Math |
| 1 | Physics |
| 1 | Programming |
| 2 | Programming |
| 1 | Physics |
| 1 | Math |
| 13 | Math |
| 13 | Programming |
| 13 | Physics |
| 2 | Math |
| 1 | Math |

Expected output:

| student_id | student_name | subject_name | attended_exams |
|---:|---|---|---:|
| 1 | Alice | Math | 3 |
| 1 | Alice | Physics | 2 |
| 1 | Alice | Programming | 1 |
| 2 | Bob | Math | 1 |
| 2 | Bob | Physics | 0 |
| 2 | Bob | Programming | 1 |

| 6 | Alex | Physics | 0 |
| 6 | Alex | Programming | 0 |
| 13 | John | Math | 1 |

Alice attended Math three times, Physics twice, and Programming once. Bob attended no Physics exam. Alex attended no exams, but still needs one zero-count row for each subject.

## Schema

`Students`:

| Column Name | Type |
|---|---|
| student_id | int |
| student_name | varchar |

`student_id` is the primary key. Each row identifies one student.

`Subjects`:

| Column Name | Type |
|---|---|
| subject_name | varchar |

`subject_name` is the primary key. Each row identifies one subject.

`Examinations`:

| Column Name | Type |
|---|---|
| student_id | int |
| subject_name | varchar |

There is no primary key; duplicate rows are possible. Each row records one attendance by the specified student in the specified subject's exam. Every student has every subject in the required output, regardless of attendance.

## My solution — SQLite

```sql
SELECT student_id,
       student_name,
       subject_name,
       (
           SELECT COUNT(*)
           FROM Examinations
           WHERE Examinations.student_id = Students.student_id
             AND Examinations.subject_name = Subjects.subject_name
       ) AS attended_exams
FROM Students
CROSS JOIN Subjects
ORDER BY student_id, subject_name;
```

### Step-by-step explanation with one example

**Starting data.** `Students` has four students, `Subjects` has three subjects, and `Examinations` records attendance. An attendance pair can appear several times: Alice and Math appears three times. Alex has no examination rows.

**1. Build every required student–subject pair.** The result must contain all subjects for every student, including those with zero attendance. `CROSS JOIN` combines each of 4 students with each of 3 subjects, giving **4 × 3 = 12** rows before counting.

```sql
SELECT Students.student_id, Students.student_name, Subjects.subject_name
FROM Students
CROSS JOIN Subjects
ORDER BY Students.student_id, Subjects.subject_name;
```

| student_id | student_name | subject_name |
|---:|---|---|
| 1 | Alice | Math |
| 1 | Alice | Physics |
| 1 | Alice | Programming |
| 2 | Bob | Math |
| 2 | Bob | Physics |
| 2 | Bob | Programming |
| 6 | Alex | Math |
| 6 | Alex | Physics |
| 6 | Alex | Programming |
| 13 | John | Math |
| 13 | John | Physics |
| 13 | John | Programming |

This table already contains Bob–Physics and all three Alex pairs, although they have no matching `Examinations` rows. The cross join does not claim that they attended; it only builds the combinations that need a count.

**2. Count examinations for the current pair.** For each row above, the subquery compares **both** the student ID and subject name with `Examinations`. For Alice–Math it acts like:

```sql
SELECT COUNT(*)
FROM Examinations
WHERE student_id = 1 AND subject_name = 'Math';
```

The count is **3** because there are three matching rows. For Bob–Physics, the same query with `student_id = 2` and `subject_name = 'Physics'` returns **0**. `COUNT(*)` counts duplicate attendance rows, as required, and returns zero when no rows match.

The comparisons `Examinations.student_id = Students.student_id` and `Examinations.subject_name = Subjects.subject_name` make this a **correlated subquery**: conceptually, its count is calculated for the current student–subject row. It produces one number, so no outer `GROUP BY` is needed.

**3. Add the count to every pair and sort.** Combine the cross join with the correlated count:

```sql
SELECT student_id,
       student_name,
       subject_name,
       (
           SELECT COUNT(*)
           FROM Examinations
           WHERE Examinations.student_id = Students.student_id
             AND Examinations.subject_name = Subjects.subject_name
       ) AS attended_exams
FROM Students
CROSS JOIN Subjects
ORDER BY student_id, subject_name;
```

The result is:

| student_id | student_name | subject_name | attended_exams |
|---:|---|---|---:|
| 1 | Alice | Math | 3 |
| 1 | Alice | Physics | 2 |
| 1 | Alice | Programming | 1 |
| 2 | Bob | Math | 1 |
| 2 | Bob | Physics | 0 |
| 2 | Bob | Programming | 1 |
| 6 | Alex | Math | 0 |
| 6 | Alex | Physics | 0 |
| 6 | Alex | Programming | 0 |
| 13 | John | Math | 1 |
| 13 | John | Physics | 1 |
| 13 | John | Programming | 1 |

`ORDER BY student_id, subject_name` puts students in ID order and their subjects in name order. Both the zero counts and the repeated attendance counts are preserved.

## Official solution

The lecture uses an outer join and grouping instead of a correlated count:

```sql
SELECT
    Students.student_id,
    Students.student_name,
    Subjects.subject_name,
    COUNT(Examinations.subject_name) AS attended_exams
FROM Students
JOIN Subjects
LEFT JOIN Examinations
    ON Students.student_id = Examinations.student_id
   AND Subjects.subject_name = Examinations.subject_name
GROUP BY Students.student_id, Subjects.subject_name
ORDER BY student_id ASC, subject_name ASC;
```

As supplied, the lecture query raises an ambiguous-column error in SQLite at `ORDER BY student_id`: both `Students` and `Examinations` have that column. Qualify the sorting columns as `ORDER BY Students.student_id ASC, Subjects.subject_name ASC`. With that correction, it matches the user's query on the example. It also relies on SQLite's allowance for `JOIN Subjects` without `ON` and for selecting `student_name` outside the `GROUP BY`. In SQL Server, write `CROSS JOIN Subjects` explicitly and also group by `Students.student_name`.

### What this tests

Creating all required combinations, retaining pairs with no attendance, and counting repeated attendance rows.

### The approach

Build the student–subject grid, left join attendance on both columns, then group and count a non-NULL `Examinations` column.

### Why this way

The grid keeps pairs such as Bob–Physics. `COUNT(Examinations.subject_name)` returns zero for the unmatched row because that right-side column is `NULL`.

### Common mistakes

Joining only existing examination rows loses zero-count pairs. Counting `*` after a left join counts its placeholder row as one. Matching only `student_id` ignores which subject was taken.
