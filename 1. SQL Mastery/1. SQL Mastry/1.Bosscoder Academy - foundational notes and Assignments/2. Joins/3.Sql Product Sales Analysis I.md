## Question and image

Report product_name, year, and price for each sale in Sales. The price is **per unit**. Return the result in any order.

**Example 1**

Input — Sales:

| sale_id | product_id | year | quantity | price |
|---:|---:|---:|---:|---:|
| 1 | 100 | 2008 | 10 | 5000 |
| 2 | 100 | 2009 | 12 | 5000 |
| 7 | 200 | 2011 | 15 | 9000 |

Input — Product:

| product_id | product_name |
|---:|---|
| 100 | Nokia |
| 200 | Apple |
| 300 | Samsung |

Expected output:

| product_name | year | price |
|---|---:|---:|
| Nokia | 2008 | 5000 |
| Nokia | 2009 | 5000 |
| Apple | 2011 | 9000 |

Sale 1 is a Nokia sale in 2008 for 5000 per unit; sale 2 is Nokia in 2009; sale 7 is Apple in 2011. Samsung has no sale in the example.

## Schema

Sales:

| Column Name | Type |
|---|---|
| sale_id | int |
| product_id | int |
| year | int |
| quantity | int |
| price | int |

(sale_id, year) is the stated composite primary key. product_id is a foreign key to Product. Each row is a sale of a product in a given year; price is per unit.

Product:

| Column Name | Type |
|---|---|
| product_id | int |
| product_name | varchar |

product_id is the primary key. Each row gives a product name.

## My solution — SQLite

```sql
SELECT Product.product_name, Sales.year, Sales.price
FROM Sales
LEFT JOIN Product
    ON Sales.product_id = Product.product_id;
```

### Step-by-step explanation with one example

**Starting data.** Each `Sales` row provides a `product_id`, year, and **per-unit** price. `Product` supplies the name for each product ID.

| sale_id | product_id | year | quantity | price |
|---:|---:|---:|---:|---:|
| 1 | 100 | 2008 | 10 | 5000 |
| 2 | 100 | 2009 | 12 | 5000 |
| 7 | 200 | 2011 | 15 | 9000 |

| Product.product_id | product_name |
|---:|---|
| 100 | Nokia |
| 200 | Apple |
| 300 | Samsung |

**1. Start from the sales.** The request is about every sale, so `Sales` is the left table. The final result needs `Sales.year` and `Sales.price`; it does not need `quantity`, because `price` is already the price per unit.

```sql
SELECT sale_id, product_id, year, price
FROM Sales
ORDER BY sale_id, year;
```

| sale_id | product_id | year | price |
|---:|---:|---:|---:|
| 1 | 100 | 2008 | 5000 |
| 2 | 100 | 2009 | 5000 |
| 7 | 200 | 2011 | 9000 |

**2. Match each sale's product ID to the product name.** `ON Sales.product_id = Product.product_id` looks up product 100 as Nokia and product 200 as Apple. Inspect the joined data with the IDs still visible:

```sql
SELECT Sales.sale_id, Sales.product_id, Product.product_name,
       Sales.year, Sales.price
FROM Sales
LEFT JOIN Product
    ON Sales.product_id = Product.product_id
ORDER BY Sales.sale_id, Sales.year;
```

| sale_id | product_id | product_name | year | price |
|---:|---:|---|---:|---:|
| 1 | 100 | Nokia | 2008 | 5000 |
| 2 | 100 | Nokia | 2009 | 5000 |
| 7 | 200 | Apple | 2011 | 9000 |

Nokia appears twice because there are two Nokia **sales**, not because `Product` has duplicate IDs. Samsung has no sale, so it does not appear: `Sales` is the preserved side of the left join.

**3. Return only the requested fields.** Remove `sale_id` and `product_id`, which were useful for checking the match but are not requested:

```sql
SELECT Product.product_name, Sales.year, Sales.price
FROM Sales
LEFT JOIN Product
    ON Sales.product_id = Product.product_id;
```

One valid output order is:

| product_name | year | price |
|---|---:|---:|
| Nokia | 2008 | 5000 |
| Nokia | 2009 | 5000 |
| Apple | 2011 | 9000 |

The user query uses `LEFT JOIN`, so a sale with no matching product would still appear with a `NULL` product name. The lecture's inner join would omit such a sale. They give the same result for this example, where every sale has a matching product. Because no output order is required, the final query has no `ORDER BY`.

## Official solution

The lecture material uses an inner join:

```sql
SELECT p.product_name, s.year, s.price
FROM Sales AS s
JOIN Product AS p
    ON s.product_id = p.product_id;
```

### What this tests

Matching fact rows to a lookup table to add descriptive product names.

### The approach

Join `Sales.product_id` to `Product.product_id`, then select the name, year, and per-unit price.

### Why this way

Each sale already has the year and price; only the product name comes from `Product`.

### Common mistakes

Joining on `sale_id` would match unrelated IDs. Multiplying `price` by `quantity` would calculate a total, but the question asks for the per-unit price.
