## Question and image

**LeetCode 1831:** [Maximum Transaction Each Day](https://leetcode.com/problems/maximum-transaction-each-day/)

This is assignment question 6, saved as Question 11 in this section.

Report the IDs of the transactions with the maximum amount on each day. If several transactions on the same day share that maximum amount, include all of them.

Return the result ordered by `transaction_id` in ascending order.

**Example 1:**

Input — Transactions:

| transaction_id | day | amount |
| ---: | --- | ---: |
| 8 | 2021-4-3 15:57:28 | 57 |
| 9 | 2021-4-28 08:47:25 | 21 |
| 1 | 2021-4-29 13:28:30 | 58 |
| 5 | 2021-4-28 16:39:59 | 40 |
| 6 | 2021-4-29 23:39:28 | 58 |

Output:

| transaction_id |
| ---: |
| 1 |
| 5 |
| 6 |
| 8 |

**Example explanation:** April 3 has only transaction 8, so it is included. On April 28, transaction 5 has amount 40 and transaction 9 has amount 21, so only 5 is included. On April 29, transactions 1 and 6 tie at the maximum amount of 58, so both are included. The final IDs appear in ascending order.

## My solution — SQLite

```sql
WITH cte AS (
    SELECT
        DATE(day) AS Calender_date,
        transaction_id,
        amount,
        RANK() OVER (
            PARTITION BY DATE(day)
            ORDER BY amount DESC
        ) AS amount_rank
    FROM Transactions
)
SELECT transaction_id
FROM cte
WHERE amount_rank = 1
ORDER BY transaction_id;
```

### Step-by-step explanation with one example

**1. Identify the rows and the required result.** One output row represents a transaction whose `amount` is the highest for its calendar date. If several transactions tie for that highest amount, each transaction gets its own output row. Return only `transaction_id`, sorted in ascending order.

The question displays dates without leading zeroes, such as `2021-4-3`. To run this example using SQLite's `DATE(day)`, the same dates are stored below as standard zero-padded timestamps, such as `2021-04-03`. The transaction IDs, times, amounts, and calendar dates are unchanged. If the displayed nonpadded strings are inserted literally as text, SQLite's `DATE()` returns `NULL` for them. For a SQLite judge that stores those exact strings, replace both `DATE(day)` expressions with `SUBSTR(day, 1, INSTR(day, ' ') - 1)`; it extracts the date text before the space while keeping the same ranking logic.

```sql
SELECT transaction_id, day, amount
FROM Transactions
ORDER BY transaction_id;
```

| transaction_id | day | amount |
|---:|---|---:|
| 1 | 2021-04-29 13:28:30 | 58 |
| 5 | 2021-04-28 16:39:59 | 40 |
| 6 | 2021-04-29 23:39:28 | 58 |
| 8 | 2021-04-03 15:57:28 | 57 |
| 9 | 2021-04-28 08:47:25 | 21 |

Each input row is one transaction. The `day` column includes a time, so two transactions on the same calendar date can have different full `day` values.

**2. Extract the calendar date.** `DATE(day)` removes the time from a standard SQLite timestamp. This makes the two April 28 rows share `2021-04-28` and the two April 29 rows share `2021-04-29`.

```sql
SELECT
    transaction_id,
    day,
    DATE(day) AS Calender_date,
    amount
FROM Transactions
ORDER BY DATE(day), amount DESC, transaction_id;
```

| transaction_id | day | Calender_date | amount |
|---:|---|---|---:|
| 8 | 2021-04-03 15:57:28 | 2021-04-03 | 57 |
| 5 | 2021-04-28 16:39:59 | 2021-04-28 | 40 |
| 9 | 2021-04-28 08:47:25 | 2021-04-28 | 21 |
| 1 | 2021-04-29 13:28:30 | 2021-04-29 | 58 |
| 6 | 2021-04-29 23:39:28 | 2021-04-29 | 58 |

Partitioning by the full timestamp would separate the April 28 transactions because their times differ. Both the displayed `Calender_date` and the window partition therefore use `DATE(day)`.

**3. Rank amounts within each calendar date.** `PARTITION BY DATE(day)` starts the ranking again for each date. `ORDER BY amount DESC` places the largest amount at rank 1. `RANK()` gives equal amounts the same rank, retaining the April 29 tie.

```sql
SELECT
    transaction_id,
    DATE(day) AS Calender_date,
    amount,
    RANK() OVER (
        PARTITION BY DATE(day)
        ORDER BY amount DESC
    ) AS amount_rank
FROM Transactions
ORDER BY DATE(day), amount DESC, transaction_id;
```

| transaction_id | Calender_date | amount | amount_rank |
|---:|---|---:|---:|
| 8 | 2021-04-03 | 57 | 1 |
| 5 | 2021-04-28 | 40 | 1 |
| 9 | 2021-04-28 | 21 | 2 |
| 1 | 2021-04-29 | 58 | 1 |
| 6 | 2021-04-29 | 58 | 1 |

April 3 has one transaction, so ID 8 ranks 1. On April 28, 40 outranks 21, so ID 5 ranks 1 and ID 9 ranks 2. On April 29, IDs 1 and 6 both have 58, so both rank 1. The window's `ORDER BY amount DESC` controls the ranking; it does not set the final order of output rows.

**4. Keep the maximum transactions and sort their IDs.** The CTE stores `amount_rank`, making it available to the outer query's `WHERE`. Rank 1 keeps every daily maximum, including ties. The final `ORDER BY transaction_id` supplies the required ascending ID order.

```sql
WITH cte AS (
    SELECT
        DATE(day) AS Calender_date,
        transaction_id,
        amount,
        RANK() OVER (
            PARTITION BY DATE(day)
            ORDER BY amount DESC
        ) AS amount_rank
    FROM Transactions
)
SELECT transaction_id
FROM cte
WHERE amount_rank = 1
ORDER BY transaction_id;
```

| transaction_id |
|---:|
| 1 |
| 5 |
| 6 |
| 8 |

**5. Check the result.** The qualifying IDs are 8 for April 3, 5 for April 28, and both 1 and 6 for April 29. Sorting `8, 5, 1, 6` produces `1, 5, 6, 8`, matching the supplied expected output. ID 9 is excluded because its amount 21 is below the April 28 maximum 40.

## My solution — SQL Server

```sql
WITH cte AS (
    SELECT
        CAST([day] AS date) AS Calender_date,
        transaction_id,
        amount,
        RANK() OVER (
            PARTITION BY CAST([day] AS date)
            ORDER BY amount DESC
        ) AS amount_rank
    FROM Transactions
)
SELECT transaction_id
FROM cte
WHERE amount_rank = 1
ORDER BY transaction_id;
```

SQL Server uses `CAST([day] AS date)` to extract the calendar date from a `datetime` value. The ranking, tie handling, CTE filter, and final ordering preserve the SQLite solution's approach.
