# 1. Intro to SQL and Advanced SELECT — Foundation Notes

**Main idea:** start with the table, choose the columns you want, keep the right rows, then arrange the result. Learn one clause at a time before combining them.

## 1. Read a table with SELECT

We will use these `Customers` rows throughout the notes:

| customer_id | name | city | country |
| --- | --- | --- | --- |
| 1 | Alice | Berlin | Germany |
| 2 | Bob | London | UK |
| 3 | Amir | Paris | France |
| 4 | Clara | Berlin | Germany |
| 5 | Sam | London | UK |
| 6 | Arjun | Berlin | Germany |
| 7 | Mira | Rome | Italy |

`SELECT` chooses output columns; `FROM` names the source table.

```sql
SELECT customer_id, name, city
FROM Customers
ORDER BY customer_id;
```

| customer_id | name | city |
| --- | --- | --- |
| 1 | Alice | Berlin |
| 2 | Bob | London |
| 3 | Amir | Paris |
| 4 | Clara | Berlin |
| 5 | Sam | London |
| 6 | Arjun | Berlin |
| 7 | Mira | Rome |

There are still seven rows. Selecting fewer columns does **not** remove rows. `SELECT *` means all columns; naming the required columns makes an answer easier to check. `ORDER BY customer_id` fixes the display order and is explained in section 7.

You can also calculate a value and give it an output name:

```sql
SELECT product_name, price * 2 AS double_price
FROM Products
WHERE product_id = 10;
```

| product_name | double_price |
| --- | ---: |
| Pen | 20 |

`AS double_price` labels the calculated column. It does not change the stored `price`.

## 2. Keep rows with WHERE

`WHERE` tests **each input row**. Only rows for which the condition is true continue to the result.

```sql
SELECT customer_id, name, city
FROM Customers
WHERE city = 'Berlin'
ORDER BY customer_id;
```

| customer_id | name | city |
| --- | --- | --- |
| 1 | Alice | Berlin |
| 4 | Clara | Berlin |
| 6 | Arjun | Berlin |

The other four customers still exist in the table; this query simply leaves them out. Text values are quoted with single quotes. Column names are not text values.

| Condition | Read it as | Example |
| --- | --- | --- |
| `= 10` | equal to 10 | `price = 10` |
| `<> 10` | different from 10 | `price <> 10` |
| `> 10`, `< 10` | strictly above, below | `price > 10` |
| `>= 10`, `<= 10` | at least, at most | `price >= 10` |

If a question says **positive** revenue, test `revenue > 0`. If it says **nonnegative**, test `revenue >= 0`: zero passes only the second test.

## 3. Combine conditions with AND, OR, NOT

- `AND`: both tests must be true.
- `OR`: at least one test must be true.
- `NOT`: reverse a test.

```sql
SELECT customer_id, name
FROM Customers
WHERE country = 'Germany' AND customer_id > 1
ORDER BY customer_id;
```

| customer_id | name |
| --- | --- |
| 4 | Clara |
| 6 | Arjun |

Alice lives in Germany but has ID 1, so she fails the second test.

```sql
SELECT customer_id, name
FROM Customers
WHERE city = 'Berlin' OR city = 'London'
ORDER BY customer_id;
```

| customer_id | name |
| --- | --- |
| 1 | Alice |
| 2 | Bob |
| 4 | Clara |
| 5 | Sam |
| 6 | Arjun |

```sql
SELECT customer_id, name
FROM Customers
WHERE NOT country = 'Germany'
ORDER BY customer_id;
```

| customer_id | name |
| --- | --- |
| 2 | Bob |
| 3 | Amir |
| 5 | Sam |
| 7 | Mira |

**Parentheses matter when AND and OR appear together.** SQL applies `AND` before `OR`:

| Condition | Matched IDs | How it is read |
| --- | --- | --- |
| `city = 'Berlin' OR city = 'London' AND customer_id > 4` | 1, 4, 5, 6 | Berlin, **or** London with ID above 4 |
| `(city = 'Berlin' OR city = 'London') AND customer_id > 4` | 5, 6 | Either city, **and** ID above 4 |

Write parentheses when the same extra condition should apply to both sides of `OR`.

## 4. Use IN and BETWEEN

`IN` is a shorter way to compare one value with a list of exact values.

```sql
SELECT customer_id, name, country
FROM Customers
WHERE country IN ('Germany', 'UK')
ORDER BY customer_id;
```

| customer_id | name | country |
| --- | --- | --- |
| 1 | Alice | Germany |
| 2 | Bob | UK |
| 4 | Clara | Germany |
| 5 | Sam | UK |
| 6 | Arjun | Germany |

This is equivalent to `country = 'Germany' OR country = 'UK'`. `IN` matches complete values; it does not match name patterns.

Our `Products` sample has these prices:

| product_id | product_name | price |
| --- | --- | ---: |
| 10 | Pen | 10 |
| 11 | Notebook | 15 |
| 12 | Mug | 20 |
| 13 | Bag | 25 |

```sql
SELECT product_name, price
FROM Products
WHERE price BETWEEN 10 AND 20
ORDER BY price;
```

| product_name | price |
| --- | ---: |
| Pen | 10 |
| Notebook | 15 |
| Mug | 20 |

`BETWEEN 10 AND 20` includes **both** 10 and 20. It means `price >= 10 AND price <= 20`. Bag is excluded because 25 is outside the range.

**Date tip:** to cover all of February 2020, including timestamps during February 29, use `event_date >= '2020-02-01' AND event_date < '2020-03-01'`. The upper boundary belongs to the next month and is excluded.

## 5. Match text with LIKE and wildcards

`LIKE` checks text against a pattern. These two wildcard characters have different jobs:

| Wildcard | Matches | Sample pattern | What it finds here |
| --- | --- | --- | --- |
| `%` | Zero or more characters | `'A%'` | Alice, Amir, Arjun |
| `_` | Exactly one character | `'_r%'` | Arjun; `r` is the second character |

```sql
SELECT customer_id, name
FROM Customers
WHERE name LIKE 'A%'
ORDER BY customer_id;
```

| customer_id | name |
| --- | --- |
| 1 | Alice |
| 3 | Amir |
| 6 | Arjun |

Read `'A%'` as “starts with A, then has any number of characters.” More useful shapes:

| Pattern | Meaning | Match in our sample |
| --- | --- | --- |
| `'%a'` | Ends in `a` | Clara, Mira |
| `'%li%'` | Contains `li` | Alice |
| `'A___'` | Starts with `A`, four letters total | Amir |
| `'_r%'` | Second letter is `r` | Arjun |

To exclude a prefix, use `name NOT LIKE 'A%'`. In SQLite, basic `LIKE` usually ignores ASCII letter case; SQL Server behavior depends on the column's collation. For bracket patterns and SQLite `GLOB`, see [Section 8](<../8. Advance string functions, regex and clause/0. Foundation Notes.md>). `LIKE '[AEIOU]%'` is **not** a vowel set in SQLite.

## 6. Remove duplicate results with DISTINCT

`SELECT city FROM Customers` produces Berlin three times and London twice because several customers share those cities. To list each city once:

```sql
SELECT DISTINCT city
FROM Customers
ORDER BY city;
```

| city |
| --- |
| Berlin |
| London |
| Paris |
| Rome |

`DISTINCT` checks the **whole selected row**. With `SELECT DISTINCT city, country`, a pair repeats only when **both** values match. It does not choose one representative customer or change the data in `Customers`.

## 7. Sort with ORDER BY

`ORDER BY` controls the returned row order. `ASC` means smallest to largest or A to Z; `DESC` reverses it. Without an outer `ORDER BY`, the output order is not guaranteed.

```sql
SELECT customer_id, name, city
FROM Customers
ORDER BY city ASC, name DESC;
```

| customer_id | name | city |
| --- | --- | --- |
| 4 | Clara | Berlin |
| 6 | Arjun | Berlin |
| 1 | Alice | Berlin |
| 5 | Sam | London |
| 2 | Bob | London |
| 3 | Amir | Paris |
| 7 | Mira | Rome |

First sort cities A to Z. **Within the same city**, sort names Z to A. The second expression is a tie-breaker; it does not reshuffle customers between cities. Add a unique ID at the end if equal sort values still need a fixed order.

## 8. Combine SELECT results with UNION

`Suppliers` contains these cities:

| supplier_id | city |
| --- | --- |
| 1 | Berlin |
| 2 | Madrid |
| 3 | Rome |

`UNION` stacks two results vertically and removes repeated **complete rows**:

```sql
SELECT city FROM Customers
UNION
SELECT city FROM Suppliers
ORDER BY city;
```

| city |
| --- |
| Berlin |
| London |
| Madrid |
| Paris |
| Rome |

`UNION ALL` stacks the rows and keeps every repeat:

```sql
SELECT city FROM Customers
UNION ALL
SELECT city FROM Suppliers
ORDER BY city;
```

| city |
| --- |
| Berlin |
| Berlin |
| Berlin |
| Berlin |
| London |
| London |
| Madrid |
| Paris |
| Rome |
| Rome |

The `UNION ALL` result has **10 rows**: seven customer rows plus three supplier rows. Berlin appears four times because three customers and one supplier have that city. `UNION` has five rows because each city appears once.

Both SELECT branches need the **same number of columns** in corresponding positions, with compatible types. The final `ORDER BY` sorts the combined result. `INTERSECT` keeps values in both results (Berlin, Rome here); `EXCEPT` keeps values from the first result absent in the second (London, Paris here). A join serves a different purpose: it connects matching rows side by side.

## 9. Handle NULL and create values with CASE

`NULL` means “missing or unknown.” It is different from zero. In our products, Notebook has known stock `0`; Mug has unknown stock `NULL`.

| product_name | stock |
| --- | ---: |
| Pen | 8 |
| Notebook | 0 |
| Mug | NULL |
| Bag | 3 |

Use `IS NULL`, not `= NULL`:

```sql
SELECT product_name
FROM Products
WHERE stock IS NULL;
```

| product_name |
| --- |
| Mug |

`CASE` lets you produce a value for each row:

```sql
SELECT product_name,
       CASE
           WHEN stock IS NULL THEN 'Unknown'
           WHEN stock = 0 THEN 'Sold out'
           ELSE 'Available'
       END AS availability
FROM Products
ORDER BY product_id;
```

| product_name | availability |
| --- | --- |
| Pen | Available |
| Notebook | Sold out |
| Mug | Unknown |
| Bag | Available |

Check the missing case first, then zero, then everything else. `CASE` creates a column; it does **not** filter out rows. `COALESCE(stock, 0)` would replace a missing stock with zero in the result, so use that only if the question says missing stock should count as zero. For division, `NULLIF(denominator, 0)` can turn a zero denominator into NULL before dividing.

## 10. Choose top rows

Sort **before** keeping the first few rows. In SQLite, `LIMIT` gives the row count:

```sql
SELECT product_name, price
FROM Products
ORDER BY price DESC, product_id ASC
LIMIT 2;
```

| product_name | price |
| --- | ---: |
| Bag | 25 |
| Mug | 20 |

SQL Server expresses the same request with `TOP`:

```sqlserver
SELECT TOP (2) product_name, price
FROM Products
ORDER BY price DESC, product_id ASC;
```

The extra `product_id` decides the order if two products share a price. `LIMIT 2` and `TOP (2)` return two rows; a request to **include every tie** needs a different approach.

## 11. Quick revision

| Question wording | Start with |
| --- | --- |
| Show these columns | `SELECT column1, column2` |
| Only rows meeting a test | `WHERE condition` |
| Both tests / either test | `AND` / `OR` |
| Exclude a condition | `NOT` or `NOT LIKE` |
| Any value in a list | `IN (...)` |
| Inclusive range | `BETWEEN low AND high` |
| Name starts with A | `LIKE 'A%'` |
| Exactly one unknown character | `_` inside a `LIKE` pattern |
| Unique selected results | `DISTINCT` |
| Largest first, then name | `ORDER BY value DESC, name ASC` |
| Merge results without / with repeats | `UNION` / `UNION ALL` |
| Missing value | `IS NULL` |
| Conditional output label | `CASE WHEN ... THEN ... ELSE ... END` |

**Before submitting:** check the exact output columns, whether duplicate rows matter, whether a boundary is inclusive, where parentheses belong, and whether the requested order has all its tie-breakers. Practice these ideas on the section's questions before reading a complete solution.

    product_id INTEGER PRIMARY KEY,
