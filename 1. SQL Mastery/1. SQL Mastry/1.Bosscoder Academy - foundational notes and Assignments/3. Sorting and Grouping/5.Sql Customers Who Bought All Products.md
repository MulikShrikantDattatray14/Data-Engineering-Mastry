## Schema

**Customer**  
customer_id, product_key

- `customer_id` — integer; not `NULL`
- `product_key` — integer; foreign key referencing `Product.product_key`
- The table may contain duplicate rows.

**Product**  
product_key

- `product_key` — integer; primary key

## My solution — SQLite

```sql
SELECT DISTINCT customer_id
FROM Customer
GROUP BY customer_id
HAVING COUNT(DISTINCT product_key) = (
    SELECT COUNT(DISTINCT product_key)
    FROM Product
)
ORDER BY customer_id ASC;
```
### Key learnings

- `GROUP BY customer_id` creates one result group per customer.
- `COUNT(DISTINCT product_key)` counts each product only once. This is necessary because the `Customer` table may contain duplicate rows.
- The subquery counts how many products exist in the complete `Product` table.
- `HAVING` compares each customer's distinct product count with the total product count because it filters after grouping and aggregation.
- The outer `SELECT DISTINCT` is redundant because `GROUP BY customer_id` already returns one row per customer, but keeping it does not make the result incorrect.
- Because `Product.product_key` is a primary key, `COUNT(*)`, `COUNT(product_key)`, and `COUNT(DISTINCT product_key)` give the same product total in the subquery.


### Step-by-step explanation with one example

We need one row per customer who bought every product listed in Product. The same Customer and Product sample tables are used throughout. Because customer purchase rows may repeat, count distinct product keys rather than purchase rows.

**Starting data**

`Customer`:

| customer_id | product_key |
| --- | --- |
| 1 | 5 |
| 2 | 6 |
| 3 | 5 |
| 3 | 6 |
| 1 | 6 |

`Product`:

| product_key |
| --- |
| 5 |
| 6 |

**1. Find how many different products must be covered**

The Product table defines the full set to buy. Its count is a single target value that every customer group must match.

```sql
SELECT COUNT(DISTINCT product_key) AS total_products
FROM Product;
```

Result:

| total_products |
| --- |
| 2 |

There are two required products: 5 and 6.

**2. Count each customer's distinct products**

GROUP BY customer_id creates one customer group, and DISTINCT ensures buying the same product repeatedly does not increase coverage.

```sql
SELECT customer_id, COUNT(DISTINCT product_key) AS products_bought
FROM Customer
GROUP BY customer_id
ORDER BY customer_id;
```

Result:

| customer_id | products_bought |
| --- | --- |
| 1 | 2 |
| 2 | 1 |
| 3 | 2 |

Customers 1 and 3 each bought two different products. Customer 2 bought only product 6, so its count is one.

**3. Compare each group against the product total**

The scalar subquery supplies the target 2 to HAVING. The product_key foreign key guarantees that counted purchased products belong to Product, so matching the complete distinct count means all products were bought.

```sql
SELECT customer_id, COUNT(DISTINCT product_key) AS products_bought
FROM Customer
GROUP BY customer_id
HAVING COUNT(DISTINCT product_key) = (
    SELECT COUNT(DISTINCT product_key) FROM Product
)
ORDER BY customer_id;
```

Result:

| customer_id | products_bought |
| --- | --- |
| 1 | 2 |
| 3 | 2 |

Only customers 1 and 3 meet the target. The final SELECT DISTINCT is kept from the saved solution, although grouping already gives one row per customer.

**4. Assemble the final query**

Keep the saved logic and return only customer_id, in ascending order.

```sql
SELECT DISTINCT customer_id
FROM Customer
GROUP BY customer_id
HAVING COUNT(DISTINCT product_key) = (
    SELECT COUNT(DISTINCT product_key)
    FROM Product
)
ORDER BY customer_id ASC;
```

Final result for this example:

| customer_id |
| --- |
| 1 |
| 3 |

**Check the result:** Manual check: customer 1 bought {5, 6}, customer 2 bought {6}, and customer 3 bought {5, 6}. Compare those sets with Product = {5, 6}; customers 1 and 3 qualify.

## My solution — SQL Server

```sql
SELECT DISTINCT customer_id
FROM Customer
GROUP BY customer_id
HAVING COUNT(DISTINCT product_key) = (
    SELECT COUNT(DISTINCT product_key)
    FROM Product
)
ORDER BY customer_id ASC;
```

The same query works in SQLite and SQL Server.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).

## Official solution

**Lecture solution supplied in the GROUP BY/HAVING notes:**

```sql
select customer_id
from Customer
group by customer_id
having count(distinct product_key) = (
    select count(product_key)
    from Product
);
```

### What this tests

Checking whether each customer bought every product despite duplicate purchase rows.

### The approach

Group purchases by customer, count their distinct product keys, and compare that count with the number of products in `Product`.

### Why this way

Repeated purchases cannot make up for a missing product. `Product.product_key` is a primary key, so counting it gives the required product total.

### Common mistakes

- `COUNT(*)` on `Customer` counts repeated purchases and can falsely qualify a customer.
- Comparing counts assumes `Customer.product_key` refers to `Product`, as the schema states.
