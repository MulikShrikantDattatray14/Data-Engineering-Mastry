## My solution — SQLite

Your final subquery solution:

```sql
SELECT order_id
FROM orders
WHERE order_id NOT IN (
    SELECT order_id
    FROM payments
    WHERE order_id IS NOT NULL
)
AND status = 'DELIVERED';
```

**3. Keep delivered orders absent from that list.** For order 10, `10 NOT IN (10)` is false. For order 11, `11 NOT IN (10)` is true.

| Delivered order_id | In payment list? | Keep? |
|---:|---|---|
| 10 | Yes | No |

The final output is:

| order_id |

**4. Check the `NULL` edge case.** If a payment row with `order_id = NULL` were added, an unfiltered `NOT IN` list would contain `(10, NULL)`. The comparison `11 NOT IN (10, NULL)` would be unknown, and order 11 would disappear. Your `WHERE order_id IS NOT NULL` keeps the list as `(10)`, so the result remains 11.

## Official solution

**Source:** [Advanced SQL 100 Query Questions, Vol. 1](<../Source Materials/Advanced_SQL_100_Query_Questions_Vol1 (2).pdf>), question 5, PDF p. 3. The source uses MySQL 8.

```sql
SELECT o.order_id, o.amount
FROM orders o
WHERE o.status = 'DELIVERED'
  AND NOT EXISTS (
      SELECT 1
      FROM payments p
      WHERE p.order_id = o.order_id
  );
```

**What this tests.** Finding rows in one table with no matching row in another.

**The approach.** Start with delivered orders. For each one, `NOT EXISTS` checks whether any payment has the same `order_id`. An order remains only if no payment matches.

**Why this works.** The correlated subquery compares each payment's `order_id` with the current order's ID. `NOT EXISTS` is true precisely when that comparison finds no row. It does not have the `NOT IN`/`NULL` trap.

**Output-column difference.** The source's answer includes `o.amount` as well as `o.order_id`, although its short task statement does not specify output columns. Your answer returns the ID requested by the illustrative output.

**Common mistakes.** Starting from `payments` loses orders that have no payment. Putting `NULL` values into a `NOT IN` subquery can suppress otherwise valid results.
