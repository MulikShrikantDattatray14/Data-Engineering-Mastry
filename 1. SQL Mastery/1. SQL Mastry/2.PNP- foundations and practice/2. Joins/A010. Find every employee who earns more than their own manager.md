## My solution — SQLite

Your final self-join solution:

```sql
SELECT
    e1.emp_id,
    e1.emp_name
FROM employees AS e1
INNER JOIN employees AS e2
    ON e1.manager_id = e2.emp_id
WHERE e1.salary > e2.salary;
```

## Official solution

**Source:** [Advanced SQL 100 Query Questions, Vol. 1](<../Source Materials/Advanced_SQL_100_Query_Questions_Vol1 (2).pdf>), question 10, PDF p. 4. The source uses MySQL 8.

```sql
SELECT e.emp_name, e.salary, m.emp_name AS manager, m.salary AS mgr_salary
FROM employees e
JOIN employees m ON m.emp_id = e.manager_id
WHERE e.salary > m.salary;
```

**What this tests.** Comparing employees with rows for their own managers in the same table.

**The approach.** Give `employees` two aliases, join each employee's `manager_id` to the manager's `emp_id`, then keep rows where the employee's salary is greater.

**Why this works.** The join connects each employee with their actual manager before comparing salaries, so employees are not compared with unrelated people.

**Output-column difference.** The source answer returns the employee's name and salary plus the manager's name and salary. Your answer returns `emp_id` and `emp_name`, which match the illustrative output in this practice file.

**Common mistakes.** Joining `e.emp_id = m.manager_id` reverses the employee and manager roles. Comparing salaries before identifying the correct manager gives the wrong relationship.
