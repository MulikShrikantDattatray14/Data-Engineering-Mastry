# PNP Q015. Product count for every category

![SOLVED](<../../_badges/solved.svg>) · Solved (recorded): 2026-10-27 ![EASY](<../../_badges/easy.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 15, pp. 29–30. **Difficulty:** Easy.

**Business scenario.** The catalogue team is cleaning up the app's category menu. An empty category leads shoppers to a blank page, so they want every category with its product count, empty ones included and listed first.

**Task.** For every row in Category , return the number of products assigned to it. A category with no products must appear with 0. Sort by product count ascending, then CategoryID .

**Expected output (as supplied):**

```text
CategoryID
CategoryName
product_count : products in that category, 0 when none
```

## My solution — SQLite

```sql
SELECT
    C.CategoryID,
    C.CategoryName,
    COUNT(P.ProductID) AS product_count
FROM Category AS C
LEFT JOIN Products AS P
    ON C.CategoryID = P.CategoryID
GROUP BY C.CategoryID, C.CategoryName
ORDER BY product_count ASC, C.CategoryID ASC;
```

### Step-by-step explanation with one example

**Starting data.** The same small example from the question has two categories. Snacks has two products; Toys has none.

`Category`:

| CategoryID | CategoryName |
|---:|---|
| 1 | Snacks |
| 2 | Toys |

`Products`:

| ProductID | CategoryID |
|---:|---:|
| 10 | 1 |
| 11 | 1 |

**1. Keep every category while matching products.** We need a result row for Toys even though there is no matching product. Start from `Category` and use a `LEFT JOIN` on `CategoryID`.

```sql
SELECT C.CategoryID, C.CategoryName, P.ProductID
FROM Category AS C
LEFT JOIN Products AS P
    ON C.CategoryID = P.CategoryID
ORDER BY C.CategoryID, P.ProductID;
```

| CategoryID | CategoryName | ProductID |
|---:|---|---:|
| 1 | Snacks | 10 |
| 1 | Snacks | 11 |
| 2 | Toys | NULL |

Snacks appears twice because it matches two products. Toys appears once with a `NULL` product ID because the left join preserves its category row. An `INNER JOIN` would have removed Toys.

**2. Count actual products per category.** Group the joined rows by both selected category columns. `COUNT(P.ProductID)` counts only non-`NULL` product IDs.

```sql
SELECT
    C.CategoryID,
    C.CategoryName,
    COUNT(P.ProductID) AS product_count
FROM Category AS C
LEFT JOIN Products AS P
    ON C.CategoryID = P.CategoryID
GROUP BY C.CategoryID, C.CategoryName
ORDER BY C.CategoryID;
```

| CategoryID | CategoryName | product_count |
|---:|---|---:|
| 1 | Snacks | 2 |
| 2 | Toys | 0 |

For Snacks, IDs 10 and 11 give a count of 2. For Toys, the one joined row has `P.ProductID = NULL`, so its count is 0. `COUNT(*)` would count that placeholder row and incorrectly give Toys a count of 1. Grouping `CategoryName` as well as `CategoryID` makes the selected columns valid in SQL Server too.

**3. Apply the requested sort.** Order by the computed count ascending, then by category ID ascending for ties.

```sql
SELECT
    C.CategoryID,
    C.CategoryName,
    COUNT(P.ProductID) AS product_count
FROM Category AS C
LEFT JOIN Products AS P
    ON C.CategoryID = P.CategoryID
GROUP BY C.CategoryID, C.CategoryName
ORDER BY product_count ASC, C.CategoryID ASC;
```

| CategoryID | CategoryName | product_count |
|---:|---|---:|
| 2 | Toys | 0 |
| 1 | Snacks | 2 |

**Manual check.** Both input categories remain. Toys has no product and therefore has 0; Snacks has two products and therefore has 2. Zero sorts before two. The example has no count tie, but `CategoryID ASC` specifies how ties are resolved. These tables show the result of the illustrative sample, not a claim that the full dataset was executed.

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 15.

```sql
SELECT cat.CategoryID,
       cat.CategoryName,
       COUNT(p.ProductID) AS product_count
FROM Category AS cat
LEFT JOIN Products AS p ON p.CategoryID = cat.CategoryID
GROUP BY cat.CategoryID, cat.CategoryName
ORDER BY product_count, cat.CategoryID;
```

**What this tests.** Preserving unmatched rows with `LEFT JOIN`, grouping at category level, and counting a nullable column after the join.

**The approach.** Start with every category, attach its products if any, count the matched `ProductID` values, and sort by count and category ID.

**Why this way.** The left join keeps empty categories. `COUNT(p.ProductID)` ignores their `NULL` product placeholder, so an empty category gets 0. Your query uses the same logic; the source omits the optional `ASC` keywords.

**Common mistakes.** An `INNER JOIN` removes empty categories. `COUNT(*)` gives an empty category 1 because the left join still produces one placeholder row. Grouping by too few columns can be invalid in SQL Server, and omitting the second sort key leaves ties unspecified.
