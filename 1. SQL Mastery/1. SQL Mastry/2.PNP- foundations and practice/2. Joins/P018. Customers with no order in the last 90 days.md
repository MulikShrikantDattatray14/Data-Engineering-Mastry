# PNP Q018. Customers with no order in the last 90 days

![SOLVED](<../../_badges/solved.svg>) · Solved (recorded): 2026-10-27 ![EASY](<../../_badges/easy.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 18, pp. 33–34. **Difficulty:** Easy.

**Business scenario.** The retention team sends a "we miss you" offer to customers who have gone quiet. The list is every registered customer with no order in the last 90 days of data, whether they went quiet or never ordered at all; the team splits the two groups later. "Last 90 days" ends on the latest OrderDate in the table, not on today's date, because the extract may be weeks old.

**Task.** Return every customer who has no order dated within the 90 days ending on the latest OrderDate in Orders . Show their name, email and sign-up date. Sort by DateEntered , then CustomerID .

**Expected output (as supplied):**

```text
CustomerID
customer_name : first and last name
Email
DateEntered
```

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

Your final query:

```sql
SELECT
    C.CustomerID,
    C.FirstName || ' ' || C.LastName AS customer_name,
    C.Email,
    C.DateEntered
FROM Customers AS C
LEFT JOIN Orders AS O
    ON C.CustomerID = O.CustomerID
   AND DATE(O.OrderDate) BETWEEN
       DATE((SELECT MAX(DATE(OrderDate)) FROM Orders), '-89 days')
       AND (SELECT MAX(DATE(OrderDate)) FROM Orders)
WHERE O.OrderID IS NULL
ORDER BY C.DateEntered, C.CustomerID;
```

### Step-by-step explanation with one example

**Starting data.** Keep the same illustrative rows from the question throughout:

`Customers`:

| CustomerID | FirstName | LastName | Email | DateEntered |
|---:|---|---|---|---|
| 1 | Asha | Rao | asha@example.com | 2023-01-01 |
| 2 | Ben | Das | ben@example.com | 2023-02-01 |
| 3 | Cia | Sen | cia@example.com | 2024-01-01 |

`Orders`:

| OrderID | CustomerID | OrderDate |
|---:|---:|---|
| 10 | 1 | 2025-03-31 |
| 11 | 2 | 2024-12-01 |

**1. Calculate the 90-day window.** The latest order date is 2025-03-31. Count it as day one and go back 89 days to 2025-01-01. `BETWEEN` includes both dates, giving 90 calendar dates.

```sql
SELECT
    MAX(DATE(OrderDate)) AS latest_date,
    DATE(MAX(DATE(OrderDate)), '-89 days') AS first_date
FROM Orders;
```

| latest_date | first_date |
|---|---|
| 2025-03-31 | 2025-01-01 |

**2. Join every customer to their orders.** Starting from `Customers` and using `LEFT JOIN` keeps Cia, who has no order. At this point Ben's older order still attaches because there is no date rule in the join.

```sql
SELECT
    C.CustomerID,
    C.FirstName,
    C.LastName,
    O.OrderID,
    O.OrderDate
FROM Customers AS C
LEFT JOIN Orders AS O
    ON C.CustomerID = O.CustomerID
ORDER BY C.CustomerID;
```

| CustomerID | FirstName | LastName | OrderID | OrderDate |
|---:|---|---|---:|---|
| 1 | Asha | Rao | 10 | 2025-03-31 |
| 2 | Ben | Das | 11 | 2024-12-01 |
| 3 | Cia | Sen | NULL | NULL |

**3. Allow only recent orders to attach.** The two conditions inside `ON` require the customer IDs to match and the order date to fall in the 90-day window. Ben's old order fails the date condition, so Ben stays as a customer with `NULL` order columns. Cia also stays with `NULL` order columns.

```sql
SELECT
    C.CustomerID,
    C.FirstName,
    C.LastName,
    O.OrderID,
    O.OrderDate
FROM Customers AS C
LEFT JOIN Orders AS O
    ON C.CustomerID = O.CustomerID
   AND DATE(O.OrderDate) BETWEEN
       DATE((SELECT MAX(DATE(OrderDate)) FROM Orders), '-89 days')
       AND (SELECT MAX(DATE(OrderDate)) FROM Orders)
ORDER BY C.CustomerID;
```

| CustomerID | FirstName | LastName | OrderID | OrderDate |
|---:|---|---|---:|---|
| 1 | Asha | Rao | 10 | 2025-03-31 |
| 2 | Ben | Das | NULL | NULL |
| 3 | Cia | Sen | NULL | NULL |

`O.OrderID IS NULL` now means **no matching recent order**. It covers customers whose orders are all too old and customers who never ordered. If a customer has several recent orders, each matched row has a non-`NULL` order ID, so that customer will not pass the final filter.

**4. Keep customers without a recent match and show the requested columns.** `WHERE O.OrderID IS NULL` removes Asha. Your expression joins first and last name with a space; the final `ORDER BY` sorts sign-up date first, then customer ID.

```sql
SELECT
    C.CustomerID,
    C.FirstName || ' ' || C.LastName AS customer_name,
    C.Email,
    C.DateEntered
FROM Customers AS C
LEFT JOIN Orders AS O
    ON C.CustomerID = O.CustomerID
   AND DATE(O.OrderDate) BETWEEN
       DATE((SELECT MAX(DATE(OrderDate)) FROM Orders), '-89 days')
       AND (SELECT MAX(DATE(OrderDate)) FROM Orders)
WHERE O.OrderID IS NULL
ORDER BY C.DateEntered, C.CustomerID;
```

| CustomerID | customer_name | Email | DateEntered |
|---:|---|---|---|
| 2 | Ben Das | ben@example.com | 2023-02-01 |
| 3 | Cia Sen | cia@example.com | 2024-01-01 |

**Manual check.** Asha's 2025-03-31 order is in the window, so she is excluded. Ben's 2024-12-01 order is before the window, so he is included. Cia has no orders and is included. These are hand-calculated results for the illustrative sample, not a claim of execution on the full dataset.

**Data note.** The supplied customer rows have first and last names. If either name part were `NULL` in other data, SQLite's `||` would return `NULL` for `customer_name`. SQLite also needs `OrderDate` stored in a format its `DATE()` function can parse; the dataset foundation note describes the date normalization on import.

## My solution — SQL Server

This keeps your join and filter logic. SQL Server uses `+` for string concatenation, `CAST(... AS date)` for SQLite's `DATE(...)` conversion, and `DATEADD` to subtract 89 days.

```sql
SELECT
    C.CustomerID,
    C.FirstName + ' ' + C.LastName AS customer_name,
    C.Email,
    C.DateEntered
FROM Customers AS C
LEFT JOIN Orders AS O
    ON C.CustomerID = O.CustomerID
   AND CAST(O.OrderDate AS date) BETWEEN
       DATEADD(day, -89, (SELECT MAX(CAST(OrderDate AS date)) FROM Orders))
       AND (SELECT MAX(CAST(OrderDate AS date)) FROM Orders)
WHERE O.OrderID IS NULL
ORDER BY C.DateEntered, C.CustomerID;
```

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 18. The supplied query uses PostgreSQL syntax.

```sql
SELECT c.CustomerID,
       CONCAT_WS(' ', c.FirstName, c.LastName) AS customer_name,
       c.Email,
       c.DateEntered
FROM Customers AS c
LEFT JOIN Orders AS o
       ON o.CustomerID = c.CustomerID
      AND o.OrderDate >= (SELECT MAX(OrderDate) FROM Orders) - 89
WHERE o.OrderID IS NULL
ORDER BY c.DateEntered, c.CustomerID;
```

**What this tests.** Finding customers with no matching order in a date window anchored to the latest order date.

**The approach.** Join each customer only to orders from the latest 90-day period, then keep customers for whom no order matched.

**Why this way.** The date condition inside `ON` leaves customers with only older orders or no orders in the result. The upper boundary is implicit because no order can be later than `MAX(OrderDate)`.

**Common mistakes.** Putting the recent-date test in `WHERE`, which removes customers without a recent match; treating an old order as sufficient when the same customer also has a recent one; or subtracting 90 days while counting the latest day as part of a 90-date inclusive window.
