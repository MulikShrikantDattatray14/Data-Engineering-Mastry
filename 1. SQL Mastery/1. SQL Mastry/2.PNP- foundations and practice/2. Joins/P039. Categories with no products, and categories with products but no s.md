# PNP Q039. Categories with no products, and categories with products but no sales

![NOT SOLVED YET](<../../_badges/not-solved-yet.svg>) ![MEDIUM](<../../_badges/medium.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 39, pp. 67–68. **Difficulty:** Medium.

**Business scenario.** The catalogue team runs a clean-up every half year. Some categories were created and never stocked; others have products that never sold. An empty category is deleted, while an unsold range is reviewed with the buyer. They want every category with its product count, how many of its products have sold, and a status naming the action.

**Task.** For every row in Category , return the number of products in it, how many of those products appear on at least one order line, the total units sold, and a status: No products , Products but no sales , Some products unsold or All products sold . Put the categories needing action first: empty categories, then the lowest share of products sold.

**Expected output (as supplied):**

```text
CategoryID , CategoryName
product_count : products in the category
products_sold : products with at least one order line
units_sold : sum of Quantity (0 when none)
status : one of the four labels above
```

## Final learner solution — SQLite

The following is the learner's exact final submitted query, preserved verbatim.

```sql
WITH category_metrics AS (
    SELECT
        C.CategoryID,
        C.CategoryName,

        COUNT(DISTINCT P.ProductID) AS product_count,

        COUNT(DISTINCT OD.ProductID) AS products_sold,

        COALESCE(SUM(OD.Quantity), 0) AS units_sold

    FROM Category AS C

    LEFT JOIN Products AS P
        ON C.CategoryID = P.CategoryID

    LEFT JOIN OrderDetails AS OD
        ON P.ProductID = OD.ProductID

    GROUP BY
        C.CategoryID,
        C.CategoryName
)

SELECT
    CategoryID,
    CategoryName,
    product_count,
    products_sold,
    units_sold,

    CASE
        WHEN product_count = 0
            THEN 'No products'

        WHEN products_sold = 0
            THEN 'Products but no sales'

        WHEN products_sold < product_count
            THEN 'Some products unsold'

        WHEN products_sold = product_count
            THEN 'All products sold'
    END AS status

FROM category_metrics

ORDER BY
    CASE
        WHEN product_count = 0 THEN 0
        ELSE 1
    END,

    CASE
        WHEN product_count > 0
            THEN products_sold * 1.0 / product_count
    END ASC,

    CategoryID;
```


## Important learnings from P039

### Learning — understanding the three ORDER BY priorities

The business requirement is: put categories needing action first—empty categories first, then categories with the lowest share of products sold.

The final query uses three sorting expressions. They are evaluated in priority order: SQL sorts by the first expression; only rows tied on that expression are compared using the second; rows still tied are compared using the third.

#### 1. First priority — empty categories first

```sql
CASE
    WHEN product_count = 0 THEN 0
    ELSE 1
END
```

This generates a temporary sort key:

| Category | product_count | Sort key |
|---|---:|---:|
| Empty | 0 | 0 |
| Unsold | 1 | 1 |
| Mixed | 2 | 1 |
| All sold | 1 | 1 |

Ascending order puts key `0` before key `1`, so the empty category is always placed first.

#### 2. Second priority — lowest share of products sold first

```sql
CASE
    WHEN product_count > 0
        THEN products_sold * 1.0 / product_count
END ASC
```

This calculates the share of products sold for categories that have products:

`products_sold / product_count`

| Category | product_count | products_sold | Share sold |
|---|---:|---:|---:|
| Empty | 0 | 0 | NULL (not applicable) |
| Unsold | 1 | 0 | 0% |
| Mixed | 2 | 1 | 50% |
| All sold | 1 | 1 | 100% |

- `1.0` makes the division floating-point in SQLite. For example, `1 / 2` evaluates to `0` with integer division, while `1 * 1.0 / 2` evaluates to `0.5`.
- The `CASE` avoids dividing by zero for an empty category by returning `NULL`.
- `ASC` sorts the smallest share first: 0%, then 50%, then 100%.

#### 3. Third priority — deterministic tie-breaker

```sql
CategoryID
```

If two categories have the same first two sort keys and the same sold-product share, `CategoryID` sorts them in ascending order. This makes tied results predictable.

#### Final priority sequence

1. Empty categories first.
2. Among non-empty categories, the lowest share of products sold first.
3. If the earlier sort values tie, the lowest `CategoryID` first.

This is equivalent to a multi-level priority list: each later ORDER BY expression only breaks ties left by the expressions before it.

#### Example knowledge check

If `product_count = 4` and `products_sold = 2`, the second expression returns:

`2 * 1.0 / 4 = 0.5`, which represents 50%.
