# PNP Q016. December 2025 orders with customer names

![SOLVED](<../../_badges/solved.svg>) · Solved (recorded): 2026-10-27 ![EASY](<../../_badges/easy.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 16, pp. 30–32. **Difficulty:** Easy.

**Business scenario.** Customer support is calling customers for feedback on orders placed in December 2025. Each agent's call sheet needs the order, the customer's full name and city, and the order amount, so the agent can greet the customer by name and confirm the right order.

**Task.** List every December 2025 order that belongs to a known customer, with the customer's full name and city. Sort by OrderDate , then OrderID .

**Expected output (as supplied):**

```text
OrderID
OrderDate
customer_name : first and last name joined with a space
City : the customer's city, spaces trimmed
Total_Order_Amount
```

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

Your submitted query uses SQLite month extraction. The second version saves the half-open date range discussed during practice.

**Solution 1 — your submitted SQLite query**

```sql
SELECT
    O.OrderID,
    O.OrderDate,
    CASE
        WHEN C.FirstName IS NULL THEN COALESCE(C.LastName, '')
        WHEN C.LastName IS NULL THEN C.FirstName
        ELSE C.FirstName || ' ' || C.LastName
    END AS customer_name,
    TRIM(C.City) AS City,
    O.Total_Order_Amount
FROM Orders AS O
INNER JOIN Customers AS C
    ON O.CustomerID = C.CustomerID
WHERE strftime('%Y-%m', O.OrderDate) = '2025-12'
ORDER BY O.OrderDate, O.OrderID;
```

**Solution 2 — half-open date range**

```sql
SELECT
    O.OrderID,
    O.OrderDate,
    CASE
        WHEN C.FirstName IS NULL THEN COALESCE(C.LastName, '')
        WHEN C.LastName IS NULL THEN C.FirstName
        ELSE C.FirstName || ' ' || C.LastName
    END AS customer_name,
    TRIM(C.City) AS City,
    O.Total_Order_Amount
FROM Orders AS O
INNER JOIN Customers AS C
    ON O.CustomerID = C.CustomerID
WHERE O.OrderDate >= '2025-12-01'
  AND O.OrderDate < '2026-01-01'
ORDER BY O.OrderDate, O.OrderID;
```

Your submitted `strftime` filter is valid for SQLite dates and timestamps stored in a format `strftime` can parse. The date-range alternative is generally preferable when `OrderDate` is indexed. Both include December 2025 and exclude January 2026.

### Step-by-step explanation with one example

**Starting data.** Use the same illustrative rows from the question. The backticks around ` Delhi ` show the spaces stored around the city name.

`Customers`:

| CustomerID | FirstName | LastName | City |
|---:|---|---|---|
| 1 | Anu | Sen | ` Delhi ` |

`Orders`:

| OrderID | CustomerID | OrderDate | Total_Order_Amount |
|---:|---:|---|---:|
| 10 | 1 | 2025-12-01 | 100 |
| 11 | 1 | 2026-01-01 | 150 |

**1. Match each order to a known customer.** `Orders.CustomerID = Customers.CustomerID` supplies the name and city. An `INNER JOIN` keeps only orders with a matching customer.

```sql
SELECT O.OrderID, O.OrderDate, O.Total_Order_Amount,
       C.FirstName, C.LastName, C.City
FROM Orders AS O
INNER JOIN Customers AS C
    ON O.CustomerID = C.CustomerID
ORDER BY O.OrderID;
```

| OrderID | OrderDate | Total_Order_Amount | FirstName | LastName | City |
|---:|---|---:|---|---|---|
| 10 | 2025-12-01 | 100 | Anu | Sen | ` Delhi ` |
| 11 | 2026-01-01 | 150 | Anu | Sen | ` Delhi ` |

Both orders match Anu. The January order remains because we have not filtered dates yet.

**2. Keep only December 2025.** Your `strftime('%Y-%m', O.OrderDate)` produces `2025-12` for order 10 and `2026-01` for order 11. The alternative date range starts at December 1 inclusive and stops at January 1 exclusive; it also handles a December 31 timestamp correctly.

```sql
SELECT O.OrderID, O.OrderDate, O.Total_Order_Amount,
       C.FirstName, C.LastName, C.City
FROM Orders AS O
INNER JOIN Customers AS C
    ON O.CustomerID = C.CustomerID
WHERE strftime('%Y-%m', O.OrderDate) = '2025-12'
ORDER BY O.OrderDate, O.OrderID;
```

| OrderID | OrderDate | Total_Order_Amount | FirstName | LastName | City |
|---:|---|---:|---|---|---|
| 10 | 2025-12-01 | 100 | Anu | Sen | ` Delhi ` |

Order 11 is excluded because its year-month is `2026-01`.

**3. Build the requested display columns.** For order 10, the name parts become `Anu Sen`, and `TRIM(C.City)` changes ` Delhi ` to `Delhi`. In SQLite, `||` joins strings and `' '` is a string containing one space. The `CASE` keeps an available name part if the other part is `NULL`; plain `FirstName || ' ' || LastName` would make the whole name `NULL` in that case. `AS customer_name` and `AS City` set the requested column names.

```sql
SELECT
    O.OrderID,
    O.OrderDate,
    CASE
        WHEN C.FirstName IS NULL THEN COALESCE(C.LastName, '')
        WHEN C.LastName IS NULL THEN C.FirstName
        ELSE C.FirstName || ' ' || C.LastName
    END AS customer_name,
    TRIM(C.City) AS City,
    O.Total_Order_Amount
FROM Orders AS O
INNER JOIN Customers AS C
    ON O.CustomerID = C.CustomerID
WHERE strftime('%Y-%m', O.OrderDate) = '2025-12'
ORDER BY O.OrderDate, O.OrderID;
```

| OrderID | OrderDate | customer_name | City | Total_Order_Amount |
|---:|---|---|---|---:|
| 10 | 2025-12-01 | Anu Sen | Delhi | 100 |

**Manual check.** One of the two sample orders is in December. It has a known customer, a two-part name, a trimmed city, and the original order amount. ## My solution — SQL Server

SQL Server uses `CONCAT_WS` to join available name parts with one space. `TRIM` works in SQL Server 2017 and later.

**Solution 1 — month extraction corresponding to your SQLite query**

```sql
SELECT
    O.OrderID,
    O.OrderDate,
    CONCAT_WS(' ', C.FirstName, C.LastName) AS customer_name,
    TRIM(C.City) AS City,
    O.Total_Order_Amount
FROM Orders AS O
INNER JOIN Customers AS C
    ON O.CustomerID = C.CustomerID
WHERE YEAR(O.OrderDate) = 2025
  AND MONTH(O.OrderDate) = 12
ORDER BY O.OrderDate, O.OrderID;
```

**Solution 2 — half-open date range**

```sql
SELECT
    O.OrderID,
    O.OrderDate,
    CONCAT_WS(' ', C.FirstName, C.LastName) AS customer_name,
    TRIM(C.City) AS City,
    O.Total_Order_Amount
FROM Orders AS O
INNER JOIN Customers AS C
    ON O.CustomerID = C.CustomerID
WHERE O.OrderDate >= '2025-12-01'
  AND O.OrderDate < '2026-01-01'
ORDER BY O.OrderDate, O.OrderID;
```

`YEAR` and `MONTH` replace SQLite's `strftime` in the first version. The second version is generally preferable for an index on `OrderDate`.

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 16. The supplied query uses PostgreSQL date-literal syntax.

```sql
SELECT o.OrderID,
       o.OrderDate,
       CONCAT_WS(' ', c.FirstName, c.LastName) AS customer_name,
       TRIM(c.City)                            AS City,
       o.Total_Order_Amount
FROM Orders AS o
JOIN Customers AS c ON c.CustomerID = o.CustomerID
WHERE o.OrderDate >= DATE '2025-12-01'
  AND o.OrderDate <  DATE '2026-01-01'
ORDER BY o.OrderDate, o.OrderID;
```

**What this tests.** An inner join on the customer key, name construction when a name part may be `NULL`, trimming city text, and a December date window.

**The approach.** Attach each known customer to their orders, retain December 2025 orders, select the requested display columns, and order by date then ID.

**Why this way.** `CONCAT_WS` skips missing name parts. The half-open date range includes every December timestamp while excluding January 1.

**Common mistakes.** Missing commas between selected expressions; using `" "` instead of the string literal `' '`; filtering by a malformed `DATE(%y,%m)` expression; using a December 31 upper bound that omits later timestamps that day; and concatenating nullable name parts with `||` without handling `NULL`.
