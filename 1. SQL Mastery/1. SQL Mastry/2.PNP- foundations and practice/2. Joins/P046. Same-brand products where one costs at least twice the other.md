# PNP Q046. Same-brand products where one costs at least twice the other

![NOT SOLVED YET](<../../_badges/not-solved-yet.svg>) ![MEDIUM](<../../_badges/medium.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 46, pp. 79–81. **Difficulty:** Medium.

**Business scenario.** The pricing team is reviewing price ladders. When one brand sells two products in the same sub-category and one costs at least twice the other, shoppers either see a clear good-better-best ladder or a gap with nothing in the middle. The team wants every such pair listed once, cheaper product on the left, so they can decide where a mid-priced pack is missing.

**Task.** Find every pair of products with the same Brand and the same Sub_Category where the pricier product's Sale_Price is at least 2 times the cheaper one's. Return each pair once. Products with no brand are not part of any brand ladder. Sort by price ratio, highest first.

**Expected output (as supplied):**

```text
Brand
Sub_Category
cheaper_product , cheaper_price
pricier_product , pricier_price
price_ratio : pricier price divided by cheaper price, 2 decimals
```

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

**Learner's final submitted query (preserved verbatim):**

```sql
WITH Products_2 AS (

    -- CTE 1: Clean the source data
    SELECT *
    FROM Products
    WHERE Brand IS NOT NULL
      AND TRIM(Brand) <> ''
      AND Sub_Category IS NOT NULL
      AND TRIM(Sub_Category) <> ''

),

product_pairs AS (

    -- CTE 2: Generate unique pairs and arrange by price
    SELECT
        P1.Brand,
        P1.Sub_Category,

        CASE
            WHEN P1.Sale_Price <= P2.Sale_Price
            THEN P1.Product
            ELSE P2.Product
        END AS cheaper_product,

        CASE
            WHEN P1.Sale_Price <= P2.Sale_Price
            THEN P1.Sale_Price
            ELSE P2.Sale_Price
        END AS cheaper_price,

        CASE
            WHEN P1.Sale_Price > P2.Sale_Price
            THEN P1.Product
            ELSE P2.Product
        END AS pricier_product,

        CASE
            WHEN P1.Sale_Price > P2.Sale_Price
            THEN P1.Sale_Price
            ELSE P2.Sale_Price
        END AS pricier_price

        /*
        Alternative approach: Calculate price_ratio directly
        in this CTE instead of creating a separate CTE.

        CASE
            WHEN P1.Sale_Price <= P2.Sale_Price
            THEN ROUND(P2.Sale_Price * 1.0 / P1.Sale_Price, 2)
            ELSE ROUND(P1.Sale_Price * 1.0 / P2.Sale_Price, 2)
        END AS price_ratio
        */

    FROM Products_2 AS P1

    INNER JOIN Products_2 AS P2
        ON P1.Brand = P2.Brand
       AND P1.Sub_Category = P2.Sub_Category
       AND P1.ProductID < P2.ProductID

),

price_ratios AS (

    -- CTE 3: Calculate the price ratio
    SELECT
        *,
        ROUND(
            pricier_price * 1.0 / cheaper_price,
            2
        ) AS price_ratio

    FROM product_pairs

)

-- Main query: Keep only ratios greater than or equal to 2.0
SELECT *
FROM price_ratios
WHERE price_ratio >= 2.0
ORDER BY price_ratio DESC;
```

**Review note:** The query applies the correct inclusive threshold (`price_ratio >= 2.0`), sorts results by `price_ratio DESC` as required, and preserves the alternative ratio calculation as a comment in the second CTE. The learner query is retained verbatim. Execution against the actual PrepNPlaced dataset has not been performed.

## Second solution — SQLite using a window function

**Purpose.** This is an alternative learning solution to the learner's original self-join approach. It uses `ROW_NUMBER()` to assign a price-based position within each Brand + Sub_Category partition, then self-joins those numbered rows to generate every unique pair. It is saved separately and does not replace the original learner solution.

### Complete query

```sql
WITH Products_2 AS (

    -- CTE 1: Clean the source data
    SELECT *
    FROM Products
    WHERE Brand IS NOT NULL
      AND TRIM(Brand) <> ''
      AND Sub_Category IS NOT NULL
      AND TRIM(Sub_Category) <> ''
      AND Sale_Price IS NOT NULL
      AND Sale_Price > 0

),

ranked_products AS (

    -- CTE 2: Assign a price-based row number
    SELECT
        *,
        ROW_NUMBER() OVER (
            PARTITION BY Brand, Sub_Category
            ORDER BY Sale_Price ASC, ProductID ASC
        ) AS price_position

    FROM Products_2

),

product_pairs AS (

    -- CTE 3: Generate unique pairs
    -- Lower price position = cheaper product
    SELECT
        P1.Brand,
        P1.Sub_Category,

        P1.Product AS cheaper_product,
        P1.Sale_Price AS cheaper_price,

        P2.Product AS pricier_product,
        P2.Sale_Price AS pricier_price

    FROM ranked_products AS P1

    INNER JOIN ranked_products AS P2
        ON P1.Brand = P2.Brand
       AND P1.Sub_Category = P2.Sub_Category
       AND P1.price_position < P2.price_position

),

price_ratios AS (

    -- CTE 4: Calculate price ratio
    SELECT
        *,
        ROUND(
            pricier_price * 1.0 / cheaper_price,
            2
        ) AS price_ratio

    FROM product_pairs

)

-- Main query: Filter qualifying pairs
SELECT *
FROM price_ratios
WHERE price_ratio >= 2.0
ORDER BY price_ratio DESC;
```

The lower row number is always the cheaper product because the window ordering sorted prices ascending. The inequality excludes self-pairs and reverse duplicates. For a partition with (n) products, the number of unique pairs is (n(n-1)/2).

#### Stage 4 — CTE `price_ratios`: calculate the ratio

For each pair:

`price_ratio = pricier_price / cheaper_price`

The multiplication by `1.0` ensures non-integer division for integer price columns; `ROUND(..., 2)` keeps two decimal places.

`WHERE price_ratio >= 2.0` retains ratios of exactly 2.00 as well as higher ratios. `ORDER BY price_ratio DESC` sorts the qualifying pairs from highest ratio to lowest.

### Execution and learning notes

- **Row-count progression:** 10 original rows → 7 cleaned rows → 7 ranked rows → 5 unique pairs → 5 ratios → 4 qualifying results.
- `PARTITION BY` in the window function creates independent numbering groups; it does not itself generate pairs.
- `ROW_NUMBER()` assigns a unique position within each partition. The self-join, not the window function, generates all product pairs.
- `P1.price_position < P2.price_position` both prevents pairing a row with itself and removes the reverse orientation. Since row numbers follow ascending price, P1 is cheaper than P2.
- `ProductID ASC` makes row numbering deterministic when two products have equal Sale_Price. Equal-priced pairs have ratio 1.00 and do not qualify.
- This alternative explicitly excludes NULL, zero and negative Sale_Price values before division. The original learner solution's cleaning CTE did not include those price checks; the two versions therefore differ on such input rows.
- The sample walkthrough is illustrative. The query has not been executed against the actual PrepNPlaced dataset, and no engine execution is claimed.
