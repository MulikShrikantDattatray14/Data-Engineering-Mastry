# PNP Q042. RANK vs DENSE_RANK vs ROW_NUMBER on order counts

![NOT SOLVED YET](<../../_badges/not-solved-yet.svg>) ![MEDIUM](<../../_badges/medium.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 42, pp. 72–74. **Difficulty:** Medium.

**Business scenario.** The CRM team runs a loyalty tier scheme based on order count. They have had three different "top 10" lists from three analysts, with different people on each, and suspect the ranking function is the cause. Order counts are small whole numbers, so many customers share the same count and ties are common. They want all three numbering schemes side by side for every customer.

**Task.** For each customer who has placed an order, return the number of orders placed and three rank columns computed over that count, highest first: ROW_NUMBER , RANK and DENSE_RANK . Sort by the row number.

**Expected output (as supplied):**

```text
CustomerID
orders_placed : number of orders
row_num : ROW_NUMBER() , unique per customer, ties broken by CustomerID
rank_num : RANK() , ties share a rank and the next rank skips
dense_rank_num : DENSE_RANK() , ties share a rank and the next rank does not skip
```

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

**Final learner solution (submitted and preserved verbatim):**

```sql
WITH customer_order_counts AS (

    SELECT
        CustomerID,
        COUNT(OrderID) AS orders_placed

    FROM Orders

    GROUP BY CustomerID

)

SELECT
    CustomerID,
    orders_placed,

    ROW_NUMBER() OVER (
        ORDER BY orders_placed DESC, CustomerID ASC
    ) AS row_num,

    RANK() OVER (
        ORDER BY orders_placed DESC
    ) AS rank_num,

    DENSE_RANK() OVER (
        ORDER BY orders_placed DESC
    ) AS dense_rank_num

FROM customer_order_counts

ORDER BY row_num;
```

**Learner approach:** Aggregate `Orders` by `CustomerID` in a CTE, then apply the three window functions to the one-row-per-customer result. Customers with at least one order are naturally included because the CTE reads from `Orders`.

**Verification:** Executed on SQLite using the illustrative sample in this record. The result matched all five expected values:
- Customer 10: 2 orders, row number 1, rank 1, dense rank 1.
- Customer 20: 2 orders, row number 2, rank 1, dense rank 1.
- Customer 30: 1 order, row number 3, rank 3, dense rank 2.

The `CustomerID ASC` tie-breaker is included only in `ROW_NUMBER()`, as required. It is intentionally omitted from `RANK()` and `DENSE_RANK()` so equal order counts remain tied. This sample execution does not replace the remaining PNP-P026 completion audit or SQL Server verification.
