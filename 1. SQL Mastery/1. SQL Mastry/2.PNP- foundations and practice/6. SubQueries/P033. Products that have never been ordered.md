# PNP Q033. Products that have never been ordered

![MEDIUM](<../../_badges/medium.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 33, pp. 56–58. **Difficulty:** Medium.

**Business scenario.** The merchandising team pays for shelf space in the warehouse and wants to delist products that have never sold. Before anything is removed from the catalogue, they want the list of products with zero order lines in the entire history. A product that appeared in even one order line, in any quantity, is not on the list.

**Task.** Return every product in Products that does not appear in any row of OrderDetails . Sort by CategoryID , then ProductID .

**Expected output (as supplied):**

```text
ProductID , Product , Brand , CategoryID , Sale_Price
```

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

The locked learner solution is preserved in the [completed practice record](../../1.1%20Practice%20questions/Subqueries/medium/PNP-P033.md).

```sql
SELECT
    P.ProductID,
    P.Product,
    P.Brand,
    P.CategoryID,
    P.Sale_Price
FROM Products P
LEFT JOIN OrderDetails OD
    ON P.ProductID = OD.ProductID
WHERE OD.OrderDetailID IS NULL
ORDER BY
    P.CategoryID ASC,
    P.ProductID ASC;
```

## Official solution

### Original course answer — PostgreSQL 16

Source: [all_100_solutions.sql, Q33, lines 410–423](../Source%20Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql#L410-L423). The original correlated `NOT EXISTS` answer is reproduced in the completed practice record.

```sql
SELECT p.ProductID,
       p.Product,
       p.Brand,
       p.CategoryID,
       p.Sale_Price
FROM Products AS p
WHERE NOT EXISTS (
    SELECT 1
    FROM OrderDetails AS od
    WHERE od.ProductID = p.ProductID
)
ORDER BY p.CategoryID, p.ProductID;
```

## Comparison with the course answer

The course uses correlated `NOT EXISTS`; the learner uses a LEFT JOIN followed by `OD.OrderDetailID IS NULL`. Both implement the same anti-match requirement. Because OrderDetailID is a non-null primary key, the learner's NULL test reliably identifies unmatched Products rows. A product with several order lines repeats at the intermediate join stage, but every matched copy is removed by the NULL filter. The learner's selected query remains unchanged.

## Verification

- The small practice fixture returns Cup only: Pen matches OrderDetails row 10; Cup has no match.
- The larger six-product fixture returns ProductIDs 202 and 205, in CategoryID then ProductID order.
- Product 201 has two matching order lines and remains excluded; multiple matches do not make an ordered product eligible.
- The saved query returns exactly the five requested Products columns.
- The SQL Server adaptation is dialect-compatible but has not been executed on a native SQL Server engine.
