# Recursive CTEs - Quick Revision Notes

**A recursive CTE starts with known rows and repeatedly adds the next rows until none qualify.** Read it as: **anchor → recursive step → stopping rule**.

## 1. Build a tiny sequence

This SQLite query makes 1, 2, 3, 4. It needs no input table.

```sql
WITH RECURSIVE numbers(n) AS (
    SELECT 1                    -- anchor: the first row
    UNION ALL
    SELECT n + 1                -- recursive step: the next row
    FROM numbers
    WHERE n < 4                -- stop after producing 4
)
SELECT n
FROM numbers
ORDER BY n;
```

| Round | Row added | Why |
|---:|---:|---|
| Anchor | 1 | `SELECT 1` |
| 1 | 2 | 1 < 4 |
| 2 | 3 | 2 < 4 |
| 3 | 4 | 3 < 4 |
| 4 | none | 4 < 4 is false |

Final output is **1, 2, 3, 4**. The test runs on the *current* value, so `n < 4` still allows 4 to be created. `n <= 4` would create 5, an off-by-one error.

## 2. Follow a hierarchy

Use this generic `Org` table:

| employee_id | manager_id |
|---:|---:|
| 1 | NULL |
| 2 | 1 |
| 3 | 1 |
| 4 | 2 |

Start at employee 1 and follow manager links downward.

```sql
WITH RECURSIVE team(employee_id, manager_id, depth) AS (
    SELECT employee_id, manager_id, 0
    FROM Org
    WHERE employee_id = 1

    UNION ALL

    SELECT e.employee_id, e.manager_id, t.depth + 1
    FROM Org AS e
    JOIN team AS t
      ON e.manager_id = t.employee_id
)
SELECT employee_id, manager_id, depth
FROM team
ORDER BY depth, employee_id;
```

The same rows progress as follows:

| Round | New employees | depth |
|---|---|---:|
| Anchor | 1 | 0 |
| Direct reports of 1 | 2, 3 | 1 |
| Direct reports of 2 or 3 | 4 | 2 |
| Direct reports of 4 | none | — |

| employee_id | manager_id | depth |
|---:|---:|---:|
| 1 | NULL | 0 |
| 2 | 1 | 1 |
| 3 | 1 | 1 |
| 4 | 2 | 2 |

The join `e.manager_id = t.employee_id` says: “Find children of the rows reached so far.” A final `WHERE depth > 0` would remove the starting person when a task asks for reports only.

## 3. Generate dates and stop safely

The same pattern makes a three-day calendar without a date table:

```sql
WITH RECURSIVE days(day) AS (
    SELECT DATE('2025-04-01')
    UNION ALL
    SELECT DATE(day, '+1 day')
    FROM days
    WHERE day < '2025-04-03'
)
SELECT day
FROM days
ORDER BY day;
```

| Round | day |
|---|---|
| Anchor | 2025-04-01 |
| 1 | 2025-04-02 |
| 2 | 2025-04-03 |

Dates must progress in the recursive step. A hierarchy should have valid, acyclic links. If links may loop, add a visited-ID path check; a depth limit bounds work but does not make a repeated employee correct. `UNION` can remove identical rows, yet does not stop a cycle when `depth` changes on every visit.

## 4. Quick checks and dialect differences

- The anchor and recursive member must return the **same number of columns**, in corresponding positions.
- `UNION ALL` keeps every generated row. Use it for normal traversal; choose deduplication only when the task requires it.
- Test on a tiny input and inspect each depth or date before writing the final filter.
- If the recursion returns too many rows, inspect the stopping rule and the relationship join first.
- SQLite, PostgreSQL and MySQL 8 use `WITH RECURSIVE`. SQL Server uses `WITH` and has its own recursion limit; SQLite date modifier syntax such as `DATE(day, '+1 day')` must be translated for other dialects.
