# PNP Q040. Days from sign-up to first order

![NOT SOLVED YET](<../../_badges/not-solved-yet.svg>) ![MEDIUM](<../../_badges/medium.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 40, pp. 68–70. **Difficulty:** Medium.

**Business scenario.** The onboarding team is testing a welcome-coupon email and needs to know when to send it. If most customers buy within a week of signing up, the email should go out on day one; if they take a month, it can wait. For every customer who has ordered, they want the number of days between sign-up and the first order. Rows where the first order seems to come before sign-up must be flagged, not hidden, because they point to a data problem.

**Task.** For each customer with at least one order, return their sign-up date, the date of their first order, the number of days between them, and a data_flag of Order before sign-up when that number is negative (NULL otherwise). Sort by days to first order, flagged rows first.

**Expected output (as supplied):**

```text
CustomerID
DateEntered : sign-up date
first_order_date : earliest OrderDate for the customer
days_to_first_order : first_order_date - DateEntered in whole days
data_flag : Order before sign-up when negative, otherwise NULL
```

## Final learner solution — SQLite

```sql
SELECT
    C.CustomerID,
    C.DateEntered,
    MIN(O.OrderDate) AS first_order_date,

    CAST(
        julianday(MIN(O.OrderDate)) - julianday(C.DateEntered)
        AS INTEGER
    ) AS days_to_first_order,

    CASE
        WHEN julianday(MIN(O.OrderDate)) - julianday(C.DateEntered) < 0
            THEN 'Order before sign-up'
        ELSE NULL
    END AS data_flag

FROM Customers AS C

INNER JOIN Orders AS O
    ON C.CustomerID = O.CustomerID

GROUP BY
    C.CustomerID,
    C.DateEntered

ORDER BY
    CASE
        WHEN julianday(MIN(O.OrderDate)) - julianday(C.DateEntered) < 0
            THEN 0
        ELSE 1
    END ASC,
    days_to_first_order ASC;
```

## Important learnings from P040

### Learning — using multiple ORDER BY priorities to put flagged rows first

The requirement says to sort by the number of days to first order, but to put rows flagged as `Order before sign-up` first. A single sort on `days_to_first_order` does not explicitly express that business priority. Use two sort keys:

1. **Business-priority key:** a `CASE` expression returns `0` when the date difference is negative (flagged) and `1` otherwise. Sorting this key `ASC` places all flagged rows before unflagged rows.
2. **Within-priority key:** `days_to_first_order ASC` sorts the rows inside each priority group by the actual day difference.

For example, the flagged values `-2` and `-1` appear before unflagged values `2`, `5` and `10`. Within each group, the numeric day difference is ascending.

The `CASE` expression in `ORDER BY` is only a sorting key; it does not add a column to the result or change the `data_flag` output. This is a reusable pattern whenever a report needs a special category first, followed by a normal sort within each category.
