# Dates and Time — Quick Revision Notes

**Main idea:** decide the time zone, the date grain, and whether the end boundary is included. Then filter a time range before grouping or comparing periods.

Sources: [Advanced SQL questions](<../Source Materials/Advanced_SQL_100_Query_Questions_Vol1 (2).pdf>) and [PrepNPlaced interview questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>). The rows below are invented teaching data, not practice-question answers.

## 1. Start with complete timestamps

| order_id | placed_at |
|---:|---|
| 101 | 2026-01-31 23:15 |
| 102 | 2026-02-01 00:10 |
| 103 | 2026-02-28 14:00 |
| 104 | 2026-03-01 00:01 |

Suppose we need all February 2026 orders. Use an inclusive start and exclusive next-month start:

    SELECT order_id, placed_at
    FROM DemoOrders
    WHERE placed_at >= '2026-02-01'
      AND placed_at <  '2026-03-01'
    ORDER BY placed_at;

| order_id | placed_at |
|---:|---|
| 102 | 2026-02-01 00:10 |
| 103 | 2026-02-28 14:00 |

Order 101 is before February; 104 is after it. The same pattern works when a column contains time as well as date. A condition ending at '2026-02-28' can accidentally exclude the rest of February 28 if that literal means midnight. Filtering the original placed_at column by a range also leaves an ordinary index on that column usable.

## 2. Group at the right calendar grain

The filtered rows above have different days but one month:

| grain | group | order count |
|---|---|---:|
| Day | 2026-02-01 | 1 |
| Day | 2026-02-28 | 1 |
| Month | 2026-02 | 2 |

Group by a date-truncated day, week, month, or quarter as required. Grouping raw timestamps would keep separate times as separate groups. The precise date function differs by SQLite, PostgreSQL, MySQL, and SQL Server, so adapt syntax while preserving the same grain.

A GROUP BY result lists only periods that have rows. If a report must also show empty days or months, first make a calendar spine containing every required period, then LEFT JOIN the facts and use zero for missing counts where appropriate.

## 3. A seven-row frame may not be seven calendar days

Imagine daily rows only for February 1 and February 28. A window frame covering the current row and six previous **rows** can jump from February 28 back to February 1. It does not imply six previous calendar dates. For a true seven-calendar-day metric, check that missing days are filled or use a date-aware range rule supported by the chosen dialect.

Say the grain before applying LAG, LEAD, a moving average, or a running total. If the question asks for monthly change, aggregate to one row per month first; then the previous row means the previous observed month.

## 4. Use date arithmetic for adjacent periods

A date difference should come from date functions, not subtraction of formatted numbers. February and March have different lengths, and leap years matter: 2024-02-28 to 2024-03-01 is two days because February 29 exists. Similarly, adding 1 to the integer 202612 produces 202613, not January 2027. Use a month-aware date operation to cross year boundaries.

For weekly reports, state which day begins a week. A Monday-based week and a Sunday-based week can assign the same order to different buckets.

## 5. Choose an explicit “as of” date

A phrase such as “last 30 days” depends on the reference date. It might mean the current clock time, a fixed reporting date, or the latest date available in the dataset. Put that choice in the explanation before filtering. A partial current month should not be compared naively with a complete previous month.

Time zones can even change the date bucket. The instant 2026-02-28 23:30 UTC is 2026-03-01 05:00 in India, so it belongs to different calendar months in those two zones. Confirm whether timestamps are stored in UTC and which zone the business report uses.

## Quick revision

1. Are values DATEs or timestamps with hours and minutes?
2. What is the start, and what is the exclusive next-period boundary?
3. Is the grain a day, week, month, quarter, or exact event?
4. Are empty calendar periods required in the output?
5. Is the period anchored to today, a supplied date, or the data's latest date?
6. Which time zone defines the reporting date?
