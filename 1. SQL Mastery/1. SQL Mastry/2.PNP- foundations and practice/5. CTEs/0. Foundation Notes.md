# CTEs - Quick Revision Notes

**A CTE names an intermediate result for one SQL statement.** Use it to make a multi-step query easy to inspect, especially when a later step needs the same result twice.

## 1. Build one named step

Use this tiny `WorkLog` table. One row is one recorded task, not one person.

| task_id | owner | hours |
|---:|---|---:|
| 1 | Ana | 2 |
| 2 | Ben | 3 |
| 3 | Ana | 4 |
| 4 | Ben | 1 |

We want one total per owner.

```sql
WITH owner_totals AS (
    SELECT owner, SUM(hours) AS total_hours
    FROM WorkLog
    GROUP BY owner
)
SELECT owner, total_hours
FROM owner_totals
ORDER BY owner;
```

The CTE first produces:

| owner | total_hours | Calculation |
|---|---:|---|
| Ana | 6 | 2 + 4 |
| Ben | 4 | 3 + 1 |

The final `SELECT` reads those two rows. The CTE does not permanently create a table; its name is available only to the statement attached to `WITH`.

## 2. Chain steps and check row meaning

Suppose the output also needs a simple workload label.

```sql
WITH owner_totals AS (
    SELECT owner, SUM(hours) AS total_hours
    FROM WorkLog
    GROUP BY owner
),
labeled AS (
    SELECT owner, total_hours,
           CASE WHEN total_hours >= 5 THEN 'busy' ELSE 'light' END AS workload
    FROM owner_totals
)
SELECT owner, total_hours, workload
FROM labeled
ORDER BY owner;
```

| After `owner_totals` | After `labeled` |
|---|---|
| Ana, 6 | Ana, 6, busy |
| Ben, 4 | Ben, 4, light |

Read from top to bottom. A later CTE can use an earlier CTE. Separate definitions with commas; write `WITH` only once. Before adding each join or grouping, say what **one row** means. Here it changes from *one task* to *one owner*. If a join duplicates an owner row, totals calculated afterward may be inflated.

## 3. Reuse a result and filter a window result

The same CTE can be read more than once in the attached statement. Here the owner totals are compared with their average:

```sql
WITH owner_totals AS (
    SELECT owner, SUM(hours) AS total_hours
    FROM WorkLog
    GROUP BY owner
)
SELECT owner, total_hours
FROM owner_totals
WHERE total_hours > (SELECT AVG(1.0 * total_hours) FROM owner_totals);
```

Average owner total = `(6 + 4) / 2 = 5`; the result is **Ana, 6**. We calculate owner totals once in the query text. This does **not** guarantee the database stores that CTE once; optimizers may inline or materialize it.

Window functions cannot normally be used directly in `WHERE`. First calculate their output, then filter in the outer query:

```sql
WITH ranked AS (
    SELECT owner, hours,
           ROW_NUMBER() OVER (
               PARTITION BY owner
               ORDER BY hours DESC, task_id
           ) AS rn
    FROM WorkLog
)
SELECT owner, hours
FROM ranked
WHERE rn = 1
ORDER BY owner;
```

`ranked` still has four task rows. Its `rn` values for Ana are 1 on 4 hours and 2 on 2 hours; for Ben they are 1 on 3 hours and 2 on 1 hour. The outer query keeps Ana 4 and Ben 3. This is a generic syntax example, not an answer to a practice prompt.

## 4. Common mistakes and dialect notes

- **No final statement:** `WITH x AS (...)` alone is incomplete; follow it with a `SELECT` or another supported statement.
- **Wrong grain:** grouping by both `owner` and `task_id` would leave one row per task, not one row per owner.
- **Join fan-out:** if a one-to-many table is joined before aggregation, check whether each input value is now repeated.
- **Scope:** a separate query cannot refer to `owner_totals` after this statement finishes.
- **Dialects:** SQLite, PostgreSQL and MySQL use `WITH ...`; SQL Server often starts with `;WITH` when another statement comes before it. In SQL Server, `AVG` of integer input can truncate, so convert to a fractional type as shown.
