# P029 · Why LEFT JOIN the units summary third?

[![Previous](../previous.svg)](03.md) [![Next](../next.svg)](🟥 05.md)  · **🟥 4 of 6**

The outer query already has `Orders.OrderID`, so it can attach the prepared `OrderDetails_2` total with a `LEFT JOIN` on `od.OrderID = o.OrderID`. The CTE contributes at most one units row per order; order 🟪 10 matches its two lines (🟪 2 + 3 = 🟥 5). Because this lookup is independent of the `Shippers` lookup—both keys come directly from `Orders`—either join can come first. A missing summary (like the separate OtherShip check for order 16) leaves the order and its amount 80 in place, with units NULL until `COALESCE` makes it 0.

<summary>Full SQLite query for this step</summary>

```sql
WITH OrderDetails_2 AS (
    SELECT OrderID, SUM(Quantity) AS total_units
    FROM OrderDetails
    GROUP BY OrderID
)
SELECT o.OrderID, o.ShipperID AS ordering_shipper_id, o.Total_Order_Amount,
       s.ShipperID AS matched_shipper_id, s.CompanyName,
       od.OrderID AS summarized_order_id, od.total_units
FROM Orders AS o
LEFT JOIN Shippers AS s
    ON o.ShipperID = s.ShipperID
LEFT JOIN `OrderDetails_2` AS od
    ON od.OrderID = o.OrderID
ORDER BY o.OrderID;
```
