# Q047 · Why sort the qualifying groups?

[![Previous](../previous.svg)](06.md) [![Next](../next.svg)](08.md) · **7 of 8**

The task asks for the highest list-price value first. Sorting happens after HAVING has removed non-qualifying brands. The learner query sorts by value descending; the official answer adds Brand as a secondary tie-breaker.

## SQL added or changed

```sql
ORDER BY list_price_value DESC;
```

## Input to this step

| 🟪 Brand | 🟩 products_listed | 🟦 products_sold | 🟦 units_sold | 🟪 list_price_value |
|---|---:|---:|---:|---:|
| Nova | 3 | 2 | 4 | 50 |
| Unbranded | 3 | 2 | 3 | 16 |

## Result · 🟪 2 rows

| 🟪 Brand | 🟩 products_listed | 🟦 products_sold | 🟦 units_sold | 🟪 list_price_value |
|---|---:|---:|---:|---:|
| Nova | 3 | 2 | 4 | 50 |
| Unbranded | 3 | 2 | 3 | 16 |

No tie occurs in this fixture. If two brands have the same value, their relative order is unspecified by the learner query.

<details>
<summary>Full SQLite query for this step</summary>

```sql
SELECT COALESCE(P.Brand, 'Unbranded') AS Brand,
       COUNT(DISTINCT P.ProductID) AS products_listed,
       COUNT(DISTINCT OD.ProductID) AS products_sold,
       COALESCE(SUM(OD.Quantity), 0) AS units_sold,
       COALESCE(SUM(P.Sale_Price * OD.Quantity), 0) AS list_price_value
FROM Products AS P
LEFT JOIN OrderDetails AS OD
    ON P.ProductID = OD.ProductID
GROUP BY COALESCE(P.Brand, 'Unbranded')
HAVING COUNT(DISTINCT P.ProductID) >= 3
ORDER BY list_price_value DESC;
```

</details>
