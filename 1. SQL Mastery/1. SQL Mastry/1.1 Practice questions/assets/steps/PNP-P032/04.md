# PNP P032 · Products priced above their category average · Why keep only prices above the benchmark?

[![Previous](../previous.svg)](03.md) [![Next](../next.svg)](05.md)  · **4 of 5**

Compare each product's own Sale_Price with the shared benchmark. Tea (100) is below 200, Coffee (200) equals 200 and fails the strict > rule, while Juice (300) is above it and survives. The benchmark is not recalculated from only the surviving product.

## SQL added or changed

```sql
WHERE Sale_Price > (SELECT category_avg_price FROM avg_sale_price)
```

## Input to this step

**Why attach the same benchmark to each product row? · 3 rows**

| --- | --- | --- | --- | --- |
| 🟦 1 | 🟦 Tea | 🟦 5009 | 🟦 100 | 🟦 200.0 |
| 🟦 2 | 🟦 Coffee | 🟦 5009 | 🟦 200 | 🟦 200.0 |
| 🟦 3 | 🟦 Juice | 🟦 5009 | 🟦 300 | 🟦 200.0 |

<summary>Full SQLite query for this step</summary>

```sql
WITH required_table AS (
SELECT
    ProductID,
    Product,
    CategoryID,
    Sale_Price
FROM Products
WHERE CategoryID = 5009
),
avg_sale_price AS (
SELECT
    AVG(Sale_Price) AS category_avg_price
FROM required_table
)
SELECT ProductID, Product, CategoryID, Sale_Price,
       (SELECT category_avg_price FROM avg_sale_price) AS category_avg_price
FROM required_table
WHERE Sale_Price > (SELECT category_avg_price FROM avg_sale_price);
```
