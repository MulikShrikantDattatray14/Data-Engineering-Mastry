## The cover's first streaming example (PDF p. 1)

The cover previews the full path: read one order line at a time, keep delivered amounts, then total them. The generator does not load all orders into memory. The simple comma split works on this supplied CSV; later lessons use `csv.DictReader` for CSV fields that may contain quoted commas.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=0&lesson=00&snippet=1>)

```python
def read_orders(path):
    with open(path, encoding='utf-8') as file:
        next(file)  # skip the header
        for line in file:
            *_, status, amount = line.rstrip().split(',')
            yield status, float(amount)

delivered = (amount for status, amount in read_orders('python_de_dataset/orders.csv')
             if status == 'delivered')
print(f'revenue: {sum(delivered):,.2f}')
```

```text
revenue: 18,972.00
```

`yield` makes each result available as the file is read. [Part 3's generator lesson](<3. Advanced Python/01. Iterators and generators.md>) explains the one-pass and memory trade-offs in detail.

### The first two records shown in the PDF

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=0&lesson=00&snippet=2>)

```python
import csv
import json
from pathlib import Path

data_dir = Path('python_de_dataset')

with (data_dir / 'orders.csv').open(newline='', encoding='utf-8') as file:
    first_order = next(csv.DictReader(file))
print(first_order)

with (data_dir / 'customers.json').open(encoding='utf-8') as file:
    customers = json.load(file)
print(customers[5])
```

Expected output from the supplied files (also shown in the PDF):

```text
{'order_id': '101', 'customer_id': '1', 'order_date': '2025-01-10', 'status': 'delivered', 'amount': '1198.00'}
{'customer_id': 6, 'name': 'Sana', 'signup_date': '2025-03-15', 'referred_by': None, 'address': {'city': None, 'pincode': None}, 'tags': []}
```

**Notice:** `csv.DictReader` gives you strings, even for numeric-looking fields. For example, the order amount is `'1198.00'`, not `1198.00`. Convert it before arithmetic. In JSON, `null` becomes Python `None`.

## What a data engineering coding round may ask

The PDF describes two common formats. Some companies use both, and almost all add SQL:

| Format | Typical task | Where to prepare |
|---|---|---|
| Algorithm style | One or two problems in roughly 40-45 minutes, usually easy to medium: arrays, strings, hash maps, two pointers, heaps, stacks, intervals; trees or graphs appear sometimes, especially in senior loops | Part 4 |
| Record processing | Parse messy CSV, JSON, logs, or events; clean, group, deduplicate, aggregate, and discuss scaling to a 50 GB input | Part 5 and the interview sets in Part 7 |

The suggested topic-frequency map is a starting guide, not a promise about any company:

| Topic | In DE loops | How deep | PDF pages |
|---|---|---|---|
| Hash maps and sets: counting, grouping, two-sum | Very often | Must be automatic | 46, 59-60 |
| Arrays and strings: two pointers, prefix sums, parsing | Very often | Must be automatic | 45, 64 |
| Sorting with custom keys and stability | Often | Know when and why | 36, 51 |
| Sliding windows, fixed and variable | Often | Easy and medium | 47, 61 |
| Heaps: top-k, merging sorted inputs, running median | Often | Easy and medium | 55, 59 |
| Stacks, queues, and intervals | Often | Easy and medium | 48, 65 |
| Binary search, including search on the answer | Sometimes | Know the template | 50 |
| Trees and graphs: BFS, DFS, topological sorting | Sometimes | Classics only | 53-54 |
| Recursion and backtracking | Sometimes | Small inputs only | 52 |
| Dynamic programming | Rarely | Four classics | 56 |
| Linked lists | Rarely | Three classics | 49 |

Before preparing for a specific round, ask whether it uses algorithm problems or record-processing tasks and check recent reports for that role. The format can vary by team and over time.

### What interviewers evaluate

- **Correctness:** handle empty input, duplicates, ties, missing values such as `None`, and other edge cases.
- **Communication:** explain the plan and why it works while solving.
- **Cost:** state time and space complexity.
- **Code quality:** use readable names and sensible decomposition.
- **Scaling:** discuss what changes when the file or event stream is too large for memory.

The PDF's experience guide is: **0-2 years:** a working solution and basic Big-O; **2-5 years:** better complexity, edge cases, production-minded code; **5+ years:** trade-offs, scaling, and design decisions.
