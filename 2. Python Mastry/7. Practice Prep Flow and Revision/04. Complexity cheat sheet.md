# 4. Complexity cheat sheet

**Source:** *Python for Data Engineering Notes*, PDF p. 78. Read this as a quick way to explain **where** a cost comes from. `n` is the number of input elements, `k` is a small selected count or value range, and `V`/`E` are graph vertices and edges.

## Data structure costs

These costs describe common Python operations. Dictionary and set O(1) times are **average case**, not a promise for every hash collision. A balanced tree is an interview structure, not a Python standard-library container.

| Structure | Access | Search | Insert | Delete | Extra storage / best use |
|---|---|---|---|---|---|
| `list` | O(1) by index | O(n) | O(1) amortized append; O(n) at front | O(1) at end; O(n) at front | O(n); ordered rows and indexing |
| `dict` / `set` | O(1) average by key | O(1) average | O(1) average | O(1) average | O(n); lookup, counting, dedupe |
| `collections.deque` | O(1) at ends | O(n) | O(1) at either end | O(1) at either end | O(n); queues, windows, BFS |
| `heapq` heap | O(1) minimum | O(n) arbitrary search | O(log n) push | O(log n) pop minimum | O(n); top-k and scheduling |
| Sorted list + `bisect` | O(1) by index | O(log n) search position | O(n) insertion shift | O(n) deletion shift | O(n); mostly static sorted lookups |
| Balanced BST / B-tree | O(log n) | O(log n) | O(log n) | O(log n) | O(n); database indexes |
| Linked list | O(n) by position | O(n) | O(1) when node is known | O(1) when node is known | O(n); pointer practice |

A list `append` is amortized O(1): an occasional resize costs more, but the average per append over many appends remains constant.

## When asked “can you do better?”

Check these options in the PDF's order, and explain each trade-off: replace a nested search with a hash map; sort first when ordering helps; use two pointers instead of a set when lower memory matters; use a size-k heap instead of sorting everything; precompute a prefix sum instead of summing the same ranges repeatedly. None is automatically best: input order, memory, ties, and repeated-query count decide.

## Say the source of the cost

For a grouped order scan, explain: "I read each of the `n` orders once, so the scan is O(n). My dictionary stores one entry per customer, so it uses O(k) extra space for `k` customers. Sorting those `k` results adds O(k log k) time." This is more useful than just saying "O(n)."

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=7&lesson=04&snippet=1>)

```python
orders = [('1', 'delivered'), ('2', 'cancelled'), ('1', 'delivered')]
counts = {}
for customer_id, status in orders:
    if status == 'delivered':
        counts[customer_id] = counts.get(customer_id, 0) + 1
print(counts)
print(sorted(counts.items(), key=lambda item: (-item[1], item[0])))
```

```text
{'1': 2}
[('1', 2)]
```

The loop is O(n), the dictionary uses O(k), and sorting the output adds O(k log k).

## Five common mistakes

| Mistake | Better explanation |
|---|---|
| Calling a loop O(n) when it does `x in some_list` each time | List membership scans: O(n × m) if the list has `m` items. Make the lookup collection a set when appropriate. |
| Forgetting an added sort | Sorting `n` items makes the overall time O(n log n), even if the later pass is O(n). |
| Calling recursion O(1) space | Count the call stack: O(depth) before any other storage. |
| Building a string with `+=` repeatedly | Repeated copying may cost O(n²) overall; collect fragments and `''.join(parts)`. |
| Ignoring output size | Emitting 2^n subsets takes at least O(2^n) output work. |

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=7&lesson=04&snippet=2>)

```python
wanted = ['delivered', 'returned']
statuses = ['delivered', 'cancelled', 'pending']
print([status for status in statuses if status in wanted])
wanted_set = set(wanted)
print([status for status in statuses if status in wanted_set])
```

```text
['delivered']
['delivered']
```

The answers match. The first membership check scans a list each time; the second checks a set on average in constant time, after paying to build it. Explain that build cost too.
