# 5. The preparation flow: ten weeks from zero to interviews

**Source:** *Python for Data Engineering Notes*, PDF p. 79. This is a suggested two-hour daily flow. If you already write basic Python comfortably, begin with week 3 and use the earlier lessons for gaps.

## The ten-week route

| Week | Read | Practise | Move on when you can... |
|---:|---|---|---|
| 1 | PDF pp. 5–14: first program through lists | Type each example, change a value, predict before running | Write a loop containing an `if` from memory. |
| 2 | pp. 15–24: collections through files | Rebuild the monthly sales report and do Practice set 0 | Break a small task into clear functions. |
| 3 | pp. 25–34: approach and Python foundations | Retype examples using the dataset and deliberately trigger their traps | Explain the Part 2 traps without notes. |
| 4 | pp. 35–44: advanced Python and complexity | Write `chunked()`, retry, and a timing decorator; do ten easy problems | State time and extra space for a snippet. |
| 5 | pp. 45–49: arrays through linked lists | Do 15 easy or medium problems, about 25 minutes each | Solve two-sum, subarray-sum-k, and longest unique substring cold. |
| 6 | pp. 50–57: search through dynamic programming | Do 15 medium problems; redo week 5 misses | Write binary search and BFS cold. |
| 7 | pp. 58–63: patterns P1–P9 | Solve each worked question cold, then vary the input file | Recognise a familiar pattern quickly. |
| 8 | pp. 64–68: patterns P10–P18 | Try two timed data questions in 45 minutes | Finish one hard data question in about 25 minutes. |
| 9 | pp. 69–74: pandas, databases, ETL, tests, Spark | Rebuild the ETL pipeline and tests from a blank file | Explain reruns, idempotency, and when to scale. |
| 10 | pp. 75–80: interview sets and revision | Do three spoken mocks: DSA, data, and mixed | Explain a solution while coding in two consecutive mocks. |

These are practice targets, not a claim that everyone learns at the same pace. Repeat a week when the stated skill is not yet comfortable.

## A two-hour day

| Minute | Work |
|---:|---|
| 0–20 | Redo one problem from three days ago without looking. |
| 20–80 | Try two new problems with a 25-minute timer each; explain your reasoning aloud. |
| 80–100 | Review anything missed and write down its pattern and trap in one line. |
| 100–120 | Read one lesson page and run its code. |

## The one-problem loop

1. Read the question. Spend about two minutes saying the input, output, and edge cases.
2. State a simple baseline approach and its time/space cost.
3. Choose a structure or pattern that improves it, then write small named steps.
4. Test one normal case and one edge case before submitting.
5. Rate the attempt **clean**, **slow**, or **failed**. Redo slow and failed problems after three days, then after seven.

You are ready for a medium interview question when you can name the pattern, explain the approach and cost in about two minutes, then write working code in about 25 minutes while talking through it. The PDF measures readiness by this skill, not by a raw problem count.

## Data engineering interview coverage

This Python path covers coding, Python data work, and DSA. Data engineering interviews also test SQL, data modelling, system design, and communication. From week 5, add one design question weekly and continue the [SQL learning path](<../../1. SQL Mastry/README.md>) alongside Python.
