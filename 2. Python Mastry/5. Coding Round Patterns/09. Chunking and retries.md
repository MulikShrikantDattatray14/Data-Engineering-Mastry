## P13. A large file is an iterator, not one giant list

Pretend the 15-row store file is 50 GB. `csv.DictReader` yields one row at a time; `islice` takes only the next four. A running total survives from one batch to the next.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=5&lesson=09&snippet=1>)

```python
import csv
from itertools import islice

def read_in_chunks(path, size):
    if size <= 0:
        raise ValueError('size must be positive')
    with open(path, newline='', encoding='utf-8') as file:
        rows = csv.DictReader(file)
        while chunk := list(islice(rows, size)):
            yield chunk

running = 0.0
for number, chunk in enumerate(read_in_chunks('python_de_dataset/orders.csv', 4), 1):
    part = sum(float(row['amount']) for row in chunk
               if row['status'] == 'delivered')
    running += part
    print(f'chunk {number}: {len(chunk)} rows +{part:,.2f} running {running:,.2f}')
```

```text
chunk 1: 4 rows +3,493.00 running 3,493.00
chunk 2: 4 rows +5,894.00 running 9,387.00
chunk 3: 4 rows +5,590.00 running 14,977.00
chunk 4: 3 rows +3,995.00 running 18,972.00
```

Only one batch of four rows is stored at a time: O(batch size) working memory. A batch can instead feed `executemany`, then commit, then move on. Pandas has a similar `read_csv(..., chunksize=100_000)` iterator. Decimal would be safer than float for actual money; float mirrors the source's demonstration.

## P14. Exponential backoff with full jitter

An API may reply `429` (rate limited) or time out temporarily. Retry only errors you expect to be transient. Each retry permits a larger delay, capped at a maximum. Pick a random wait between zero and that cap so many workers do not retry together. Stop after a fixed number of attempts.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=5&lesson=09&snippet=2>)

```python
import random

rng = random.Random(7)  # repeatable classroom example
def backoff(base=1.0, cap=30.0, attempts=6):
    for retry_number in range(attempts):
        upper = min(cap, base * 2 ** retry_number)
        yield round(rng.uniform(0, upper), 2)
print('planned waits:', list(backoff()))

class RateLimited(Exception):
    pass

replies = iter([RateLimited('429'), RateLimited('429'), '200 OK'])
def fake_api():
    response = next(replies)
    if isinstance(response, Exception):
        raise response
    return response

def with_retry(call, attempts=5, base=0.01):
    for number in range(attempts):
        try:
            return call()
        except RateLimited as error:
            if number == attempts - 1:
                raise  # the last failed attempt is visible to the caller
            wait = rng.uniform(0, min(30.0, base * 2 ** number))
            print(f'try {number + 1}: {error}, planned sleep {wait:.4f}s')
            # In a real client: time.sleep(wait)
    raise AssertionError('unreachable')

print(with_retry(fake_api))
```

**Expected output with seed 7:**

```text
planned waits: [0.32, 0.3, 2.6, 0.58, 8.57, 10.97]
try 1: 429, planned sleep 0.0006s
try 2: 429, planned sleep 0.0101s
200 OK
``n
The playground deliberately does not sleep. The PDF's simulated client does use `time.sleep`. For a real API, honor `Retry-After` when offered, set a timeout, retry only suitable status codes/exceptions, and log the final failure. A changing operation such as charging a card also needs an idempotency key before automatic retry.
