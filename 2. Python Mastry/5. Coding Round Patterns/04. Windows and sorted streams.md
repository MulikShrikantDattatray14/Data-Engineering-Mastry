## P5. A three-day rolling total

Picture a window over April 1–3. Move it to April 2–4: add April 4, remove April 1. The `deque` remembers the amounts inside the window, and `total` avoids re-summing them each time.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=5&lesson=04&snippet=1>)

```python
from collections import deque

daily = [('04-01', 0), ('04-02', 1999), ('04-03', 0),
         ('04-04', 0), ('04-05', 846), ('04-06', 0), ('04-07', 0)]
window = deque()
total = 0
for day, amount in daily:
    window.append(amount)
    total += amount
    if len(window) > 3:
        total -= window.popleft()
    print(day, '3-day:', total)
```

```text
04-01 3-day: 0
04-02 3-day: 1999
04-03 3-day: 1999
04-04 3-day: 1999
04-05 3-day: 846
04-06 3-day: 846
04-07 3-day: 846
```

With n days and a window of k, this takes O(n) time and O(k) memory. Re-summing a slice at each day takes O(nk). **Days with no orders must still appear as zero rows**; otherwise “three rows” is not “three days.” For a moving average, divide by `len(window)`. A moving maximum needs a monotonic deque because subtracting an expired value does not tell you the new maximum.

## P6. Merge streams that are already sorted

The web feed and app feed each arrive in timestamp order. Compare their front items, output the earlier one, and advance only that feed. `heapq.merge` does this lazily; two pointers show the same logic for lists.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=5&lesson=04&snippet=2>)

```python
import heapq

web = [('10:00', 'u1 view'), ('10:20', 'u1 checkout'), ('11:00', 'u3 view')]
app = [('10:05', 'u1 cart'), ('10:22', 'u1 purchase')]
print([event for _, event in heapq.merge(web, app)])

def merge_two(left, right):
    i = j = 0
    result = []
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    return result + left[i:] + right[j:]

print(merge_two([1, 4, 9], [2, 3, 10, 11]))
```

```text
['u1 view', 'u1 cart', 'u1 checkout', 'u1 purchase', 'u3 view']
[1, 2, 3, 4, 9, 10, 11]
```

For two inputs with n total elements, the pointer algorithm takes O(n) time. Its **output list** uses O(n) memory; the `heapq.merge` iterator can feed another operation without materializing the merged stream. For K sorted files, `heapq.merge` keeps roughly one next item per file and takes O(n log K) time. Concatenating and sorting uses O(n log n) time and holds all rows.
