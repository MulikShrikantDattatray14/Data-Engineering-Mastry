**Source:** [PDF p. 68](<../Source/1793477658005.pdf#page=68>). Both are DE Medium.

## P17. Clean, validate, then separate good and bad

`orders_dirty.csv` has seven rows. One validator returns a cleaned copy and **all** reasons the row fails. Good rows go to the load list; rejected rows go to quarantine with their reasons so the source can be fixed and replayed.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=5&lesson=11&snippet=1>)

```python
import csv
from datetime import date

allowed = {'delivered', 'cancelled', 'returned'}

def validate(row):
    errors = []
    if not row['customer_id'].strip():
        errors.append('customer_id missing')
    try:
        date.fromisoformat(row['order_date'])
    except ValueError:
        errors.append(f"bad date {row['order_date']}")
    status = row['status'].strip().lower()
    if status not in allowed:
        errors.append(f'unknown status {status!r}')
    try:
        if float(row['amount']) <= 0:
            errors.append(f"amount {row['amount']} <= 0")
    except ValueError:
        errors.append(f"amount not numeric {row['amount']!r}")
    return {**row, 'status': status}, errors

good, quarantine = [], []
with open('python_de_dataset/orders_dirty.csv', newline='', encoding='utf-8') as file:
    for row in csv.DictReader(file):
        cleaned, errors = validate(row)
        (quarantine if errors else good).append((cleaned, errors))
print('good:', [(row['order_id'], row['status']) for row, _ in good])
for row, errors in quarantine:
    print('bad ', row['order_id'], errors)
```

```text
good: [('121', 'delivered'), ('122', 'delivered')]
bad  116 ['amount -50 <= 0']
bad  117 ['customer_id missing']
bad  118 ['bad date 2025-02-30']
bad  119 ["unknown status 'shipped'"]
bad  120 ["amount not numeric 'abc'"]
```

Order 122 contains `DELIVERED ` and passes because status is normalized **before** it is checked. The example uses lists so you can inspect both outputs; a production version can stream clean rows to a loader and bad rows to a quarantine file/table. Add checks for missing columns, `None`, and duplicate IDs if the data contract requires them.

## P18. Emit inserts, deletes and field changes

Key both snapshots by `customer_id`. `new - old` gives inserted IDs; `old - new` gives deleted IDs; shared IDs need a field-by-field comparison. This is the basic shape of change data capture from daily dumps.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=5&lesson=11&snippet=2>)

```python
import csv

def load_snapshot(path):
    with open(path, newline='', encoding='utf-8') as file:
        return {row['customer_id']: row for row in csv.DictReader(file)}

old = load_snapshot('python_de_dataset/snapshot_day1.csv')
new = load_snapshot('python_de_dataset/snapshot_day2.csv')
inserts = sorted(new.keys() - old.keys(), key=int)
deletes = sorted(old.keys() - new.keys(), key=int)
updates = []
for customer_id in sorted(old.keys() & new.keys(), key=int):
    changed = {field: (old[customer_id].get(field), new[customer_id].get(field))
               for field in new[customer_id]
               if old[customer_id].get(field) != new[customer_id].get(field)}
    if changed:
        updates.append((customer_id, changed))
print('inserts:', inserts, 'deletes:', deletes)
for customer_id, changed in updates:
    print('update', customer_id, changed)
```

```text
inserts: ['9'] deletes: ['8']
update 4 {'city': ('Bengaluru', 'Pune')}
update 6 {'city': ('', 'Chennai')}
```

The second update shows an empty city becoming Chennai. These changed IDs can feed an SCD Type 2 load, but deciding effective timestamps and how to handle a late snapshot is a separate design choice. This comparison is O(n+m) expected time and stores both keyed snapshots: O(n+m) memory.
