# 06. Split sessions and find consecutive streaks (P8 and P9)

**Source:** [PDF p. 63](<../Source/1793477658005.pdf#page=63>). **P8:** DE/DA Hard. **P9:** DE/DA Medium.

These two questions both compare neighboring dates. They differ in the boundary rule: a **session** starts after too much idle time; a **streak** starts when yesterday is absent.

## P8. A 30-minute idle gap starts a new session

Group events per user, parse the ISO timestamps, then sort each group. For every event, compare its time with the previous event for that user. A gap **greater than** 30 minutes starts a new session; exactly 30 minutes stays in the current one.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=5&lesson=06&snippet=1>)

```python
import json
from collections import defaultdict
from datetime import datetime, timedelta

gap_limit = timedelta(minutes=30)
by_user = defaultdict(list)
with open('python_de_dataset/events.jsonl', encoding='utf-8') as file:
    for line in file:
        event = json.loads(line)
        by_user[event['user_id']].append(
            (datetime.fromisoformat(event['ts']), event['event']))

for user_id, events in sorted(by_user.items()):
    events.sort()
    sessions = []
    previous = None
    for timestamp, event_name in events:
        if previous is None or timestamp - previous > gap_limit:
            sessions.append([])
        sessions[-1].append(event_name)
        previous = timestamp
    print(user_id, sessions)
```

```text
1 [['view', 'cart', 'checkout', 'purchase'], ['view']]
2 [['view', 'view'], ['cart']]
3 [['view', 'cart', 'checkout']]
4 [['view']]
```

User 1 returns at 14:00, creating a second session. User 2 waits 38 minutes before the cart event. Sorting is essential when a file or stream is not guaranteed ordered; the work is O(n log n) overall for sorting, O(n) for the scan. A streaming production version needs a late-event policy or watermark. If asked for average session length, decide whether a one-event session counts as zero minutes.

## P9. Start only where yesterday is missing

Put each user's login dates in a set. Only a day with no previous-day login may begin a streak. Walk forward until the next date is absent. This avoids restarting a count at every date.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=5&lesson=06&snippet=2>)

```python
import csv
from collections import defaultdict
from datetime import date, timedelta

one_day = timedelta(days=1)
days = defaultdict(set)
with open('python_de_dataset/logins.csv', newline='', encoding='utf-8') as file:
    for row in csv.DictReader(file):
        days[int(row['user_id'])].add(date.fromisoformat(row['login_date']))

for user_id, logins in sorted(days.items()):
    best = (0, None)
    for start in logins:
        if start - one_day not in logins:
            length = 1
            while start + length * one_day in logins:
                length += 1
            if length > best[0] or (length == best[0] and start < best[1]):
                best = (length, start)
    print(user_id, 'longest:', best[0], 'days from', best[1])
```

```text
1 longest: 3 days from 2025-04-01
2 longest: 2 days from 2025-04-01
3 longest: 4 days from 2025-04-03
```

Each date belongs to one walked run, so the scan is O(n) average time after making the sets, O(n) memory. The tie rule here chooses the **earlier** start date. The PDF's `max((length, start))` chooses the later start when lengths tie; either is valid only if the question has not specified otherwise. For a “one missed day allowed” streak, the PDF suggests that a day starts a streak only when **neither** of the two previous days is present. During the forward walk, also track whether you have already used the one permitted missing day; stop at a second gap. Merely changing the start test does not enforce the full rule. P8 sessionization is the Python counterpart of SQL `LAG()` plus a running group sum.
