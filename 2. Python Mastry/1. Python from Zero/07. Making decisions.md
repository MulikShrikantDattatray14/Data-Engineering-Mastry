# 07. Making decisions: if, elif, else

**Source:** Python for Data Engineering Notes, PDF page 11 (Lesson 7).

An `if` block runs when its condition is true. `elif` checks another possibility if earlier tests failed. `else` handles everything left over.

## Put conditions in the right order

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=07&snippet=1>)

~~~python
amount = 1198
if amount >= 2000:
    bucket = "large"
elif amount >= 1000:
    bucket = "medium"
else:
    bucket = "small"
print(amount, "->", bucket)
~~~

Output:

~~~text
1198 -> medium
~~~

Python checks from top to bottom and runs only the **first** matching block. Here 1198 is not at least 2000, but it is at least 1000. If we checked `>= 1000` first, a 2500 order would be labelled medium before Python reached the large test. Put the stricter threshold first.

Every `if`, `elif`, and `else` line ends in a colon. The code inside its block must be indented. Missing either the colon or indentation raises `SyntaxError` or `IndentationError`.

## Turn a store rule into a function

A member gets free delivery. For nonmembers in Bengaluru, Mumbai, or Delhi, orders of at least 500 get free delivery and smaller ones cost 40. Other cities cost 80.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=07&snippet=2>)

~~~python
def delivery_fee(amount, city, is_member):
    if is_member:
        return 0
    if city in ["Bengaluru", "Mumbai", "Delhi"]:
        if amount >= 500:
            return 0
        return 40
    return 80

print(delivery_fee(300, "Pune", True))
print(delivery_fee(799, "Mumbai", False))
print(delivery_fee(300, "Mumbai", False))
print(delivery_fee(300, "Pune", False))
~~~

Output:

~~~text
0
0
40
80
~~~

Read one call at a time. The first call exits at `if is_member`. The second reaches the metro-city block and exits at the amount check. The third is a small metro-city order. The fourth is outside the metro list. Each `return` leaves the function immediately, so later rules are skipped. This is called an **early return**.

## Short conditional expressions

For a simple choice between two values:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=07&snippet=3>)

~~~python
amount = 796
label = "free delivery" if amount >= 500 else "pay delivery"
print(label)
~~~

Output:

~~~text
free delivery
~~~

Use the full `if` block when the rule has several steps; use this form when one expression stays easy to read.

## Match one of several cases

Python 3.10+ has `match`:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=07&snippet=4>)

~~~python
status = "returned"
match status:
    case "delivered":
        print("count the revenue")
    case "cancelled" | "returned":
        print("exclude from revenue")
    case _:
        print("unknown status")
~~~

Output:

~~~text
exclude from revenue
~~~

The `|` inside the case means either literal status. `case _` catches unmatched values.

### 18. Python If...Else

**Source:** [W3Schools Python If Statement](https://www.w3schools.com/python/python_conditions.asp) | **Main lesson:** [07. Making decisions](<07. Making decisions.md>)

An if block runs when its condition is true. An elif offers another condition, and else handles anything left. The indented lines belong to their block.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=07&snippet=6>)

~~~python
amount = 1198
is_delivered = True
if is_delivered and amount >= 1000:
    print('priority delivered order')
elif is_delivered:
    print('standard delivered order')
else:
    print('not delivered')
print('check complete')
~~~

~~~text
priority delivered order
check complete
~~~

The first true branch runs, then the program continues after the whole decision. Zero, an empty string, None, and empty collections are false-like in a condition; a nonempty string such as 'False' is true-like. Compare explicitly when the meaning matters.

### 19. Python Match

**Source:** [W3Schools Python Match](https://www.w3schools.com/python/python_match.asp) | **Related lesson:** [07. Making decisions](<07. Making decisions.md>)

Match is another way to choose among several cases. It is available in Python 3.10 and newer. A vertical bar groups alternatives; case _ is the fallback. A guard adds one more condition.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=07&snippet=7>)

~~~python
status = 'returned'
fee = 50
match status:
    case 'delivered' | 'shipped':
        print('close the order')
    case 'returned' if fee > 0:
        print('refund after fee')
    case _:
        print('review manually')
~~~

~~~text
refund after fee
~~~

Put the fallback last. The match expression is evaluated once, then cases are checked in order. For a simple yes/no decision, if is often clearer; match helps when there are several distinct shapes or values.
