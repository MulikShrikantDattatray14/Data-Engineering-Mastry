# 13. Which data structure?

**Source:** *Python for Data Engineering Notes*, page 17 of 80 (Lesson 13).

Choose a container by the question you need to answer. The same store data can be represented four ways, but each way makes a different task easy.

| Container | Example | Order | Can change? | Duplicates | Best question |
|---|---|---|---|---|---|
| List | `[1, 2, 2]` | Yes, indexed | Yes | Yes | "Which item came first?" |
| Tuple | `(date, amount)` | Yes, indexed | No | Yes | "Is this one fixed record?" |
| Set | `{1, 2}` | No | Yes | No | "Have I seen this ID?" |
| Dictionary | `{"Mouse": 799}` | Insertion order | Yes | Keys unique; values may repeat | "What value belongs to this key?" |

## Why the choice matters

| Lookup question | List | Tuple | Set | Dictionary |
|---|---|---|---|---|
| `value in container` | Scans values, O(n) | Scans values, O(n) | Average O(1) | Checks **keys**, average O(1) |

A dictionary is the right choice when you need a value *by key*, such as `price_by_product["Mouse"]`. A set is the simpler choice when you only need to know whether an ID was seen. Fast lookup uses more memory than a plain list, and building the set or dictionary has a cost.

Suppose we must check whether customer ID `999_999` is already loaded among a million IDs.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=13&snippet=1>)

```python
import time

ids_list = list(range(1_000_000))
ids_set = set(ids_list)

start = time.perf_counter()
print(999_999 in ids_list)
list_ms = (time.perf_counter() - start) * 1000

start = time.perf_counter()
print(999_999 in ids_set)
set_ms = (time.perf_counter() - start) * 1000

print(f"list {list_ms:.2f} ms vs set {set_ms:.4f} ms")
```

Both membership checks print `True`. The PDF's sample run measured `list 10.66 ms vs set 0.0049 ms`; your numbers will differ. A list may inspect each item. A set usually looks up membership directly. Part 4 explains the Big-O reason. Building the set itself also costs time and memory, so it pays off when you perform many lookups.

## Convert only when the task calls for it

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=13&snippet=2>)

```python
names = ["Aarav", "Diya", "Aarav", "Kabir"]
print(list(dict.fromkeys(names)))   # remove duplicates, keep first order

ids = [101, 102, 103]
amounts = [1198, 796, 1499]
print(dict(zip(ids, amounts)))      # pair same-position items
print(sorted({"b": 2, "a": 1}.items()))
print(tuple(ids))
```

```text
['Aarav', 'Diya', 'Kabir']
{101: 1198, 102: 796, 103: 1499}
[('a', 1), ('b', 2)]
(101, 102, 103)
```

The PDF also demonstrates turning a list and a string into sets:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=13&snippet=3>)

```python
names = ["Aarav", "Diya", "Aarav", "Kabir"]
print(list(set(names)))  # each name once
print(set("banana"))     # each letter once
```

One possible output is:

```text
['Diya', 'Kabir', 'Aarav']
{'a', 'n', 'b'}
```

Both remove duplicates, but **their displayed order can vary**. `dict.fromkeys(names)` keeps each name's first appearance. `zip(ids, amounts)` pairs `101` with `1198`, `102` with `796`, and so on.

## Quick store decisions

| Task | Pick | Why |
|---|---|---|
| Keep 15 orders in arrival order | List | Position matters |
| Remember loaded customer IDs | Set | Fast "seen before?" check |
| Look up price by product name | Dictionary | Key-to-value lookup |
| Return `(minimum, maximum)` | Tuple | Fixed pair |
| Count orders per status | Dictionary | Status-to-count mapping |
