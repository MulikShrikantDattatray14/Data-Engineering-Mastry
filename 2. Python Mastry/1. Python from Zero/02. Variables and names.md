# 02. Variables and names

**Source:** Python for Data Engineering Notes, PDF page 6 (Lesson 2).

A variable gives a value a name. Think of it as a label on the store's data: `orders` labels the order count, and `city` labels a city name. `=` assigns a value; it does not ask whether two values are equal.

## Create, change, and inspect values

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=02&snippet=1>)

~~~python
orders = 15
city = "Bengaluru"
price = 799.0
is_delivered = True

print(orders, city, price, is_delivered)
orders = orders + 1
print("now:", orders)
print(type(orders), type(city), type(price), type(is_delivered))
~~~

Output (shown without terminal line wrapping):

~~~text
15 Bengaluru 799.0 True
now: 16
<class 'int'> <class 'str'> <class 'float'> <class 'bool'>
~~~

Step by step: `orders` begins as 15. `orders = orders + 1` reads that value, adds 1, and stores 16 under the same name. `type()` tells us whether a value is a whole number (`int`), text (`str`), decimal number (`float`), or true/false (`bool`). Python uses the latest assigned value.

## Handy assignments

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=02&snippet=2>)

~~~python
a, b = 10, 20
a, b = b, a
print(a, b)

x = y = 0
GST_RATE = 0.18
total = 1000 * (1 + GST_RATE)
print(x, y, total)
~~~

Output:

~~~text
20 10
0 0 1180.0
~~~

`a, b = b, a` swaps values without a third variable. `x = y = 0` gives two names the same value. Uppercase `GST_RATE` signals a constant by convention: Python does not enforce that promise.

## Choose names you can understand next week

| Good | Problematic | Why |
|---|---|---|
| `order_total` | `order total` | Spaces are not allowed; use `snake_case` |
| `order2` | `2order` | A name cannot start with a digit |
| `total_amount` | `class`, `for`, `if` | Python reserves keywords |
| `customer_city` | `cc`, `x1`, `data2` | Meaningful names make code easier to explain |

Names are case sensitive:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=02&snippet=3>)

~~~python
Amount = 100
amount = 200
print(Amount, amount)
~~~

Output:

~~~text
100 200
~~~

Python sees two different names. A name must be assigned before it is used. Try using a name before creating it:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=02&snippet=4>)

~~~python
print(total_orders)
~~~

Python reports:

~~~text
NameError: name 'total_orders' is not defined
~~~

Assign `total_orders` on an earlier line before printing it.

## A tiny store example

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=02&snippet=5>)

~~~python
product_name = "Wireless Mouse"
unit_price = 799
quantity = 2
total_cost = unit_price * quantity
print(product_name, quantity, total_cost)
~~~

Output:

~~~text
Wireless Mouse 2 1598
~~~

Now changing `quantity` is enough to calculate a new total. Next we will look at the arithmetic operators that make this work.

### 07. Python Variables

**Source:** [Python Variables](https://www.w3schools.com/python/python_variables.asp). **Mentor lesson:** [Variables and names](<02. Variables and names.md>).

A variable name points to a value as soon as you assign it with `=`. Python does not need a separate declaration. You can reassign the name, and `type()` tells you what kind of value it currently holds.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=02&snippet=6>)

```python
order_total = 1198
order_total += 796
city = "Pune"
City = "Delhi"

print(order_total, type(order_total).__name__)
print(city, City)
```

```text
1994 int
Pune Delhi
```

`+=` adds to the old value and stores the result. `city` and `City` are different names because capitalization matters. Use clear names such as `order_total`; avoid spaces and names that start with a digit. Python permits a name to point to a different type later, but changing types unexpectedly can make a program harder to understand.

### 08. Python Data Types

**Source:** [Python Data Types](https://www.w3schools.com/python/python_datatypes.asp). **Mentor lessons:** [Variables and names](<02. Variables and names.md>), [Tuples and sets](<11. Tuples and sets.md>), and [Dictionaries](<12. Dictionaries - key and value.md>).

A type determines what a value can do. Start with the types you will see in store data:

| Value | Type | Use |
|---|---|---|
| `101` | `int` | Order ID or count |
| `1198.5` | `float` | A decimal result |
| `"delivered"` | `str` | Text status |
| `True` | `bool` | Yes/no flag |
| `[101, 102]` | `list` | Ordered, editable items |
| `(101, 1198)` | `tuple` | Fixed pair |
| `{101, 102}` | `set` | Unique items |
| `{"id": 101}` | `dict` | Key to value |
| `None` | `NoneType` | No value |

The W3Schools page also lists `complex`, `range`, `frozenset`, and binary types (`bytes`, `bytearray`, `memoryview`). You can recognize them now and learn their uses when needed. In this Part 1 path, lists, dictionaries, strings, numbers, and `None` appear most often.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=02&snippet=7>)

```python
values = [101, 1198.5, "delivered", True, None, [1, 2], {"id": 101}]
print([type(value).__name__ for value in values])
```

```text
['int', 'float', 'str', 'bool', 'NoneType', 'list', 'dict']
```

A string that *looks* like a number is still text. For instance, CSV readers initially give you `"1198.5"`; convert it before arithmetic.
