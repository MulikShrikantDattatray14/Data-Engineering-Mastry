# 17. Reading errors without panic

**Source:** *Python for Data Engineering Notes*, page 21 of 80 (Lesson 17).

An error is a clue about **where** Python stopped and **why**. Read a traceback from the bottom: the final line names the exception and its message; the lines above point to the code location.

## Read one real failure

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=17&snippet=1>)

```python
def average(values):
    return sum(values) / len(values)

orders = []
print(average(orders))
```

```text
ZeroDivisionError: division by zero
```

`len(orders)` is `0`, so the function divides by zero. A quick repair is to decide what an empty average should mean:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=17&snippet=2>)

```python
def average(values):
    if not values:
        return 0
    return sum(values) / len(values)

print(average([]))
print(average([1198, 796]))
```

```text
0
997.0
```

For a real reporting system, you might choose `None` instead of `0` to distinguish "no data" from a true zero average. State the choice before writing the function.

## A small error dictionary for your brain

| Error | What happened | Typical cause | First check |
|---|---|---|---|
| `SyntaxError` | Python cannot read the statement | Missing colon, quote, bracket | This line and the one above |
| `IndentationError` | Block spacing is wrong | No indent after `:`, mixed tabs/spaces | Use four spaces per level |
| `NameError` | Name is unknown | Typo, capitalization, used too early | Spelling and creation order |
| `TypeError` | Value is the wrong kind | `"5" + 5` | Check `type()`; convert if appropriate |
| `ValueError` | Type is allowed, value is not | `int("abc")`, `float("")` | Validate or catch it |
| `IndexError` | List position does not exist | `items[10]` in a short list | Check `len(items)` |
| `KeyError` | Dictionary key is absent | `customer["phone"]` | Use `.get()` if optional |
| `ZeroDivisionError` | Divisor is zero | Average of an empty list | Check before dividing |
| `FileNotFoundError` | Path cannot be opened | Wrong name or folder | Inspect the path with `pathlib` |

## Handle expected bad data, keep processing

A file may contain valid amounts and a few unreadable rows:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=17&snippet=3>)

```python
rows = ["1198", "796", "abc", "", "1499"]
total, bad = 0, []

for row in rows:
    try:
        total += float(row)
    except ValueError:
        bad.append(row)

print("total:", total, "| could not read:", bad)
```

```text
total: 3493.0 | could not read: ['abc', '']
```

The loop processes all five rows. It totals the three valid amounts and records the two rejected ones. Catch the **specific error** you expect. A bare `except:` can hide an unrelated programming bug.

## Debug the value immediately before it is used

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=17&snippet=4>)

```python
orders = [
    {"id": 101, "amount": "1198"},
    {"id": 102, "amount": 796},
]
total = 0

for order in orders:
    kind = type(order["amount"]).__name__
    print("DEBUG", order["id"], repr(order["amount"]), kind)
    total += float(order["amount"])

print("total:", total)
assert total == 1994.0, f"expected 1994, got {total}"
print("check passed")
```

```text
DEBUG 101 '1198' str
DEBUG 102 796 int
total: 1994.0
check passed
```

`repr` exposes the quotes around a text value. `type` confirms one amount is text and the other is an integer. `assert` stops the program if the expected condition is false; it is a quick development check, not a substitute for validating production input.

### 32. Python Try...Except

[W3Schools: Python Try...Except](https://www.w3schools.com/python/python_try_except.asp) | [Part 1 Lesson 17](<17. Reading errors.md>) | [Part 1 Lesson 6](<06. Input and output.md>)

Use **try** around code that might fail for an expected reason. Catch a **specific exception**, such as **ValueError**, so unrelated bugs still surface. **else** runs only when the try block succeeds; **finally** runs either way.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=17&snippet=5>)

~~~python
raw = "abc"

try:
    quantity = int(raw)
except ValueError:
    print("Quantity must be a whole number")
else:
    print("Quantity:", quantity)
finally:
    print("Check complete")
~~~

Output:

~~~text
Quantity must be a whole number
Check complete
~~~

To reject an invalid value deliberately, **raise ValueError("quantity cannot be negative")**. In file work, a **with** block is usually the clearest way to close an opened file, even when an error occurs.
