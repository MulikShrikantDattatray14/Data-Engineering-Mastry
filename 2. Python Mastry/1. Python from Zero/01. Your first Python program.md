## What Python does

A Python program is a text file ending in `.py`. The Python interpreter reads its instructions from top to bottom. `print()` sends a value to the screen.

Save this as `hello.py`:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=01&snippet=1>)

~~~python
# A comment is for the human reading the file.
print("Hello, data engineer!")
print("Orders today:", 15)
print(2 + 3)
~~~

Output:

~~~text
Hello, data engineer!
Orders today: 15
5
~~~

The first line is a comment, so Python skips it. The first `print()` displays text. The second displays text and a number with a space between them. The third calculates `2 + 3` before printing it.

You can write code in VS Code, or try small pieces in Jupyter. A virtual environment (`.venv`) keeps one project's libraries separate from another project's libraries.

## Three rules to notice immediately

### 1. Indentation has meaning

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=01&snippet=2>)

~~~python
amount = 1198
if amount > 1000:
    print("big order")  # Four spaces: inside the if block
print("done")           # Back at the left edge: after the block
~~~

Output:

~~~text
big order
done
~~~

`1198 > 1000` is true, so Python runs the indented line. It then continues with `print("done")`. Removing the indentation after `if` causes an error because Python expects a block.

### 2. Capital letters matter

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=01&snippet=3>)

~~~python
print("Amount")
Print("Amount")
~~~

The first line prints `Amount`. The second raises `NameError`: Python knows `print`, but `Print` is a different name. Read the last line of a traceback first; it tells you what failed.

A typical final line for `Print("Amount")` is:

~~~text
NameError: name 'Print' is not defined
~~~

Python may also suggest `print` in the message, depending on the version.

### 3. Instructions run in order

Python normally reads one instruction per line, top to bottom. If line 5 raises an error, lines 1 to 4 may already have run; line 6 will not run.

## Words to keep

| Word | Plain meaning |
|---|---|
| Program or script | A `.py` file containing instructions |
| Terminal | The text window in which you run a command such as `py hello.py` |
| Interpreter | The Python program that reads and runs the instructions |
| Output | What the program prints or otherwise produces |
| Virtual environment | A private set of installed libraries for a project |

<a id="topic-04"></a>
### 04. Python Syntax

**Source:** [Python Syntax](https://www.w3schools.com/python/python_syntax.asp). **Mentor lessons:** [Your first Python program](<01. Your first Python program.md>) and [Making decisions](<07. Making decisions.md>).

Python usually ends one instruction at the end of a line. A colon starts a block, and the following indented lines belong to that block. Four spaces are the usual indentation.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=01&snippet=11>)

```python
amount = 1198
if amount > 1000:
    print("Big order")
print("Check complete")
```

```text
Big order
Check complete
```

The first print is inside `if`; the second is outside it. If you remove the four spaces before `print("Big order")`, Python raises an `IndentationError`. Lines in the **same** block must use consistent indentation. Your Lesson 1 exercise records the exact error you observed.

<a id="topic-06"></a>
### 06. Python Comments

**Source:** [Python Comments](https://www.w3schools.com/python/python_comments.asp). **Mentor lesson:** [Your first Python program](<01. Your first Python program.md>).

A `#` tells Python to ignore the rest of that line. Use a comment to explain *why* a step exists or temporarily disable a line while testing.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=01&snippet=12>)

```python
# Count this amount because the order was delivered.
amount = 1198
# amount = 0  # disabled during this experiment
print("amount:", amount)  # this note is ignored
```

```text
amount: 1198
```

For several comment lines, put `#` on each line. Triple-quoted text creates a string, not a true comment; inside a function, a triple-quoted string at the start is usually a **docstring**.
