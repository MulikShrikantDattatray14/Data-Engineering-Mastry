# 16. Modules, packages and pip

**Source:** *Python for Data Engineering Notes*, page 20 of 80 (Lesson 16).

A **module** is a `.py` file whose functions and values you can import. A **package** groups modules. Python includes a standard library, and `pip` installs other packages into your environment.

## Use what Python already provides

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=16&snippet=1>)

```python
import math
import random
from datetime import date, timedelta
import statistics as st

print(math.sqrt(144), math.ceil(4.2), math.floor(4.8))

random.seed(1)
print(random.randint(1, 6), random.choice(["Pune", "Delhi"]))

print(date(2025, 4, 1) + timedelta(days=30))
print(st.mean([1198, 796, 1499]), st.median([1198, 796, 1499]))
```

The PDF shows this output for Python 3.12:

```text
12.0 5 4
2 Pune
2025-05-01
1164.3333333333333 1198
```

`import math` gives `math.sqrt`. `from datetime import date` brings `date` directly into the file. `as st` is an alias. Seeding `random` makes this particular demonstration repeatable in the source environment.

## Install packages in the active virtual environment

Run these in a terminal, not in a Python file:

```text
pip install pandas requests
pip list
pip freeze > requirements.txt
pip install -r requirements.txt
```

The first command installs packages. `pip list` shows what is installed. `pip freeze` records exact installed versions; the last command installs those versions elsewhere. Activate the project's `.venv` first, as shown in Lesson 1.

## Run code only when a file is executed

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=16&snippet=4>)

```python
# tool.py
def main():
    print("running the tool")

if __name__ == "__main__":
    main()
```

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=16&snippet=5>)

```python
# check_tool.py
import tool
print("imported; its __name__ is", tool.__name__)
```

Running `python check_tool.py` prints:

```text
imported; its __name__ is tool
```

Running `python tool.py` prints:

```text
running the tool
```

The PDF demonstrates the same contrast by creating `tool.py`, importing it, and then running it via `subprocess.run([sys.executable, "tool.py"], capture_output=True, text=True)`. Its combined output is `imported; its __name__ is tool` and `run directly: running the tool`. The `__main__` condition prevents a pipeline from starting just because another script imported its helpers.

## Run the PDF's file-creation demo

The PDF also creates and imports modules in one run. Do this **separately** from the two-file example above: create a new, empty `module_creation_demo` folder, save the following code there as `demo.py`, and run `demo.py` from that folder. It creates `helpers.py` and `tool.py`, so do not run it where you keep files with those names.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=16&snippet=6>)

```python
from pathlib import Path
import subprocess
import sys

Path("helpers.py").write_text(
    "def clean(text):\n"
    "    return text.strip().lower()\n"
    "STATUSES = {'delivered', 'cancelled', 'returned'}\n",
    encoding="utf-8",
)

import helpers
print(helpers.clean("  DELIVERED  "), sorted(helpers.STATUSES))

Path("tool.py").write_text(
    "def main():\n"
    "    print('running the tool')\n\n"
    "if __name__ == '__main__':\n"
    "    main()\n",
    encoding="utf-8",
)

import tool
print("imported; its __name__ is", tool.__name__)
run = subprocess.run(
    [sys.executable, "tool.py"],
    capture_output=True,
    text=True,
    check=True,
)
print("run directly:", run.stdout.strip())
```

Expected output:

```text
delivered ['cancelled', 'delivered', 'returned']
imported; its __name__ is tool
run directly: running the tool
```

`Path.write_text()` creates each Python file. Importing `tool` defines `main()` but does not call it. `subprocess.run()` starts a second Python process and executes `tool.py`, so the `__main__` block runs. `sorted(...)` makes the set of statuses display in a reliable order.

### 26. Python Modules

[W3Schools: Python Modules](https://www.w3schools.com/python/python_modules.asp) | [Part 1 Lesson 16](<16. Modules packages and pip.md>)

A **module** is a Python file you can import. It lets you keep a reusable function in one place and call it from another file. For example, create **pricing.py** and **main.py** in the same empty folder:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=16&snippet=7>)

~~~python
# pricing.py
def sale_total(price, discount_percent):
    return round(price * (1 - discount_percent / 100), 2)
~~~

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=16&snippet=8>)

~~~python
# main.py
import pricing as price_tools

print(price_tools.sale_total(800, 25))
~~~

Run main.py. Output:

~~~text
600.0
~~~

The name after **import** is the filename without .py; the alias after **as** is a shorter local name. You can also write **from pricing import sale_total** and then call **sale_total(800, 25)**. Python includes modules such as **math** without installing anything. **dir(pricing)** lists names defined in a module, including special names added by Python. Importing a file also executes its top-level statements, so put command-line work under the main guard explained in Lesson 16.

### 27. Python Dates

[W3Schools: Python Dates](https://www.w3schools.com/python/python_datetime.asp) | [PDF preview: dates and time zones, p. 27](<../Source/1793477658005.pdf#page=27>)

The built-in **datetime** module holds dates and times as values you can inspect and format. Use **strftime** to produce display text; use **timedelta** to add a duration.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=16&snippet=9>)

~~~python
from datetime import datetime, timedelta

placed = datetime.fromisoformat("2025-04-20T10:30:00")
ship_by = placed.date() + timedelta(days=2)

print(placed.strftime("%A"))
print(ship_by.isoformat())
~~~

Output:

~~~text
Sunday
2025-04-22
~~~

**%A** means full weekday name; **%Y-%m-%d** formats a year, month, and day. **datetime.now()** changes on every run, so a fixed date is easier to practice with. This example has no time-zone information; the PDF revisits time zones later.

### 31. Python PIP

[W3Schools: Python PIP](https://www.w3schools.com/python/python_pip.asp) | [Part 1 Lesson 16](<16. Modules packages and pip.md>)

**pip** installs third-party Python packages. Run these commands in a terminal after activating your project's virtual environment:

~~~powershell
python -m pip --version
python -m pip install pandas
python -m pip list
~~~

The first command reports pip's version, the second installs pandas into the active environment, and the third lists installed packages. The listing and version vary by machine. **python -m pip uninstall pandas** removes that package if you no longer need it. Search for packages on [PyPI](https://pypi.org/). Calling pip through **python -m pip** makes it easier to see which interpreter receives the install.

<a id="topic-36"></a>
### 36. Python VirtualEnv

[W3Schools: Python VirtualEnv](https://www.w3schools.com/python/python_virtualenv.asp) | [Part 1 Lesson 1](<01. Your first Python program.md>) | [Part 1 Lesson 16](<16. Modules packages and pip.md>)

A virtual environment keeps one project's installed packages separate from another project's packages. Create it once in your project folder, activate it, install what this project needs, and deactivate it when finished.

Windows PowerShell:

~~~powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install pandas
deactivate
~~~

macOS or Linux:

~~~sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install pandas
deactivate
~~~

When active, the terminal prompt normally shows **(.venv)**. Inside that environment, **python -m pip** targets its Python installation. Keep the .venv folder out of version control and record package requirements separately. Creating an environment does not install third-party packages automatically.
