# 06. Input and output

**Source:** Python for Data Engineering Notes, PDF page 10 (Lesson 6).

`print()` sends information out. `input()` asks a person for text. Even simple programs become useful when they can read a value, calculate, and display a clear result.

## Control what print displays

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=06&snippet=1>)

~~~python
print("a", "b", "c")
print("a", "b", "c", sep=" | ")
print("loading", end="... ")
print("done")
print()
print("Line 1\nLine 2")
~~~

Output:

~~~text
a b c
a | b | c
loading... done

Line 1
Line 2
~~~

By default, `print()` puts a space between items and ends with a newline. `sep` changes the separator, `end` changes what comes last, and an empty `print()` makes a blank line. The `\n` inside a string starts a new line.

## Ask for an order's details

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=06&snippet=2>)

~~~python
name = input("Your name: ")
qty = int(input("How many items? "))
price = float(input("Price per item: "))
total = qty * price
print()
print(f"Hi {name}, your total is {total:,.2f}")
~~~

If the person types `Meera`, `3`, and `249`, the PDF shows this output (the typed values are omitted):

~~~text
Your name: How many items? Price per item:

Hi Meera, your total is 747.00
~~~

The empty `print()` creates the blank line before the greeting. A terminal may also echo what the person typed. `input()` always returns **text**, so `int()` and `float()` convert the two numeric answers before multiplication.

## Handle a bad answer

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=06&snippet=3>)

~~~python
raw = "abc"
try:
    qty = int(raw)
except ValueError:
    print("Please type a whole number, not", repr(raw))
~~~

Output:

~~~text
Please type a whole number, not 'abc'
~~~

`int("abc")` raises a `ValueError`. The `except` block catches it so you can explain the problem, ask again, or skip a bad data row instead of crashing the whole program. Later lessons cover exceptions in more detail.

## Print a small store receipt

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=06&snippet=4>)

~~~python
items = [
    ("Wireless Mouse", 1, 799),
    ("Gel Pens", 3, 149),
    ("Water Bottle", 1, 399),
]
print(f"{'item':<16}{'qty':>4}{'amount':>10}")
print("-" * 30)
total = 0
for name, qty, price in items:
    line = qty * price
    total += line
    print(f"{name:<16}{qty:>4}{line:>10,.2f}")
print("-" * 30)
print(f"{'total':<16}{'':>4}{total:>10,.2f}")
~~~

Output:

~~~text
item             qty    amount
------------------------------
Wireless Mouse     1    799.00
Gel Pens           3    447.00
Water Bottle       1    399.00
------------------------------
total                 1,645.00
~~~

The tuple for each item gives its name, quantity, and price. The `for` loop repeats the same calculation and print for each item; Lesson 8 explains loops fully. Widths such as `<16` (left aligned) and `>10` (right aligned) make the columns readable.

## An extra store example

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=06&snippet=5>)

~~~python
order_id = 101
status = "delivered"
print("order", order_id, status, sep=" | ")
~~~

Output:

~~~text
order | 101 | delivered
~~~

A small, consistent output format makes a later log easier to read.

**Data engineering connection:** Pipelines usually take input from files, databases, APIs, or command-line options rather than asking a person. The habit is the same: convert incoming text to the type you need and handle bad values.

### 05. Python Output

**Source:** [Python Output](https://www.w3schools.com/python/python_output.asp). **Mentor lessons:** [Your first Python program](<01. Your first Python program.md>) and [Input and output](<06. Input and output.md>).

`print()` displays values. Separate arguments with commas; Python adds spaces between them. `sep` changes that separator, and `end` changes the ending (normally a newline).

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=06&snippet=6>)

```python
print("order", 101, "ready")
print("order", 101, sep=":")
print("loading", end=" -> ")
print("done")
```

```text
order 101 ready
order:101
loading -> done
```

Text must be quoted: `"ready"` is text, while an unquoted `ready` means "look for a variable named ready." Both single and double quotes work for strings.

### 35. Python User Input

[W3Schools: Python User Input](https://www.w3schools.com/python/python_user_input.asp) | [Part 1 Lesson 6](<06. Input and output.md>)

**input()** pauses until a person types and presses Enter. It always returns a **string**, even when the person types digits. Convert and validate before using it as a number.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=06&snippet=7>)

~~~python
raw = input("Quantity: ")

try:
    quantity = int(raw)
except ValueError:
    print("Please enter a whole number")
else:
    print("Units:", quantity)
~~~

If the person types **3**, a terminal run looks like:

~~~text
Quantity: 3
Units: 3
~~~

If they type **three**, the ValueError branch prints the help message. For a repeated prompt, place input and conversion in a **while** loop and stop once conversion succeeds. Production data pipelines usually read files or APIs rather than waiting for terminal input.
