# 15. Functions part 2: a mini pipeline

**Source:** *Python for Data Engineering Notes*, page 19 of 80 (Lesson 15).

Functions are values: Python can pass them to another function, put them in a list, and run them in sequence. That lets us specify how to sort records and split a processing job into small, readable stages.

## Put functions in a list and chain them

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=15&snippet=1>)

```python
def remove_spaces(text):
    return text.strip()

def lowercase(text):
    return text.lower()

steps = [remove_spaces, lowercase]
status = "  DELIVERED  "
for step in steps:
    status = step(status)
print(status)
```

```text
delivered
```

The first function removes outside spaces; the second lowercases the result. The loop passes each stage's output into the next stage. Later pipelines use the same idea with rows and files.

## Tell `sorted` which part to compare

The store keeps products as `(name, price)` pairs.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=15&snippet=2>)

```python
products = [
    ("Mouse", 799), ("Hub", 1499),
    ("Pens", 149), ("Lamp", 1199),
]

def by_price(item):
    return item[1]

print(sorted(products, key=by_price))
print(sorted(products, key=lambda item: item[1], reverse=True))
print(max(products, key=lambda item: item[1]))
```

```text
[('Pens', 149), ('Mouse', 799), ('Lamp', 1199), ('Hub', 1499)]
[('Hub', 1499), ('Lamp', 1199), ('Mouse', 799), ('Pens', 149)]
('Hub', 1499)
```

Without `key`, tuples compare starting at the product name. With `key=by_price`, the comparison uses `item[1]`, the price. `lambda item: item[1]` is a tiny unnamed function for a single expression. The same `key` idea works with `min` and `max`.

## One row through three pipeline stages

Input lines arrive as text, and one is malformed:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=15&snippet=3>)

```python
raw_rows = [
    "101, Delivered ,1198",
    "102,cancelled,1999",
    "bad row",
    "103,  delivered,1499",
]
```

Stage 1 parses a line. A malformed shape becomes `None` so the later stage can discard it.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=15&snippet=4>)

```python
def parse(line):
    parts = line.split(",")
    if len(parts) != 3:
        return None
    order_id, status, amount = parts
    return {
        "id": int(order_id),
        "status": status.strip().lower(),
        "amount": float(amount),
    }
```

Stage 2 keeps delivered orders. Stage 3 counts and sums them:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=15&snippet=5>)

```python
def keep_delivered(rows):
    return [row for row in rows if row and row["status"] == "delivered"]

def summarise(rows):
    return {
        "orders": len(rows),
        "revenue": sum(row["amount"] for row in rows),
    }

parsed = [parse(line) for line in raw_rows]
clean = keep_delivered(parsed)
print(clean)
print(summarise(clean))
```

```text
[{'id': 101, 'status': 'delivered', 'amount': 1198.0}, {'id': 103, 'status': 'delivered', 'amount': 1499.0}]
{'orders': 2, 'revenue': 2697.0}
```

Follow order `101`: its extra spaces disappear, the status becomes lowercase, and it reaches the summary. Order `102` parses but is filtered because it was cancelled. `"bad row"` becomes `None`. Order `103` reaches the summary. Real pipelines add stronger validation: a three-field row with an invalid number still needs error handling.

This pattern will return throughout the notes: **read and parse -> clean and filter -> aggregate and output**.

## Accept any number of amounts

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=15&snippet=6>)

```python
def report(*amounts, currency="Rs"):
    total = sum(amounts)
    print(f"{len(amounts)} orders, total {currency} {total:,}")

report(1198, 796, 1499)
report(1999, currency="INR")
```

```text
3 orders, total Rs 3,493
1 orders, total INR 1,999
```

`*amounts` gathers positional values into a tuple. The source output says `"1 orders"` because the function has no singular-word rule; try adding one.
