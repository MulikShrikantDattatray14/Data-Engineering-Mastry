# 11. Tuples and sets

**Source:** *Python for Data Engineering Notes*, page 15 of 80 (Lesson 11).

Lists are useful when order and editing matter. Two other containers solve different jobs: a **tuple** holds a fixed record, and a **set** holds unique values.

## Tuple: a record that stays fixed

A coordinate belongs together as one pair:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=11&snippet=1>)

```python
point = (12.97, 77.59)
print(point[0], len(point))

lat, lon = point
print(lat, lon)

def min_max(values):
    return min(values), max(values)

low, high = min_max([747, 3498, 1048])
print(low, high)
```

```text
12.97 2
12.97 77.59
747 3498
```

The function returns two values as a tuple; the caller unpacks them into `low` and `high`. A tuple cannot be changed after creation: `point[0] = 5` raises `TypeError`. Use tuples for a coordinate, a `(date, amount)` pair, or another record whose shape should stay fixed.

## Set: keep each value once

The store receives repeated statuses. A set keeps one of each:

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=11&snippet=2>)

```python
statuses = ["delivered", "cancelled", "delivered",
            "returned", "delivered"]
unique = set(statuses)
print(sorted(unique), len(unique))

ids = {101, 102, 103}
ids.add(104)
ids.add(101)  # already present, so no extra copy
print(sorted(ids), 102 in ids)
```

```text
['cancelled', 'delivered', 'returned'] 3
[101, 102, 103, 104] True
```

We used `sorted(...)` only to make the displayed output predictable. A set has **no promised iteration order**.

## Compare two sets of customers

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=11&snippet=3>)

```python
yesterday = {101, 102, 103, 104}
today = {103, 104, 105}

print("new today:", sorted(today - yesterday))
print("in both:", sorted(today & yesterday))
print("all:", sorted(yesterday | today))
```

```text
new today: [105]
in both: [103, 104]
all: [101, 102, 103, 104, 105]
```

Read the operators as questions: `-` means "in the first set but not the second"; `&` means "in both"; `|` means "in either." This is handy when comparing yesterday's and today's data files.

| Feature | List | Tuple | Set |
|---|---|---|---|
| Example | `[1, 2]` | `(1, 2)` | `{1, 2}` |
| Keeps order and positions? | Yes | Yes | No |
| Can change? | Yes | No | Yes, with add/remove |
| Duplicates? | Allowed | Allowed | Removed |
| Best fit | Sequence you edit | Fixed record | Uniqueness or membership |

> **Watch out:** An empty set is `set()`. `{}` makes an empty dictionary.

### 15. Python Tuples

**Source:** [W3Schools Python Tuples](https://www.w3schools.com/python/python_tuples.asp) | **Main lesson:** [11. Tuples and sets](<11. Tuples and sets.md>)

A tuple is an ordered record whose positions cannot be reassigned. It may contain repeated values. Unpacking gives each position a name.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=11&snippet=4>)

~~~python
order = (101, 'Pune', 1198)
order_id, city, amount = order
print(city, amount)
print(type((101,)), type((101)))
~~~

~~~text
Pune 1198
<class 'tuple'> <class 'int'>
~~~

The comma makes (101,) a one-item tuple; parentheses alone around 101 only group an expression. Use a tuple for a fixed pair such as (date, amount). The tuple itself cannot be changed, although a mutable object stored inside one can still change.

### 16. Python Sets

**Source:** [W3Schools Python Sets](https://www.w3schools.com/python/python_sets.asp) | **Main lesson:** [11. Tuples and sets](<11. Tuples and sets.md>)

A set stores each distinct value once. It has no positions, so sort it before displaying it when the output order matters. You can add or remove members.

[▶ Run and edit this example](<http://127.0.0.1:8765/?lesson=11&snippet=5>)

~~~python
loaded = {101, 102, 102}
loaded.add(103)
today = {102, 104}
print(sorted(loaded))
print('new:', sorted(today - loaded))
print('shared:', sorted(today & loaded))
~~~

~~~text
[101, 102, 103]
new: [104]
shared: [102]
~~~

An empty set is set(); {} is an empty dictionary. A set member must be hashable, so a list cannot be a member. True and 1 also count as the same set member because they compare equal.
