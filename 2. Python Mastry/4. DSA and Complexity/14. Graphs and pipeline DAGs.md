# 14. Graphs and pipeline DAGs

**Source:** [Python for Data Engineering Notes, page 54](<../Source/1793477658005.pdf#page=54>).

A graph connects items with edges. A pipeline DAG is a directed graph with no cycle: a task can run only after its inputs finish. A graph can also describe neighbouring cells in a grid.

## Topological order of a data pipeline

Count each task's unfinished prerequisites (indegree). Begin with tasks whose count is zero. Completing one task reduces its dependents' counts.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=14&snippet=1>)

~~~python
from collections import defaultdict, deque

dependencies = [
    ("extract_orders", "clean_orders"),
    ("extract_customers", "dim_customer"),
    ("clean_orders", "fact_orders"),
    ("dim_customer", "fact_orders"),
    ("fact_orders", "daily_report"),
    ("dim_customer", "daily_report"),
]

def run_order(edges):
    children = defaultdict(list)
    indegree = defaultdict(int)
    for before, after in edges:
        children[before].append(after)
        indegree.setdefault(before, 0)
        indegree[after] += 1

    ready = deque(sorted(task for task, count in indegree.items() if count == 0))
    result = []
    while ready:
        task = ready.popleft()
        result.append(task)
        for child in children[task]:
            indegree[child] -= 1
            if indegree[child] == 0:
                ready.append(child)

    if len(result) != len(indegree):
        raise ValueError("cycle: some tasks wait on each other")
    return result

print(run_order(dependencies))
try:
    run_order(dependencies + [("daily_report", "extract_orders")])
except ValueError as error:
    print(error)
~~~

Expected output:

~~~text
['extract_customers', 'extract_orders', 'dim_customer', 'clean_orders', 'fact_orders', 'daily_report']
cycle: some tasks wait on each other
~~~

This is Kahn's algorithm. With V tasks and E dependencies, it takes O(V + E) time. Include isolated tasks explicitly if you adapt this function for a task catalog: the edge list alone cannot reveal them.

## BFS finds connected groups in a grid

Treat each "1" cell as connected to adjacent up, down, left, and right "1" cells. The first unseen cell in a group starts a flood fill.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=14&snippet=2>)

~~~python
from collections import deque

def islands(grid):
    if not grid:
        return 0
    rows, columns = len(grid), len(grid[0])
    seen = set()
    count = 0
    for row in range(rows):
        for column in range(columns):
            if grid[row][column] != "1" or (row, column) in seen:
                continue
            count += 1
            queue = deque([(row, column)])
            seen.add((row, column))
            while queue:
                y, x = queue.popleft()
                for dy, dx in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                    ny, nx = y + dy, x + dx
                    inside = 0 <= ny < rows and 0 <= nx < columns
                    if inside and grid[ny][nx] == "1" and (ny, nx) not in seen:
                        seen.add((ny, nx))
                        queue.append((ny, nx))
    return count

grid = ["11000", "11010", "00011", "00000"]
print(islands(grid))
~~~

Expected output:

~~~text
2
~~~

Mark a cell as seen when it **enters** the queue so another neighbour does not queue it again. Time is O(rows × columns).

| Question | Useful method |
|---|---|
| Valid task run order | Topological sort |
| Cycle in dependencies | Unprocessed tasks after topological sort |
| Fewest steps when every edge costs one | BFS |
| Cheapest path with unequal positive edge costs | Dijkstra with a heap |
| Connected groups | BFS, DFS or union-find |
