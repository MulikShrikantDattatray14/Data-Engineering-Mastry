# 09. Linked lists

**Source:** [Python for Data Engineering Notes, page 49](<../Source/1793477658005.pdf#page=49>).

A linked-list node stores a value and a reference to the next node. You must walk from the head to reach the fifth node, so lookup by position is O(n). Once you hold a node, linking a new node after it is O(1). Python lists are arrays; they are not linked lists.

## Classic 1: reverse the links

Keep three references: previous, current, and next. Save next before changing the current link.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=09&snippet=1>)

~~~python
from dataclasses import dataclass

@dataclass
class Node:
    value: int
    next: "Node | None" = None

def to_list(head):
    values = []
    while head is not None:
        values.append(head.value)
        head = head.next
    return values

def reverse(head):
    previous = None
    while head is not None:
        next_node = head.next
        head.next = previous
        previous = head
        head = next_node
    return previous

head = Node(1, Node(2, Node(3, Node(4))))
print(to_list(reverse(head)))
~~~

Expected output:

~~~text
[4, 3, 2, 1]
~~~

This changes links in place: O(n) time and O(1) extra space.

## Classic 2: detect a cycle

A slow pointer advances one node; a fast pointer advances two. If the list loops, they eventually meet. Use identity (is), because we are asking whether they point at the **same node**.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=09&snippet=2>)

~~~python
class Node:
    def __init__(self, value, next_node=None):
        self.value = value
        self.next = next_node

def has_cycle(head):
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False

first = Node(1)
second = Node(2)
third = Node(3)
first.next, second.next, third.next = second, third, second
print(has_cycle(first), has_cycle(Node(1, Node(2))))
~~~

Expected output:

~~~text
True False
~~~

Time O(n), extra space O(1). A visited set also works but costs O(n) memory.

## Classic 3: merge sorted linked lists

A dummy head removes the special case for the first output node. Always attach the smaller next value.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=09&snippet=3>)

~~~python
class Node:
    def __init__(self, value, next_node=None):
        self.value = value
        self.next = next_node

def build(values):
    head = None
    for value in reversed(values):
        head = Node(value, head)
    return head

def merge(left, right):
    dummy = tail = Node(0)
    while left is not None and right is not None:
        if left.value <= right.value:
            tail.next, left = left, left.next
        else:
            tail.next, right = right, right.next
        tail = tail.next
    tail.next = left if left is not None else right
    return dummy.next

merged = merge(build([1, 4, 9]), build([2, 3, 10]))
values = []
while merged is not None:
    values.append(merged.value)
    merged = merged.next
print(values)
~~~

Expected output:

~~~text
[1, 2, 3, 4, 9, 10]
~~~

The merge touches each node once and reuses the existing nodes.

| Operation | Python list | Linked list |
|---|---|---|
| Read item at index i | O(1) | O(n) |
| Add at front | O(n) shifting | O(1) |
| Add after a held node | O(n) to insert at list position | O(1) to relink |
| Extra per-item reference | None required | Next pointer |

In data engineering, `collections.deque` and LRU caches are more common than a hand-built linked list. A deque uses linked blocks, giving efficient operations at both ends. An LRU cache combines a hash map for O(1) average key lookup with a doubly linked list for O(1) recent-item movement; Python's `OrderedDict` provides both behaviours with `move_to_end()` and `popitem(last=False)`. [Part 5's P16 lesson](<../5. Coding Round Patterns/10. Pagination and LRU caching.md>) builds that cache. A plain Python list would require shifting elements when moving a middle item to the front.

class Node:
    def __init__(self, value, next_node=None):
