# 15. Heaps and greedy choices

**Source:** [Python for Data Engineering Notes, page 55](<../Source/1793477658005.pdf#page=55>).

A min-heap keeps its smallest value at the top. Push and pop cost O(log n). A greedy method makes a locally best choice; it works only when that choice can be shown to lead to a global best answer.

## Reuse the earliest available room

Sort bookings by start time. The heap stores current checkout times. Reuse a room if its earliest checkout is no later than the next check-in.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=15&snippet=1>)

~~~python
import heapq

bookings = [
    ("05-01", "05-04"), ("05-03", "05-06"), ("05-06", "05-08"),
    ("05-02", "05-05"), ("05-04", "05-07"),
]

def rooms_needed(stays):
    checkouts = []
    for start, end in sorted(stays):
        if checkouts and checkouts[0] <= start:
            heapq.heapreplace(checkouts, end)
        else:
            heapq.heappush(checkouts, end)
    return len(checkouts)

print(rooms_needed(bookings))
~~~

Expected output:

~~~text
3
~~~

The heap grows only when all earlier rooms remain busy. Sorting plus heap operations cost O(n log n).

## Choose the most non-overlapping jobs

Picking the job that finishes earliest leaves the most room for later jobs. Sort by end time.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=15&snippet=2>)

~~~python
bookings = [
    ("05-01", "05-04"), ("05-03", "05-06"), ("05-06", "05-08"),
    ("05-02", "05-05"), ("05-04", "05-07"),
]

def max_jobs(windows):
    chosen = 0
    last_end = ""
    for start, end in sorted(windows, key=lambda window: window[1]):
        if start >= last_end:
            chosen += 1
            last_end = end
    return chosen

print(max_jobs(bookings))
~~~

Expected output:

~~~text
2
~~~

This earliest-finish rule is optimal for the maximum number of non-overlapping intervals. Other problems need their own proof; “greedy” is not automatically correct.

## Keep the running median of a stream

Use a max-heap for the lower half (store negated numbers) and a min-heap for the upper half. Balance their sizes after each new latency value.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=15&snippet=3>)

~~~python
import heapq

class RunningMedian:
    def __init__(self):
        self.lower = []
        self.upper = []

    def add(self, value):
        heapq.heappush(self.lower, -value)
        heapq.heappush(self.upper, -heapq.heappop(self.lower))
        if len(self.upper) > len(self.lower):
            heapq.heappush(self.lower, -heapq.heappop(self.upper))

    def median(self):
        if len(self.lower) > len(self.upper):
            return -self.lower[0]
        return (-self.lower[0] + self.upper[0]) / 2

median = RunningMedian()
for latency in (120, 340, 95, 410, 180, 150):
    median.add(latency)
    print(latency, "->", median.median())
~~~

Expected output:

~~~text
120 -> 120
340 -> 230.0
95 -> 120
410 -> 230.0
180 -> 180
150 -> 165.0
~~~

Each insertion is O(log n), and reading the median is O(1). A size-k min-heap similarly keeps the k largest values of a long stream in O(k) memory. heapq.merge combines sorted streams with one current item per stream.

**Greedy trap:** To make 6 with coins [1, 3, 4], taking the largest coin first uses 4 + 1 + 1 (three coins). Taking 3 + 3 uses two. The next lesson solves this with dynamic programming.
