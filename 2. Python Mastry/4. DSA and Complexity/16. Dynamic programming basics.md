# 16. Dynamic programming basics

**Source:** [Python for Data Engineering Notes, page 56](<../Source/1793477658005.pdf#page=56>).

Dynamic programming (DP) remembers answers to smaller problems so the same work is not repeated. Begin by stating how a small answer depends on earlier answers. Then choose a cache (top-down) or a table (bottom-up).

## Fibonacci: repeated work, cache, then two variables

The plain recursive version recomputes earlier terms many times. A cache changes it to O(n) time. An iterative version needs only the previous two values: O(1) extra space.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=16&snippet=1>)

~~~python
from functools import lru_cache

calls = 0
def fib_slow(n):
    global calls
    calls += 1
    return n if n < 2 else fib_slow(n - 1) + fib_slow(n - 2)

@lru_cache(maxsize=None)
def fib_memo(n):
    return n if n < 2 else fib_memo(n - 1) + fib_memo(n - 2)

def fib_iterative(n):
    previous, current = 0, 1
    for _ in range(n):
        previous, current = current, previous + current
    return previous

print(fib_slow(25), calls)
print(fib_memo(25), fib_iterative(25), fib_iterative(90))
~~~

Expected output:

~~~text
75025 242785
75025 75025 2880067194370816120
~~~

The small input makes the slow version safe to run here. Its call count shows why it becomes impractical as n grows.

## Coin change: a smaller answer for each amount

Let best[a] be the fewest coins needed for amount a. Try each coin c and improve best[a] using best[a - c] + 1.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=16&snippet=2>)

~~~python
def min_coins(coins, amount):
    infinity = float("inf")
    best = [0] + [infinity] * amount
    for current in range(1, amount + 1):
        for coin in coins:
            if coin <= current:
                best[current] = min(best[current], best[current - coin] + 1)
    return -1 if best[amount] == infinity else best[amount]

print(min_coins([1, 3, 4], 6))
print(min_coins([1, 2, 5, 10, 20, 50], 88))
~~~

Expected output:

~~~text
2
6
~~~

This takes O(amount × number of coin types) time and O(amount) memory. It finds 3 + 3 for 6, beating the greedy three-coin result.

## Maximum contiguous sum: keep only the best ending here

At each new day's change, either extend the earlier run or start a new one. This is Kadane's algorithm.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=16&snippet=3>)

~~~python
def max_subarray(values):
    best = ending_here = values[0]
    for value in values[1:]:
        ending_here = max(value, ending_here + value)
        best = max(best, ending_here)
    return best

print(max_subarray([5, -2, -8, 3, 4, -1, 6, -9]))
~~~

Expected output:

~~~text
12
~~~

The best run is 3 + 4 - 1 + 6 = 12. This version expects a nonempty input. Time O(n), extra space O(1).

## Climbing stairs: two previous counts

To reach step n by moves of one or two steps, add the ways to reach n-1 and n-2.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=16&snippet=4>)

~~~python
def climb(steps):
    one_back = two_back = 1
    for _ in range(steps):
        one_back, two_back = two_back, one_back + two_back
    return one_back

print(climb(10))
~~~

Expected output:

~~~text
89
~~~
