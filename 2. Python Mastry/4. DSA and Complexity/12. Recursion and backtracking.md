# 12. Recursion and backtracking

**Source:** [Python for Data Engineering Notes, page 52](<../Source/1793477658005.pdf#page=52>).

Recursion solves a smaller version of the same problem. It needs a stopping case and a step that moves toward that case. Backtracking tries a choice, explores it, undoes it, then tries another choice.

## Walk nested order data

Dictionaries and lists may contain one another. A plain value ends the recursion.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=12&snippet=1>)

~~~python
def depth(value):
    if isinstance(value, dict) and value:
        return 1 + max(depth(child) for child in value.values())
    if isinstance(value, list) and value:
        return 1 + max(depth(child) for child in value)
    return 0

payload = {"order": {"id": 114, "items": [{"sku": 4, "tags": ["new"]}]}}
print(depth(payload), depth(42), depth({}))
~~~

Expected output:

~~~text
5 0 0
~~~

For n nested values and maximum nesting depth d, the walk is O(n) time and O(d) call-stack space. Very deep untrusted data may exceed Python's recursion limit.

## Try every subset

For each grouping column, choose “skip” or “take.” Copy the current path when a complete choice is reached; otherwise later changes would alter stored answers.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=12&snippet=2>)

~~~python
def subsets(items):
    answer, path = [], []
    def choose(position):
        if position == len(items):
            answer.append(path.copy())
            return
        choose(position + 1)
        path.append(items[position])
        choose(position + 1)
        path.pop()
    choose(0)
    return answer

print(subsets(["city", "status"]))
~~~

Expected output:

~~~text
[[], ['status'], ['city'], ['city', 'status']]
~~~

There are 2ⁿ subsets for n items. All permutations grow even faster, at n!, because the next position can choose any still-unused item.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=12&snippet=3>)

~~~python
from itertools import permutations

print(len(list(permutations("abcd"))))
print(list(permutations([1, 2, 3]))[:3])
~~~

Expected output:

~~~text
24
[(1, 2, 3), (1, 3, 2), (2, 1, 3)]
~~~

## Prune impossible branches

For balanced brackets, never close more brackets than have been opened. That rule prevents exploring strings that cannot become valid.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=12&snippet=4>)

~~~python
def valid_brackets(pairs):
    answer = []
    def choose(text, opened, closed):
        if len(text) == 2 * pairs:
            answer.append(text)
            return
        if opened < pairs:
            choose(text + "(", opened + 1, closed)
        if closed < opened:
            choose(text + ")", opened, closed + 1)
    choose("", 0, 0)
    return answer

print(valid_brackets(3))
~~~

Expected output:

~~~text
['((()))', '(()())', '(())()', '()(())', '()()()']
~~~

Recursion fits nested JSON, trees and small choice spaces. For a long flat scan or uncertain depth, prefer a loop or explicit stack.

## More from W3Schools

[W3Schools Recursion](https://www.w3schools.com/python/python_recursion.asp) introduces the smaller-problem pattern. Here is a small recursive total:

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=12&snippet=5>)

~~~python
def total(values):
    if not values:
        return 0
    return values[0] + total(values[1:])

print(total([3, 4, 5]))
~~~

Expected output:

~~~text
12
~~~

This small teaching example slices at every call, adding copying cost. For a long flat list, use sum(values).
