# 10. Binary search

**Source:** [Python for Data Engineering Notes, page 50](<../Source/1793477658005.pdf#page=50>).

Binary search halves a sorted search space after each check. For a million sorted items, that is around twenty checks. It also works over possible **answers** when a yes/no condition changes only once.

## Find the first value at or after a target

Use a half-open range [left, right). The answer may be at right = len(values), meaning no item qualifies.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=10&snippet=1>)

~~~python
from bisect import bisect_left

def lower_bound(values, target):
    left, right = 0, len(values)
    while left < right:
        middle = (left + right) // 2
        if values[middle] < target:
            left = middle + 1
        else:
            right = middle
    return left

dates = ["2025-01-10", "2025-02-02", "2025-03-05", "2025-04-20"]
for target in ("2025-02-02", "2025-03-01", "2026-01-01"):
    print(target, lower_bound(dates, target), bisect_left(dates, target))
~~~

Expected output:

~~~text
2025-02-02 1 1
2025-03-01 2 2
2026-01-01 4 4
~~~

ISO-format dates sort in calendar order. Check index < len(dates) before reading dates[index].

## Search a feasible throughput

A batch system processes files one at a time. At a given rows-per-hour rate, each file takes a whole number of hours. Find the slowest rate that still finishes within eight hours. If a rate works, every faster rate also works: that monotonic rule permits binary search.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=10&snippet=2>)

~~~python
from math import ceil

file_sizes = [120_000, 45_000, 300_000, 80_000, 210_000]

def hours_needed(rate):
    return sum(ceil(rows / rate) for rows in file_sizes)

def minimum_rate(deadline_hours):
    left, right = 1, max(file_sizes)
    while left < right:
        middle = (left + right) // 2
        if hours_needed(middle) <= deadline_hours:
            right = middle
        else:
            left = middle + 1
    return left

rate = minimum_rate(8)
print(rate, hours_needed(rate))
print(rate - 1, hours_needed(rate - 1))
~~~

Expected output:

~~~text
120000 8
119999 9
~~~

Each feasibility check reads all n files. Total time is O(n log M), where M is the largest candidate rate.

## Find when a report first became wrong

The same template can search date partitions **only if** every date from a certain point onward is bad.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=10&snippet=3>)

~~~python
from datetime import date, timedelta

days = [date(2025, 3, 1) + timedelta(days=i) for i in range(60)]
first_bad = date(2025, 4, 7)
checks = 0
left, right = 0, len(days)
while left < right:
    middle = (left + right) // 2
    checks += 1
    if days[middle] >= first_bad:
        right = middle
    else:
        left = middle + 1
print(days[left].isoformat(), checks)
~~~

Expected output:

~~~text
2025-04-07 6
~~~

If good and bad days alternate, binary search cannot safely discard half the dates.
