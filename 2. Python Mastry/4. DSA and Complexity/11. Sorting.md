# 11. Sorting

**Source:** [Python for Data Engineering Notes, page 51](<../Source/1793477658005.pdf#page=51>).

Sorting often makes a hard question simple: equal values become neighbours, intervals can be merged from left to right, and two pointers can move predictably. In ordinary Python work, use sorted() or list.sort(); interviews may also ask how a sort works.

## Merge sort splits and combines

Each split halves the input. Merging a level touches every value. That gives O(n log n) time and O(n) extra space.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=11&snippet=1>)

~~~python
def merge_sort(values):
    if len(values) <= 1:
        return values[:]
    middle = len(values) // 2
    left = merge_sort(values[:middle])
    right = merge_sort(values[middle:])
    merged = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            j += 1
    return merged + left[i:] + right[j:]

print(merge_sort([1999, 747, 3498, 796, 1348]))
~~~

Expected output:

~~~text
[747, 796, 1348, 1999, 3498]
~~~

Using <= for ties keeps the original order of equal-key items, making this merge stable.

## Counting sort when the key range is tiny

Instead of comparing items, count each integer. This works when values lie in a known small non-negative range.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=11&snippet=2>)

~~~python
def counting_sort(values, largest):
    counts = [0] * (largest + 1)
    for value in values:
        counts[value] += 1
    return [value for value, count in enumerate(counts) for _ in range(count)]

print(counting_sort([3, 1, 2, 3, 0, 2, 1], 3))
~~~

Expected output:

~~~text
[0, 1, 1, 2, 2, 3, 3]
~~~

Time O(n + k), extra space O(k) plus the output, where k is the range size. Validate inputs before using this for arbitrary data.

| Sort | Typical time | Extra space | Stable? | Where it fits |
|---|---|---|---|---|
| Python Timsort | O(n log n), often faster on ordered runs | Up to O(n) | Yes | Everyday Python |
| Merge sort | O(n log n) | O(n) | Yes | Merging sorted chunks |
| Quick sort | Average O(n log n), worst O(n²) | Depends on implementation | Usually no | Interview theory |
| Heap sort | O(n log n) | Often O(1) in place | No | Heap theory |
| Counting sort | O(n + k) | O(k) | Can be stable | Small integer keys |

## A custom comparison: largest concatenated number

Compare a+b with b+a as strings to decide which value should appear first.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=11&snippet=3>)

~~~python
from functools import cmp_to_key

def largest_number(numbers):
    parts = [str(number) for number in numbers]
    def compare(left, right):
        if left + right > right + left:
            return -1
        if left + right < right + left:
            return 1
        return 0
    parts.sort(key=cmp_to_key(compare))
    result = "".join(parts)
    return "0" if result.startswith("0") else result

print(largest_number([3, 30, 34, 5, 9]))
print(largest_number([0, 0]))
~~~

Expected output:

~~~text
9534330
0
~~~

For data too large for RAM, sort chunks that fit, write them, then merge sorted streams. Python's heapq.merge illustrates the merge stage; databases and distributed engines use related strategies.

Read [W3Schools Merge Sort](https://www.w3schools.com/python/python_dsa_mergesort.asp) and [Quick Sort](https://www.w3schools.com/python/python_dsa_quicksort.asp). The standard-library merge of two sorted streams is useful for files that were sorted in chunks:

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=4&lesson=11&snippet=4>)

~~~python
from heapq import merge

first_chunk = [747, 1348, 1999]
second_chunk = [796, 1499, 3498]
print(list(merge(first_chunk, second_chunk)))
~~~

Expected output:

~~~text
[747, 796, 1348, 1499, 1999, 3498]
~~~
