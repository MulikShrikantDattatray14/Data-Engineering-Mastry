# Tuples and Sets — Foundation Notes

**Main idea:** A tuple holds an ordered sequence that cannot be reassigned element-by-element. A set stores unique values with no positional indexing.

## 1. Tuples — ordered and immutable

```python
transaction = (101, "SUCCESS", 2500, "INR")
print(transaction[0])   # 101
print(transaction[-1])  # INR
print(len(transaction)) # 4
```

You cannot write `transaction[2] = 3000` because tuples are immutable. Create a **new tuple** instead:

```python
updated_transaction = transaction[:2] + (3000,) + transaction[3:]
print(updated_transaction) # (101, 'SUCCESS', 3000, 'INR')
```

`(3000,)` is a one-element tuple; the comma matters. The original tuple stays unchanged. A tuple can contain mutable objects, but its element references cannot be reassigned.

**JavaScript link:** Like using an array as a fixed record by convention, but Python enforces that tuple element positions cannot be reassigned. `Object.freeze()` is only a rough comparison; it is not equivalent in every detail.

## 2. Sets — unique members

```python
ids = {10, 20, 30, 20, 10}
ids.add(40)
print(len(ids))   # 4
print(20 in ids)  # True
print(50 in ids)  # False
```

- Repeated values appear once.
- `set()` makes an empty set; `{}` makes an empty dictionary.
- Sets don't support `ids[0]`; order is not guaranteed.
- Members must be hashable (for example, an `int` or `str`, not a mutable `list`).

**JavaScript link:** Python `set` is close to JavaScript `Set`: uniqueness and membership, but JS Set retains insertion order while Python set does **not** promise it.

## 3. Comparing sets (reference example)

```python
yesterday = {101, 102, 103}
today = {102, 104}
print(sorted(today - yesterday)) # [104] new today
print(sorted(today & yesterday)) # [102] in both
```

## Quick revision

- Tuple: `(1, 2)`; list: `[1, 2]`; set: `{1, 2}`.
- Access a tuple item by position, e.g. `t[1]` (not `[value]`).
- `tuple(my_list)` returns a new tuple; assign it if you want to keep it.
