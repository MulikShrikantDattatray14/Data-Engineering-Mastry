# Lists and Slicing — Foundation Notes

**Main idea:** A list is an ordered, mutable collection. It is Python's closest equivalent to a JavaScript `Array`.

## 1. Create and update

```python
numbers = [10, 20, 30]
numbers.append(40)
numbers[0] = 5
print(numbers)      # [5, 20, 30, 40]
print(numbers[-1])  # 40
print(len(numbers)) # 4
```

| JavaScript Array | Python list |
|---|---|
| `arr.push(40)` | `arr.append(40)` |
| `arr.length` | `len(arr)` |
| `arr.at(-1)` | `arr[-1]` |
| `arr.slice(1,3)` | `arr[1:3]` |

Lists may contain duplicates and different types.

## 2. Keep original data unchanged while cleaning

```python
sales = [1200, 1500, -300, 1800, 0, 2200]
cleaned_sales = []
for value in sales:
    if value > 0:
        cleaned_sales.append(value)
print(cleaned_sales)      # [1200, 1500, 1800, 2200]
print(len(cleaned_sales)) # 4
```

The input list stays unchanged. This is the foundation for ETL data cleaning.

## 3. Slicing: start, stop, step

```python
sales = [100, 200, 300, 400, 500, 600, 700]
print(sales[:3])    # [100, 200, 300]
print(sales[-3:])   # [500, 600, 700]
print(sales[::2])   # [100, 300, 500, 700]
print(sales[::-1])  # [700, 600, 500, 400, 300, 200, 100]
```

- `start` is included; `stop` is excluded.
- `step=2` visits every second index; it does **not** return only two items.
- A negative step walks backward. `[::-1]` reverses a list.
- Slicing creates a new list (with references to the same contained objects), so it does not change the original outer list.

## Quick revision

- `numbers[1]` returns one value, while `numbers[1:2]` returns a list.
- `sales[1::2]` starts at index 1; `sales[::2]` starts at index 0.
- `sales[-1:-3]` is empty because the default step is forward.
- **Revision priority:** slicing steps, especially negative steps.
