A generator produces one value when asked, pauses, then resumes. That lets a pipeline pull rows from a file without keeping the whole file in memory.

## Follow one row through a lazy pipeline

Each stage receives an iterable and yields its own result. Calling a generator function creates the generator object; work begins when <code>sum()</code> pulls values. A generator is consumed after one pass.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=01&snippet=1>)

~~~python
import csv

def read_rows(path):
    with open(path, newline="", encoding="utf-8") as file:
        yield from csv.DictReader(file)

def delivered(rows):
    for row in rows:
        if row["status"] == "delivered":
            yield row

def amounts(rows):
    for row in rows:
        yield float(row["amount"])

pipeline = amounts(delivered(read_rows("python_de_dataset/orders.csv")))
print(type(pipeline).__name__)
print(sum(pipeline))
print(sum(pipeline))
~~~

Expected output:

~~~text
generator
18972.0
0
~~~

If you need the same data twice, create the pipeline twice or store the values in a list. A list supports <code>len()</code> and indexing; a generator does not.

## See when values are produced

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=01&snippet=2>)

~~~python
def numbers():
    for value in range(3):
        print("produce", value)
        yield value

for value in numbers():
    print("consume", value)
~~~

Expected output:

~~~text
produce 0
consume 0
produce 1
consume 1
produce 2
consume 2
~~~

A <code>for</code> loop calls <code>iter()</code> and repeatedly calls <code>next()</code>. It stops when the iterator raises <code>StopIteration</code>. The optional default in <code>next(iterator, default)</code> avoids that exception.

## Delegate to another generator

<code>yield from</code> passes through values from another iterable or generator.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=01&snippet=3>)

~~~python
values = iter([10, 20])
print(next(values), next(values), next(values, "done"))

def flatten(items):
    for item in items:
        if isinstance(item, list):
            yield from flatten(item)
        else:
            yield item

print(list(flatten([1, [2, [3, 4]], 5])))
~~~

Expected output:

~~~text
10 20 done
[1, 2, 3, 4, 5]
~~~

A generator object stays small while values flow through it, but materializing it with <code>list()</code> uses O(n) memory. Its exact byte size varies by Python version.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=01&snippet=4>)

~~~python
import sys

as_list = [x for x in range(1000)]
as_generator = (x for x in range(1000))
print(sys.getsizeof(as_list) > sys.getsizeof(as_generator))
print(sum(as_generator))
~~~

Expected output:

~~~text
True
499500
~~~

The generator can still retain references to input data it closes over; object size alone is not total pipeline memory.
