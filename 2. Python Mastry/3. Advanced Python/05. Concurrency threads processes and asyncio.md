Choose concurrency by what the work spends time doing. API calls wait for I/O; parsing or hashing large blocks uses CPU. The right tool depends on that difference.

| Tool | Good fit | Main cost |
|---|---|---|
| Threads | Several independent I/O waits | Shared-memory coordination |
| Processes | CPU work on independent chunks | Separate memory and data transfer |
| asyncio | Many I/O waits through async-aware libraries | All blocking calls must be avoided |

Standard CPython builds usually have a Global Interpreter Lock for Python bytecode in one process. Threads still overlap I/O waits. Optional free-threaded builds have different behavior, so measure the runtime you use.

## Threads overlap waiting

<code>ThreadPoolExecutor.map()</code> returns results in input order even if workers finish in another order.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=05&snippet=1>)

~~~python
from concurrent.futures import ThreadPoolExecutor
from time import sleep

def fetch(page):
    sleep(0.01)  # stand-in for an API wait
    return f"page {page}: 100 rows"

with ThreadPoolExecutor(max_workers=3) as pool:
    results = list(pool.map(fetch, [1, 2, 3]))
print(results)
~~~

Expected output:

~~~text
['page 1: 100 rows', 'page 2: 100 rows', 'page 3: 100 rows']
~~~

The PDF compares five 0.3-second waits: sequential work takes about 1.5 seconds, while five threads take about 0.3 seconds. These are illustrations, not fixed timings.

## Processes split CPU work

A process has its own interpreter and memory. The worker must be defined at module level, and the main guard is needed for spawn-based systems such as Windows. The local runner saves the snippet as a script before running it.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=05&snippet=2>)

~~~python
from concurrent.futures import ProcessPoolExecutor

def checksum(chunk):
    return sum(x * x % 7 for x in chunk)

if __name__ == "__main__":
    chunks = [range(0, 5), range(5, 10)]
    with ProcessPoolExecutor(max_workers=2) as pool:
        print(list(pool.map(checksum, chunks)))
~~~

Expected output:

~~~text
[9, 10]
~~~

For tiny chunks, process startup costs more than the work. Use a large enough CPU task before expecting speedup.

## asyncio coordinates many waits in one thread

An <code>async</code> function is a coroutine. <code>await</code> yields control while waiting, and <code>gather()</code> collects results in argument order. A normal blocking function inside the event loop can stall every coroutine.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=05&snippet=3>)

~~~python
import asyncio

async def fetch_async(page):
    await asyncio.sleep(0)
    return page * 100

async def main():
    rows = await asyncio.gather(*(fetch_async(p) for p in [1, 2, 3]))
    print(rows)

asyncio.run(main())
~~~

Expected output:

~~~text
[100, 200, 300]
~~~

## More from W3Schools: asyncio

The [asyncio module reference](https://www.w3schools.com/python/ref_module_asyncio.asp) shows coroutines and event loops. This original example runs two small waits:

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=05&snippet=4>)

~~~python
import asyncio

async def label(value):
    await asyncio.sleep(0)
    return f"order {value}"

async def main():
    print(await asyncio.gather(label(101), label(102)))

asyncio.run(main())
~~~

Expected output:

~~~text
['order 101', 'order 102']
~~~
