Use a class when a row has rules of its own, or when several pipeline sources should share one interface. A <code>dataclass</code> removes repetitive initializer and representation code.

## A validated, typed order

<code>frozen=True</code> prevents ordinary field reassignment; <code>slots=True</code> reduces per-instance overhead. <code>__post_init__</code> checks the record after construction. A class method can turn one CSV row into a typed object.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=03&snippet=1>)

~~~python
from dataclasses import dataclass
from datetime import date
from decimal import Decimal

@dataclass(frozen=True, slots=True)
class Order:
    order_id: int
    customer_id: int
    order_date: date
    status: str
    amount: Decimal

    def __post_init__(self):
        if self.amount <= 0:
            raise ValueError("amount must be positive")

    @classmethod
    def from_row(cls, row):
        return cls(
            int(row["order_id"]), int(row["customer_id"]),
            date.fromisoformat(row["order_date"]),
            row["status"].strip().lower(), Decimal(row["amount"])
        )

row = {"order_id": "101", "customer_id": "1",
       "order_date": "2025-01-10", "status": " Delivered ",
       "amount": "1198.00"}
order = Order.from_row(row)
print(order.order_id, order.status, order.amount)
print(order == Order.from_row(row))
try:
    Order(116, 8, date(2025, 5, 2), "delivered", Decimal("-50"))
except ValueError as error:
    print("rejected:", error)
~~~

Expected output:

~~~text
101 delivered 1198.00
True
rejected: amount must be positive
~~~

Frozen records can still contain mutable nested fields, so use immutable field values when you need truly stable records.

## One interface for two file types

An abstract base class says each extractor must provide <code>rows()</code>. The pipeline can then call <code>rows()</code> without knowing how each file is stored. Keep the file open while yielding its rows.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=03&snippet=2>)

~~~python
import csv
import json
from abc import ABC, abstractmethod

class Extractor(ABC):
    @abstractmethod
    def rows(self):
        pass

class CsvExtractor(Extractor):
    def __init__(self, path):
        self.path = path
    def rows(self):
        with open(self.path, newline="", encoding="utf-8") as file:
            yield from csv.DictReader(file)

class JsonlExtractor(Extractor):
    def __init__(self, path):
        self.path = path
    def rows(self):
        with open(self.path, encoding="utf-8") as file:
            for line in file:
                yield json.loads(line)

sources = [
    CsvExtractor("python_de_dataset/orders.csv"),
    JsonlExtractor("python_de_dataset/events.jsonl"),
]
for source in sources:
    print(type(source).__name__, sum(1 for _ in source.rows()))
~~~

Expected output:

~~~text
CsvExtractor 15
JsonlExtractor 12
~~~

You cannot instantiate <code>Extractor</code> directly because its required method has no implementation. Prefer a pipeline composed of a few steps over a deep inheritance chain.

## More from W3Schools: classes and methods

See [Python Classes](https://www.w3schools.com/python/python_classes.asp) and [Class Methods](https://www.w3schools.com/python/python_class_methods.asp). This original example adds a second way to create a small order:

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=3&lesson=03&snippet=3>)

~~~python
class SimpleOrder:
    def __init__(self, order_id):
        self.order_id = order_id

    @classmethod
    def from_text(cls, text):
        return cls(int(text))

print(SimpleOrder.from_text("101").order_id)
~~~

Expected output:

~~~text
101
~~~
