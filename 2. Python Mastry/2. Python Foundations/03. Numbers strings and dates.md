Money, text, and timestamps need explicit rules in a pipeline. A value that looks fine on one machine can change meaning on another.

## Money: start with text, then use Decimal

Binary floats cannot represent many decimal fractions exactly: <code>0.1 + 0.2</code> prints a value slightly above 0.3. Constructing <code>Decimal(0.1)</code> preserves that already-rounded float; it cannot recover the intended tenth. Build <code>Decimal</code> from the CSV string, and choose a rounding rule explicitly. Python's built-in <code>round()</code> uses ties-to-even for exact halves.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=2&lesson=03&snippet=1>)

~~~python
from decimal import Decimal, ROUND_HALF_UP

print(0.1 + 0.2, 0.1 + 0.2 == 0.3)
print(Decimal("0.1") + Decimal("0.2"))
print(Decimal(0.1))
price = Decimal("2.675")
print(price.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))
print(round(2.5), round(3.5))
print(7 // 2, -7 // 2, int(-3.5))
~~~

Expected output:

~~~text
0.30000000000000004 False
0.3
0.1000000000000000055511151231257827021181583404541015625
2.68
2 4
3 -4 -3
~~~

<code>//</code> rounds down toward negative infinity; <code>int()</code> truncates toward zero. This difference matters for negative adjustments.

## Text: normalize, format, and encode

A string is text; UTF-8 encoding turns it into bytes for a file. Open text files with <code>encoding="utf-8"</code>. For a long output string, collect pieces and join them once.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=2&lesson=03&snippet=2>)

~~~python
status = "  DELIVERED \n"
amount = 1198.5
word = "café"
print(repr(status.strip().lower()))
print(f"{amount:,.2f} | {amount:>10.1f} | {0.256:.1%}")
print(len(word), len(word.encode("utf-8")))
parts = "101,1,2025-01-10,delivered,1198.00".split(",")
print(parts[3], "|".join(parts[:2]))
print(len("₹".encode("utf-8")))
~~~

Expected output:

~~~text
'delivered'
1,198.50 |     1198.5 | 25.6%
4 5
delivered 101|1
3
~~~

The width in <code>:&gt;10.1f</code> right-aligns the number in ten character positions. The accented character in <code>café</code> occupies one character but two UTF-8 bytes; the rupee symbol uses three bytes.

## Dates: know which time zone a timestamp means

A timestamp without a time zone is naive: <code>tzinfo</code> is <code>None</code>, so Python cannot infer what region its clock time describes. The store's local 10:00 in India is 04:30 UTC on the same day. Prefer a named time zone such as <code>ZoneInfo("Asia/Kolkata")</code> for real data because it handles historical rules. The fallback below uses the present-day fixed offset if the machine lacks time-zone data.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=2&lesson=03&snippet=3>)

~~~python
from datetime import date, datetime, timedelta, timezone
from zoneinfo import ZoneInfo, ZoneInfoNotFoundError

naive = datetime.strptime("2025-04-01 10:00", "%Y-%m-%d %H:%M")
print(naive.isoformat(), naive.tzinfo)
try:
    india = ZoneInfo("Asia/Kolkata")
except ZoneInfoNotFoundError:
    india = timezone(timedelta(hours=5, minutes=30))
local = naive.replace(tzinfo=india)
print(local.astimezone(timezone.utc).isoformat())
print(date(2025, 3, 31) + timedelta(days=1))
print((date(2025, 4, 28) - date(2025, 3, 12)).days)
print(local.strftime("%Y-%m"), local.weekday())
~~~

Expected output:

~~~text
2025-04-01T10:00:00 None
2025-04-01T04:30:00+00:00
2025-04-01
47
2025-04 1
~~~

Store comparable timestamps in UTC, then convert for display. Mixing naive and aware datetimes raises <code>TypeError</code>.
