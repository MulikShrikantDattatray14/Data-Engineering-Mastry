## First solve the question on one machine

For each customer, return the largest delivered order. `rank(method='dense')` keeps ties, like SQL `DENSE_RANK() = 1`. The source Spark example uses the same rule.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=06&snippet=1>)

```python
import pandas as pd

orders = pd.read_csv('python_de_dataset/orders.csv')
delivered = orders.loc[orders.status == 'delivered'].copy()
delivered['rank'] = delivered.groupby('customer_id')['amount'].rank(
    method='dense', ascending=False)
answer = delivered.loc[delivered['rank'] == 1,
                       ['customer_id', 'order_id', 'amount']]
print(answer.sort_values(['customer_id', 'order_id']).to_string(index=False))
```

**Expected:** seven customers, IDs 1–7. Their largest delivered orders are 114/2397, 111/1999, 109/747, 106/1048, 108/3498, 110/1998 and 112/846 respectively. If two delivered orders tie on amount, this rank retains both; use a second ordering key if the question wants one.

## The same window in PySpark (requires PySpark and a working local Spark runtime)

The following corresponds to the PDF's local Spark 4 example. The playground may show `ModuleNotFoundError` or a Java/Spark setup error until PySpark and its runtime are installed. `filter`, `withColumn` and `select` describe a plan; `.show()` triggers execution.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=06&snippet=2>)

```python
from pyspark.sql import SparkSession, Window, functions as F

spark = (SparkSession.builder.master('local[2]')
         .appName('orders').config('spark.ui.enabled', 'false').getOrCreate())
try:
    spark.sparkContext.setLogLevel('ERROR')
    orders = spark.read.csv('python_de_dataset/orders.csv',
                            header=True, inferSchema=True)
    window = Window.partitionBy('customer_id').orderBy(F.col('amount').desc())
    (orders.filter(F.col('status') == 'delivered')
       .withColumn('rnk', F.dense_rank().over(window))
       .filter('rnk = 1')
       .select('customer_id', 'order_id', 'amount')
       .orderBy('customer_id')
       .show())
finally:
    spark.stop()
```

**Expected Spark output:**

```text
+-----------+--------+------+
|customer_id|order_id|amount|
+-----------+--------+------+
|          1|     114|2397.0|
|          2|     111|1999.0|
|          3|     109| 747.0|
|          4|     106|1048.0|
|          5|     108|3498.0|
|          6|     110|1998.0|
|          7|     112| 846.0|
+-----------+--------+------+
```

| Task | Pandas | PySpark |
|---|---|---|
| Filter | `df[df.status == 'delivered']` | `df.filter(F.col('status') == 'delivered')` |
| New column | `df.assign(rev=df.qty * df.price)` | `df.withColumn('rev', F.col('qty') * F.col('price'))` |
| Group and sum | `df.groupby('c').agg(t=('amt','sum'))` | `df.groupBy('c').agg(F.sum('amt').alias('t'))` |
| Join | `a.merge(b, on='id', how='left')` | `a.join(b, 'id', 'left')` |
| Window rank | group + `rank` | `F.dense_rank().over(Window.partitionBy(...))` |
| Execution | Eager, local memory | Lazy plan, action such as `show`, `count`, or write |

Pandas fits one machine's memory. Spark splits data across partitions and machines; it adds shuffle and deployment costs, so data size and operational needs should drive the choice.

## Airflow describes when the pipeline runs (illustrative; requires Airflow 3 and a scheduler)

The PDF's DAG uses a **logical run date** so a later rerun for April 1 still loads April 1. It passes paths between tasks, not entire datasets. `@task(retries=3)` asks Airflow to retry a failed extract. Airflow 3 imports these decorators from `airflow.sdk`; Airflow 2 uses `airflow.decorators`. This block defines a DAG; it does not perform a real S3 read or warehouse write.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=06&snippet=3>)

```python
from airflow.sdk import dag, task
import pendulum

@dag(schedule='@daily', catchup=False, tags=['orders'],
     start_date=pendulum.datetime(2025, 4, 1, tz='Asia/Kolkata'))
def orders_daily():
    @task(retries=3)
    def extract(ds=None) -> str:
        return f's3://raw/orders/{ds}.csv'

    @task
    def transform(path: str) -> str:
        return path.replace('raw', 'clean')

    @task
    def load(path: str) -> int:
        raise NotImplementedError('Connect a warehouse MERGE here')

    load(transform(extract()))

orders_daily()
```

The placeholder load task makes the missing integration explicit. In a real DAG, use an idempotent partition overwrite or key-based merge, pass small identifiers through XCom, and log row counts. Airflow schedules and observes the job; it does not replace the transformation logic from Lesson 04.
