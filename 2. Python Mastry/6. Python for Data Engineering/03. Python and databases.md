## Step 1: bulk load, then pass values separately

`executemany` inserts the store orders into an in-memory SQLite database. A placeholder `?` sends a status as **data**. Building SQL with an f-string lets user input alter the query text.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=03&snippet=1>)

```python
import csv
import sqlite3

connection = sqlite3.connect(':memory:')
connection.execute('CREATE TABLE orders (order_id INTEGER PRIMARY KEY, '
                   'customer_id INT, order_date TEXT, status TEXT, amount REAL)')
with open('python_de_dataset/orders.csv', newline='', encoding='utf-8') as file:
    rows = [tuple(row.values()) for row in csv.DictReader(file)]
connection.executemany('INSERT INTO orders VALUES (?, ?, ?, ?, ?)', rows)
connection.commit()

query = 'SELECT COUNT(*), SUM(amount) FROM orders WHERE status = ?'
print(connection.execute(query, ('delivered',)).fetchone())

user_input = "x' OR '1'='1"
unsafe = f"SELECT COUNT(*) FROM orders WHERE status = '{user_input}'"
print('f-string:', connection.execute(unsafe).fetchone()[0], 'rows')
safe = 'SELECT COUNT(*) FROM orders WHERE status = ?'
print('param:   ', connection.execute(safe, (user_input,)).fetchone()[0], 'rows')
```

```text
(12, 18972.0)
f-string: 15 rows
param:    0 rows
```

The deliberately unsafe query is a classroom example only. In real code, always use driver parameters. SQLite uses `?`; other drivers use their documented placeholder style. A `fetchmany` loop keeps large query results out of memory.

## Step 2: a transaction rolls back as one unit

An order is inserted successfully, then another transaction updates order 101 and attempts a duplicate primary key. The second transaction fails; the status update is rolled back. After that, an upsert changes order 115.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=03&snippet=2>)

```python
import csv
import sqlite3

connection = sqlite3.connect(':memory:')
connection.execute('CREATE TABLE orders (order_id INTEGER PRIMARY KEY, '
                   'customer_id INT, order_date TEXT, status TEXT, amount REAL)')
with open('python_de_dataset/orders.csv', newline='', encoding='utf-8') as file:
    connection.executemany('INSERT INTO orders VALUES (?,?,?,?,?)',
                           (tuple(row.values()) for row in csv.DictReader(file)))
connection.commit()

with connection:
    connection.execute("INSERT INTO orders VALUES (116, 8, '2025-05-02', 'delivered', 499)")
try:
    with connection:
        connection.execute("UPDATE orders SET status = 'returned' WHERE order_id = 101")
        connection.execute("INSERT INTO orders VALUES (101, 1, '2025-01-10', 'dup', 0)")
except sqlite3.IntegrityError as error:
    print('rolled back:', error)
print(connection.execute('SELECT status FROM orders WHERE order_id = 101').fetchone())

connection.execute("INSERT INTO orders VALUES (115, 5, '2025-04-28', 'returned', 1598) "
                   'ON CONFLICT(order_id) DO UPDATE SET status = excluded.status')
print(connection.execute('SELECT order_id, status FROM orders '
                         'WHERE order_id IN (115, 116)').fetchall())
```

```text
rolled back: UNIQUE constraint failed: orders.order_id
('delivered',)
[(115, 'returned'), (116, 'delivered')]
```

`with connection:` commits on success and rolls back on an exception. `ON CONFLICT` is SQLite/PostgreSQL upsert syntax; MySQL uses `ON DUPLICATE KEY UPDATE`. Keep input values parameterized even in an upsert.

## Step 3: pandas can read and write tables

This standalone block builds a fresh in-memory database, loads the product CSV, and reads an aggregate query. It requires pandas.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=03&snippet=3>)

```python
import sqlite3
import pandas as pd

connection = sqlite3.connect(':memory:')
pd.read_csv('python_de_dataset/products.csv').to_sql('products', connection, index=False)
query = ('SELECT category, COUNT(*) AS n, MAX(price) AS top '
         'FROM products GROUP BY category ORDER BY category')
print(pd.read_sql(query, connection).to_string(index=False))
```

```text
   category  n  top
Electronics  4 1999
       Home  2 1199
 Stationery  2  249
```

For large results, iterate `cursor.fetchmany(10_000)` or `pd.read_sql(..., chunksize=...)`. A single DataFrame returned without chunks must fit in memory.
