# 02. Pandas results can be wrong without an error

**Source:** [PDF p. 70](<../Source/1793477658005.pdf#page=70>). Requires **pandas** and **NumPy** in the local Python environment.

Four habits matter here: preserve missing group keys, assign with one `.loc`, validate joins, and use column operations instead of Python loops over rows.

## Trap 1: groupby drops missing keys

Sana's city is missing. Grouping by city with the default `dropna=True` removes her order amount from the report. The grand total must reconcile to the input.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=02&snippet=1>)

```python
import json
import pandas as pd

with open('python_de_dataset/customers.json', encoding='utf-8') as file:
    customers = pd.json_normalize(json.load(file))
orders = pd.read_csv('python_de_dataset/orders.csv')
joined = orders.merge(customers[['customer_id', 'address.city']],
                      on='customer_id', validate='many_to_one')
by_city = joined.groupby('address.city')['amount'].sum()
complete = joined.groupby('address.city', dropna=False)['amount'].sum()
missing_amount = joined.loc[joined['address.city'].isna(), 'amount'].sum()
print('default grouped total:', by_city.sum())
print('input total:', joined['amount'].sum())
print('missing-city amount:', missing_amount)
print('complete total:', complete.sum())
```

```text
default grouped total: 21270.0
input total: 23268.0
missing-city amount: 1998.0
complete total: 23268.0
```

`dropna=False` keeps a missing-key group. Another choice is `fillna('Unknown')` before grouping. The code prints the missing-city amount directly from the source rows so no special NaN index lookup is needed.

## Traps 2 and 3: chained assignment and duplicate lookup keys

`frame[mask]['amount'] = 0` may update a temporary object. Select rows and column together with `.loc[mask, 'amount']`. A duplicate customer key on the right side of a merge can multiply rows; `validate='many_to_one'` exposes it.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=02&snippet=2>)

```python
import pandas as pd

frame = pd.read_csv('python_de_dataset/orders.csv')
returned = frame.status == 'returned'
temporary = frame[returned]
temporary['amount'] = 0  # changing a filtered temporary does not reliably change frame
print('original after temporary edit:', frame.loc[returned, 'amount'].tolist())
frame.loc[returned, 'amount'] = 0
print('original after .loc edit:', frame.loc[returned, 'amount'].tolist())

duplicate_lookup = pd.DataFrame({'customer_id': [1, 1], 'tier': ['gold', 'new']})
try:
    frame.merge(duplicate_lookup, on='customer_id', validate='many_to_one')
except pd.errors.MergeError:
    print('MergeError: customer lookup has duplicate keys')
```

```text
original after temporary edit: [798.0]
original after .loc edit: [0.0]
MergeError: customer lookup has duplicate keys
```

The source demonstrates a chained assignment directly; this version makes the temporary object explicit so the same lesson runs predictably across pandas versions. The `validate` check protects totals from a join fan-out.

## Speed habit: operate on columns

For `qty × price`, multiplying two full columns delegates the work to optimized array code. `apply(axis=1)` and `iterrows()` call Python for each row. The following reduced-size benchmark fits the playground's short run limit; **do not memorize the milliseconds**, which change by machine.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=02&snippet=3>)

```python
import time
import numpy as np
import pandas as pd

size = 5_000
rng = np.random.default_rng(0)
frame = pd.DataFrame({'qty': rng.integers(1, 5, size), 'price': 799.0})

def measure(action):
    start = time.perf_counter()
    result = action()
    return (time.perf_counter() - start) * 1_000, result

row_product = lambda row: row.qty * row.price
for label, action in [
    ('vectorized', lambda: frame.qty * frame.price),
    ('apply', lambda: frame.apply(row_product, axis=1)),
    ('iterrows', lambda: [row_product(row) for _, row in frame.iterrows()]),
]:
    milliseconds, values = measure(action)
    print(label, 'rows:', len(values), 'milliseconds:', round(milliseconds, 1))

statuses = pd.Series(['delivered', 'cancelled', 'returned'] * 10_000)
print('text KB:', statuses.memory_usage(deep=True) // 1024)
print('category KB:', statuses.astype('category').memory_usage(deep=True) // 1024)
```

**Expected relationship:** all three methods produce 5,000 results; vectorized is typically fastest, `iterrows` slowest. Category dtype uses less memory for the repeated statuses. The PDF benchmarks 200,000 rows and reports approximate timings on its machine; this smaller version keeps the idea interactive.

## W3Schools extension: identify four kinds of dirty data

The [W3Schools cleaning overview](https://www.w3schools.com/python/pandas/pandas_cleaning.asp) names four common issues: [empty cells](https://www.w3schools.com/python/pandas/pandas_cleaning_empty_cells.asp), [wrong formats](https://www.w3schools.com/python/pandas/pandas_cleaning_wrong_format.asp), [wrong values](https://www.w3schools.com/python/pandas/pandas_cleaning_wrong_data.asp), and [duplicates](https://www.w3schools.com/python/pandas/pandas_cleaning_duplicates.asp). The supplied dirty order file contains the first three. We add a controlled duplicate to demonstrate the fourth.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=02&snippet=4>)

```python
import pandas as pd

dirty = pd.read_csv('python_de_dataset/orders_dirty.csv')
dates = pd.to_datetime(dirty.order_date, errors='coerce')
amounts = pd.to_numeric(dirty.amount, errors='coerce')
print('missing customer IDs:', int(dirty.customer_id.isna().sum()))
print('bad date IDs:', dirty.loc[dates.isna(), 'order_id'].tolist())
print('bad amount IDs:', dirty.loc[amounts.isna() | amounts.le(0),
                                   'order_id'].tolist())

with_repeat = pd.concat([dirty, dirty.iloc[[0]]], ignore_index=True)
print('duplicate order IDs:', with_repeat.loc[
    with_repeat.duplicated(subset='order_id'), 'order_id'].tolist())
print('rows after key dedupe:', len(with_repeat.drop_duplicates(subset='order_id')))
```

```text
missing customer IDs: 1
bad date IDs: [118]
bad amount IDs: [116, 120]
duplicate order IDs: [116]
rows after key dedupe: 7
```

`errors='coerce'` turns an unparseable value into a missing marker that `isna()` can find. `dropna()` would remove a row; `fillna()` would replace a missing value. A missing customer ID should normally be quarantined rather than invented. For duplicate order IDs, define which record wins before calling `drop_duplicates`; if the newest timestamp wins, apply Part 5's P4 logic.
