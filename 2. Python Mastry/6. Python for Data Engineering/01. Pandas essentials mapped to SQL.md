**Source:** [PDF p. 69](<../Source/1793477658005.pdf#page=69>). These examples need **pandas**, installed in the local Python environment used by the playground. Pandas reads the included store files.

You already know the question shape from SQL: filter delivered orders, group by month, calculate counts and totals. Pandas changes the method names, not the underlying reasoning. A method chain reads from top to bottom like a query plan.

## Step 1: read, inspect, filter and aggregate

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=01&snippet=1>)

```python
import pandas as pd

orders = pd.read_csv('python_de_dataset/orders.csv', parse_dates=['order_date'])
print(orders.shape)
print(orders.dtypes.to_string())

monthly = (orders
    .query("status == 'delivered'")
    .assign(month=lambda frame: frame.order_date.dt.to_period('M'))
    .groupby('month', as_index=False)
    .agg(orders=('order_id', 'count'),
         revenue=('amount', 'sum'),
         avg=('amount', 'mean')))
monthly[['revenue', 'avg']] = monthly[['revenue', 'avg']].round(1)
print(monthly.to_string(index=False))
```

**Expected shape and all five column types:**

```text
(15, 5)
order_id                int64
customer_id             int64
order_date     datetime64[us]
status                    str
amount                float64
``n
The monthly delivered results are Jan **2 / 1994.0**, Feb **2 / 2847.0**, Mar **4 / 7291.0**, Apr **4 / 6840.0** (order count / revenue). Their average amounts are 997.0, 1423.5, 1822.8, and 1710.0. `parse_dates` matters: without a datetime column, `.dt.to_period('M')` fails. `agg` names each result column directly.

## Step 2: merge three tables, then pivot

`order_items` has quantities, `products` has categories, and `orders` has dates and statuses. Each item joins to one product. `validate='many_to_one'` makes pandas raise if the product lookup contains duplicate IDs, rather than quietly multiplying revenue.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=01&snippet=2>)

```python
import pandas as pd

orders = pd.read_csv('python_de_dataset/orders.csv', parse_dates=['order_date'])
items = pd.read_csv('python_de_dataset/order_items.csv')
products = pd.read_csv('python_de_dataset/products.csv')

lines = (items
    .merge(products, on='product_id', how='left', validate='many_to_one')
    .merge(orders[['order_id', 'order_date', 'status']],
           on='order_id', validate='many_to_one')
    .query("status == 'delivered'")
    .assign(revenue=lambda frame: frame.qty * frame.unit_price,
            month=lambda frame: frame.order_date.dt.month))
print(lines.pivot_table(index='category', columns='month',
                        values='revenue', aggfunc='sum', fill_value=0))
```

**Expected pivot:** Electronics: 799, 1499, 5096, 4396 across months 1–4; Home: 399, 1199, 1199, 1997; Stationery: 796, 149, 996, 447. This is the same join, group and pivot logic used in SQL. We preserve `items` with a left join to `products`, then require an order match for dated, delivered line sales.

| SQL idea | Pandas shape | Important detail |
|---|---|---|
| `WHERE status = 'delivered'` | `.query(...)` or a boolean mask | Filtering does not change the source frame by itself |
| `GROUP BY ... SUM()` | `.groupby(...).agg(total=('amount','sum'))` | Missing grouping keys drop by default; Lesson 02 fixes that |
| `JOIN ... ON` | `.merge(..., on=..., how='left')` | Use `validate` when cardinality is known |
| `SUM() OVER (PARTITION BY k)` | `.groupby(k)['amount'].transform('sum')` | `transform` keeps original rows |
| `LAG(x) OVER (...)` | sort, then `.groupby(k)['x'].shift(1)` | Sort first or previous has no useful meaning |
| `ORDER BY ... LIMIT n` | `.sort_values(...).head(n)` or `.nlargest(n, ...)` | Specify a tie rule when required |

## W3Schools extension: make a DataFrame, then read a CSV

The [W3Schools pandas introduction](https://www.w3schools.com/python/pandas/default.asp), [DataFrames lesson](https://www.w3schools.com/python/pandas/pandas_dataframes.asp), and [CSV lesson](https://www.w3schools.com/python/pandas/pandas_csv.asp) introduce tables with named columns, `.loc` selection, and `read_csv`. Try those ideas on the same store data. `.loc['second', 'amount']` uses a row **label**; `read_csv` gives a full DataFrame, while `nrows=3` lets us inspect a small sample first.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=01&snippet=3>)

```python
import pandas as pd

small = pd.DataFrame({'order_id': [101, 102], 'amount': [1198, 796]},
                     index=['first', 'second'])
print('labeled lookup:', small.loc['second', 'amount'])

orders_sample = pd.read_csv('python_de_dataset/orders.csv', nrows=3)
print('sample columns:', orders_sample.columns.tolist())
print(orders_sample[['order_id', 'amount']].to_string(index=False))
```

```text
labeled lookup: 796
sample columns: ['order_id', 'customer_id', 'order_date', 'status', 'amount']
 order_id  amount
      101  1198.0
      102   796.0
      103  1499.0
```

`to_string(index=False)` prints every selected sample row. On a large full file, start with `.head()` instead of printing the entire frame. The W3Schools examples use small generic tables; the code here applies their same operations to the supplied orders.
