# 04. Build a small ETL pipeline you can rerun

**Source:** [PDF p. 72](<../Source/1793477658005.pdf#page=72>). **ETL** means extract rows, transform values, then load them. This chapter connects the Part 5 streaming patterns to a database table.

The task is to load one requested day of orders. If the same day is run again, its rows should be replaced, not duplicated. The source uses `warehouse.db`; the runnable lesson uses an in-memory SQLite database so each playground run starts fresh. A production script can change the connection to `sqlite3.connect('warehouse.db')` and accept `--src` and `--date` from the scheduler.

## Step 1: three functions, one transaction

- `extract` yields only source rows for the requested day.
- `transform` converts IDs and amount, normalizes status, and yields database tuples.
- `load` deletes that day and inserts replacement rows **inside one transaction**. If insertion fails, the delete rolls back too.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=04&snippet=1>)

```python
import argparse
import csv
import logging
import sqlite3
import sys

logging.basicConfig(level=logging.INFO, stream=sys.stdout,
                    format='%(levelname)s %(name)s: %(message)s')
log = logging.getLogger('orders_daily')

def extract(path, day):
    with open(path, newline='', encoding='utf-8') as file:
        for row in csv.DictReader(file):
            if row['order_date'] == day:
                yield row

def transform(rows):
    for row in rows:
        yield (int(row['order_id']), int(row['customer_id']),
               row['order_date'], row['status'].strip().lower(),
               round(float(row['amount']), 2))

def load(connection, day, rows):
    with connection:
        connection.execute('DELETE FROM fact_orders WHERE order_date = ?', (day,))
        cursor = connection.executemany(
            'INSERT INTO fact_orders VALUES (?,?,?,?,?)', rows)
    return cursor.rowcount

def main(argv, connection):
    parser = argparse.ArgumentParser(description='Load one day of orders')
    parser.add_argument('--date', required=True)
    parser.add_argument('--src', default='python_de_dataset/orders.csv')
    args = parser.parse_args(argv)
    count = load(connection, args.date,
                 transform(extract(args.src, args.date)))
    total = connection.execute('SELECT COUNT(*) FROM fact_orders').fetchone()[0]
    log.info('date=%s loaded=%d table_rows=%d', args.date, count, total)

connection = sqlite3.connect(':memory:')
connection.execute('CREATE TABLE fact_orders (order_id INT PRIMARY KEY, '
                   'customer_id INT, order_date TEXT, status TEXT, amount REAL)')
main(['--date', '2025-04-20'], connection)
main(['--date', '2025-04-20'], connection)
main(['--date', '2025-04-28'], connection)
```

```text
INFO orders_daily: date=2025-04-20 loaded=1 table_rows=1
INFO orders_daily: date=2025-04-20 loaded=1 table_rows=1
INFO orders_daily: date=2025-04-28 loaded=1 table_rows=2
```

The second April 20 run still leaves one row. We use the **run date**, not `date.today()`, so a later backfill repeats the intended day. The generators keep input memory small, while `logging` adds level and job name for filtering.

## Step 2: a bad command must fail visibly

`argparse` exits with code 2 when the required date is missing. This short, standalone example catches it so the playground stays open; the actual ETL program should let its process exit nonzero for a scheduler to detect failure.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=04&snippet=2>)

```python
import argparse

parser = argparse.ArgumentParser(prog='orders_daily')
parser.add_argument('--date', required=True)
try:
    parser.parse_args([])
except SystemExit as error:
    print('bad arguments, exit code', error.code)
```

**Expected stdout:** `bad arguments, exit code 2`. `argparse` also prints usage to stderr.

| Design choice | Why it matters |
|---|---|
| Delete the selected day and insert replacements in one transaction | Reruns and backfills keep the same table; a failure cannot leave a half-loaded day |
| Extract/transform as generators | Large files do not need to be loaded into a list |
| Transform separate from I/O | You can test cleaning on a few in-memory rows |
| Log the run date, count and total | You can trace what the scheduler did |
| Exit nonzero on bad input | The scheduler can mark the task failed |

Blind append, an unstable `now()` date, and unrelated side effects inside `load` break idempotency. Another valid production method is `MERGE` on a stable order key. For very large loads, use batches; do not assume a single transaction can hold unlimited rows.
