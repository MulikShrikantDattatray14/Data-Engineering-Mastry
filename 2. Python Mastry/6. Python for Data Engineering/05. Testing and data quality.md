# 05. Test the code and check the data

**Source:** [PDF p. 73](<../Source/1793477658005.pdf#page=73>). **Unit tests** check code against known examples. **Data quality checks** examine the actual input on every pipeline run. A production pipeline needs both.

## Step 1: make a transform easy to test

The source maps alternate spellings of status to one canonical value. Amount parsing accepts commas but rejects zero and negative amounts. The first block is a normal runnable demonstration and also creates `transform.py` in the playground's temporary practice folder for the pytest block below.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=05&snippet=1>)

```python
# transform.py
STATUS = {'delivered': 'delivered', 'dlvd': 'delivered',
          'cancelled': 'cancelled', 'canceled': 'cancelled',
          'returned': 'returned'}

def normalize_status(raw):
    key = (raw or '').strip().lower()
    return STATUS.get(key, 'unknown')

def to_amount(text):
    value = float(str(text).replace(',', ''))
    if value <= 0:
        raise ValueError(f'amount must be > 0: {value}')
    return round(value, 2)

if __name__ == '__main__':
    print(normalize_status(' DLVD '), to_amount('1,198.50'))
```

```text
delivered 1198.5
```

The source's six pytest cases cover four status inputs, valid money text, and a negative amount. `parametrize` runs one test function against several rows. `pytest.raises` checks the failure path. Pytest is installed in this project's Python environment.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=05&snippet=2>)

```python
# test_transform.py
import pytest
from transform import normalize_status, to_amount

@pytest.mark.parametrize('raw, expected', [
    (' DLVD ', 'delivered'),
    ('Canceled', 'cancelled'),
    (None, 'unknown'),
    ('shipped', 'unknown'),
])
def test_normalize_status(raw, expected):
    assert normalize_status(raw) == expected

def test_amount_parses_commas():
    assert to_amount('1,198.50') == 1198.5

def test_amount_rejects_negative():
    with pytest.raises(ValueError, match='> 0'):
        to_amount('-50')

if __name__ == '__main__':
    raise SystemExit(pytest.main(['-q', __file__]))
```

**Expected:** `6 passed`. The runner copies the earlier `transform.py` example into this lesson's temporary folder. On the command line, these could also be two normal files and run with `pytest -q`.

## Step 2: check every real load

The dataset checks unique order IDs, known customers, allowed statuses, present customer IDs and positive amounts. `pd.to_numeric(..., errors='coerce')` turns a bad amount such as `abc` into a missing value, which fails the positive check.

[▶ Run and edit this example](<http://127.0.0.1:8765/?part=6&lesson=05&snippet=3>)

```python
import json
import pandas as pd

def run_checks(orders, customers):
    known = set(customers.customer_id)
    checks = {
        'order_id unique': orders.order_id.is_unique,
        'no null customer_id': orders.customer_id.notna().all(),
        'status allowed': orders.status.isin(
            ['delivered', 'cancelled', 'returned']).all(),
        'amount > 0': (pd.to_numeric(orders.amount, errors='coerce') > 0).all(),
        'customer exists': orders.customer_id.isin(known).all(),
    }
    return [name for name, passed in checks.items() if not passed]

with open('python_de_dataset/customers.json', encoding='utf-8') as file:
    customers = pd.json_normalize(json.load(file))
for filename in ['orders.csv', 'orders_dirty.csv']:
    orders = pd.read_csv('python_de_dataset/' + filename)
    failed = run_checks(orders, customers)
    print(filename, '->', 'PASS' if not failed else f'FAIL {failed}')
```

```text
orders.csv -> PASS
orders_dirty.csv -> FAIL ['no null customer_id', 'status allowed', 'amount > 0', 'customer exists']
```

The raw dirty file includes `DELIVERED `, which fails this raw status check. In a real pipeline, normalize first, then check, then load; keep a quarantine output for rejected rows as in Part 5. A failing **blocking** check should stop the load.

| Check type | Input | When it runs | Example |
|---|---|---|---|
| Unit | Fixed small values | Every commit or local run | `normalize_status(' DLVD ')` |
| Integration | Several wired steps, test file and database | Before deploy and in CI | Run ETL into temporary SQLite |
| Data quality | Actual run's records | Every pipeline run | Missing customer or invalid amount |

Libraries such as Great Expectations, Soda, pandera, and dbt tests add reporting or framework structure; the plain checks above show the essential logic.
