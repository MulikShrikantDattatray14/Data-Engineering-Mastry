# 4. SQL Report Contiguous Dates

## Question and image

**Assignment question 2.** Saved as Question 4 in this section because Questions 1 and 2 are classroom practice problems.

A system runs one independent task every day. Each task either fails or succeeds.

Write a solution to report each continuous interval of days from 2019-01-01 through 2019-12-31. Return period_state as failed or succeeded, together with the interval's start_date and end_date. Return the result ordered by start_date.

**Example 1**

Input — Failed:

| fail_date |
|---|
| 2018-12-28 |
| 2018-12-29 |
| 2019-01-04 |
| 2019-01-05 |

Input — Succeeded:

| success_date |
|---|
| 2018-12-30 |
| 2018-12-31 |
| 2019-01-01 |
| 2019-01-02 |
| 2019-01-03 |
| 2019-01-06 |

Output:

| period_state | start_date | end_date |
|---|---|---|
| succeeded | 2019-01-01 | 2019-01-03 |
| failed | 2019-01-04 | 2019-01-05 |
| succeeded | 2019-01-06 | 2019-01-06 |

**Example explanation:** Ignore the 2018 rows because the requested period begins on 2019-01-01. Tasks succeeded from January 1 through January 3, failed on January 4 and 5, then succeeded on January 6. Each uninterrupted run becomes one result row.

## My solution — SQLite

```sql
WITH daily_states AS (
    SELECT fail_date AS task_date, 'failed' AS period_state
    FROM Failed
    WHERE fail_date >= '2019-01-01'
      AND fail_date < '2020-01-01'

    UNION ALL

    SELECT success_date AS task_date, 'succeeded' AS period_state
    FROM Succeeded
    WHERE success_date >= '2019-01-01'
      AND success_date < '2020-01-01'
),
neighbor_dates AS (
    SELECT
        task_date,
        period_state,
        LAG(task_date) OVER (ORDER BY task_date) AS prev_date,
        LAG(period_state) OVER (ORDER BY task_date) AS prev_state
    FROM daily_states
),
marked_days AS (
    SELECT
        task_date,
        period_state,
        CASE
            WHEN prev_date IS NULL
              OR prev_state <> period_state
              OR task_date <> DATE(prev_date, '+1 day') THEN 1
            ELSE 0
        END AS is_start
    FROM neighbor_dates
),
grouped_days AS (
    SELECT
        task_date,
        period_state,
        SUM(is_start) OVER (
            ORDER BY task_date
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        ) AS group_id
    FROM marked_days
)
SELECT
    period_state,
    MIN(task_date) AS start_date,
    MAX(task_date) AS end_date
FROM grouped_days
GROUP BY group_id, period_state
ORDER BY start_date;
```

### Step-by-step explanation with one example

**1. Filter and combine the daily results.** The two date tables need the same columns before UNION ALL: task_date and a fixed period_state. Each branch keeps dates from 2019-01-01 through 2019-12-31. Filtering here removes the 2018 rows before we form periods.

```sql
SELECT fail_date AS task_date, 'failed' AS period_state
FROM Failed
WHERE fail_date >= '2019-01-01'
  AND fail_date < '2020-01-01'

UNION ALL

SELECT success_date AS task_date, 'succeeded' AS period_state
FROM Succeeded
WHERE success_date >= '2019-01-01'
  AND success_date < '2020-01-01'
```

The daily_states CTE contains these rows when displayed in date order:

| task_date | period_state |
|---|---|
| 2019-01-01 | succeeded |
| 2019-01-02 | succeeded |
| 2019-01-03 | succeeded |
| 2019-01-04 | failed |
| 2019-01-05 | failed |
| 2019-01-06 | succeeded |

**2. Inspect the previous row.** LAG reads the previous date and previous state when rows are ordered by task_date. The first row has no predecessor, so both values are NULL.

| task_date | period_state | prev_date | prev_state |
|---|---|---|---|
| 2019-01-01 | succeeded | NULL | NULL |
| 2019-01-02 | succeeded | 2019-01-01 | succeeded |
| 2019-01-03 | succeeded | 2019-01-02 | succeeded |
| 2019-01-04 | failed | 2019-01-03 | succeeded |
| 2019-01-05 | failed | 2019-01-04 | failed |
| 2019-01-06 | succeeded | 2019-01-05 | failed |

We also inspected the next row with LEAD while exploring the problem. In the final query, each group's latest date supplies its end_date, so the query only needs the previous row to detect starts.

**3. Mark every new period.** The CASE in marked_days returns 1 when there is no previous date, the state changed, or the current date is not the next calendar day. Otherwise it returns 0. The date-gap test is a useful guard even though the prompt says the system runs a task every day.

| task_date | period_state | Reason | is_start |
|---|---|---|---:|
| 2019-01-01 | succeeded | First 2019 row | 1 |
| 2019-01-02 | succeeded | Consecutive day, same state | 0 |
| 2019-01-03 | succeeded | Consecutive day, same state | 0 |
| 2019-01-04 | failed | State changes from succeeded | 1 |
| 2019-01-05 | failed | Consecutive day, same state | 0 |
| 2019-01-06 | succeeded | State changes from failed | 1 |

For January 4, the previous date plus one day equals January 4, but the previous state is succeeded, so January 4 still begins a new period.

**4. Give each period its own group ID.** The running SUM adds is_start from the first row through the current row. It stays unchanged within a run and increases at each new run. The explicit ROWS frame means exactly the preceding rows plus this row are included.

| task_date | period_state | is_start | Running sum | group_id |
|---|---|---:|---|---:|
| 2019-01-01 | succeeded | 1 | 1 | 1 |
| 2019-01-02 | succeeded | 0 | 1 + 0 | 1 |
| 2019-01-03 | succeeded | 0 | 1 + 0 + 0 | 1 |
| 2019-01-04 | failed | 1 | 1 + 0 + 0 + 1 | 2 |
| 2019-01-05 | failed | 0 | 1 + 0 + 0 + 1 + 0 | 2 |
| 2019-01-06 | succeeded | 1 | 1 + 0 + 0 + 1 + 0 + 1 | 3 |

**5. Turn each group into one interval.** Group by group_id and period_state. MIN(task_date) gives the first date, and MAX(task_date) gives the last date.

| group_id | period_state | start_date | end_date |
|---:|---|---|---|
| 1 | succeeded | 2019-01-01 | 2019-01-03 |
| 2 | failed | 2019-01-04 | 2019-01-05 |
| 3 | succeeded | 2019-01-06 | 2019-01-06 |

Grouping only by period_state would merge groups 1 and 3, even though a failed period separates them. The final SELECT omits group_id and sorts by start_date. A one-day run, such as January 6, has the same start_date and end_date.

## My solution — SQL Server

SQL Server uses the same CTE pattern. Its next-day calculation is `DATEADD(day, 1, prev_date)`.

```sql
;WITH daily_states AS (
    SELECT fail_date AS task_date, 'failed' AS period_state
    FROM Failed
    WHERE fail_date >= '2019-01-01'
      AND fail_date < '2020-01-01'

    UNION ALL

    SELECT success_date AS task_date, 'succeeded' AS period_state
    FROM Succeeded
    WHERE success_date >= '2019-01-01'
      AND success_date < '2020-01-01'
),
neighbor_dates AS (
    SELECT
        task_date,
        period_state,
        LAG(task_date) OVER (ORDER BY task_date) AS prev_date,
        LAG(period_state) OVER (ORDER BY task_date) AS prev_state
    FROM daily_states
),
marked_days AS (
    SELECT
        task_date,
        period_state,
        CASE
            WHEN prev_date IS NULL
              OR prev_state <> period_state
              OR task_date <> DATEADD(day, 1, prev_date) THEN 1
            ELSE 0
        END AS is_start
    FROM neighbor_dates
),
grouped_days AS (
    SELECT
        task_date,
        period_state,
        SUM(is_start) OVER (
            ORDER BY task_date
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        ) AS group_id
    FROM marked_days
)
SELECT
    period_state,
    MIN(task_date) AS start_date,
    MAX(task_date) AS end_date
FROM grouped_days
GROUP BY group_id, period_state
ORDER BY start_date;
```
