# 2. SQL Find The Subtasks That Did Not Execute

## Question and image

For each task, report the IDs of its subtasks that did not execute. Each task has subtasks numbered from 1 through `subtasks_count`. Return the rows in any order.

**Example 1**

Input — Tasks:

| task_id | subtasks_count |
|---:|---:|
| 1 | 3 |
| 2 | 2 |
| 3 | 4 |

Input — Executed:

| task_id | subtask_id |
|---:|---:|
| 1 | 2 |
| 3 | 1 |
| 3 | 2 |
| 3 | 3 |
| 3 | 4 |

Output:

| task_id | subtask_id |
|---:|---:|
| 1 | 1 |
| 1 | 3 |
| 2 | 1 |
| 2 | 2 |

**Example explanation:** Task 1 has three subtasks but only subtask 2 executed, so 1 and 3 are missing. Task 2 has no executed subtasks, so both 1 and 2 are missing. All four subtasks of task 3 executed.

## Schema

**Tasks**

| Column Name | Type |
|---|---|
| task_id | int |
| subtasks_count | int |

- `task_id` contains unique values.
- A task's subtasks are numbered 1 through `subtasks_count`.
- `subtasks_count` is between 2 and 20, inclusive.

**Executed**

| Column Name | Type |
|---|---|
| task_id | int |
| subtask_id | int |

- `(task_id, subtask_id)` is unique.
- Each row represents a subtask that executed successfully.
- Every `subtask_id` is at most its task's `subtasks_count`.
