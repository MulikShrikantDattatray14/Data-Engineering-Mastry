# 13. SQL The Most Frequently Ordered Product For Each Customer

## Question and image

**LeetCode 1596:** [The Most Frequently Ordered Products for Each Customer](https://leetcode.com/problems/the-most-frequently-ordered-products-for-each-customer/)

Find the most frequently ordered product or products for each customer who has placed at least one order. If a customer's products are tied for the highest order count, include all tied products.

Return `customer_id`, `product_id`, and `product_name`, ordered by `customer_id` and then `product_id`, both in ascending order.

## My solution — SQLite

```sql
WITH order_details AS (
    SELECT
        O.order_id,
        O.order_date,
        O.customer_id,
        C.name AS customer_name,
        O.product_id,
        P.product_name,
        P.price
    FROM Orders AS O
    INNER JOIN Customers AS C
        ON O.customer_id = C.customer_id
    INNER JOIN Products AS P
        ON O.product_id = P.product_id
),
product_counts AS (
    SELECT
        order_details.*,
        COUNT(*) OVER (
            PARTITION BY customer_id, product_id
        ) AS product_frequency
    FROM order_details
),
ranked_products AS (
    SELECT
        customer_id,
        product_id,
        product_name,
        RANK() OVER (
            PARTITION BY customer_id
            ORDER BY product_frequency DESC
        ) AS frequency_rank
    FROM product_counts
)
SELECT DISTINCT customer_id, product_id, product_name
FROM ranked_products
WHERE frequency_rank = 1
ORDER BY customer_id, product_id;
```

### Step-by-step explanation with one example

**1. Define the output and the starting rows.** One result row represents one of a customer's most frequently ordered products. Return `customer_id`, `product_id`, and `product_name`. Products tied for that customer's highest frequency must all appear, while customers with no orders must not appear. Sort by `customer_id` and then `product_id`.

The supplied example has 10 `Orders` rows, five `Customers` rows, and four `Products` rows. Each order row identifies one customer and one product. Alice (customer 1) has four orders, while John (customer 5) has none. The order dates help identify individual orders but do not change how many times a product appears.

**2. Join the orders to customer and product details.** Start with `Orders` so one intermediate row still represents one order. The two inner joins add the matching customer's name and the ordered product's name and price. The sample keeps all 10 orders because every order has matching customer and product records. John and the never-ordered hard disk do not generate order rows.

```sql
SELECT

FROM Orders AS O
INNER JOIN Customers AS C

INNER JOIN Products AS P
```

**3. Count orders for each customer–product pair.** `PARTITION BY customer_id, product_id` creates a separate counting window for each pair. `COUNT(*)` counts the order rows in that pair, so Alice's keyboard frequency is 1 and her mouse frequency is 3. The window function preserves one row per order and repeats the pair's frequency on each of those rows.

```sql
WITH order_details AS (
    SELECT
        O.order_id,
        O.order_date,
        O.customer_id,
        C.name AS customer_name,
        O.product_id,
        P.product_name,
        P.price
    FROM Orders AS O
    INNER JOIN Customers AS C
        ON O.customer_id = C.customer_id
    INNER JOIN Products AS P
        ON O.product_id = P.product_id
)
SELECT
    order_id,
    customer_id,
    product_id,
    product_name,
    COUNT(*) OVER (
        PARTITION BY customer_id, product_id
    ) AS product_frequency
FROM order_details
ORDER BY order_id;
```

| 7 | 3 | 3 | screen | 2 |
| 8 | 1 | 2 | mouse | 3 |

`PARTITION BY customer_id` alone would give Alice's total of 4 on both her keyboard and mouse rows. Adding `product_id` makes the count specific to each product. No window `ORDER BY` is needed because we want the whole pair's frequency, not a running count. The `product_counts` CTE stores all 10 rows and adds this frequency column.

**4. Rank product frequencies within each customer.** The next window partitions by `customer_id` so each customer has an independent competition among products. `ORDER BY product_frequency DESC` puts the highest frequency first. `RANK()` gives equal frequencies the same rank, retaining Bob's three products tied at frequency 1.

**5. Filter the winners and remove repeated order rows.** `WHERE frequency_rank = 1` keeps every highest-frequency product, including ties. It still leaves three identical Alice mouse rows and two identical Tom screen rows, because the earlier windows kept one row per order. `SELECT DISTINCT` reduces each repeated customer–product result to one row.
