## Question and image

**LeetCode 603:** [Consecutive Available Seats](https://leetcode.com/problems/consecutive-available-seats/)

Find every free seat that has at least one adjacent free seat in the cinema.

Return the result table ordered by seat_id in ascending order.

The test cases are generated so that more than two seats are consecutively available.

**Example 1:**

Input:

Cinema table:

| seat_id | free |
| --- | --- |
| 1 | 1 |
| 2 | 0 |
| 3 | 1 |
| 4 | 1 |
| 5 | 1 |

Output:

| seat_id |
| --- |
| 3 |
| 4 |
| 5 |

**Example explanation:** Seats 3, 4, and 5 form a consecutive run of free seats. Seat 1 is free, but its neighboring seat 2 is occupied, so seat 1 is not in the result.

## My solution — SQLite

```sql
WITH neighbors AS (
    SELECT
        seat_id,
        free,
        LAG(seat_id) OVER (ORDER BY seat_id) AS prev_seat_id,
        LAG(free) OVER (ORDER BY seat_id) AS prev_free,
        LEAD(seat_id) OVER (ORDER BY seat_id) AS next_seat_id,
        LEAD(free) OVER (ORDER BY seat_id) AS next_free
    FROM Cinema
),
classified AS (
    SELECT
        seat_id,
        CASE
            WHEN free = 1 AND (
                (prev_free = 1 AND prev_seat_id = seat_id - 1)
                OR
                (next_free = 1 AND next_seat_id = seat_id + 1)
            )
            THEN 'IN'
            ELSE 'OUT'
        END AS seat_status
    FROM neighbors
)
SELECT seat_id
FROM classified
WHERE seat_status = 'IN'
ORDER BY seat_id;
```

### Step-by-step explanation with one example

**1. Define the result and inspect the seats.** One result row represents a free seat with at least one free neighboring seat. The output contains only `seat_id` and must be sorted in ascending order. In the supplied sample, `free = 1` means available and `free = 0` means occupied.

```sql
SELECT seat_id, free
FROM Cinema
ORDER BY seat_id;
```

| seat_id | free |
|---:|---:|
| 1 | 1 |
| 2 | 0 |
| 3 | 1 |
| 4 | 1 |
| 5 | 1 |

Seat 1 is free but isolated. Seats 3, 4, and 5 form a run of free seats. We will carry these same five rows through every stage.

**2. Attach the previous and next seat information.** `LAG` reads the preceding row and `LEAD` reads the following row after `ORDER BY seat_id`. Each function is used for both `seat_id` and `free`, so we can check the neighbor's availability and its actual ID. This window calculation keeps all five original rows.

```sql
SELECT
    seat_id,
    free,
    LAG(seat_id) OVER (ORDER BY seat_id) AS prev_seat_id,
    LAG(free) OVER (ORDER BY seat_id) AS prev_free,
    LEAD(seat_id) OVER (ORDER BY seat_id) AS next_seat_id,
    LEAD(free) OVER (ORDER BY seat_id) AS next_free
FROM Cinema
ORDER BY seat_id;
```

| seat_id | free | prev_seat_id | prev_free | next_seat_id | next_free |
|---:|---:|---:|---:|---:|---:|
| 1 | 1 | NULL | NULL | 2 | 0 |
| 2 | 0 | 1 | 1 | 3 | 1 |
| 3 | 1 | 2 | 0 | 4 | 1 |
| 4 | 1 | 3 | 1 | 5 | 1 |
| 5 | 1 | 4 | 1 | NULL | NULL |

The first row has no previous row, so its `LAG` values are `NULL`. The last row has no following row, so its `LEAD` values are `NULL`. The window's `ORDER BY` determines which rows these functions read; the outer `ORDER BY` displays the intermediate result in seat order.

**3. Label each seat `IN` or `OUT`.** The seat itself must be free. It then qualifies if its previous seat is free with ID `seat_id - 1`, **or** its next seat is free with ID `seat_id + 1`. Checking the ID difference matters because adjacent rows in sorted data are not necessarily seats with consecutive IDs. This calculation uses columns produced by `neighbors`, so it belongs in a later query stage.

```sql
WITH neighbors AS (
    SELECT
        seat_id,
        free,
        LAG(seat_id) OVER (ORDER BY seat_id) AS prev_seat_id,
        LAG(free) OVER (ORDER BY seat_id) AS prev_free,
        LEAD(seat_id) OVER (ORDER BY seat_id) AS next_seat_id,
        LEAD(free) OVER (ORDER BY seat_id) AS next_free
    FROM Cinema
)
SELECT
    seat_id,
    free,
    prev_seat_id,
    prev_free,
    next_seat_id,
    next_free,
    CASE
        WHEN free = 1 AND (
            (prev_free = 1 AND prev_seat_id = seat_id - 1)
            OR
            (next_free = 1 AND next_seat_id = seat_id + 1)
        )
        THEN 'IN'
        ELSE 'OUT'
    END AS seat_status
FROM neighbors
ORDER BY seat_id;
```

| seat_id | free | prev_seat_id | prev_free | next_seat_id | next_free | seat_status |
|---:|---:|---:|---:|---:|---:|:---|
| 1 | 1 | NULL | NULL | 2 | 0 | OUT |
| 2 | 0 | 1 | 1 | 3 | 1 | OUT |
| 3 | 1 | 2 | 0 | 4 | 1 | IN |
| 4 | 1 | 3 | 1 | 5 | 1 | IN |
| 5 | 1 | 4 | 1 | NULL | NULL | IN |

Seat 2 has free neighbors but is occupied itself, so it is `OUT`. Seat 3 qualifies through seat 4; seat 4 qualifies through seats 3 and 5; seat 5 qualifies through seat 4 even though its next seat is `NULL`. If seat IDs had a gap, the numeric ID checks would prevent two nonadjacent IDs from qualifying merely because they are neighboring rows.

**4. Keep only the qualifying IDs.** The `classified` CTE stores the `seat_status` values. The outer query can then filter on that completed column and return only the requested `seat_id`.

```sql
WITH neighbors AS (
    SELECT
        seat_id,
        free,
        LAG(seat_id) OVER (ORDER BY seat_id) AS prev_seat_id,
        LAG(free) OVER (ORDER BY seat_id) AS prev_free,
        LEAD(seat_id) OVER (ORDER BY seat_id) AS next_seat_id,
        LEAD(free) OVER (ORDER BY seat_id) AS next_free
    FROM Cinema
),
classified AS (
    SELECT
        seat_id,
        CASE
            WHEN free = 1 AND (
                (prev_free = 1 AND prev_seat_id = seat_id - 1)
                OR
                (next_free = 1 AND next_seat_id = seat_id + 1)
            )
            THEN 'IN'
            ELSE 'OUT'
        END AS seat_status
    FROM neighbors
)
SELECT seat_id
FROM classified
WHERE seat_status = 'IN'
ORDER BY seat_id;
```

| seat_id |
|---:|
| 3 |
| 4 |
| 5 |

**5. Check the sample.** The input has five seats. Classification keeps three `IN` rows, and the final query returns their IDs in the required ascending order. That matches the supplied output. The rule asks for every free seat in an adjacent free pair or longer run, so checking both sides includes the end seats of a run.
