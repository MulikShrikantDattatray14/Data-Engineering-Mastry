# 2. SQL Restaurant Growth

## Question and image

[**1321. Restaurant Growth**](https://leetcode.com/problems/restaurant-growth/)

A restaurant has at least one customer visit every day. For each day with a complete **seven-day window** (the current day and the preceding six days), report:

- `visited_on`: the current day;
- `amount`: total amount paid during those seven days;
- `average_amount`: that seven-day total divided by 7, rounded to two decimal places.

Return rows in ascending `visited_on` order. Multiple customers may visit on the same date.

**Example 1 — input:**

Customer:

| customer_id | name | visited_on | amount |
|---:|---|---|---:|
| 1 | Jhon | 2019-01-01 | 100 |
| 2 | Daniel | 2019-01-02 | 110 |
| 3 | Jade | 2019-01-03 | 120 |
| 4 | Khaled | 2019-01-04 | 130 |
| 5 | Winston | 2019-01-05 | 110 |
| 6 | Elvis | 2019-01-06 | 140 |
| 7 | Anna | 2019-01-07 | 150 |
| 8 | Maria | 2019-01-08 | 80 |
| 9 | Jaze | 2019-01-09 | 110 |
| 1 | Jhon | 2019-01-10 | 130 |
| 3 | Jade | 2019-01-10 | 150 |

**Output:**

| visited_on | amount | average_amount |
|---|---:|---:|
| 2019-01-07 | 860 | 122.86 |
| 2019-01-08 | 840 | 120.00 |
| 2019-01-09 | 840 | 120.00 |
| 2019-01-10 | 1000 | 142.86 |

**Explanation:** Each output date covers that day and the six calendar days before it. The `amount` is the sum of every customer payment in that window; `average_amount` is that sum divided by 7.

| Output date | Seven-day window | Payments included | `amount` | `average_amount` |
|---|---|---|---:|---:|
| 2019-01-07 | Jan 1–7 | 100 + 110 + 120 + 130 + 110 + 140 + 150 | 860 | 860 ÷ 7 = 122.86 |
| 2019-01-08 | Jan 2–8 | 110 + 120 + 130 + 110 + 140 + 150 + 80 | 840 | 840 ÷ 7 = 120.00 |
| 2019-01-09 | Jan 3–9 | 120 + 130 + 110 + 140 + 150 + 80 + 110 | 840 | 840 ÷ 7 = 120.00 |
| 2019-01-10 | Jan 4–10 | 130 + 110 + 140 + 150 + 80 + 110 + 130 + 150 | 1,000 | 1,000 ÷ 7 = 142.86 |

January 10 has two customer payments, so both count in the last seven-day window.

## My solution — SQLite

Your final solution groups visits by date before applying a seven-row window to those daily totals.

```sql
WITH daily AS (
    SELECT
        visited_on,
        SUM(amount) AS daily_amount
    FROM Customer
    GROUP BY visited_on
),
seven_day_totals AS (
    SELECT
        visited_on,
        SUM(daily_amount) OVER (
            ORDER BY visited_on
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        ) AS seven_day_amount,
        COUNT(*) OVER (
            ORDER BY visited_on
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        ) AS days_in_window
    FROM daily
)
SELECT
    visited_on,
    seven_day_amount AS amount,
    ROUND(seven_day_amount / 7.0, 2) AS average_amount
FROM seven_day_totals
WHERE days_in_window = 7
ORDER BY visited_on;
```

### Step-by-step explanation with one example

**1. Start with the visit rows.** In the supplied `Customer` example, January 10 has two visits, so a row in `Customer` is a customer payment, not necessarily a whole day. These are the input dates and amounts used below:

| visited_on | amount |
| --- | ---: |
| 2019-01-01 | 100 |
| 2019-01-02 | 110 |
| 2019-01-03 | 120 |
| 2019-01-04 | 130 |
| 2019-01-05 | 110 |
| 2019-01-06 | 140 |
| 2019-01-07 | 150 |
| 2019-01-08 | 80 |
| 2019-01-09 | 110 |
| 2019-01-10 | 130 |
| 2019-01-10 | 150 |

**2. Make one row per date.** `GROUP BY visited_on` combines all customer payments on the same date. This is necessary before using a `ROWS` window: on raw `Customer`, seven rows could mean seven visits rather than seven days.

```sql
SELECT
    visited_on,
    SUM(amount) AS daily_amount
FROM Customer
GROUP BY visited_on
ORDER BY visited_on;
```

| visited_on | daily_amount |
| --- | ---: |
| 2019-01-01 | 100 |
| 2019-01-02 | 110 |
| 2019-01-03 | 120 |
| 2019-01-04 | 130 |
| 2019-01-05 | 110 |
| 2019-01-06 | 140 |
| 2019-01-07 | 150 |
| 2019-01-08 | 80 |
| 2019-01-09 | 110 |
| 2019-01-10 | 280 |

The January 10 row is `130 + 150 = 280`. The `ORDER BY` here is only for displaying this intermediate table; the window query specifies its own ordering.

**3. Calculate the moving total and the number of days present.** In the `seven_day_totals` CTE, `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW` covers the current daily row and up to six earlier daily rows. `SUM(daily_amount)` adds their payments; `COUNT(*)` counts how many daily rows are actually in that frame. The `ORDER BY visited_on` inside each `OVER` makes the frame move chronologically. Because the question guarantees a visit every day, seven daily rows form seven consecutive calendar days.

```sql
WITH daily AS (
    SELECT visited_on, SUM(amount) AS daily_amount
    FROM Customer
    GROUP BY visited_on
)
SELECT
    visited_on,
    SUM(daily_amount) OVER (
        ORDER BY visited_on
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS seven_day_amount,
    COUNT(*) OVER (
        ORDER BY visited_on
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS days_in_window
FROM daily
ORDER BY visited_on;
```

| visited_on | seven_day_amount | days_in_window |
| --- | ---: | ---: |
| 2019-01-01 | 100 | 1 |
| 2019-01-02 | 210 | 2 |
| 2019-01-03 | 330 | 3 |
| 2019-01-04 | 460 | 4 |
| 2019-01-05 | 570 | 5 |
| 2019-01-06 | 710 | 6 |
| 2019-01-07 | 860 | 7 |
| 2019-01-08 | 840 | 7 |
| 2019-01-09 | 840 | 7 |
| 2019-01-10 | 1000 | 7 |

For January 7, the sum is `100 + 110 + 120 + 130 + 110 + 140 + 150 = 860`. For January 8, the frame drops January 1 and adds January 8: `860 - 100 + 80 = 840`. For January 10, it includes the daily amount 280, which already contains both customer payments.

**4. Keep only complete seven-day windows.** The first six rows have totals, but their frames contain fewer than seven days; they are not `NULL`. The outer query filters `days_in_window = 7` after both window calculations are complete. Filtering those early days before the window calculation would remove amounts needed for January 7.

| visited_on | seven_day_amount | days_in_window |
| --- | ---: | ---: |
| 2019-01-07 | 860 | 7 |
| 2019-01-08 | 840 | 7 |
| 2019-01-09 | 840 | 7 |
| 2019-01-10 | 1000 | 7 |

**5. Compute the average and final order.** The final `SELECT` renames the seven-day total to `amount`, divides it by `7.0` for decimal arithmetic, and rounds the result to two decimal places. `ORDER BY visited_on` controls the order of the final result.

| visited_on | amount | average_amount |
| --- | ---: | ---: |
| 2019-01-07 | 860 | 122.86 |
| 2019-01-08 | 840 | 120.00 |
| 2019-01-09 | 840 | 120.00 |
| 2019-01-10 | 1000 | 142.86 |

**Manual check:** January 10 covers January 4–10: `130 + 110 + 140 + 150 + 80 + 110 + 280 = 1000`. Its average is `ROUND(1000 / 7.0, 2) = 142.86`. The complete query above produced these four rows on the sample in SQLite.

## My solution — SQL Server

```sql
WITH daily AS (
    SELECT
        visited_on,
        SUM(amount) AS daily_amount
    FROM Customer
    GROUP BY visited_on
),
seven_day_totals AS (
    SELECT
        visited_on,
        SUM(daily_amount) OVER (
            ORDER BY visited_on
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        ) AS seven_day_amount,
        COUNT(*) OVER (
            ORDER BY visited_on

    visited_on,
```
