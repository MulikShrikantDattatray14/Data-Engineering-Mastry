**LeetCode 1077:** [Project Employees III](https://leetcode.com/problems/project-employees-iii/)

Report the most experienced employee or employees in each project. If multiple employees on a project share the highest number of experience years, include all of them.

Return the result ordered by `project_id` in ascending order, then `employee_id` in ascending order.

**Example 1:**

Input — Project:

| project_id | employee_id |
| ---: | ---: |
| 1 | 1 |
| 1 | 2 |
| 1 | 3 |
| 2 | 1 |
| 2 | 4 |

Input — Employee:

| employee_id | name | experience_years |
| ---: | --- | ---: |
| 1 | Khaled | 3 |
| 2 | Ali | 2 |
| 3 | John | 3 |
| 4 | Doe | 2 |

Output:

| project_id | employee_id |
| ---: | ---: |
| 1 | 1 |
| 1 | 3 |
| 2 | 1 |

**Example explanation:** On project 1, employees 1 and 3 each have the maximum experience of 3 years, so both appear. On project 2, employee 1 has 3 years and employee 4 has 2 years, so only employee 1 appears.

## Schema

- `employee_id` references `Employee.employee_id`.
- Each row assigns an employee to a project.

**Employee**

- `employee_id` is the primary key.
- Each row describes one employee.

## My solution — SQLite

```sql
WITH joined_employees AS (
    SELECT
        P.project_id,
        P.employee_id,
        E.experience_years
    FROM Project AS P
    INNER JOIN Employee AS E
        ON P.employee_id = E.employee_id
),
ranked_employees AS (
    SELECT
        project_id,
        employee_id,
        experience_years,
        RANK() OVER (
            PARTITION BY project_id
            ORDER BY experience_years DESC
        ) AS experience_rank
    FROM joined_employees
)
SELECT project_id, employee_id
FROM ranked_employees
WHERE experience_rank = 1
ORDER BY project_id ASC, employee_id ASC;
```

### Step-by-step explanation with one example

**1. Define the output and inspect both inputs.** One output row represents an employee with the highest experience on a particular project. Return `project_id` and `employee_id`. If several employees share that highest experience, return every tied employee. Sort first by `project_id` and then by `employee_id`, both ascending.

`Project` has one row per project and employee assignment:

```sql
SELECT project_id, employee_id
FROM Project
ORDER BY project_id, employee_id;
```

| project_id | employee_id |
|---:|---:|
| 1 | 1 |
| 1 | 2 |
| 1 | 3 |
| 2 | 1 |
| 2 | 4 |

`Employee` supplies each assigned employee's experience:

```sql
SELECT employee_id, name, experience_years
FROM Employee
ORDER BY employee_id;
```

| employee_id | name | experience_years |
|---:|---|---:|
| 1 | Khaled | 3 |
| 2 | Ali | 2 |
| 3 | John | 3 |
| 4 | Doe | 2 |

Employee 1 appears on two projects in `Project`. These are two distinct assignments, so that employee must be considered separately within each project.

**2. Join each assignment to its experience.** `Project.employee_id` links to the unique `Employee.employee_id`. The inner join gives one row per assignment, now with `experience_years` available for comparison. All five sample assignments find matching employees.

```sql
SELECT
    P.project_id,
    P.employee_id,
    E.experience_years
FROM Project AS P
INNER JOIN Employee AS E
    ON P.employee_id = E.employee_id
ORDER BY P.project_id, P.employee_id;
```

| project_id | employee_id | experience_years |
|---:|---:|---:|
| 1 | 1 | 3 |
| 1 | 2 | 2 |
| 1 | 3 | 3 |
| 2 | 1 | 3 |
| 2 | 4 | 2 |

The first CTE, `joined_employees`, stores these same three columns. A row still represents one project and employee assignment; grouping has not removed any employees.

**3. Rank experience separately for each project.** `PARTITION BY project_id` restarts the ranking for project 1 and project 2. `ORDER BY experience_years DESC` gives the largest number of years rank 1. `RANK()` assigns equal years the same rank, so Khaled and John both rank 1 on project 1.

```sql
WITH joined_employees AS (
    SELECT
        P.project_id,
        P.employee_id,
        E.experience_years
    FROM Project AS P
    INNER JOIN Employee AS E
        ON P.employee_id = E.employee_id
)
SELECT
    project_id,
    employee_id,
    experience_years,
    RANK() OVER (
        PARTITION BY project_id
        ORDER BY experience_years DESC
    ) AS experience_rank
FROM joined_employees
ORDER BY project_id, experience_years DESC, employee_id;
```

| project_id | employee_id | experience_years | experience_rank |
|---:|---:|---:|---:|
| 1 | 1 | 3 | 1 |
| 1 | 3 | 3 | 1 |
| 1 | 2 | 2 | 3 |
| 2 | 1 | 3 | 1 |
| 2 | 4 | 2 | 2 |

On project 1, two employees share rank 1, so the next rank is 3. That gap is normal for `RANK()` and does not affect a filter for rank 1. Employee 1 is ranked again within project 2 and receives rank 1 there too. The second CTE, `ranked_employees`, keeps all five joined rows and adds `experience_rank`.

**4. Keep only rank 1 and assemble the final query.** The outer query can filter `experience_rank` after the window calculation has been completed in the second CTE. It selects only the requested IDs and applies the required sort.

