# 5. SQL Friend Requests Ii Who Has The Most Friends

## Question and image

**5. Sql Friend Requests Ii Who Has The Most Friends**

Table: RequestAccepted

| Column Name | Type |
|---|---|
| requester_id | int |
| accepter_id | int |
| accept_date | date |

(requester_id, accepter_id) is the primary key (combination of columns with unique values) for this table.

This table contains the ID of the user who sent the request, the ID of the user who received the request, and the date when the request was accepted.

Write a solution to find the people who have the most friends and the most friends number.

The test cases are such that only one person has the most friends.

**Example 1:**

Example:

Input:

RequestAccepted table:

| requester_id | accepter_id | accept_date |
|---|---|---|
| 1 | 2 | 2016/06/03 |
| 1 | 3 | 2016/06/08 |
| 2 | 3 | 2016/06/08 |
| 3 | 4 | 2016/06/09 |

Output:

| id | num |
|---|---|
| 3 | 3 |

Explanation:

The person with id 3 is a friend of people 1, 2, and 4, so he has three friends in total, which is the most number than any others.

## My solution — SQLite

### Using joins

Requires [SQLite 3.39 or later](https://www.sqlite.org/releaselog/3_39_0.html). The current practice platform rejects FULL OUTER JOIN; use the UNION ALL version below on that platform.

```sql
SELECT
    COALESCE(r.requester_id, a.accepter_id) AS id,
    COALESCE(r.requester_count, 0)
        + COALESCE(a.accepter_count, 0) AS num
FROM (
    SELECT
        requester_id,
        COUNT(requester_id) AS requester_count
    FROM RequestAccepted
    GROUP BY requester_id
) AS r
FULL OUTER JOIN (
    SELECT
        accepter_id,
        COUNT(accepter_id) AS accepter_count
    FROM RequestAccepted
    GROUP BY accepter_id
) AS a
    ON r.requester_id = a.accepter_id
ORDER BY num DESC
LIMIT 1;
```

### Using UNION ALL

```sql
SELECT
    id,
    SUM(friend_count) AS num
FROM (
    SELECT
        requester_id AS id,
        COUNT(requester_id) AS friend_count
    FROM RequestAccepted
    GROUP BY requester_id

    UNION ALL

    SELECT
        accepter_id AS id,
        COUNT(accepter_id) AS friend_count
    FROM RequestAccepted
    GROUP BY accepter_id
) AS friend_counts
GROUP BY id
ORDER BY num DESC
LIMIT 1;
```

### Step-by-step explanation with one example

We need the ID of the one person with the most friends and that person's friend count. Use the supplied RequestAccepted rows throughout. Each accepted request contributes one friendship to its requester and one to its accepter. Both saved approaches begin by counting those two roles separately.

**Starting data**

`RequestAccepted`:

| requester_id | accepter_id | accept_date |
| --- | --- | --- |
| 1 | 2 | 2016/06/03 |
| 1 | 3 | 2016/06/08 |
| 2 | 3 | 2016/06/08 |
| 3 | 4 | 2016/06/09 |

**1. Count friendships where a person is the requester**

Group by requester_id so each person gets one count for the requests they sent and had accepted.

```sql
SELECT requester_id, COUNT(requester_id) AS requester_count
FROM RequestAccepted
GROUP BY requester_id
ORDER BY requester_id;
```

Result:

| requester_id | requester_count |
| --- | --- |
| 1 | 2 |
| 2 | 1 |
| 3 | 1 |

Person 1 sent two accepted requests; persons 2 and 3 sent one each. Person 4 has no requester row.

**2. Count friendships where a person is the accepter**

Group by accepter_id to count accepted requests received by each person. This is a second contribution to the same person's total.

```sql
SELECT accepter_id, COUNT(accepter_id) AS accepter_count
FROM RequestAccepted
GROUP BY accepter_id
ORDER BY accepter_id;
```

Result:

| accepter_id | accepter_count |
| --- | --- |
| 2 | 1 |
| 3 | 2 |
| 4 | 1 |

Person 2 received one request, person 3 received two, and person 4 received one. Person 1 has no accepter row.

**3. Join the two role summaries while preserving unmatched IDs**

For the saved join approach, FULL OUTER JOIN combines matching person IDs and retains people appearing on only one side. Display the raw counts first to see where NULLs appear.

```sql
SELECT r.requester_id, r.requester_count,
       a.accepter_id, a.accepter_count
FROM (
    SELECT requester_id, COUNT(requester_id) AS requester_count
    FROM RequestAccepted
    GROUP BY requester_id
) AS r
FULL OUTER JOIN (
    SELECT accepter_id, COUNT(accepter_id) AS accepter_count
    FROM RequestAccepted
    GROUP BY accepter_id
) AS a ON r.requester_id = a.accepter_id
ORDER BY COALESCE(r.requester_id, a.accepter_id);
```

Result:

| requester_id | requester_count | accepter_id | accepter_count |
| --- | --- | --- | --- |
| 1 | 2 | NULL | NULL |
| 2 | 1 | 2 | 1 |
| 3 | 1 | 3 | 2 |
| NULL | NULL | 4 | 1 |

Person 1 has NULL accepter columns, and person 4 has NULL requester columns. An inner join would drop those people. A missing role means zero friendships in that role, not an unknown final total.

**4. Turn missing counts into zero and add the two roles**

COALESCE(r.requester_id, a.accepter_id) chooses whichever ID exists. COALESCE(count, 0) makes the addition work when one summary row is absent: a number plus NULL would otherwise produce NULL.

```sql
SELECT COALESCE(r.requester_id, a.accepter_id) AS id,
       COALESCE(r.requester_count, 0)
       + COALESCE(a.accepter_count, 0) AS num
FROM (
    SELECT requester_id, COUNT(requester_id) AS requester_count
    FROM RequestAccepted
    GROUP BY requester_id
) AS r
FULL OUTER JOIN (
    SELECT accepter_id, COUNT(accepter_id) AS accepter_count
    FROM RequestAccepted
    GROUP BY accepter_id
) AS a ON r.requester_id = a.accepter_id
ORDER BY id;
```

Result:

| id | num |
| --- | --- |
| 1 | 2 |
| 2 | 2 |
| 3 | 3 |
| 4 | 1 |

The totals are 2 for person 1, 2 for person 2, 3 for person 3, and 1 for person 4. Sorting by num descending and taking one row will select person 3.

**5. Alternatively stack the two grouped role counts**

The saved UNION ALL approach puts both role summaries into the same columns, id and friend_count. It preserves every contribution instead of joining them side by side.

```sql
SELECT requester_id AS id, COUNT(requester_id) AS friend_count
FROM RequestAccepted
GROUP BY requester_id
UNION ALL
SELECT accepter_id AS id, COUNT(accepter_id) AS friend_count
FROM RequestAccepted
GROUP BY accepter_id;
```

Result:

| id | friend_count |
| --- | --- |
| 1 | 2 |
| 2 | 1 |
| 3 | 1 |
| 2 | 1 |
| 3 | 2 |
| 4 | 1 |

Person 2 appears twice with friend_count 1. UNION ALL must retain both identical (2, 1) rows so that person 2's total is 2. UNION could remove one and undercount.

**6. Sum the stacked counts for each person**

A second GROUP BY id brings together a person's requester and accepter counts. SUM(friend_count) adds the available contributions; people with only one role still have one row to sum.

```sql
SELECT id, SUM(friend_count) AS num
FROM (
    SELECT requester_id AS id, COUNT(requester_id) AS friend_count
    FROM RequestAccepted
    GROUP BY requester_id
    UNION ALL
    SELECT accepter_id AS id, COUNT(accepter_id) AS friend_count
    FROM RequestAccepted
    GROUP BY accepter_id
) AS friend_counts
GROUP BY id
ORDER BY id;
```

Result:

| id | num |
| --- | --- |
| 1 | 2 |
| 2 | 2 |
| 3 | 3 |
| 4 | 1 |

This produces the same four totals as the full-join approach. The remaining operation is to rank totals and retain the largest one.

**7. Assemble the saved join solution**

Keep the full join and COALESCE expressions, then ORDER BY num DESC and LIMIT 1. The unique-winner guarantee removes the need for a tie-break.

```sql
SELECT
    COALESCE(r.requester_id, a.accepter_id) AS id,
    COALESCE(r.requester_count, 0)
        + COALESCE(a.accepter_count, 0) AS num
FROM (
    SELECT
        requester_id,
        COUNT(requester_id) AS requester_count
    FROM RequestAccepted
    GROUP BY requester_id
) AS r
FULL OUTER JOIN (
    SELECT
        accepter_id,
        COUNT(accepter_id) AS accepter_count
    FROM RequestAccepted
    GROUP BY accepter_id
) AS a
    ON r.requester_id = a.accepter_id
ORDER BY num DESC
LIMIT 1;
```

Final result for this example:

| id | num |
| --- | --- |
| 3 | 3 |

This form runs in the local modern SQLite used for the walkthrough. The current practice platform previously rejected FULL OUTER JOIN, as documented above.

**8. Assemble the saved UNION ALL solution**

Keep both grouped role counts with UNION ALL, sum by id, then return the largest total. This is the saved alternative for the older practice platform.

```sql
SELECT
    id,
    SUM(friend_count) AS num
FROM (
    SELECT
        requester_id AS id,
        COUNT(requester_id) AS friend_count
    FROM RequestAccepted
    GROUP BY requester_id

    UNION ALL

    SELECT
        accepter_id AS id,
        COUNT(accepter_id) AS friend_count
    FROM RequestAccepted
    GROUP BY accepter_id
) AS friend_counts
GROUP BY id
ORDER BY num DESC
LIMIT 1;
```

Final result for this example:

| id | num |
| --- | --- |
| 3 | 3 |

**Check the result:** Manual check: person 1 is friends with 2 and 3; person 2 with 1 and 3; person 3 with 1, 2, and 4; person 4 with 3. Person 3 has the unique maximum of three friends.
