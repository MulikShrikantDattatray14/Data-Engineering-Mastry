# 11. SQL Friendly Movies Streamed Last Month

## Question and image

**11. Sql Friendly Movies Streamed Last Month**

Table: TVProgram

| Column Name | Type |
|---|---|
| program_date | date |
| content_id | int |
| channel | varchar |

`(program_date, content_id)` is the primary key (combination of columns with unique values) for this table.

This table contains information of the programs on the TV.

`content_id` is the id of the program in some channel on the TV.

Table: Content

| Column Name | Type |
|---|---|
| content_id | varchar |
| title | varchar |
| Kids_content | enum |
| content_type | varchar |

`content_id` is the primary key (column with unique values) for this table.

`Kids_content` is an ENUM (category) of types (`'Y'`, `'N'`) where:

`'Y'` means is content for kids otherwise `'N'` is not content for kids.

`content_type` is the category of the content as movies, series, etc.

Write a solution to report the distinct titles of the kid-friendly movies streamed in June 2020.

The result table format is in following example.

## My solution — SQLite

### Primary solution — half-open date range

```sql
SELECT DISTINCT
    C.title AS title
FROM TVProgram AS T
JOIN Content AS C
    ON T.content_id = C.content_id
WHERE C.Kids_content = 'Y'
  AND C.content_type = 'Movies'
  AND T.program_date >= '2020-06-01'
  AND T.program_date < '2020-07-01'
ORDER BY C.title ASC;
```

### Alternative 1 — SQLite `STRFTIME()`

```sql
SELECT DISTINCT
    C.title AS title
FROM TVProgram AS T
JOIN Content AS C
    ON T.content_id = C.content_id
WHERE C.Kids_content = 'Y'
  AND C.content_type = 'Movies'
  AND STRFTIME('%Y-%m', T.program_date) = '2020-06'
ORDER BY C.title ASC;
```

### Alternative 2 — timestamp-prefix matching

```sql
SELECT DISTINCT
    C.title AS title
FROM TVProgram AS T
JOIN Content AS C
    ON T.content_id = C.content_id
WHERE C.Kids_content = 'Y'
  AND C.content_type = 'Movies'
  AND T.program_date LIKE '2020-06-%'
ORDER BY C.title ASC;
```

### Key learnings

- `DISTINCT` ensures that a qualifying title appears once even when the movie was streamed multiple times.
- Joining on `content_id` connects each scheduled program to its title and content classifications.
- `Kids_content = 'Y'` and `content_type = 'Movies'` keep only kid-friendly movies.
- The half-open range `>= '2020-06-01' AND < '2020-07-01'` includes every June timestamp, including all times on June 30.
- `STRFTIME('%Y-%m', program_date) = '2020-06'` explicitly extracts the year and month in SQLite.
- `program_date LIKE '2020-06-%'` matches the supplied ISO-style timestamp representation directly.
- The practice platform returned `4/5` for all three logically equivalent SQLite date filters. No failing test details were provided, so the remaining discrepancy could not be identified from the stated requirements.

### Step-by-step explanation with one example

We need distinct movie titles that are kid-friendly and were streamed in June 2020. Use the supplied TVProgram and Content rows for every step and all three saved date-filter variants.

**Starting data**

`TVProgram`:

| program_date | content_id | channel |
| --- | --- | --- |
| 2020-06-10 08:00 | 1 | LC-Channel |
| 2020-05-11 12:00 | 2 | LC-Channel |
| 2020-05-12 12:00 | 3 | LC-Channel |
| 2020-05-13 14:00 | 4 | Disney Ch |
| 2020-06-18 14:00 | 4 | Disney Ch |
| 2020-07-15 16:00 | 5 | Disney Ch |

`Content`:

| content_id | title | Kids_content | content_type |
| --- | --- | --- | --- |
| 1 | Leetcode Movie | N | Movies |
| 2 | Alg. for Kids | Y | Series |
| 3 | Database Sols | N | Series |
| 4 | Aladdin | Y | Movies |
| 5 | Cinderella | Y | Movies |

**1. Attach content details to every scheduled program**

TVProgram tells us when something aired. Content tells us its title, whether it is for kids, and its content type. Join using content_id.

```sql
SELECT T.program_date, T.content_id, C.title, C.Kids_content, C.content_type
FROM TVProgram AS T
JOIN Content AS C ON T.content_id = C.content_id
ORDER BY T.program_date;
```

Result:

| program_date | content_id | title | Kids_content | content_type |
| --- | --- | --- | --- | --- |
| 2020-05-11 12:00 | 2 | Alg. for Kids | Y | Series |
| 2020-05-12 12:00 | 3 | Database Sols | N | Series |
| 2020-05-13 14:00 | 4 | Aladdin | Y | Movies |
| 2020-06-10 08:00 | 1 | Leetcode Movie | N | Movies |
| 2020-06-18 14:00 | 4 | Aladdin | Y | Movies |
| 2020-07-15 16:00 | 5 | Cinderella | Y | Movies |

Aladdin appears twice because it aired in both May and June. A join preserves those two broadcast rows.

**2. Keep kid-friendly movies**

Both classification conditions must hold: Kids_content must be Y and content_type must be Movies. A kid-friendly series still fails the movie requirement.

```sql
SELECT T.program_date, C.title
FROM TVProgram AS T
JOIN Content AS C ON T.content_id = C.content_id
WHERE C.Kids_content = 'Y'
  AND C.content_type = 'Movies'
ORDER BY T.program_date;
```

Result:

| program_date | title |
| --- | --- |
| 2020-05-13 14:00 | Aladdin |
| 2020-06-18 14:00 | Aladdin |
| 2020-07-15 16:00 | Cinderella |

Two Aladdin broadcasts and one Cinderella broadcast survive the content tests. Leetcode Movie fails the kids condition; the two series fail the movie condition.

**3. Keep June broadcasts**

The primary solution uses an inclusive June 1 lower bound and an exclusive July 1 upper bound. This includes every June timestamp, including times late on June 30.

```sql
SELECT T.program_date, C.title
FROM TVProgram AS T
JOIN Content AS C ON T.content_id = C.content_id
WHERE C.Kids_content = 'Y'
  AND C.content_type = 'Movies'
  AND T.program_date >= '2020-06-01'
  AND T.program_date < '2020-07-01'
ORDER BY T.program_date;
```

Result:

| program_date | title |
| --- | --- |
| 2020-06-18 14:00 | Aladdin |

Only the June 18 Aladdin broadcast remains. The May Aladdin broadcast and July Cinderella broadcast are excluded.

**4. Inspect the alternative month extraction**

STRFTIME extracts the year and month from the same timestamp values. Matching 2020-06 tests both year and month.

```sql
SELECT program_date, STRFTIME('%Y-%m', program_date) AS year_month
FROM TVProgram
ORDER BY program_date;
```

Result:

| program_date | year_month |
| --- | --- |
| 2020-05-11 12:00 | 2020-05 |
| 2020-05-12 12:00 | 2020-05 |
| 2020-05-13 14:00 | 2020-05 |
| 2020-06-10 08:00 | 2020-06 |
| 2020-06-18 14:00 | 2020-06 |
| 2020-07-15 16:00 | 2020-07 |

Both June timestamps produce 2020-06. Prefix matching with LIKE 2020-06-% selects the same month for these supplied ISO-style strings.

**5. Assemble the saved half-open range solution**

Select DISTINCT titles so repeated qualifying broadcasts do not repeat a movie title.

```sql
SELECT DISTINCT
    C.title AS title
FROM TVProgram AS T
JOIN Content AS C
    ON T.content_id = C.content_id
WHERE C.Kids_content = 'Y'
  AND C.content_type = 'Movies'
  AND T.program_date >= '2020-06-01'
  AND T.program_date < '2020-07-01'
ORDER BY C.title ASC;
```

Final result for this example:

| title |
| --- |
| Aladdin |

**6. Assemble the saved STRFTIME variant**

Keep the same joins, content filters, DISTINCT, and sorting; use the extracted year-month to select June.

```sql

    C.title AS title
```

**7. Assemble the saved timestamp-prefix variant**

For the supplied ISO-style timestamp format, the prefix 2020-06- identifies June 2020. All other saved logic remains the same.

```sql
SELECT DISTINCT
    C.title AS title
FROM TVProgram AS T
JOIN Content AS C
    ON T.content_id = C.content_id
WHERE C.Kids_content = 'Y'
  AND C.content_type = 'Movies'

```

| title |
| --- |
| Aladdin |

## My solution — SQL Server

```sql
SELECT DISTINCT
    C.title AS title
FROM TVProgram AS T
JOIN Content AS C
    ON T.content_id = C.content_id
WHERE C.Kids_content = 'Y'
  AND C.content_type = 'Movies'
  AND T.program_date >= '2020-06-01'
  AND T.program_date < '2020-07-01'
ORDER BY C.title ASC;
```

The primary half-open date-range solution works in both SQLite and SQL Server.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation.
