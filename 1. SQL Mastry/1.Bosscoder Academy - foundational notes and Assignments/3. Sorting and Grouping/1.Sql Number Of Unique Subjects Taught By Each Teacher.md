## Question and image

**1. Sql Number Of Unique Subjects Taught By Each Teacher**

Table: Teacher

| Column Name | Type |
|---|---|
| teacher_id | int |
| subject_id | int |
| dept_id | int |

`(subject_id, dept_id)` is the primary key (combinations of columns with unique values) of this table.

Each row in this table indicates that the teacher with `teacher_id` teaches the subject `subject_id` in the department `dept_id`.

Write a solution to calculate the number of unique subjects each teacher teaches in the university.

Return the result table in any order.

**Example 1:**

Input:

Teacher table:

| teacher_id | subject_id | dept_id |
|---|---|---|
| 1 | 2 | 3 |
| 1 | 2 | 4 |
| 1 | 3 | 3 |
| 2 | 1 | 1 |
| 2 | 2 | 1 |
| 2 | 3 | 1 |
| 2 | 4 | 1 |

Output:

| teacher_id | cnt |
|---|---|
| 1 | 2 |
| 2 | 4 |

*Explanation:*

Teacher 1:

- They teach subject 2 in departments 3 and 4.
- They teach subject 3 in department 3.

Teacher 2:

- They teach subject 1 in department 1.
- They teach subject 2 in department 1.
- They teach subject 3 in department 1.
- They teach subject 4 in department 1.

## Schema

**Teacher**  
teacher_id, subject_id, dept_id

- `teacher_id` — integer
- `subject_id` — integer
- `dept_id` — integer
- `(subject_id, dept_id)` is the primary key.

Each row records that a teacher teaches a subject in a department.

## My solution — SQLite

```sql
SELECT
    teacher_id,
    COUNT(DISTINCT subject_id) AS cnt
FROM Teacher
GROUP BY teacher_id
ORDER BY teacher_id;
```

`GROUP BY teacher_id` creates one result row per teacher. `COUNT(DISTINCT subject_id)` counts each subject only once for that teacher, even when the teacher teaches that subject in multiple departments.

### Step-by-step explanation with one example

We need one row per teacher, containing the number of different subjects that teacher teaches. Keep the supplied Teacher example throughout. A row represents a teacher, subject, and department combination; it does not necessarily represent a new subject.

**Starting data**

`Teacher`:

| teacher_id | subject_id | dept_id |
| --- | --- | --- |
| 1 | 2 | 3 |
| 1 | 2 | 4 |
| 1 | 3 | 3 |
| 2 | 1 | 1 |
| 2 | 2 | 1 |
| 2 | 3 | 1 |
| 2 | 4 | 1 |

**1. Inspect the teacher and subject pairs**

First separate the subject being counted from the department where it is taught. Keep both rows for subject 2 initially so the repetition is visible.

```sql
SELECT teacher_id, subject_id, dept_id
FROM Teacher
ORDER BY teacher_id, subject_id, dept_id;
```

Result:

| teacher_id | subject_id | dept_id |
| --- | --- | --- |
| 1 | 2 | 3 |
| 1 | 2 | 4 |
| 1 | 3 | 3 |
| 2 | 1 | 1 |
| 2 | 2 | 1 |
| 2 | 3 | 1 |
| 2 | 4 | 1 |

Teacher 1 teaches subject 2 in two departments. Those are two input rows but only one distinct subject.

**2. Compare row counts with distinct subject counts**

GROUP BY teacher_id creates one group per teacher. COUNT(DISTINCT subject_id) removes repeated subject IDs inside that teacher's group.

```sql
SELECT teacher_id,
       COUNT(*) AS teaching_rows,
       COUNT(DISTINCT subject_id) AS cnt
FROM Teacher
GROUP BY teacher_id
ORDER BY teacher_id;
```

Result:

| teacher_id | teaching_rows | cnt |
| --- | --- | --- |
| 1 | 3 | 2 |
| 2 | 4 | 4 |

Teacher 1 has three teaching rows but two subjects: 2 and 3. Teacher 2 has four teaching rows and four subjects: 1, 2, 3, and 4.

**3. Assemble the final query**

The saved query selects only the two requested columns and orders the teacher IDs ascending.

```sql
SELECT
    teacher_id,
    COUNT(DISTINCT subject_id) AS cnt
FROM Teacher
GROUP BY teacher_id
ORDER BY teacher_id;
```

Final result for this example:

| teacher_id | cnt |
| --- | --- |
| 1 | 2 |
| 2 | 4 |

**Check the result:** Manual check: teacher 1 contributes {2, 3}, so cnt is 2; teacher 2 contributes {1, 2, 3, 4}, so cnt is 4. Grouping by department as well would answer a different question.

## My solution — SQL Server

```sql
SELECT
    teacher_id,
    COUNT(DISTINCT subject_id) AS cnt
FROM Teacher
GROUP BY teacher_id
ORDER BY teacher_id;
```

The same query works in SQLite and SQL Server.

> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
## Official solution

Lecture solution supplied in the GROUP BY/HAVING material:

```sql
SELECT teacher_id, COUNT(DISTINCT(subject_id)) AS cnt
FROM Teacher
GROUP BY teacher_id;
```

### What this tests

Counting unique subjects within each teacher's group.

### The approach

Group by `teacher_id`, then count distinct `subject_id` values in each group.

### Why this way

Teaching the same subject in two departments creates two rows but still represents one unique subject for that teacher.

### Common mistakes

`COUNT(*)` counts teaching rows rather than unique subjects. Grouping by `dept_id` would split a teacher's total across departments. The lecture allows any output order; the saved user solution adds `ORDER BY teacher_id` for a consistent display.
