# 9. SQL Actors And Directors Who Cooperated At Least Three Times

## Question and image

**9. Sql Actors And Directors Who Cooperated At Least Three Times**

Table: ActorDirector

| Column Name | Type |
|---|---|
| actor_id | int |
| director_id | int |
| timestamp | int |

`timestamp` is the primary key (column with unique values) for this table.

Write a solution to find all the pairs (`actor_id`, `director_id`) where the actor has cooperated with the director at least three times.

Return the result table ordered by `actor_id`.

**Example 1:**

Input:

ActorDirector table:

| actor_id | director_id | timestamp |
|---|---|---|
| 1 | 1 | 0 |
| 1 | 1 | 1 |
| 1 | 1 | 2 |
| 1 | 2 | 3 |
| 1 | 2 | 4 |
| 2 | 1 | 5 |
| 2 | 1 | 6 |

Output:

| actor_id | director_id |
|---|---|
| 1 | 1 |

Explanation: The only pair is (1, 1) where they cooperated exactly 3 times.

## Schema

**ActorDirector**  
actor_id, director_id, timestamp

- `actor_id` — integer
- `director_id` — integer
- `timestamp` — integer; primary key

## My solution — SQLite

```sql
SELECT
    actor_id,
    director_id
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING COUNT(timestamp) >= 3
ORDER BY actor_id ASC;
```

### Key learnings

- The question asks for actor-director “pairs,” so `actor_id` and `director_id` must be grouped together.
- Grouping only by `actor_id` would combine that actor's work with different directors and could produce an incorrect collaboration count.
- `COUNT(timestamp)` counts the cooperation records in each actor-director group. Because `timestamp` is a primary key, it is never `NULL`.
- “At least three times” means `>= 3`. Using `= 3` would wrongly exclude pairs that cooperated more than three times.
- `HAVING` filters the groups after their cooperation counts have been calculated.
- `ORDER BY actor_id ASC` satisfies the required result ordering.

### Step-by-step explanation with one example

We need one result row per actor-director pair that cooperated at least three times. Use the supplied ActorDirector rows throughout. Each timestamp identifies one cooperation record.

**Starting data**

`ActorDirector`:

| actor_id | director_id | timestamp |
| --- | --- | --- |
| 1 | 1 | 0 |
| 1 | 1 | 1 |
| 1 | 1 | 2 |
| 1 | 2 | 3 |
| 1 | 2 | 4 |
| 2 | 1 | 5 |
| 2 | 1 | 6 |

**1. Count cooperation records per pair**

A pair is defined by both actor_id and director_id. Grouping only by actor would mix that actor's work with different directors.

```sql
SELECT actor_id, director_id, COUNT(timestamp) AS cooperation_count
FROM ActorDirector
GROUP BY actor_id, director_id
ORDER BY actor_id, director_id;
```

Result:

| actor_id | director_id | cooperation_count |
| --- | --- | --- |
| 1 | 1 | 3 |
| 1 | 2 | 2 |
| 2 | 1 | 2 |

Pair (1, 1) has three records; (1, 2) has two; (2, 1) has two. Actor 1's five total records cannot be treated as five collaborations with one director.

**2. Retain pairs with at least three records**

Use HAVING after aggregation, and use >= 3 because pairs cooperating four or more times must also qualify.

```sql
SELECT actor_id, director_id, COUNT(timestamp) AS cooperation_count
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING COUNT(timestamp) >= 3
ORDER BY actor_id;
```

Result:

| actor_id | director_id | cooperation_count |
| --- | --- | --- |
| 1 | 1 | 3 |

Only pair (1, 1) remains in the sample.

**3. Assemble the final query**

The final query removes the diagnostic cooperation_count column and orders by actor_id.

```sql
SELECT
    actor_id,
    director_id
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING COUNT(timestamp) >= 3
ORDER BY actor_id ASC;
```

Final result for this example:

| actor_id | director_id |
| --- | --- |
| 1 | 1 |

**Check the result:** Manual check: timestamps 0, 1, and 2 belong to actor 1 and director 1, giving three records. Each other pair has only two records and fails the threshold.

## My solution — SQL Server

```sql
SELECT
    actor_id,
    director_id
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING COUNT(timestamp) >= 3
ORDER BY actor_id ASC;
```

The same query works in SQLite and SQL Server.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
