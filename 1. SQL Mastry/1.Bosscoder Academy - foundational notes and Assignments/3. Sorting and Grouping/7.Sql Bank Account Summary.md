# 7. SQL Bank Account Summary

## Question and image

**7. Sql Bank Account Summary**

Table: Users

| Column Name | Type |
|---|---|
| account | int |
| name | varchar |

`account` is the primary key (column with unique values) for this table.

Each row of this table contains the account number of each user in the bank.

There will be no two users having the same name in the table.

Table: Transactions

| Column Name | Type |
|---|---|
| trans_id | int |
| account | int |
| amount | int |
| transacted_on | date |

`trans_id` is the primary key (column with unique values) for this table.

Each row of this table contains all changes made to all accounts.

`amount` is positive if the user received money and negative if they transferred money.

All accounts start with a balance of 0.

Write a solution to report the name and balance of users with a balance higher than 10000. The balance of an account is equal to the sum of the amounts of all transactions involving that account.

**Example 1:**

Input:

Users table:

| account | name |
|---|---|
| 900001 | Alice |
| 900002 | Bob |
| 900003 | Charlie |

Transactions table:

| trans_id | account | amount | transacted_on |
|---|---|---|---|
| 1 | 900001 | 7000 | 2020-08-01 |
| 2 | 900001 | 7000 | 2020-09-01 |
| 3 | 900001 | -3000 | 2020-09-02 |
| 4 | 900002 | 1000 | 2020-09-12 |
| 5 | 900003 | 6000 | 2020-08-07 |
| 6 | 900003 | 6000 | 2020-09-07 |
| 7 | 900003 | -4000 | 2020-09-11 |

Output:

| name | balance |
|---|---|
| Alice | 11000 |

*Explanation:*

Alice's balance is (7000 + 7000 - 3000) = 11000.

Bob's balance is 1000.

Charlie's balance is (6000 + 6000 - 4000) = 8000.

## Schema

**Users**  
account, name

- `account` — integer; primary key
- `name` — varchar; unique across users

**Transactions**  
trans_id, account, amount, transacted_on

- `trans_id` — integer; primary key
- `account` — integer
- `amount` — integer; positive when money is received and negative when money is transferred
- `transacted_on` — date
- Every account begins with a balance of 0.

## My solution — SQLite

```sql
SELECT
    U.name,
    SUM(T.amount) AS balance
FROM Users AS U
JOIN Transactions AS T
    ON U.account = T.account
GROUP BY U.name
HAVING SUM(T.amount) > 10000;
```

### Key learnings

- Joining `Users` to `Transactions` through `account` connects each transaction amount to the corresponding user's name.
- `SUM(T.amount)` calculates each user's balance because positive amounts add money and negative amounts subtract money.
- `GROUP BY U.name` creates one group per user. It is valid here because the question guarantees that user names are unique.
- `WHERE` filters individual transaction rows before grouping. `HAVING` filters the completed user groups after `SUM(T.amount)` has been calculated.
- Therefore, filtering an aggregate balance requires `HAVING SUM(T.amount) > 10000`.
- No `ORDER BY` is necessary because the question does not specify a result order.

### Step-by-step explanation with one example

We need one result row per user whose total account balance is greater than 10000. Use the supplied Users and Transactions examples. Balances start at zero, so every signed transaction amount contributes directly to the balance.

**Starting data**

`Users`:

| account | name |
| --- | --- |
| 900001 | Alice |
| 900002 | Bob |
| 900003 | Charlie |

`Transactions`:

| trans_id | account | amount | transacted_on |
| --- | --- | --- | --- |
| 1 | 900001 | 7000 | 2020-08-01 |
| 2 | 900001 | 7000 | 2020-09-01 |
| 3 | 900001 | -3000 | 2020-09-02 |
| 4 | 900002 | 1000 | 2020-09-12 |
| 5 | 900003 | 6000 | 2020-08-07 |
| 6 | 900003 | 6000 | 2020-09-07 |
| 7 | 900003 | -4000 | 2020-09-11 |

**1. Attach each transaction to the user name**

Users contains the name; Transactions contains the amounts. Join by account so every amount is associated with the correct person.

```sql
SELECT U.name, T.trans_id, T.account, T.amount
FROM Users AS U
JOIN Transactions AS T ON U.account = T.account
ORDER BY T.trans_id;
```

Result:

| name | trans_id | account | amount |
| --- | --- | --- | --- |
| Alice | 1 | 900001 | 7000 |
| Alice | 2 | 900001 | 7000 |
| Alice | 3 | 900001 | -3000 |
| Bob | 4 | 900002 | 1000 |
| Charlie | 5 | 900003 | 6000 |
| Charlie | 6 | 900003 | 6000 |
| Charlie | 7 | 900003 | -4000 |

Alice has three transactions, Bob one, and Charlie three. Negative amounts are withdrawals and must remain in the data.

**2. Add all signed amounts per user**

The problem guarantees unique names, so GROUP BY U.name identifies each user. SUM includes positive and negative values to calculate the net balance.

```sql
SELECT U.name, SUM(T.amount) AS balance
FROM Users AS U
JOIN Transactions AS T ON U.account = T.account
GROUP BY U.name
ORDER BY U.name;
```

Result:

| name | balance |
| --- | --- |
| Alice | 11000 |
| Bob | 1000 |
| Charlie | 8000 |

Alice has 11000, Bob 1000, and Charlie 8000. Filtering individual amounts before SUM would calculate the wrong balance.

**3. Assemble the final query**

HAVING SUM(T.amount) > 10000 keeps users after their complete balance has been calculated. Strictly greater means a balance of exactly 10000 would be excluded.

```sql
SELECT
    U.name,
    SUM(T.amount) AS balance
FROM Users AS U
JOIN Transactions AS T
    ON U.account = T.account
GROUP BY U.name
HAVING SUM(T.amount) > 10000;
```

Final result for this example:

| name | balance |
| --- | --- |
| Alice | 11000 |

**Check the result:** Manual check: Alice = 7000 + 7000 - 3000 = 11000; Bob = 1000; Charlie = 6000 + 6000 - 4000 = 8000. Only Alice exceeds 10000.

## My solution — SQL Server

```sql
SELECT
    U.name,
    SUM(T.amount) AS balance
FROM Users AS U
JOIN Transactions AS T
    ON U.account = T.account
GROUP BY U.name
HAVING SUM(T.amount) > 10000;
```

The same query works in SQLite and SQL Server.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
