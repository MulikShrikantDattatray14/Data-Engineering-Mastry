# 25. Monthly revenue across the full history

## Question and image

Using the Chinook `Invoice` table, produce chart-ready total revenue for every month in the store's history, with one row per calendar month.

Return exactly two columns:

- `Month` — year and month formatted as `YYYY-MM`, for example `2023-07`
- `Revenue` — the sum of `Total` for that month, rounded to 2 decimal places

Sort by `Month` ascending.

The history spans several years. A result containing exactly 12 rows has incorrectly combined the same months from different years.

Expected output: `Month`, `Revenue` — 60 rows; order matters.

## My solution — SQLite

```sql
select
    strftime('%Y-%m', InvoiceDate) as Month,
    round(sum(Total), 2) as Revenue
from Invoice
group by Month
order by Month;
```

**1. Label each invoice with its year and month**

strftime with %Y-%m creates a calendar-month key. Including the year keeps January 2023 separate from January 2024.

```sql
SELECT InvoiceId, InvoiceDate, STRFTIME('%Y-%m', InvoiceDate) AS Month, Total
FROM Invoice
ORDER BY InvoiceId;
```

Result:

| InvoiceId | InvoiceDate | Month | Total |
| --- | --- | --- | --- |
| 1 | 2023-01-10 10:00:00 | 2023-01 | 10.25 |
| 2 | 2023-01-28 12:00:00 | 2023-01 | 20.1 |
| 3 | 2023-02-05 09:00:00 | 2023-02 | 5 |
| 4 | 2024-01-01 08:00:00 | 2024-01 | 7.5 |
| 5 | 2024-01-20 14:00:00 | 2024-01 | 2.5 |
| 6 | 2024-02-08 17:00:00 | 2024-02 | 8.25 |

Invoices 1 and 2 share 2023-01; invoices 4 and 5 share 2024-01. Those are different groups despite having the same month number.

**2. Sum invoice totals inside each month**

GROUP BY Month makes one row per year-month label. Add Total within each group before rounding.

```sql
SELECT STRFTIME('%Y-%m', InvoiceDate) AS Month, SUM(Total) AS UnroundedRevenue
FROM Invoice
GROUP BY Month;
```

Result:

| Month | UnroundedRevenue |
| --- | --- |
| 2023-01 | 30.35 |
| 2023-02 | 5 |
| 2024-01 | 10 |
| 2024-02 | 8.25 |

January 2023 totals 10.25 + 20.10 = 30.35. January 2024 totals 7.50 + 2.50 = 10. The other two month totals each come from one invoice.

**3. Assemble the final query**

Combine the steps using the saved solution. The query below preserves the original logic.

```sql
select
    strftime('%Y-%m', InvoiceDate) as Month,
    round(sum(Total), 2) as Revenue
from Invoice
group by Month
order by Month;
```

Final result for this example:

| Month | Revenue |
| --- | --- |
| 2023-01 | 30.35 |
| 2023-02 | 5 |
| 2024-01 | 10 |
| 2024-02 | 8.25 |

**Check the result:** The four monthly totals are 30.35, 5, 10, and 8.25; together they equal the six invoices' total of 53.60. YYYY-MM sorts chronologically across years. The saved query returns months present in Invoice; it does not generate rows for absent months.

## Official solution

```sql
SELECT
    strftime('%Y-%m', InvoiceDate) AS Month,
    ROUND(SUM(Total), 2) AS Revenue
FROM Invoice
GROUP BY strftime('%Y-%m', InvoiceDate)
ORDER BY Month ASC;
```

### What this tests

Creating a year-month grouping key from a timestamp and aggregating revenue at the correct calendar-month level.

### The approach

1. Convert each `InvoiceDate` into a `YYYY-MM` label with `strftime('%Y-%m', InvoiceDate)`.
2. Group invoices by that year-month value so the same month in different years remains separate.
3. Sum each month's `Total` and round the result to two decimal places.
4. Sort by `Month` ascending. The zero-padded `YYYY-MM` format sorts chronologically as text.

### Why this way

Deriving the time bucket directly in the aggregation makes the result's monthly grain clear. Changing the format string allows the same pattern to create daily, weekly, or hourly summaries.

### Common mistakes

- Using only `%m`, which combines the same month from every year into 12 groups.
- Grouping by the complete timestamp, which creates separate groups for individual invoice dates or times.
- Sorting by revenue when the requested result is a chronological time series.
