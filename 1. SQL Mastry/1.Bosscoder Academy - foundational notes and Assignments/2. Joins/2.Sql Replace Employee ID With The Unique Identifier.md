# 2. SQL Replace Employee ID With The Unique Identifier

![SOLVED](<../../_badges/solved.svg>) ![UNRATED](<../../_badges/unrated.svg>) · Solved (recorded): 2026-10-26

## Question and image

Show the unique ID and name of **each employee**. If an employee has no unique ID in EmployeeUNI, display NULL for the unique ID.

Return the result in any order.

**Example 1**

Input — Employees:

| id | name |
|---:|---|
| 1 | Alice |
| 7 | Bob |
| 11 | Meir |
| 90 | Winston |
| 3 | Jonathan |

Input — EmployeeUNI:

| id | unique_id |
|---:|---:|
| 3 | 1 |
| 11 | 2 |
| 90 | 3 |

Expected output:

| unique_id | name |
|---:|---|
| NULL | Alice |
| 1 | Jonathan |
| NULL | Bob |
| 2 | Meir |
| 3 | Winston |

Alice and Bob have no unique ID. Meir, Winston, and Jonathan have the IDs shown in EmployeeUNI. The output order is only one possible order; none is required.

## Schema

Employees:

| Column Name | Type |
|---|---|
| id | int |
| name | varchar |

id is the primary key. Each row holds an employee ID and name.

EmployeeUNI:

| Column Name | Type |
|---|---|
| id | int |
| unique_id | int |

(id, unique_id) is the stated composite primary key. Each row associates an employee ID with a unique ID.

## My solution — SQLite

```sql
SELECT unique_id, name
FROM Employees
LEFT JOIN EmployeeUNI
    ON Employees.id = EmployeeUNI.id;
```

### Step-by-step explanation with one example

**Starting data.** `Employees` lists five people. `EmployeeUNI` has unique IDs for Jonathan, Meir, and Winston, but no rows for Alice or Bob.

| Employees.id | name |
|---:|---|
| 1 | Alice |
| 7 | Bob |
| 11 | Meir |
| 90 | Winston |
| 3 | Jonathan |

| EmployeeUNI.id | unique_id |
|---:|---:|
| 3 | 1 |
| 11 | 2 |
| 90 | 3 |

**1. Keep all employee rows.** The task needs employees whether or not they have a unique ID. `Employees` goes on the left of `LEFT JOIN`.

**2. Match the two ID columns.** `ON Employees.id = EmployeeUNI.id` finds each employee's corresponding unique ID. To inspect the match, temporarily include the employee's ordinary ID:

```sql
SELECT Employees.id, Employees.name, EmployeeUNI.unique_id
FROM Employees
LEFT JOIN EmployeeUNI
    ON Employees.id = EmployeeUNI.id
ORDER BY Employees.id;
```

| id | name | unique_id |
|---:|---|---:|
| 1 | Alice | NULL |
| 3 | Jonathan | 1 |
| 7 | Bob | NULL |
| 11 | Meir | 2 |
| 90 | Winston | 3 |

For Alice (`id = 1`) and Bob (`id = 7`), there is no matching `EmployeeUNI.id`. The left join still returns them and fills `unique_id` with `NULL`. For Jonathan, `Employees.id = 3` matches `EmployeeUNI.id = 3`, bringing in `unique_id = 1`. Meir and Winston match in the same way.

**3. Return only the requested columns.** Drop the ordinary `id` and keep `unique_id` with `name`:

```sql
SELECT unique_id, name
FROM Employees
LEFT JOIN EmployeeUNI
    ON Employees.id = EmployeeUNI.id;
```

One valid result is:

| unique_id | name |
|---:|---|
| NULL | Alice |
| 1 | Jonathan |
| NULL | Bob |
| 2 | Meir |
| 3 | Winston |

No `COALESCE` is needed: the question asks for `NULL` when a unique ID is missing. No `ORDER BY` is required, so row order can vary. The stated key `(id, unique_id)` does not make `EmployeeUNI.id` alone unique; if one employee has several mappings, the join can return several rows for that employee.

## Official solution

The lecture material uses the same left join with short aliases:

```sql
SELECT eu.unique_id AS unique_id, e.name AS name
FROM Employees AS e
LEFT JOIN EmployeeUNI AS eu
    ON e.id = eu.id;
```

### What this tests

Preserving employees who have no related row in another table.

### The approach

Start from `Employees`, left join `EmployeeUNI` on the employee ID, and return the unique ID and name.

### Why this way

An unmatched employee remains in the result with a `NULL` unique ID.

### Common mistakes

An inner join drops Alice and Bob. Joining `Employees.id` to `EmployeeUNI.unique_id` compares different kinds of IDs.
