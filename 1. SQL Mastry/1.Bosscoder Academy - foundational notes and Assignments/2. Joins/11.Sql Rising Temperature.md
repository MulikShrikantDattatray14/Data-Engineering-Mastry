# 11. SQL Rising Temperature

## Question and image

The `Weather` table records one temperature for each `recordDate`. Find the IDs of dates whose temperature is higher than on the previous calendar day (yesterday).

**Example 1**

Input — `Weather`:

| id | recordDate | temperature |
|---:|---|---:|
| 1 | 2015-01-01 | 10 |
| 2 | 2015-01-02 | 25 |
| 3 | 2015-01-03 | 20 |
| 4 | 2015-01-04 | 30 |

Output:

| id |
|---:|
| 2 |
| 4 |

January 2 is warmer than January 1 (`25 > 10`), and January 4 is warmer than January 3 (`30 > 20`).

## Schema

`Weather`:

| Column Name | Type |
|---|---|
| id | int |
| recordDate | date |
| temperature | int |

`id` contains unique values. No two rows have the same `recordDate`. Each row records the temperature on that date.

## My solution — SQLite

```sql
SELECT w2.id
FROM Weather AS w1
JOIN Weather AS w2
    ON date(w1.recordDate, '+1 day') = w2.recordDate
   AND w1.temperature < w2.temperature;
```

### Step-by-step explanation with one example

**Starting data.** Each row is one date's temperature:

| id | recordDate | temperature |
|---:|---|---:|
| 1 | 2015-01-01 | 10 |
| 2 | 2015-01-02 | 25 |
| 3 | 2015-01-03 | 20 |
| 4 | 2015-01-04 | 30 |

**1. Pair each date with the next calendar day.** In the self-join, `w1` is yesterday and `w2` is the day whose ID we may return. `date(w1.recordDate, '+1 day')` computes the next calendar date. Only a `w2` row with that exact date matches.

```sql
SELECT
    w1.id AS yesterday_id,
    w1.recordDate AS yesterday_date,
    w1.temperature AS yesterday_temp,
    w2.id AS today_id,
    w2.recordDate AS today_date,
    w2.temperature AS today_temp
FROM Weather AS w1
JOIN Weather AS w2
    ON date(w1.recordDate, '+1 day') = w2.recordDate
ORDER BY w2.recordDate;
```

| yesterday_id | yesterday_date | yesterday_temp | today_id | today_date | today_temp |
|---:|---|---:|---:|---|---:|
| 1 | 2015-01-01 | 10 | 2 | 2015-01-02 | 25 |
| 2 | 2015-01-02 | 25 | 3 | 2015-01-03 | 20 |
| 3 | 2015-01-03 | 20 | 4 | 2015-01-04 | 30 |

This compares actual neighboring dates. If January 3 were missing, January 4 would have no yesterday match, even though January 2 would then be the preceding row in a date-sorted table.

**2. Compare the temperatures in each pair.** Keep the `w2` row only when yesterday's temperature is lower: `w1.temperature < w2.temperature`.

```sql
SELECT
    w1.recordDate AS yesterday_date,
    w1.temperature AS yesterday_temp,
    w2.id AS today_id,
    w2.recordDate AS today_date,
    w2.temperature AS today_temp,
    CASE
        WHEN w1.temperature < w2.temperature THEN 'keep'
        ELSE 'discard'
    END AS decision
FROM Weather AS w1
JOIN Weather AS w2
    ON date(w1.recordDate, '+1 day') = w2.recordDate
ORDER BY w2.recordDate;
```

| yesterday_date | yesterday_temp | today_id | today_date | today_temp | decision |
|---|---:|---:|---|---:|---|
| 2015-01-01 | 10 | 2 | 2015-01-02 | 25 | keep |
| 2015-01-02 | 25 | 3 | 2015-01-03 | 20 | discard |
| 2015-01-03 | 20 | 4 | 2015-01-04 | 30 | keep |

The `CASE` column just makes the comparison visible; the final query uses the inequality directly in the join condition. On January 2, `10 < 25`; on January 4, `20 < 30`. January 3 fails because `25 < 20` is false.

**3. Return today's ID for the kept pairs.** The complete query at the top selects `w2.id` after both join conditions are applied:

| id |
|---:|
| 2 |
| 4 |

The question does not require a particular output order. Because `recordDate` is unique, a date has at most one yesterday match, so this join does not duplicate a returned ID.

## My solution — SQL Server

SQL Server uses `DATEADD` for the one-day date calculation; the self-join logic stays the same.

```sql
SELECT w2.id
FROM Weather AS w1
JOIN Weather AS w2
    ON DATEADD(day, 1, w1.recordDate) = w2.recordDate
   AND w1.temperature < w2.temperature;
```
