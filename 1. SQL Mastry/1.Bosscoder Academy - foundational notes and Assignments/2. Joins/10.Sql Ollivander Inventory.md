## Schema

`Wands`:

| Column Name | Type |
|---|---|
| id | Integer |
| code | Integer |
| coins_needed | Integer |
| power | Integer |

`id` identifies the wand, `code` links to its properties, `coins_needed` is its cost in gold galleons, and higher `power` means a better-quality wand.

`Wands_Property`:

| Column Name | Type |
|---|---|
| code | Integer |
| age | Integer |
| is_evil | Integer |

`code` identifies the wand properties. `is_evil = 0` means non-evil. The supplied code–age mapping is one-to-one: distinct codes map to distinct ages.

## My solution — SQLite

```sql
SELECT w.id,
       p.age,
       w.coins_needed,
       w.power
FROM Wands AS w
JOIN Wands_Property AS p
    ON w.code = p.code
WHERE p.is_evil = 0
  AND w.coins_needed = (
      SELECT MIN(w2.coins_needed)
      FROM Wands AS w2
      JOIN Wands_Property AS p2
          ON w2.code = p2.code
      WHERE p2.is_evil = 0
        AND w2.power = w.power
        AND p2.age = p.age
  )
ORDER BY w.power DESC, p.age DESC;
```

### Step-by-step explanation with one example

**Starting data.** `Wands` has 20 wand rows with IDs, codes, prices, and powers. `Wands_Property` maps each code to an age and an evil flag. In the sample, code `3` has `is_evil = 1`; codes `1`, `2`, `4`, and `5` are non-evil.

**1. Attach age and evil status, then keep non-evil wands.** `w.code = p.code` finds the property row for each wand. `WHERE p.is_evil = 0` removes the six code-3 wands (IDs 2, 3, 4, 7, 8, and 13). The remaining 14 rows are:

```sql
SELECT w.id, w.code, p.age, w.coins_needed, w.power
FROM Wands AS w
JOIN Wands_Property AS p ON w.code = p.code
WHERE p.is_evil = 0
ORDER BY w.power DESC, p.age DESC, w.coins_needed;
```

Notice that evil wand **4** costs only 734 at power 8. It must not win because it was filtered out before the minimum is chosen.

**2. Compare prices within the same power *and* age.** For an outer row with `power = 7` and `age = 40`, inspect the candidates the correlated subquery considers:

```sql
SELECT w2.id AS candidate_id, w2.coins_needed
FROM Wands AS w2
JOIN Wands_Property AS p2 ON w2.code = p2.code
WHERE p2.is_evil = 0
  AND w2.power = 7
  AND p2.age = 40
ORDER BY w2.id;
```

| candidate_id | coins_needed |
|---:|---:|
| 6 | 6773 |
| 15 | 6018 |
| 17 | 8798 |

Now take their minimum:

```sql
SELECT MIN(w2.coins_needed) AS cheapest_price
FROM Wands AS w2
JOIN Wands_Property AS p2 ON w2.code = p2.code
WHERE p2.is_evil = 0
  AND w2.power = 7
  AND p2.age = 40;
```

| cheapest_price |
|---:|
| 6018 |

Outer wand 15 passes `w.coins_needed = 6018`; IDs 6 and 17 fail. The actual subquery uses `w2.power = w.power` and `p2.age = p.age` instead of fixed numbers, so it repeats this comparison for each outer wand's own power and age.

## My solution — SQL Server

The same query works in SQL Server:

```sql
SELECT w.id,
       p.age,
       w.coins_needed,
       w.power
FROM Wands AS w
JOIN Wands_Property AS p
    ON w.code = p.code
WHERE p.is_evil = 0
  AND w.coins_needed = (
      SELECT MIN(w2.coins_needed)
      FROM Wands AS w2
      JOIN Wands_Property AS p2
          ON w2.code = p2.code
      WHERE p2.is_evil = 0
        AND w2.power = w.power
        AND p2.age = p.age
  )
ORDER BY w.power DESC, p.age DESC;
```
