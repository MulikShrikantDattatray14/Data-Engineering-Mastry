## Question and image

Delete duplicate email rows from `Person`, keeping the row with the **smallest `id`** for each email. The lecture version asks SQL users to write a `DELETE` statement, not a `SELECT`; the displayed answer is the remaining `Person` table.

The assignment copy asks to show the remaining rows ordered by `id`. A `DELETE` changes which rows remain but does not set their display order. The example below is shown in `id` order for easy comparison.

**Example 1**

Input — `Person`:

| id | email |
|---:|---|
| 1 | john@example.com |
| 2 | bob@example.com |
| 3 | john@example.com |

Expected remaining `Person` table:

| id | email |
|---:|---|
| 1 | john@example.com |
| 2 | bob@example.com |

`john@example.com` appears twice. Keep its row with the smaller ID, 1.
