The table shows the user activities for a factory website.

(machine_id, process_id, activity_type) is the primary key (combination of columns with unique values) of this table.

machine_id is the ID of a machine.

process_id is the ID of a process running on the machine with ID machine_id.

activity_type is an ENUM (category) of type ('start', 'end').

timestamp is a float representing the current time in seconds.

'start' means the machine starts the process at the given timestamp and 'end' means the machine ends the process at the given timestamp.

The `start` timestamp will always be less than or equal to the `end` timestamp for every `(machine_id, process_id)` pair.

It is guaranteed that each (machine_id, process_id) pair has a 'start' and 'end' timestamp.

There is a factory website that has several machines, each running one or more processes. Write a solution to find the **average time** each machine takes to complete a process.

The time to complete a process is the `'end' timestamp` minus the `'start' timestamp`. The average time is calculated by the total time to complete every process on the machine divided by the number of processes that were run on that machine.

The resulting table should have the `machine_id` along with the **average time** as `processing_time`, which should be **rounded to 3 decimal places**.

Return the result table in **any order**.

The result format is in the following example.

**Example 1:**

**Input:**

Activity table:

| machine_id | process_id | activity_type | timestamp |
|---|---|---|---|
| 0 | 0 | start | 0.712 |
| 0 | 0 | end | 1.520 |
| 0 | 1 | start | 3.140 |
| 0 | 1 | end | 4.120 |
| 1 | 0 | start | 0.550 |
| 1 | 0 | end | 1.550 |
| 1 | 1 | start | 0.430 |
| 1 | 1 | end | 1.420 |
| 2 | 0 | start | 4.100 |
| 2 | 0 | end | 4.512 |
| 2 | 1 | start | 2.500 |
| 2 | 1 | end | 5.000 |

**Output:**

| machine_id | processing_time |
|---|---|
| 0 | 0.894 |
| 1 | 0.995 |
| 2 | 1.456 |

**Explanation:**

There are 3 machines running 2 processes each.

Machine 0's average time is ((1.520 - 0.712) + (4.120 - 3.140)) / 2 = 0.894

Machine 1's average time is ((1.550 - 0.550) + (1.420 - 0.430)) / 2 = 0.995

Machine 2's average time is ((4.512 - 4.100) + (5.000 - 2.500)) / 2 = 1.456

## My solution — SQLite

```sql
SELECT
    S.machine_id,
    ROUND(
        AVG(E.timestamp - S.timestamp),
        3
    ) AS processing_time
FROM Activity AS S
JOIN Activity AS E
    ON S.machine_id = E.machine_id
    AND S.process_id = E.process_id
    AND S.activity_type = 'start'
    AND E.activity_type = 'end'
GROUP BY S.machine_id;
```

### Step-by-step explanation with one example

First calculate **one duration per process**, then use `GROUP BY machine_id` to calculate each machine's average. We use the original example throughout.

**1. Define the required output**

We need **one row per machine**, with these columns:

| Column | Meaning |
|---|---|
| machine_id | The machine |
| processing_time | Its average process duration, rounded to three decimal places |

We are averaging **durations**, so we must first calculate:

```text
process duration = end timestamp - start timestamp
```

**2. Look at how the input stores those times**

The original `Activity` table is:

| machine_id | process_id | activity_type | timestamp |
|---|---|---|---|
| 0 | 0 | start | 0.712 |
| 0 | 0 | end | 1.520 |
| 0 | 1 | start | 3.140 |
| 0 | 1 | end | 4.120 |
| 1 | 0 | start | 0.550 |
| 1 | 0 | end | 1.550 |
| 1 | 1 | start | 0.430 |
| 1 | 1 | end | 1.420 |
| 2 | 0 | start | 4.100 |
| 2 | 0 | end | 4.512 |
| 2 | 1 | start | 2.500 |
| 2 | 1 | end | 5.000 |

Each row represents **one event**: either a process starting or ending.

For machine `0`, process `0`:

```text
1.520 - 0.712 = 0.808 seconds
```

But those two timestamps are in different rows. Our next task is therefore:

> Put each process's start timestamp and end timestamp beside each other.

**3. Give the same table two roles**

We can reference `Activity` twice:

- `S` represents the start rows.
- `E` represents the end rows.

These are aliases for the same table. We are not creating two new tables.

To understand these two roles, first inspect the start rows:

```sql
SELECT
    machine_id,
    process_id,
    timestamp AS start_time
FROM Activity
WHERE activity_type = 'start';
```

Result:

| machine_id | process_id | start_time |
|---|---|---|
| 0 | 0 | 0.712 |
| 0 | 1 | 3.140 |
| 1 | 0 | 0.550 |
| 1 | 1 | 0.430 |
| 2 | 0 | 4.100 |
| 2 | 1 | 2.500 |

Then inspect the end rows:

```sql
SELECT
    machine_id,
    process_id,
    timestamp AS end_time
FROM Activity
WHERE activity_type = 'end';
```

Result:

| machine_id | process_id | end_time |
|---|---|---|
| 0 | 0 | 1.520 |
| 0 | 1 | 4.120 |
| 1 | 0 | 1.550 |
| 1 | 1 | 1.420 |
| 2 | 0 | 4.512 |
| 2 | 1 | 5.000 |

We now understand which rows should be paired.

**4. Match each start with its correct end**

The matching rows must belong to:

- The **same machine**.
- The **same process** on that machine.

That gives us:

```sql
ON S.machine_id = E.machine_id
AND S.process_id = E.process_id
```

Matching only `process_id` would be incorrect because process `0` exists on all three machines.

We also require:

```sql
AND S.activity_type = 'start'
AND E.activity_type = 'end'
```

Otherwise, matching the IDs alone would also allow start-to-start and end-to-end matches.

The complete query for inspecting the pairs is:

```sql
SELECT
    S.machine_id,
    S.process_id,
    S.timestamp AS start_time,
    E.timestamp AS end_time
FROM Activity AS S
JOIN Activity AS E
    ON S.machine_id = E.machine_id
    AND S.process_id = E.process_id
    AND S.activity_type = 'start'
    AND E.activity_type = 'end';
```

Result:

| machine_id | process_id | start_time | end_time |
|---|---|---|---|
| 0 | 0 | 0.712 | 1.520 |
| 0 | 1 | 3.140 | 4.120 |
| 1 | 0 | 0.550 | 1.550 |
| 1 | 1 | 0.430 | 1.420 |
| 2 | 0 | 4.100 | 4.512 |
| 2 | 1 | 2.500 | 5.000 |

**The twelve event rows have become six process rows.**

Each row now contains both timestamps needed for subtraction. An ordinary inner `JOIN` is sufficient because the question guarantees a start and end for every process.

**5. Calculate the duration of each process**

Now the subtraction is straightforward:

```sql
E.timestamp - S.timestamp
```

Here is the query:

```sql
SELECT
    S.machine_id,
    S.process_id,
    E.timestamp - S.timestamp AS duration
FROM Activity AS S
JOIN Activity AS E
    ON S.machine_id = E.machine_id
    AND S.process_id = E.process_id
    AND S.activity_type = 'start'
    AND E.activity_type = 'end';
```

Result, displaying durations to three decimal places for readability:

| machine_id | process_id | duration |
|---|---|---|
| 0 | 0 | 0.808 |
| 0 | 1 | 0.980 |
| 1 | 0 | 1.000 |
| 1 | 1 | 0.990 |
| 2 | 0 | 0.412 |
| 2 | 1 | 2.500 |

For example:

```text
Machine 2, process 0: 4.512 - 4.100 = 0.412
Machine 2, process 1: 5.000 - 2.500 = 2.500
```

The query keeps the original calculated values. We will apply rounding to the final average.

**6. Group these durations by machine and calculate the average**

This is where `GROUP BY machine_id` belongs:

```sql
GROUP BY S.machine_id
```

We now want:

> Collect all process durations belonging to each machine, then average them.

The average expression is:

```sql
AVG(E.timestamp - S.timestamp)
```

To inspect the calculation, we can show the total time, process count, and average together:

```sql
SELECT
    S.machine_id,
    SUM(E.timestamp - S.timestamp) AS total_time,
    COUNT(*) AS process_count,
    AVG(E.timestamp - S.timestamp) AS average_time
FROM Activity AS S
JOIN Activity AS E
    ON S.machine_id = E.machine_id
    AND S.process_id = E.process_id
    AND S.activity_type = 'start'
    AND E.activity_type = 'end'
GROUP BY S.machine_id;
```

Result:

| machine_id | total_time | process_count | average_time |
|---|---|---|---|
| 0 | 1.788 | 2 | 0.894 |
| 1 | 1.990 | 2 | 0.995 |
| 2 | 2.912 | 2 | 1.456 |

Check each machine manually:

```text
Machine 0:
(0.808 + 0.980) / 2
= 1.788 / 2
= 0.894

Machine 1:
(1.000 + 0.990) / 2
= 1.990 / 2
= 0.995

Machine 2:
(0.412 + 2.500) / 2
= 2.912 / 2
= 1.456
```

**Do not hardcode division by `2`.** The example has two processes per machine, but another input could have different counts. `AVG()` uses the number of durations in each machine's group automatically.

A process with duration `0` also belongs in that average.

We group only by `machine_id` because the final output needs one row per machine. Adding `process_id` would keep separate groups for individual processes.

**7. Round the average and assemble the final query**

The question requires three decimal places, so wrap the average in:

```sql
ROUND(AVG(E.timestamp - S.timestamp), 3)
```

The final SQLite query is:

```sql
SELECT
    S.machine_id,
    ROUND(
        AVG(E.timestamp - S.timestamp),
        3
    ) AS processing_time
FROM Activity AS S
JOIN Activity AS E
    ON S.machine_id = E.machine_id
    AND S.process_id = E.process_id
    AND S.activity_type = 'start'
    AND E.activity_type = 'end'
GROUP BY S.machine_id;
```

Final output:

| machine_id | processing_time |
|---|---|
| 0 | 0.894 |
| 1 | 0.995 |
| 2 | 1.456 |

Round only after averaging. Rounding individual durations before averaging could change the final result. No `ORDER BY` is required because any result order is accepted.

All six example queries were executed in SQLite. The intermediate results and final output match the walkthrough; the final query also handles different process counts and zero-duration processes.
