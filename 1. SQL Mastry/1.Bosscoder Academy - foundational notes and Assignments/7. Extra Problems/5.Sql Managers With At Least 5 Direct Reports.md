id is the primary key (column with unique values) for this table.

Each row of this table indicates the name of an employee, their department, and the id of their manager.

If managerId is null, then the employee does not have a manager.

No employee will be the manager of themself.

Write a solution to find managers with at least **five direct reports**.

Return the result table in **any order**.

## Schema

**Employee**

| Column Name | Type |
|---|---|
| id | int |
| name | varchar |
| department | varchar |
| managerId | int |

- `id` is the primary key.
- Each row records an employee's name, department, and manager ID.
- A NULL `managerId` means the employee has no manager.
- No employee is their own manager.

## My solution — SQLite

```sql
SELECT E1.name
FROM Employee AS E1
JOIN Employee AS E2
    ON E1.id = E2.managerId
GROUP BY E2.managerId
HAVING COUNT(E2.managerId) >= 5;
```

### Step-by-step explanation with one example

Use the supplied example throughout. The final query preserves the self-join, grouping, and counting approach used in the confirmed SQLite solution.

**1. Define the output and understand the starting rows**

We need one result row per manager who has at least five direct reports. The output contains the manager's `name`, and any result order is accepted.

The starting `Employee` table is:

| id | name | department | managerId |
|---|---|---|---|
| 101 | John | A | NULL |
| 102 | Dan | A | 101 |
| 103 | James | A | 101 |
| 104 | Amy | A | 101 |
| 105 | Anne | A | 101 |
| 106 | Ron | B | 101 |

Each row represents an employee. The `id` identifies that employee, while `managerId` identifies the employee they report to directly.

For example, Dan's `managerId = 101` points to John's `id = 101`. John has no manager himself, but other employees can still report to him.

Our task is:

> Connect employees to their managers, count the employees reporting directly to each manager, and keep managers whose count is at least five.

**2. Use the same table in two roles and match the relationship**

Use `Employee` twice, with these aliases:

- `E1` represents the manager.
- `E2` represents the employee reporting directly to that manager.

The relationship is:

```sql
ON E1.id = E2.managerId
```

We match the manager's own ID to the ID stored in the employee's manager column. Testing that two IDs differ would not establish this relationship.

Inspect both sides of the self-join:

```sql
SELECT
    E1.id AS manager_id,
    E1.name AS manager_name,
    E2.id AS employee_id,
    E2.name AS employee_name,
    E2.department AS employee_department
FROM Employee AS E1
JOIN Employee AS E2
    ON E1.id = E2.managerId
ORDER BY E2.id;
```

Result:

| manager_id | manager_name | employee_id | employee_name | employee_department |
|---|---|---|---|---|
| 101 | John | 102 | Dan | A |
| 101 | John | 103 | James | A |
| 101 | John | 104 | Amy | A |
| 101 | John | 105 | Anne | A |
| 101 | John | 106 | Ron | B |

Each joined row represents **one manager and one direct report**.

John's ID matches five employee rows. Ron is included even though he is in department B: the question does not require a manager and their reports to share a department.

John's own row is not counted as his direct report. Its `managerId` is NULL, so it does not match John's ID as a report row.

**3. Understand why selecting the manager name alone repeats it**

If we select only the manager's name at this stage:

```sql
SELECT E1.name
FROM Employee AS E1
JOIN Employee AS E2
    ON E1.id = E2.managerId;
```

Result:

| name |
|---|
| John |
| John |
| John |
| John |
| John |

These five rows correspond to Dan, James, Amy, Anne, and Ron. Selecting fewer columns does not remove the joined rows.

The repeated manager names tell us there are multiple reports to count. We need to group these rows by manager before filtering by that count.

**4. Group the reports by manager and count them**

Group using the report rows' `managerId`:

```sql
GROUP BY E2.managerId
```

Through the join condition, `E2.managerId` equals `E1.id`. Therefore, each group belongs to one manager.

Inspect the manager ID, name, and report count together:

```sql
SELECT
    E2.managerId,
    E1.name,
    COUNT(E2.managerId) AS direct_reports
FROM Employee AS E1
JOIN Employee AS E2
    ON E1.id = E2.managerId
GROUP BY E2.managerId;
```

Result:

| managerId | name | direct_reports |
|---|---|---|
| 101 | John | 5 |

The five joined rows become one manager group.

`COUNT(E2.managerId)` works here because every matched report has a non-NULL manager ID. Each employee contributes one row, so the count is the number of direct reports.

Grouping by manager ID also keeps different managers with the same name in separate groups. In SQLite, selecting `E1.name` here is valid; all rows in a group refer to the same manager because `E1.id` is the primary key.

**5. Keep only groups with at least five reports**

The condition applies to the count of a whole group, so use `HAVING`:

```sql
HAVING COUNT(E2.managerId) >= 5
```

`WHERE` filters individual rows before grouping. `HAVING` filters groups using results such as `COUNT()`.

Inspect the qualifying groups:

```sql
SELECT
    E2.managerId,
    E1.name,
    COUNT(E2.managerId) AS direct_reports
FROM Employee AS E1
JOIN Employee AS E2
    ON E1.id = E2.managerId
GROUP BY E2.managerId
HAVING COUNT(E2.managerId) >= 5;
```

Result:

| managerId | name | direct_reports |
|---|---|---|
| 101 | John | 5 |

John remains because `5 >= 5`. The word "at least" includes exactly five reports; a count below five would be excluded.

**6. Assemble the final query and return only the required column**

The final result needs the manager's name, so remove the diagnostic ID and count columns from the SELECT list. The grouping and HAVING condition still perform their work.

```sql
SELECT E1.name
FROM Employee AS E1
JOIN Employee AS E2
    ON E1.id = E2.managerId
GROUP BY E2.managerId
HAVING COUNT(E2.managerId) >= 5;
```

Final output:

| name |
|---|
| John |

Read the logic in this order:

1. Match each manager to employees whose `managerId` points directly to that manager.
2. Group those employee rows by manager ID.
3. Count the direct reports in each group.
4. Keep groups with at least five reports.
5. Return the manager's name.

Manual check: Dan, James, Amy, Anne, and Ron all have `managerId = 101`, so John has exactly five direct reports and qualifies. Only direct links are counted; the query does not follow additional levels of management. No `ORDER BY` is needed because the question accepts any order.

## My solution — SQL Server

SQL Server requires the selected, non-aggregated name column in GROUP BY. Adding E1.name alongside the manager ID preserves the same groups and counting logic.

```sql
SELECT E1.name
FROM Employee AS E1
JOIN Employee AS E2
    ON E1.id = E2.managerId
GROUP BY E2.managerId, E1.name
HAVING COUNT(E2.managerId) >= 5;
```
