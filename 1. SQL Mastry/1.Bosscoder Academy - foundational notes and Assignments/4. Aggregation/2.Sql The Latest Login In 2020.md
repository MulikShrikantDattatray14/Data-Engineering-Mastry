# 2. SQL The Latest Login In 2020

## Question and image

**2. Sql The Latest Login In 2020**

Table: Logins

| Column Name | Type |
|---|---|
| user_id | int |
| time_stamp | datetime |

`(user_id, time_stamp)` is the primary key (combination of columns with unique values) for this table. Each row contains information about the login time for the user with ID `user_id`.

Write a solution to report the latest login for all users in the year 2020. Do not include the users who did not login in 2020.

You can refer to the following example for understanding.

**Example 1:**

Input:

Logins table:

| user_id | time_stamp |
|---|---|
| 6 | 2020-06-30 15:06:07 |
| 6 | 2021-04-21 14:06:06 |
| 6 | 2019-03-07 00:18:15 |
| 8 | 2020-02-01 05:10:53 |
| 8 | 2020-12-30 00:46:50 |
| 2 | 2020-01-16 02:49:50 |
| 2 | 2019-08-25 07:59:08 |
| 14 | 2019-07-14 09:00:00 |
| 14 | 2021-01-06 11:59:59 |

Output:

| user_id | last_stamp |
|---|---|
| 6 | 2020-06-30 15:06:07 |
| 8 | 2020-12-30 00:46:50 |
| 2 | 2020-01-16 02:49:50 |

Explanation:

User 6 logged into their account 3 times but only once in 2020, so we include this login in the result table.

User 8 logged into their account 2 times in 2020, once in February and once in December. We include only the latest one (December) in the result table.

User 2 logged into their account 2 times but only once in 2020, so we include this login in the result table.

User 14 did not login in 2020, so we do not include them in the result table.

- (`user_id`, `time_stamp`) is the primary key.

## My solution — SQLite

```sql
SELECT
    user_id,
    MAX(time_stamp) AS last_stamp
FROM Logins
WHERE time_stamp >= '2020-01-01'
  AND time_stamp < '2021-01-01'
GROUP BY user_id;
```

### Key learnings

- `WHERE` first keeps only login rows from 2020.
- `GROUP BY user_id` then creates one group for each user who logged in during 2020.
- `MAX(time_stamp)` finds the latest timestamp inside each user's filtered 2020 group.
- Filtering before calculating `MAX()` is essential. Otherwise, a login from 2021 could become the user's maximum timestamp.
- Users without a 2020 row are naturally excluded because they have no rows left after the `WHERE` filter.
- The half-open range `>= '2020-01-01' AND < '2021-01-01'` includes every possible timestamp in 2020.
- `LIMIT 1` must not be used because the query must return the latest login for every qualifying user, not only one user.

### Step-by-step explanation with one example

Use the supplied example throughout. Each query below runs against these same starting rows; intermediate SELECT statements do not modify the tables.

**Starting data**

`Logins`:

| user_id | time_stamp |
| --- | --- |
| 6 | 2020-06-30 15:06:07 |
| 6 | 2021-04-21 14:06:06 |
| 6 | 2019-03-07 00:18:15 |

**1. Keep only login rows in 2020**

Filtering must happen before finding each maximum. Otherwise user 6 could receive a 2021 login.

```sql
SELECT user_id, time_stamp
FROM Logins
WHERE time_stamp >= '2020-01-01'
  AND time_stamp < '2021-01-01'
ORDER BY user_id, time_stamp;
```

Result:

| user_id | time_stamp |
| --- | --- |
| 2 | 2020-01-16 02:49:50 |
| 6 | 2020-06-30 15:06:07 |
| 8 | 2020-02-01 05:10:53 |
| 8 | 2020-12-30 00:46:50 |

Four login rows remain. The lower boundary includes the beginning of 2020 and the exclusive upper boundary excludes all of 2021. User 14 has no remaining row.

**2. Group the retained logins by user**

A result row represents one user. COUNT here is only a diagnostic to show how many filtered logins MAX considers in each group.

```sql
SELECT user_id, COUNT(*) AS login_count, MAX(time_stamp) AS last_stamp
FROM Logins
WHERE time_stamp >= '2020-01-01'
  AND time_stamp < '2021-01-01'
GROUP BY user_id;
```

Result:

| user_id | login_count | last_stamp |
| --- | --- | --- |
| 2 | 1 | 2020-01-16 02:49:50 |
| 6 | 1 | 2020-06-30 15:06:07 |
| 8 | 2 | 2020-12-30 00:46:50 |

User 8 has two candidate logins, so MAX selects December 30. Users 2 and 6 each have one candidate.

**3. Assemble the final query**

Combine the steps using the saved solution. The query below preserves the original logic.

```sql
SELECT
    user_id,
    MAX(time_stamp) AS last_stamp
FROM Logins
WHERE time_stamp >= '2020-01-01'
  AND time_stamp < '2021-01-01'
GROUP BY user_id;
```

Final result for this example:

| user_id | last_stamp |
| --- | --- |
| 2 | 2020-01-16 02:49:50 |
| 6 | 2020-06-30 15:06:07 |
| 8 | 2020-12-30 00:46:50 |

**Check the result:** The final query removes the diagnostic count and returns users 2, 6, and 8 with their latest 2020 timestamps. No output ordering is required; a different row order from the prompt has the same result.

## My solution — SQL Server

```sql
SELECT
    user_id,
    MAX(time_stamp) AS last_stamp
FROM Logins
WHERE time_stamp >= '2020-01-01'
  AND time_stamp < '2021-01-01'
GROUP BY user_id;
```

The same query works in SQLite and SQL Server.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
