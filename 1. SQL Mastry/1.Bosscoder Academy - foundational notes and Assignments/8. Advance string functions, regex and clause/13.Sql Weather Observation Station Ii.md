# 13. SQL Weather Observation Station II

## Question and image

**7. Sql Weather Observation Station Ii**

Query the list of CITY names from STATION that do not start with vowels and do not end with vowels. Your result cannot contain duplicates.

Input Format

The STATION table is described as follows:

| Field | Type |
|---|---|
| ID | NUMBER |
| CITY | VARCHAR2(21) |
| STATE | VARCHAR2(2) |
| LAT_N | NUMBER |
| LONG_W | NUMBER |

where LAT_N is the northern latitude and LONG_W is the western longitude.

| 4 | Boston | MA | 42.4 | -71.1 |

**Output:**

| CITY |

## My solution — SQLite

```sql
SELECT DISTINCT CITY
FROM STATION
WHERE CITY NOT GLOB '[AEIOUaeiou]*'
  AND CITY NOT GLOB '*[AEIOUaeiou]';
```

### Step-by-step explanation with one example

**1. Define the output and inspect STATION**

The final result needs only CITY, with each qualifying name once. Each name must pass both conditions: it must not start with a vowel, and it must not end with a vowel. The question does not require a particular output order.

Use the same supplied sample throughout:

```sql
SELECT ID, CITY, STATE, LAT_N, LONG_W
FROM STATION;
```

| ID | CITY | STATE | LAT_N | LONG_W |
|---|---|---|---|---|
| 1 | Seattle | WA | 47.6 | -122.3 |
| 2 | Austin | TX | 30.3 | -97.7 |
| 3 | Chicago | IL | 41.8 | -87.6 |
| 4 | Boston | MA | 42.4 | -71.1 |
| 5 | Orlando | FL | 28.5 | -81.3 |

ID identifies the station row in this example. CITY contains the name we need to inspect and return. The state and coordinates do not affect this requirement. These tables show rows in sample order; the final solution does not impose a sort order.

**2. Keep names that do not start with a vowel**

```sql
SELECT ID, CITY
FROM STATION
WHERE CITY NOT GLOB '[AEIOUaeiou]*';
```

| ID | CITY |
|---|---|
| 1 | Seattle |
| 3 | Chicago |
| 4 | Boston |

`[AEIOUaeiou]` matches one uppercase or lowercase English vowel. The `*` after the group accepts any remaining characters, so the complete pattern checks whether the first character is a vowel. `NOT GLOB` keeps names that fail that initial-vowel pattern.

Seattle, Chicago, and Boston remain because their first characters are S, C, and B. Austin and Orlando are excluded because they begin with A and O.

The wildcard is necessary: `[AEIOUaeiou]` alone matches an entire value made of just one vowel. It would not check the first character of a longer name.

**3. Also require that the name does not end with a vowel**

```sql
SELECT ID, CITY
FROM STATION
WHERE CITY NOT GLOB '[AEIOUaeiou]*'
  AND CITY NOT GLOB '*[AEIOUaeiou]';
```

| ID | CITY |
|---|---|
| 4 | Boston |

Here `*` appears before the vowel group, so the group tests the final character. AND requires both checks to pass for the same city.

Among the three names retained by the first check, Seattle ends with e and Chicago ends with o, so both are excluded. Boston ends with n, so it remains. Listing lowercase vowels is necessary because GLOB is case-sensitive.

This step-by-step filtering is a way to understand the result; SQL does not guarantee that it evaluates WHERE conditions in that written order.

**4. Return only unique city names and assemble the final query**

```sql
SELECT DISTINCT CITY
FROM STATION
WHERE CITY NOT GLOB '[AEIOUaeiou]*'
  AND CITY NOT GLOB '*[AEIOUaeiou]';
```

| CITY |
|---|
| Boston |

`SELECT CITY` returns the single requested column. `DISTINCT` removes repeated values from that selected column. The sample contains only one qualifying Boston row, so duplicate removal does not change its output. If several station rows contained Boston, the final result would still display Boston once.

`SELECT DISTINCT *` would return every column and compare complete rows for duplicate removal. Different station IDs or coordinates would make two rows different even when their CITY values match. Selecting only CITY therefore matters both for the output shape and for the requested duplicate removal.

**5. Manually verify the same sample**

| CITY | First character | Last character | Does not start with a vowel? | Does not end with a vowel? | Keep with AND? |
|---|---|---|---|---|---|
| Seattle | S | e | Yes | No | No |
| Austin | A | n | No | Yes | No |
| Chicago | C | o | Yes | No | No |
| Boston | B | n | Yes | Yes | Yes |
| Orlando | O | o | No | No | No |

Only Boston has two true conditions, matching the supplied output. This query checks for nonvowel endpoints; it does not require every character inside the name to be a nonvowel. There is no counting or grouping calculation, so no aggregate or GROUP BY is needed.

## My solution — SQL Server

```sql
SELECT DISTINCT CITY COLLATE Latin1_General_100_BIN2 AS CITY
FROM STATION
WHERE CITY COLLATE Latin1_General_100_BIN2 NOT LIKE N'[AEIOUaeiou]%'
  AND CITY COLLATE Latin1_General_100_BIN2 NOT LIKE N'%[AEIOUaeiou]';
```

SQL Server LIKE supports bracket groups, so the SQLite GLOB pattern is adapted with `NOT LIKE` and `%` instead of `*`. AND still requires both endpoint checks, and DISTINCT still removes repeated city names. See [SQL Server LIKE](https://learn.microsoft.com/en-us/sql/t-sql/language-elements/like-transact-sql?view=sql-server-ver17).

`COLLATE Latin1_General_100_BIN2` makes character comparisons explicit rather than inheriting case or accent equivalences from a database default. Applying it to the selected CITY expression also keeps differently cased names distinct, consistent with SQLite's default binary text comparison for these examples. The N prefix makes the patterns Unicode, keeping trailing spaces significant for end-character matching. These are dialect adaptations; the user's filtering and duplicate-removal approach is preserved.
