Table: `Queries`

| Column Name | Type |
|---|---|
| query_name | varchar |
| result | varchar |
| position | int |
| rating | int |

This table may have duplicate rows.

This table contains information collected from some queries on a database.

The position column has a value from 1 to 500.

The rating column has a value from 1 to 5. Query with rating less than 3 is a poor query.

We define query `quality` as:

> The average of the ratio between query rating and its position.

We also define `poor query percentage` as:

> The percentage of all queries with rating less than 3.

Write a solution to find each `query_name`, the `quality` and `poor_query_percentage`.

Both `quality` and `poor_query_percentage` should be **rounded to 2 decimal places**.

Return the result table in **any order**.

The result format is in the following example.

**Example 1:**

**Input:**

Queries table:

| query_name | result | position | rating |
|---|---|---|---|
| Dog | Golden Retriever | 1 | 5 |
| Dog | German Shepherd | 2 | 5 |
| Dog | Mule | 200 | 1 |
| Cat | Shirazi | 5 | 2 |
| Cat | Siamese | 3 | 3 |
| Cat | Sphynx | 7 | 4 |

**Output:**

| query_name | quality | poor_query_percentage |
|---|---|---|
| Dog | 2.50 | 33.33 |
| Cat | 0.66 | 33.33 |

**Explanation:**

Dog queries quality is ((5 / 1) + (5 / 2) + (1 / 200)) / 3 = 2.50

Dog queries poor\_ query_percentage is (1 / 3) \* 100 = 33.33

Cat queries quality equals ((2 / 5) + (3 / 3) + (4 / 7)) / 3 = 0.66

Cat queries poor\_ query_percentage is (1 / 3) \* 100 = 33.33

## My solution — SQLite

### Approach 1: Correlated subquery

The user's current solution, with table aliases made explicit throughout:

```sql
SELECT
    Q1.query_name,
    ROUND(
        SUM(Q1.rating * 1.0 / Q1.position) / COUNT(Q1.query_name),
        2
    ) AS quality,
    ROUND(
        (
            SELECT COUNT(Q2.rating)
            FROM Queries AS Q2
            WHERE Q2.rating < 3
              AND Q2.query_name = Q1.query_name
        ) * 100.0 / COUNT(Q1.query_name),
        2
    ) AS poor_query_percentage
FROM Queries AS Q1
GROUP BY Q1.query_name;
```

### Approach 2: Two CTEs and a join

This preserves the user's earlier solution from [Section 5, Question 1](<../5. CTEs/1.Sql Queries Quality And Percentage.md>). That prompt required ordering by `query_name`; the current prompt allows any order, so keeping the earlier `ORDER BY` is also valid.

```sql
WITH Quality AS (
    SELECT
        query_name,
        ROUND(
            SUM(rating * 1.0 / position) / COUNT(*),
            2
        ) AS quality
    FROM Queries
    GROUP BY query_name
),
Poor_quality_percentage AS (
    SELECT
        query_name,
        ROUND(
            SUM(CASE WHEN rating < 3 THEN 1 ELSE 0 END)
                * 100.0 / COUNT(*),
            2
        ) AS poor_query_percentage
    FROM Queries
    GROUP BY query_name
)
SELECT
    Quality.query_name AS query_name,
    ROUND(Quality.quality, 2) AS quality,
    ROUND(Poor_quality_percentage.poor_query_percentage, 2)
        AS poor_query_percentage
FROM Quality
JOIN Poor_quality_percentage
    ON Quality.query_name = Poor_quality_percentage.query_name
ORDER BY Quality.query_name ASC;
```

### Step-by-step explanation with one example

**1. Define the output and use the same input for both approaches**

Return one row per `query_name`, containing `quality` and `poor_query_percentage`, each rounded to two decimal places.

Use the supplied `Queries` table throughout:

| query_name | result | position | rating |
|---|---|---|---|
| Dog | Golden Retriever | 1 | 5 |
| Dog | German Shepherd | 2 | 5 |
| Dog | Mule | 200 | 1 |
| Cat | Shirazi | 5 | 2 |
| Cat | Siamese | 3 | 3 |
| Cat | Sphynx | 7 | 4 |

Both groups contain three rows. Dog has one poor result, Mule; Cat has one poor result, Shirazi. A rating of 3 is not poor because the condition is strictly `rating < 3`.

The calculations are:

- Quality: sum of the individual `rating / position` ratios divided by the group's row count.
- Poor-query percentage: the group's poor-row count divided by its total row count, multiplied by 100.

**2. Calculate each row's contribution to quality**

The denominator is `position`, not `rating`. Multiplying by `1.0` keeps the fractional part of division in SQLite.

```sql
SELECT
    query_name,
    result,
    rating,
    position,
    rating * 1.0 / position AS quality_contribution
FROM Queries;
```

| query_name | result | rating | position | quality_contribution |
|---|---|---|---|---|
| Dog | Golden Retriever | 5 | 1 | 5 |
| Dog | German Shepherd | 5 | 2 | 2.5 |
| Dog | Mule | 1 | 200 | 0.005 |
| Cat | Shirazi | 2 | 5 | 0.4 |
| Cat | Siamese | 3 | 3 | 1 |
| Cat | Sphynx | 4 | 7 | 0.5714285714... |

The last value is abbreviated for readability. This is an average of individual ratios; it is not the ratio of the total ratings to the total positions.

**3. Group the ratios and calculate quality**

In the correlated-subquery approach, the outer query groups the rows by `Q1.query_name`:

```sql
SELECT
    Q1.query_name,
    COUNT(Q1.query_name) AS total_rows,
    ROUND(
        SUM(Q1.rating * 1.0 / Q1.position) / COUNT(Q1.query_name),
        2
    ) AS quality
FROM Queries AS Q1
GROUP BY Q1.query_name;
```

| query_name | total_rows | quality |
|---|---|---|
| Cat | 3 | 0.66 |
| Dog | 3 | 2.50 |

For Dog, `(5 + 2.5 + 0.005) / 3 = 2.501666...`, which rounds to `2.50`.

For Cat, `(0.4 + 1 + 4/7) / 3 = 0.657142...`, which rounds to `0.66`.

Duplicate input rows must still contribute to these calculations. The query deliberately does not use `DISTINCT`.

**4. Approach 1: Count poor rows belonging to the current outer group**

`Q1` refers to the rows summarized by the outer query. `Q2` refers to the same table inside the subquery.

The condition `Q2.query_name = Q1.query_name` connects the subquery to the current group. For the Dog group, only Dog rows with `rating < 3` are counted; for the Cat group, only Cat rows with `rating < 3` are counted.

```sql
SELECT
    Q1.query_name,
    COUNT(Q1.query_name) AS total_rows,
    (
        SELECT COUNT(Q2.rating)
        FROM Queries AS Q2
        WHERE Q2.rating < 3
          AND Q2.query_name = Q1.query_name
    ) AS poor_rows
FROM Queries AS Q1
GROUP BY Q1.query_name;
```

| query_name | total_rows | poor_rows |
|---|---|---|
| Cat | 3 | 1 |
| Dog | 3 | 1 |

Without the name-matching condition, the subquery would count both poor rows in the entire table and return 2 for each outer group. Adding `GROUP BY query_name` inside an unconnected subquery would produce separate counts without selecting the count belonging to the current outer group.

The correlated subquery uses an aggregate without its own `GROUP BY`, so it returns one count for the current name. If that name has no poor rows, the count is 0.

**5. Approach 1: Convert the count to a percentage and assemble the query**

For each sample group, the percentage is `1 * 100.0 / 3 = 33.3333...`. Multiplication by `100.0` both converts the fraction to a percentage and makes the division decimal. Round after completing the calculation.

```sql
SELECT
    Q1.query_name,
    ROUND(
        SUM(Q1.rating * 1.0 / Q1.position) / COUNT(Q1.query_name),
        2
    ) AS quality,
    ROUND(
        (
            SELECT COUNT(Q2.rating)
            FROM Queries AS Q2
            WHERE Q2.rating < 3
              AND Q2.query_name = Q1.query_name
        ) * 100.0 / COUNT(Q1.query_name),
        2
    ) AS poor_query_percentage
FROM Queries AS Q1
GROUP BY Q1.query_name;
```

| query_name | quality | poor_query_percentage |
|---|---|---|
| Cat | 0.66 | 33.33 |
| Dog | 2.50 | 33.33 |

The current problem allows any row order. `ROUND(..., 2)` rounds the numeric value; SQLite may display `2.5` rather than padding it to `2.50`. Both represent the same value.

**6. Approach 2: Mark poor rows using CASE**

The earlier CTE solution calculates the poor-row count through flags. Each poor row contributes 1, and each other row contributes 0:

```sql
SELECT
    query_name,
    result,
    rating,
    CASE WHEN rating < 3 THEN 1 ELSE 0 END AS poor_flag
FROM Queries;
```

| query_name | result | rating | poor_flag |
|---|---|---|---|
| Dog | Golden Retriever | 5 | 0 |
| Dog | German Shepherd | 5 | 0 |
| Dog | Mule | 1 | 1 |
| Cat | Shirazi | 2 | 1 |
| Cat | Siamese | 3 | 0 |
| Cat | Sphynx | 4 | 0 |

Adding each group's flags gives its poor-row count: `0 + 0 + 1 = 1` for Dog, and `1 + 0 + 0 = 1` for Cat. The other rows remain present for the denominator.

**7. Approach 2: Build the two summaries separately**

The `Quality` CTE calculates the same average of ratios as before:

```sql
WITH Quality AS (
    SELECT
        query_name,
        ROUND(
            SUM(rating * 1.0 / position) / COUNT(*),
            2
        ) AS quality
    FROM Queries
    GROUP BY query_name
)
SELECT * FROM Quality;
```

| query_name | quality |
|---|---|
| Cat | 0.66 |
| Dog | 2.50 |

The `Poor_quality_percentage` CTE sums the flags, divides by all rows in the group, and converts to a percentage:

```sql
WITH Poor_quality_percentage AS (
    SELECT
        query_name,
        ROUND(
            SUM(CASE WHEN rating < 3 THEN 1 ELSE 0 END)
                * 100.0 / COUNT(*),
            2
        ) AS poor_query_percentage
    FROM Queries
    GROUP BY query_name
)
SELECT * FROM Poor_quality_percentage;
```

| query_name | poor_query_percentage |
|---|---|
| Cat | 33.33 |
| Dog | 33.33 |

Each CTE produces one row per query name. `COUNT(*)` counts all rows in each group. For the non-NULL names in this example, it equals `COUNT(query_name)` in the first approach.

**8. Approach 2: Join the summaries and assemble the final query**

Join the CTEs on `query_name` so Cat's quality is combined with Cat's percentage and Dog's quality with Dog's percentage. Because each summary has one row per name, this join does not multiply the group's rows.

```sql
WITH Quality AS (
    SELECT
        query_name,
        ROUND(
            SUM(rating * 1.0 / position) / COUNT(*),
            2
        ) AS quality
    FROM Queries
    GROUP BY query_name
),
Poor_quality_percentage AS (
    SELECT
        query_name,
        ROUND(
            SUM(CASE WHEN rating < 3 THEN 1 ELSE 0 END)
                * 100.0 / COUNT(*),
            2
        ) AS poor_query_percentage
    FROM Queries
    GROUP BY query_name
)
SELECT
    Quality.query_name AS query_name,
    ROUND(Quality.quality, 2) AS quality,
    ROUND(Poor_quality_percentage.poor_query_percentage, 2)
        AS poor_query_percentage
FROM Quality
JOIN Poor_quality_percentage
    ON Quality.query_name = Poor_quality_percentage.query_name
ORDER BY Quality.query_name ASC;
```

| query_name | quality | poor_query_percentage |
|---|---|---|
| Cat | 0.66 | 33.33 |
| Dog | 2.50 | 33.33 |

The final `ROUND` calls repeat rounding already done in the CTEs. They are retained from the user's saved solution.

**9. Check both approaches with the same example**

- Both return one Cat row and one Dog row.
- Both calculate quality from individual `rating / position` ratios.
- Both divide the poor-row count by all three rows for that name.
- Both produce `33.33` for the sample percentages because each group has one poor row out of three; their quality values differ.
- Both preserve duplicate input rows as contributions to the calculations.
- The CTE version explicitly sorts by name. The correlated version can return either group first, which satisfies the current prompt.

Both saved queries rely on non-NULL query names for their intended results. In the correlated version, `COUNT(query_name)` is 0 for a NULL-name group, and the equality condition does not match NULL names. In SQLite, that group's divisions return NULL. In the CTE version, the equality join omits the NULL-name group. The original logic is preserved.
