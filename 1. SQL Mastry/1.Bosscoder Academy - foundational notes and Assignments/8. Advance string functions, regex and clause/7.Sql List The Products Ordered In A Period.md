## Schema

**Products**

| Column Name | Type |
|---|---|
| product_id | int |
| product_name | varchar |
| product_category | varchar |

- `product_id` is the primary key.
- Each row describes a company product.

**Orders**

| Column Name | Type |
|---|---|
| product_id | int |
| order_date | date |
| unit | int |

- Duplicate rows are allowed.
- `product_id` is a foreign key referencing `Products`.
- `unit` is the number of products ordered on `order_date`.

## My solution — SQLite

```sql
SELECT
    Products.product_name AS product_name,
    SUM(Orders.unit) AS unit
FROM Products
JOIN Orders
    ON Products.product_id = Orders.product_id
WHERE Orders.order_date > '2020-01-31'
  AND Orders.order_date < '2020-03-01'
GROUP BY Orders.product_id
HAVING SUM(Orders.unit) >= 100
ORDER BY unit DESC, product_name DESC;
```

This assignment version requires the total units in descending order, with product names in descending order when totals tie.

### Step-by-step explanation with one example

**1. Define the output and inspect the two input tables**

Return one row for each product whose total ordered units in February 2020 are at least 100. The output columns are `product_name` and the total as `unit`. Sort by the total descending, then by product name descending for equal totals.

Use the same supplied data throughout.

`Products`:

`Orders`:

`Products` gives each product's name. `Orders` gives its order dates and quantities. The shared `product_id` connects the tables.

**2. Join each order to its product name**

`JOIN` without a join type means an inner join. A product must have matching orders to reach the required total, so an inner join fits this problem.

```sql

    Products.product_name,
    Orders.order_date,
    Orders.unit
FROM Products
JOIN Orders
    ON Products.product_id = Orders.product_id
ORDER BY Orders.product_id, Orders.order_date, Orders.unit;
```

|---|---|---|---|
| 1 | Leetcode Solutions | 2020-02-05 | 60 |
| 1 | Leetcode Solutions | 2020-02-10 | 70 |
| 2 | Jewels of Stringology | 2020-01-18 | 30 |
| 2 | Jewels of Stringology | 2020-02-11 | 80 |

The ordering in these inspection queries makes the intermediate tables easy to read. The final query uses the required total-unit and product-name ordering instead.

**3. Keep only the orders from February 2020**

Filter the rows before calculating product totals:

```sql
SELECT
    Orders.product_id,
    Products.product_name,
    Orders.order_date,
    Orders.unit
FROM Products
JOIN Orders
    ON Products.product_id = Orders.product_id
WHERE Orders.order_date > '2020-01-31'
  AND Orders.order_date < '2020-03-01'
ORDER BY Orders.product_id, Orders.order_date, Orders.unit;
```

| product_id | product_name | order_date | unit |
|---|---|---|---|
| 1 | Leetcode Solutions | 2020-02-05 | 60 |
| 1 | Leetcode Solutions | 2020-02-10 | 70 |
| 2 | Jewels of Stringology | 2020-02-11 | 80 |
| 3 | HP | 2020-02-17 | 2 |
| 3 | HP | 2020-02-24 | 3 |
| 5 | Leetcode Kit | 2020-02-25 | 50 |
| 5 | Leetcode Kit | 2020-02-27 | 50 |

Seven rows remain. The January order for product 2 and all March orders are excluded. Product 4 has no February order, so it has no rows left to group.

For the supplied ISO date-only values, later than `2020-01-31` and earlier than `2020-03-01` covers February 2020, including February 29.

**4. Group the remaining rows by product and add their units**

`GROUP BY Orders.product_id` creates one group per product. Keep the product ID as the grouping key because different products can have the same name.

Compare the number of order entries with the number of units:

```sql
SELECT
    Orders.product_id,
    Products.product_name,
    COUNT(Orders.unit) AS order_entries,
    SUM(Orders.unit) AS total_units
FROM Products
JOIN Orders
    ON Products.product_id = Orders.product_id
WHERE Orders.order_date > '2020-01-31'
  AND Orders.order_date < '2020-03-01'
GROUP BY Orders.product_id
ORDER BY Orders.product_id;
```

| product_id | product_name | order_entries | total_units |
|---|---|---|---|
| 1 | Leetcode Solutions | 2 | 130 |
| 2 | Jewels of Stringology | 1 | 80 |
| 3 | HP | 2 | 5 |
| 5 | Leetcode Kit | 2 | 100 |

For product 1, `COUNT(Orders.unit)` gives 2 because there are two non-NULL quantity entries. `SUM(Orders.unit)` gives `60 + 70 = 130`, which is what the problem asks for.

Product 5's total is `50 + 50 = 100`. Its additional March quantity of 50 was already excluded by `WHERE`.

Duplicate order rows are permitted by the schema. Each row contributes its units; using `DISTINCT` would incorrectly discard legitimate repeated orders.

**5. Keep only groups whose total is at least 100**

`WHERE` selected the individual order rows. `HAVING` now checks the aggregate for each product group.

| product_id | February total | Keep? |
|---|---|---|
| 1 | 130 | Yes |
| 2 | 80 | No |
| 3 | 5 | No |
| 5 | 100 | Yes |

The comparison is `>= 100`, so the product with exactly 100 units qualifies.

The total is needed in both places: `SUM(Orders.unit)` in `SELECT` displays it, and `SUM(Orders.unit)` in `HAVING` decides whether the group qualifies.

**6. Sort the qualifying groups, assemble the query, and check the result**

`ORDER BY unit DESC` places the largest total first. Here, `unit` is the output alias for `SUM(Orders.unit)`. `product_name DESC` is the second sorting rule and applies when two totals are equal. It orders tied product names in descending alphabetical order.

```sql
SELECT
    Products.product_name AS product_name,
    SUM(Orders.unit) AS unit
FROM Products
JOIN Orders
    ON Products.product_id = Orders.product_id
WHERE Orders.order_date > '2020-01-31'
  AND Orders.order_date < '2020-03-01'
GROUP BY Orders.product_id
HAVING SUM(Orders.unit) >= 100
ORDER BY unit DESC, product_name DESC;
```

| product_name | unit |
|---|---|
| Leetcode Solutions | 130 |
| Leetcode Kit | 100 |

The result contains two qualifying products. Product 1 has `60 + 70 = 130` February units. Product 5 has `50 + 50 = 100`. Products 2 and 3 are below the threshold; product 4 has no February orders.

The query displays the product name from `Products` and the aggregated quantity under the required alias `unit`. In SQLite, selecting that name while grouping by the joined product ID works here because the primary key ensures every row in the product group has the same name.

The sample has no tied totals: 130 comes before 100, so Leetcode Solutions comes before Leetcode Kit. The second ordering expression is still necessary to handle equal totals in other inputs. Both sorting directions are descending, as required.

## My solution — SQL Server

```sql
SELECT
    Products.product_name AS product_name,
    SUM(Orders.unit) AS unit
FROM Products
JOIN Orders
    ON Products.product_id = Orders.product_id
WHERE Orders.order_date > '2020-01-31'
  AND Orders.order_date < '2020-03-01'
GROUP BY Orders.product_id, Products.product_name
HAVING SUM(Orders.unit) >= 100
ORDER BY unit DESC, product_name DESC;
```

The join, date-only bounds, total calculation, and threshold are unchanged. SQL Server requires the selected, non-aggregated `Products.product_name` to appear in `GROUP BY`, so it is grouped along with `Orders.product_id`.

Keeping the ID in the grouping prevents distinct products with the same name from being merged. The date bounds apply to the schema's `DATE` column. The same `ORDER BY unit DESC, product_name DESC` preserves the required descending total and tie-break ordering.
