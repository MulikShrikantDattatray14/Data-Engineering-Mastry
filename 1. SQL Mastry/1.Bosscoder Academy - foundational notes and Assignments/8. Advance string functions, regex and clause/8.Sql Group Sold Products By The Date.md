# 8. SQL Group Sold Products By The Date

## Question and image

**2. Sql Group Sold Products By The Date**

Table Activities:

| Column Name | Type |
|---|---|
| sell_date | date |
| product | varchar |

There is no primary key (column with unique values) for this table. It may contain duplicates.

Each row of this table contains the product name and the date it was sold in a market.

Write a solution to find for each date the number of different products sold and their names.

The sold products names for each date should be sorted lexicographically.

Return the result table ordered by sell_date.

**Example 1:**

Example:

**Input:**

Activities table:

| sell_date | product |
|---|---|
| 2020-05-30 | Headphone |
| 2020-06-01 | Pencil |
| 2020-06-02 | Mask |
| 2020-05-30 | Basketball |
| 2020-06-01 | Bible |
| 2020-06-02 | Mask |
| 2020-05-30 | T-Shirt |

**Output:**

| sell_date | num_sold | products |
|---|---|---|
| 2020-05-30 | 3 | Basketball,Headphone,T-shirt |
| 2020-06-01 | 2 | Bible,Pencil |
| 2020-06-02 | 1 | Mask |

**Explanation:**

For 2020-05-30, Sold items were (Headphone, Basketball, T-shirt), we sort them lexicographically and separate them by a comma.

For 2020-06-01, Sold items were (Pencil, Bible), we sort them lexicographically and separate them by a comma.

For 2020-06-02, the Sold item is (Mask), we just return it.

## My solution — SQLite

### Solution 1 — SQLite 3.44.0 or newer

```sql
SELECT
    sell_date,
    COUNT(DISTINCT product) AS num_sold,
    GROUP_CONCAT(DISTINCT product ORDER BY product ASC) AS products
FROM Activities
GROUP BY sell_date
ORDER BY sell_date;
```

This version requires **SQLite 3.44.0 or newer**, which supports an `ORDER BY` clause inside aggregate functions. [SQLite 3.44.0 release notes](https://www.sqlite.org/releaselog/3_44_0.html)

### Solution 2 — Older SQLite compatible syntax

Use this version when the SQLite runner does not support `ORDER BY` inside `GROUP_CONCAT`. The subquery removes duplicate date-product pairs and sorts them before the outer query combines each date's products.

```sql
SELECT
    sell_date,
    COUNT(DISTINCT product) AS num_sold,
    GROUP_CONCAT(product) AS products
FROM (
    SELECT DISTINCT sell_date, product
    FROM Activities
    ORDER BY sell_date, product ASC
) AS sorted_products
GROUP BY sell_date
ORDER BY sell_date;
```

`sorted_products` is the alias of the derived table. This version keeps the same counting, duplicate-removal, alphabetical-list, and date-ordering requirements as Solution 1. It uses the sorted-subquery approach for SQLite; Solution 1 expresses the aggregate's ordering directly when the engine supports it.

### Step-by-step explanation with one example

**1. Define the output and inspect the same input rows**

Each result row represents one `sell_date`. It must contain the number of different products as `num_sold` and their comma-separated names as `products`. The names must be alphabetical, and the final rows must be ordered by date.

Use the supplied `Activities` table throughout:

| sell_date | product |
|---|---|
| 2020-05-30 | Headphone |
| 2020-06-01 | Pencil |
| 2020-06-02 | Mask |
| 2020-05-30 | Basketball |
| 2020-06-01 | Bible |
| 2020-06-02 | Mask |
| 2020-05-30 | T-Shirt |

There are seven sale rows but only three different dates. The repeated `Mask` sale should not increase the number of different products or repeat the name in the final list.

**2. Group by date and count the different products**

`GROUP BY sell_date` puts all rows for the same date into one group. `COUNT(DISTINCT product)` counts each different non-NULL product once within that group.

Use this query to compare sale rows with different products:

```sql
SELECT
    sell_date,
    COUNT(product) AS sale_rows,
    COUNT(DISTINCT product) AS num_sold
FROM Activities
GROUP BY sell_date
ORDER BY sell_date;
```

| sell_date | sale_rows | num_sold |
|---|---|---|
| 2020-05-30 | 3 | 3 |
| 2020-06-01 | 2 | 2 |
| 2020-06-02 | 2 | 1 |

On May 30, all three products differ. On June 1, both products differ. On June 2, both rows contain `Mask`, so the distinct count is only 1. The final query returns `num_sold`; `sale_rows` is included here only to explain the difference.

**3. Identify the names that should appear once per date**

To inspect the distinct values in alphabetical order, run:

```sql
SELECT DISTINCT sell_date, product
FROM Activities
ORDER BY sell_date, product;
```

| sell_date | product |
|---|---|
| 2020-05-30 | Basketball |
| 2020-05-30 | Headphone |
| 2020-05-30 | T-Shirt |
| 2020-06-01 | Bible |
| 2020-06-01 | Pencil |
| 2020-06-02 | Mask |

This inspection query shows six distinct date-product pairs. Only the repeated `Mask` pair is removed. A product sold on different dates would still belong to each date's group.

These are the names we want the final aggregate to combine. Solution 1 performs this duplicate removal directly inside `GROUP_CONCAT`; the inspection query is not an additional required step in that version. Solution 2 uses this distinct, sorted result as its input, as explained in step 7.

**4. Combine each date's distinct names in alphabetical order**

`GROUP_CONCAT(DISTINCT product ORDER BY product ASC)` performs the string aggregation for each date:

- `DISTINCT product` removes repeated names within that date.
- `ORDER BY product ASC` specifies the order in which the aggregate combines the names.
- `GROUP_CONCAT` joins the names with a comma by default.

```sql
SELECT
    sell_date,
    GROUP_CONCAT(DISTINCT product ORDER BY product ASC) AS products
FROM Activities
GROUP BY sell_date
ORDER BY sell_date;
```

| sell_date | products |
|---|---|
| 2020-05-30 | Basketball,Headphone,T-Shirt |
| 2020-06-01 | Bible,Pencil |
| 2020-06-02 | Mask |

For June 1, `Bible` comes before `Pencil`. For June 2, the duplicate `Mask` is listed only once. `DISTINCT` inside `COUNT` affects only the count, so the separate `DISTINCT` inside `GROUP_CONCAT` is also needed in this query.

The ordering inside the aggregate controls the product names; the final `ORDER BY sell_date` controls the date rows. These are two separate ordering requirements. [SQLite aggregate documentation](https://www.sqlite.org/lang_aggfunc.html)

**5. Assemble the final query**

Return the date, the distinct count, and the ordered product list together:

```sql
SELECT
    sell_date,
    COUNT(DISTINCT product) AS num_sold,
    GROUP_CONCAT(DISTINCT product ORDER BY product ASC) AS products
FROM Activities
GROUP BY sell_date
ORDER BY sell_date;
```

| sell_date | num_sold | products |
|---|---|---|
| 2020-05-30 | 3 | Basketball,Headphone,T-Shirt |
| 2020-06-01 | 2 | Bible,Pencil |
| 2020-06-02 | 1 | Mask |

The aliases `num_sold` and `products` give the required output column names. `ORDER BY sell_date` sorts the result rows ascending by default.

**6. Check the result manually**

- May 30 has three different products: Basketball, Headphone, and T-Shirt. The count is 3 and the names are alphabetical.
- June 1 has two different products: Bible and Pencil. The count is 2 and the names are alphabetical.
- June 2 has two sale rows for the same product, Mask. The count is 1 and the list contains Mask once.
- The output contains exactly three rows, one per date, in ascending date order.
- The query preserves product spelling. The supplied input says `T-Shirt`, so the executed result also says `T-Shirt`. The prompt's displayed `T-shirt` is a source inconsistency, not a requirement to change the case.

**7. Use the same example with the older SQLite version**

The logic stays the same: one occurrence of each product per date, an alphabetical list of those products, and one result row per date. The location of the duplicate removal and sorting changes.

**First, prepare the rows that will be combined.**

```sql
SELECT DISTINCT sell_date, product
FROM Activities
ORDER BY sell_date, product ASC;
```

| sell_date | product |
|---|---|
| 2020-05-30 | Basketball |
| 2020-05-30 | Headphone |
| 2020-05-30 | T-Shirt |
| 2020-06-01 | Bible |
| 2020-06-01 | Pencil |
| 2020-06-02 | Mask |

The seven starting rows become six distinct date-product pairs. Only the repeated `Mask` row for June 2 is removed. May 30's products are now Basketball, Headphone, and T-Shirt; June 1's products are Bible and Pencil. A product sold on two different dates still belongs to both dates.

This is the same intermediate table inspected in step 3. In Solution 2, it becomes the actual input to the outer query.

**Next, combine the prepared product rows within each date.**

```sql
SELECT
    sell_date,
    GROUP_CONCAT(product) AS products
FROM (
    SELECT DISTINCT sell_date, product
    FROM Activities
    ORDER BY sell_date, product ASC
) AS sorted_products
GROUP BY sell_date
ORDER BY sell_date;
```

| sell_date | products |
|---|---|
| 2020-05-30 | Basketball,Headphone,T-Shirt |
| 2020-06-01 | Bible,Pencil |
| 2020-06-02 | Mask |

For this SQLite approach, the ordered subquery supplies the product names to the aggregate. `GROUP_CONCAT(product)` combines them using commas. It does not need its own `DISTINCT` because the input already contains each product once per date.

The inner ordering prepares the product lists. The outer `ORDER BY sell_date` orders the result rows; these clauses serve different purposes.

**Finally, include the distinct count and assemble Solution 2.**

```sql
SELECT
    sell_date,
    COUNT(DISTINCT product) AS num_sold,
    GROUP_CONCAT(product) AS products
FROM (
    SELECT DISTINCT sell_date, product
    FROM Activities
    ORDER BY sell_date, product ASC
) AS sorted_products
GROUP BY sell_date
ORDER BY sell_date;
```

| sell_date | num_sold | products |
|---|---|---|
| 2020-05-30 | 3 | Basketball,Headphone,T-Shirt |
| 2020-06-01 | 2 | Bible,Pencil |
| 2020-06-02 | 1 | Mask |

May 30 has three distinct products, June 1 has two, and June 2 has one. This agrees with the manual check in step 6 and the result of Solution 1.

`COUNT(DISTINCT product)` is retained from the original solution. Deduplicating in the subquery already prevents repeats, but retaining this expression preserves the original counting rule, including ignoring NULL product values. The earlier `Mask` duplicate neither increases the count nor appears twice in the list.

## My solution — SQL Server

Both SQLite versions have the following SQL Server equivalent. Duplicate removal happens in the derived table, while the alphabetical list order is specified explicitly inside `WITHIN GROUP`.

```sql
SELECT
    sell_date,
    COUNT(DISTINCT product) AS num_sold,
    STRING_AGG(CONVERT(varchar(max), product), ',')
        WITHIN GROUP (ORDER BY product ASC) AS products
FROM (
    SELECT DISTINCT sell_date, product
    FROM Activities
) AS distinct_products
GROUP BY sell_date
ORDER BY sell_date;
```

SQL Server uses `STRING_AGG` with `WITHIN GROUP (ORDER BY ...)` for an ordered string list. Its syntax does not accept `DISTINCT` directly inside `STRING_AGG`, so the derived table first selects distinct `sell_date, product` pairs. This preserves the user's rule that each product appears once per date, while retaining the distinct count and final date ordering.

`CONVERT(varchar(max), product)` lets the aggregate produce a long product list without the fixed-length limit associated with a normal `varchar` input. `STRING_AGG` requires SQL Server 2017 or newer; its ordering clause requires database compatibility level 110 or above. [Microsoft STRING_AGG documentation](https://learn.microsoft.com/en-us/sql/t-sql/functions/string-agg-transact-sql?view=sql-server-ver17)
