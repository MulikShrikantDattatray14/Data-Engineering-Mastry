# 1. SQL Queries Quality And Percentage

## Question and image

**1. Sql Queries Quality And Percentage**

Table: Queries

| Column Name | Type |
|---|---|
| query_name | varchar |
| result | varchar |
| position | int |
| rating | int |

This table may have duplicate rows.

This table contains information collected from some queries on a database.

The `position` column has a value from 1 to 500.

The `rating` column has a value from 1 to 5. Query with rating less than 3 is a poor query.

We define query quality as:

The average of the ratio between query rating and its position.

We also define poor query percentage as:

The percentage of all queries with rating less than 3.

Write a solution to find each `query_name`, the quality and `poor_query_percentage`.

Both quality and `poor_query_percentage` should be rounded to 2 decimal places.

Return the result table ordered by `query_name`.

**Example 1:**

Input:

Queries table:

| query_name | result | position | rating |
|---|---|---|---|
| Dog | Golden Retriever | 1 | 5 |
| Dog | German Shepherd | 2 | 5 |
| Dog | Mule | 200 | 1 |
| Cat | Shirazi | 5 | 2 |
| Cat | Siamese | 3 | 3 |
| Cat | Sphynx | 7 | 4 |

Output:

| query_name | quality | poor_query_percentage |
|---|---|---|
| Cat | 0.66 | 33.33 |
| Dog | 2.50 | 33.33 |

*Explanation:*

Dog queries quality is ((5 / 1) + (5 / 2) + (1 / 200)) / 3 = 2.50

Dog queries poor_ query_percentage is (1 / 3) * 100 = 33.33

Cat queries quality equals ((2 / 5) + (3 / 3) + (4 / 7)) / 3 = 0.66

Cat queries poor_ query_percentage is (1 / 3) * 100 = 33.33

## Schema

**Queries**  
query_name, result, position, rating

- `query_name` — varchar
- `result` — varchar
- `position` — integer from 1 to 500
- `rating` — integer from 1 to 5
- The table may contain duplicate rows.
- A rating below 3 identifies a poor query.

## My solution — SQLite

```sql
WITH Quality AS (
    SELECT
        query_name,
        ROUND(
            SUM(rating * 1.0 / position) / COUNT(*),
            2
        ) AS quality
    FROM Queries
    GROUP BY query_name
),
Poor_quality_percentage AS (
    SELECT
        query_name,
        ROUND(
            SUM(CASE WHEN rating < 3 THEN 1 ELSE 0 END)
                * 100.0 / COUNT(*),
            2
        ) AS poor_query_percentage
    FROM Queries
    GROUP BY query_name
)
SELECT
    Quality.query_name AS query_name,
    ROUND(Quality.quality, 2) AS quality,
    ROUND(Poor_quality_percentage.poor_query_percentage, 2)
        AS poor_query_percentage
FROM Quality
JOIN Poor_quality_percentage
    ON Quality.query_name = Poor_quality_percentage.query_name
ORDER BY Quality.query_name ASC;
```

### Step-by-step explanation with one example

Use the supplied example throughout. Each result below is produced from those same rows; the final query preserves your saved approach.

**Starting data**

`Queries`:

| query_name | result | position | rating |
| --- | --- | --- | --- |
| Dog | Golden Retriever | 1 | 5 |
| Dog | German Shepherd | 2 | 5 |
| Dog | Mule | 200 | 1 |
| Cat | Shirazi | 5 | 2 |
| Cat | Siamese | 3 | 3 |
| Cat | Sphynx | 7 | 4 |

**1. Calculate the contribution of each query result**

Quality averages rating divided by position. A poor result contributes 1 to the poor-query count and every other result contributes 0.

```sql
SELECT query_name, result, position, rating,
       rating * 1.0 / position AS quality_contribution,
       CASE WHEN rating < 3 THEN 1 ELSE 0 END AS poor_flag
FROM Queries;
```

Result:

| query_name | result | position | rating | quality_contribution | poor_flag |
| --- | --- | --- | --- | --- | --- |
| Dog | Golden Retriever | 1 | 5 | 5 | 0 |
| Dog | German Shepherd | 2 | 5 | 2.5 | 0 |
| Dog | Mule | 200 | 1 | 0.005 | 1 |
| Cat | Shirazi | 5 | 2 | 0.4 | 1 |
| Cat | Siamese | 3 | 3 | 1 | 0 |
| Cat | Sphynx | 7 | 4 | 0.5714285714285714 | 0 |

For Dog, the contributions are 5, 2.5, and 0.005. Only Mule is poor. Multiplying by 1.0 keeps the fractional division; duplicate rows still contribute separately.

**2. Build one quality value per query name**

The Quality CTE adds the contributions and divides by the number of rows in that query group.

```sql
WITH Quality AS (
    SELECT
        query_name,
        ROUND(
            SUM(rating * 1.0 / position) / COUNT(*),
            2
        ) AS quality
    FROM Queries
    GROUP BY query_name
)
SELECT * FROM Quality;
```

Result:

| query_name | quality |
| --- | --- |
| Cat | 0.66 |
| Dog | 2.5 |

Dog gives 7.505 / 3 = 2.501666..., rounded to 2.50. Cat gives (0.4 + 1 + 4/7) / 3, rounded to 0.66.

**3. Build one poor-query percentage per query name**

Calculate the percentage separately, using all rows of each name as the denominator.

```sql
SELECT
        query_name,
        ROUND(
            SUM(CASE WHEN rating < 3 THEN 1 ELSE 0 END)
                * 100.0 / COUNT(*),
            2
        ) AS poor_query_percentage
    FROM Queries
    GROUP BY query_name;
```

Result:

| query_name | poor_query_percentage |
| --- | --- |
| Cat | 33.33 |
| Dog | 33.33 |

Each name has one poor result among three results, so both percentages are 1 * 100.0 / 3 = 33.33 after rounding.

**4. Assemble the final query**

Join the two summaries by query_name. Each summary has one row per name, so the join combines the two measures without multiplying result rows. Sort by query_name.

```sql
WITH Quality AS (
    SELECT
        query_name,
        ROUND(
            SUM(rating * 1.0 / position) / COUNT(*),
            2
        ) AS quality
    FROM Queries
    GROUP BY query_name
),
Poor_quality_percentage AS (
    SELECT
        query_name,
        ROUND(
            SUM(CASE WHEN rating < 3 THEN 1 ELSE 0 END)
                * 100.0 / COUNT(*),
            2
        ) AS poor_query_percentage
    FROM Queries
    GROUP BY query_name
)
SELECT
    Quality.query_name AS query_name,
    ROUND(Quality.quality, 2) AS quality,
    ROUND(Poor_quality_percentage.poor_query_percentage, 2)
        AS poor_query_percentage
FROM Quality
JOIN Poor_quality_percentage
    ON Quality.query_name = Poor_quality_percentage.query_name
ORDER BY Quality.query_name ASC;
```

Final result for this example:

| query_name | quality | poor_query_percentage |
| --- | --- | --- |
| Cat | 0.66 | 33.33 |
| Dog | 2.5 | 33.33 |

**Check the result:** The answer has two rows, one for Cat and one for Dog. Both poor percentages are 33.33, but their quality values differ because rating/position differs.

The saved join uses `Quality.query_name = Poor_quality_percentage.query_name`. It assumes non-NULL query names: if a NULL name is present, both CTEs create its group but the equality join does not match those NULL values, so that group is omitted. The original query is preserved.
