# 3. SQL Confirmation Rate

## Question and image

**3. Sql Confirmation Rate**

Table: Signups

| Column Name | Type |
|---|---|
| user_id | int |
| time_stamp | datetime |

`user_id` is the column of unique values for this table.

Each row contains information about the signup time for the user with ID `user_id`.

Table: Confirmations

| Column Name | Type |
|---|---|
| user_id | int |
| time_stamp | datetime |
| action | ENUM |

(`user_id`, `time_stamp`) is the primary key (combination of columns with unique values) for this table.

`user_id` is a foreign key (reference column) to the Signups table.

`action` is an ENUM (category) of the type (`'confirmed'`, `'timeout'`).

Each row of this table indicates that the user with ID `user_id` requested a confirmation message at `time_stamp` and that confirmation message was either confirmed (`'confirmed'`) or expired without confirming (`'timeout'`).

The confirmation rate of a user is the number of `'confirmed'` messages divided by the total number of requested confirmation messages. The confirmation rate of a user that did not request any confirmation messages is 0.

Write a solution to find the confirmation rate of each user.

Return the result table ordered by `user_id` in ascending order

**Example 1:**

Example:

Input:

Signups table:

| user_id | time_stamp |
|---|---|
| 3 | 2020-03-21 10:16:13 |
| 7 | 2020-01-04 13:57:59 |
| 2 | 2020-07-29 23:09:44 |
| 6 | 2020-12-09 10:39:37 |

Confirmations table:

| user_id | time_stamp | action |
|---|---|---|
| 3 | 2021-01-06 03:30:46 | timeout |
| 3 | 2021-07-14 14:00:00 | timeout |
| 7 | 2021-06-12 11:57:29 | confirmed |
| 7 | 2021-06-13 12:58:28 | confirmed |
| 7 | 2021-06-14 13:59:27 | confirmed |
| 2 | 2021-01-22 00:00:00 | confirmed |
| 2 | 2021-02-28 23:59:59 | timeout |

Output:

| user_id | confirmation_rate |
|---|---|
| 2 | 0.5 |
| 3 | 0.0 |
| 6 | 0.0 |
| 7 | 1.0 |

*Explanation:*

User 6 did not request any confirmation messages. The confirmation rate is 0.

User 3 made 2 requests and both timed out. The confirmation rate is 0.

User 7 made 3 requests and all were confirmed. The confirmation rate is 1.

User 2 made 2 requests where one was confirmed and the other timed out. The confirmation rate is 1 / 2 = 0.5.

## Schema

**Signups**  
user_id, time_stamp

- `user_id` - int, unique
- `time_stamp` - datetime

**Confirmations**  
user_id, time_stamp, action

- `user_id` - int, foreign key referencing `Signups.user_id`
- `time_stamp` - datetime
- `action` - ENUM containing `'confirmed'` or `'timeout'`
- (`user_id`, `time_stamp`) is the composite primary key.

## My solution — SQLite

```sql
WITH per_user_confirmed_action AS (
    SELECT
        S.user_id,
        SUM(
            CASE
                WHEN C.action = 'confirmed' THEN 1
                ELSE 0
            END
        ) AS Per_user_confirmed_action
    FROM Signups AS S
    LEFT JOIN Confirmations AS C
        ON S.user_id = C.user_id
    GROUP BY S.user_id
),
total_users AS (
    SELECT
        S.user_id,
        SUM(
            CASE
                WHEN C.action IN ('confirmed', 'timeout') THEN 1
                ELSE 0
            END
        ) AS total_request_count
    FROM Signups AS S
    LEFT JOIN Confirmations AS C
        ON S.user_id = C.user_id
    GROUP BY S.user_id
)
SELECT
    P.user_id,
    ROUND(
        CASE
            WHEN T.total_request_count = 0 THEN 0.0
            ELSE P.Per_user_confirmed_action * 1.0
                / T.total_request_count
        END,
        2
    ) AS confirmation_rate
FROM per_user_confirmed_action AS P
LEFT JOIN total_users AS T
    ON P.user_id = T.user_id
ORDER BY P.user_id ASC;
```

**1. Keep every signup while attaching its requests**

A user with no confirmation request still needs an output row, so start from Signups and LEFT JOIN Confirmations.

```sql
SELECT S.user_id, C.time_stamp, C.action
FROM Signups AS S
LEFT JOIN Confirmations AS C ON S.user_id = C.user_id
ORDER BY S.user_id, C.time_stamp;
```

Result:

| user_id | time_stamp | action |
| --- | --- | --- |
| 2 | 2021-01-22 00:00:00 | confirmed |
| 2 | 2021-02-28 23:59:59 | timeout |
| 3 | 2021-01-06 03:30:46 | timeout |
| 3 | 2021-07-14 14:00:00 | timeout |
| 6 | NULL | NULL |
| 7 | 2021-06-12 11:57:29 | confirmed |
| 7 | 2021-06-13 12:58:28 | confirmed |
| 7 | 2021-06-14 13:59:27 | confirmed |

User 6 gets one placeholder row with NULL request columns. That placeholder is not a real request.

**2. Count confirmed actions per user**

The first CTE turns confirmed into 1 and every other joined row into 0, then adds those flags per signup.

```sql
WITH per_user_confirmed_action AS (
    SELECT
        S.user_id,
        SUM(
            CASE
                WHEN C.action = 'confirmed' THEN 1
                ELSE 0
            END
        ) AS Per_user_confirmed_action
    FROM Signups AS S
    LEFT JOIN Confirmations AS C
        ON S.user_id = C.user_id
    GROUP BY S.user_id
)
SELECT * FROM per_user_confirmed_action ORDER BY user_id;
```

Result:

| user_id | Per_user_confirmed_action |
| --- | --- |
| 2 | 1 |
| 3 | 0 |
| 6 | 0 |
| 7 | 3 |

User 2 has one success, user 7 has three, and users 3 and 6 have none.

**3. Count actual requests per user**

The second CTE counts both valid action values as requests. The NULL placeholder contributes 0, which is essential for user 6.

```sql
WITH total_users AS (
    SELECT
        S.user_id,
        SUM(
            CASE
                WHEN C.action IN ('confirmed', 'timeout') THEN 1
                ELSE 0
            END
        ) AS total_request_count
    FROM Signups AS S
    LEFT JOIN Confirmations AS C
        ON S.user_id = C.user_id
    GROUP BY S.user_id

SELECT * FROM total_users ORDER BY user_id;
```

Result:

| user_id | total_request_count |
| --- | --- |
| 2 | 2 |
| 3 | 2 |
| 6 | 0 |
| 7 | 3 |

The counts are 2, 2, 0, and 3. COUNT(*) on the raw LEFT JOIN would instead count user 6's placeholder as one.

**4. Assemble the final query**

Join the two per-user summaries. Return 0.0 for zero requests; otherwise divide confirmed_count by request_count using decimal arithmetic. Round and sort by user_id.

```sql

    SELECT
        S.user_id,
        SUM(
            CASE
                WHEN C.action = 'confirmed' THEN 1
                ELSE 0
            END
        ) AS Per_user_confirmed_action
    FROM Signups AS S
    LEFT JOIN Confirmations AS C
        ON S.user_id = C.user_id
    GROUP BY S.user_id
),
total_users AS (
    SELECT
        S.user_id,
        SUM(
            CASE
                WHEN C.action IN ('confirmed', 'timeout') THEN 1
                ELSE 0
            END
        ) AS total_request_count
    FROM Signups AS S
    LEFT JOIN Confirmations AS C
        ON S.user_id = C.user_id
    GROUP BY S.user_id
)
SELECT
    P.user_id,
    ROUND(
        CASE
            WHEN T.total_request_count = 0 THEN 0.0
            ELSE P.Per_user_confirmed_action * 1.0
```
