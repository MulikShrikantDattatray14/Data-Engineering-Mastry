# 11. SQL Article Views I

## Question and image

Find every author who viewed at least one of their **own** articles. Return each author's ID as `id`, sorted by `id` ascending.

`Views` may contain duplicate rows. An author viewed their own article when `author_id = viewer_id`.

**Example 1**

Input — `Views`:

| article_id | author_id | viewer_id | view_date |
|---:|---:|---:|---|
| 1 | 3 | 5 | 2019-08-01 |
| 1 | 3 | 6 | 2019-08-02 |
| 2 | 7 | 7 | 2019-08-01 |
| 2 | 7 | 6 | 2019-08-02 |
| 4 | 7 | 1 | 2019-07-22 |
| 3 | 4 | 4 | 2019-07-21 |
| 3 | 4 | 4 | 2019-07-21 |

Expected output:

| id |
|---:|
| 4 |
| 7 |

Authors 4 and 7 viewed their own articles. Author 4's matching view row appears twice, but the result lists that author once.

## Schema

`Views`:

| Column Name | Type |
|---|---|
| article_id | int |
| author_id | int |
| viewer_id | int |
| view_date | date |

There is no primary key and rows may be duplicates. Each row records a view of an article by `viewer_id`; `author_id` is the article's author.

## My solution — SQLite

```sql
SELECT DISTINCT author_id AS id
FROM Views
WHERE author_id = viewer_id
ORDER BY id ASC;
```

### Step-by-step explanation with one example

**Starting data.** One row records one view. The table can contain duplicate rows, and one author might view their own article more than once.

| article_id | author_id | viewer_id | view_date |
|---:|---:|---:|---|
| 1 | 3 | 5 | 2019-08-01 |
| 1 | 3 | 6 | 2019-08-02 |
| 2 | 7 | 7 | 2019-08-01 |
| 2 | 7 | 6 | 2019-08-02 |
| 4 | 7 | 1 | 2019-07-22 |
| 3 | 4 | 4 | 2019-07-21 |
| 3 | 4 | 4 | 2019-07-21 |

**1. Keep views made by the author.** The same person is both author and viewer when `author_id = viewer_id`.

```sql
SELECT article_id, author_id, viewer_id, view_date
FROM Views
WHERE author_id = viewer_id;
```

| article_id | author_id | viewer_id | view_date |
|---:|---:|---:|---|
| 2 | 7 | 7 | 2019-08-01 |
| 3 | 4 | 4 | 2019-07-21 |
| 3 | 4 | 4 | 2019-07-21 |

Author 3's views and author 7's views by other people are excluded. Both matching rows for author 4 remain because `WHERE` checks each row and does not remove duplicates.

**2. Keep the author ID and name the output column `id`.** Without `DISTINCT`, author 4 still appears twice:

```sql
SELECT author_id AS id
FROM Views
WHERE author_id = viewer_id;
```

| id |
|---:|
| 7 |
| 4 |
| 4 |

`AS id` changes the output column label; it does not change the underlying `author_id` column.

**3. Remove repeated IDs and sort.** The result asks for authors, so each qualifying author should appear once. `DISTINCT` reduces the two `4` rows to one, then `ORDER BY id ASC` puts 4 before 7.

```sql
SELECT DISTINCT author_id AS id
FROM Views
WHERE author_id = viewer_id
ORDER BY id ASC;
```

| id |
|---:|
| 4 |
| 7 |

The `view_date` does not affect whether the author viewed their own article. `DISTINCT` would still be needed if author 4's two self-views happened on different dates: the required result has one row per author.
