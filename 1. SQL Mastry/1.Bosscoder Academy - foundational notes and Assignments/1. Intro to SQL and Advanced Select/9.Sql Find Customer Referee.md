# 9. SQL Find Customer Referee

## Question and image

Return the names of customers who were **not referred by customer 2**, including customers with **no referee**. A missing `referee_id` is `NULL`. No output order is specified.

**Example 1**

Input — `Customer`:

| id | name | referee_id |
|---:|---|---:|
| 1 | Will | NULL |
| 2 | Jane | NULL |
| 3 | Alex | 2 |
| 4 | Bill | NULL |
| 5 | Zack | 1 |
| 6 | Mark | 2 |

Expected output:

| name |
|---|
| Will |
| Jane |
| Bill |
| Zack |

Will, Jane, and Bill have no referee. Zack was referred by customer 1. Alex and Mark were referred by customer 2, so they are excluded.

## Schema

`Customer`:

| Column Name | Type |
|---|---|
| id | int |
| name | varchar |
| referee_id | int |

`id` is the primary key. `referee_id` identifies the referring customer; `NULL` means no customer referred this row.

## My solution — SQLite

```sql
SELECT name
FROM Customer
WHERE referee_id != 2 OR referee_id IS NULL;
```

### Step-by-step explanation with one example

**Starting data.** Each row is one customer. We want the names of customers whose referee is someone other than 2 **or** who have no referee.

| id | name | referee_id |
|---:|---|---:|
| 1 | Will | NULL |
| 2 | Jane | NULL |
| 3 | Alex | 2 |
| 4 | Bill | NULL |
| 5 | Zack | 1 |
| 6 | Mark | 2 |

**1. Check `referee_id != 2`.** This is true for Zack because `1 != 2`. It is false for Alex and Mark because their referee is 2. For `NULL`, the result is **unknown**, not true.

```sql
SELECT id, name, referee_id,
       referee_id != 2 AS different_from_2
FROM Customer;
```

| id | name | referee_id | different_from_2 |
|---:|---|---:|---:|
| 1 | Will | NULL | NULL |
| 2 | Jane | NULL | NULL |
| 3 | Alex | 2 | 0 |
| 4 | Bill | NULL | NULL |
| 5 | Zack | 1 | 1 |
| 6 | Mark | 2 | 0 |

SQLite displays true as `1` and false as `0`. A `WHERE` clause keeps only true rows, so `WHERE referee_id != 2` alone would return Zack but miss Will, Jane, and Bill.

**2. Find customers with no referee.** Use `IS NULL` to detect missing referee IDs:

```sql
SELECT id, name
FROM Customer
WHERE referee_id IS NULL;
```

| id | name |
|---:|---|
| 1 | Will |
| 2 | Jane |
| 4 | Bill |

`= NULL` would not work for this test. These three customers must be included even though `referee_id != 2` was unknown for them.

**3. Combine the two qualifying cases.** `OR` keeps a row when either its referee is known and different from 2, or its referee is missing.

```sql
SELECT name
FROM Customer
WHERE referee_id != 2 OR referee_id IS NULL;
```

| name |
|---|
| Will |
| Jane |
| Bill |
| Zack |

Alex and Mark fail both conditions because their referee is 2. This output follows the example's displayed order; without `ORDER BY`, SQL does not promise that order, and the prompt does not require one.

## My solution — SQL Server

The same query works in SQL Server:

```sql
SELECT name
FROM Customer
WHERE referee_id != 2 OR referee_id IS NULL;
```

`<>` is another spelling for “not equal” in both SQLite and SQL Server; the user's `!=` is retained here.
