## Question and image

Find the `tweet_id` values of invalid tweets in `Tweets`. A tweet is invalid when its `content` contains **strictly more than 15 characters**. Spaces and `!` are characters too. No output order is specified.

**Example 1**

Input — `Tweets`:

| tweet_id | content |
|---:|---|
| 1 | Let us Code |
| 2 | More than fifteen chars are here! |

Expected output:

| tweet_id |
|---:|
| 2 |

Tweet 1 has 11 characters, so it is valid. Tweet 2 has 33 characters, so it is invalid.

## Schema

`Tweets`:

| Column Name | Type |
|---|---|
| tweet_id | int |
| content | varchar |

`tweet_id` is the primary key. `content` contains alphanumeric characters, `!`, or spaces, with no other special characters.

## My solution — SQLite

```sql
SELECT tweet_id
FROM Tweets
WHERE LENGTH(content) > 15;
```

### Step-by-step explanation with one example

**Starting data.** Each row is one tweet. The result needs only the IDs of tweets with more than 15 characters.

| tweet_id | content |
|---:|---|
| 1 | Let us Code |
| 2 | More than fifteen chars are here! |

**1. Count the characters.** SQLite's `LENGTH(content)` counts the characters in the text, including spaces and `!`.

```sql
SELECT tweet_id, content,
       LENGTH(content) AS character_count
FROM Tweets;
```

| tweet_id | content | character_count |
|---:|---|---:|
| 1 | Let us Code | 11 |
| 2 | More than fifteen chars are here! | 33 |

For tweet 1, `Let` (3) + space (1) + `us` (2) + space (1) + `Code` (4) = **11**. Tweet 2 uses **33** characters.

**2. Keep only counts above 15.** “Strictly greater than 15” means `> 15`; a tweet of exactly 15 characters is valid.

```sql
SELECT tweet_id, content,
       LENGTH(content) AS character_count
FROM Tweets
WHERE LENGTH(content) > 15;
```

| tweet_id | content | character_count |
|---:|---|---:|
| 2 | More than fifteen chars are here! | 33 |

Tweet 1 fails because `11 > 15` is false. Tweet 2 passes because `33 > 15` is true.

**3. Return just the requested ID.** The length is needed for filtering, but the output requires only `tweet_id`:

```sql
SELECT tweet_id
FROM Tweets
WHERE LENGTH(content) > 15;
```

| tweet_id |
|---:|
| 2 |

`tweet_id` is unique, so no `DISTINCT` is needed. The prompt does not require an output order.

## My solution — SQL Server

SQL Server uses `LEN`, but `LEN(content)` omits trailing spaces. Because spaces count toward the tweet limit, append a non-space marker and subtract its one character:

```sql
SELECT tweet_id
FROM Tweets
WHERE LEN(content + '.') - 1 > 15;
```

For example, a tweet containing 15 letters followed by one space has 16 characters: `LEN(content)` would report 15, while `LEN(content + '.') - 1` reports 16. This adaptation was reviewed from [Microsoft's `LEN` documentation](https://learn.microsoft.com/en-us/sql/t-sql/functions/len-transact-sql); it was not executed on a SQL Server instance. SQLite's [`LENGTH` documentation](https://www.sqlite.org/lang_corefunc.html#length) describes its character-count behavior.
