# 1. SQL All People Report To The Given Manager

## Question and image

**Classroom practice question 1; assignment question 3.**

Find the `employee_id` of all employees who report directly or indirectly to the head of the company. The head has `employee_id = 1`, and the indirect relationship does not exceed three managers. Return the result ordered by employee_id in ascending order for the assignment. The earlier classroom version allowed any order.

**Example 1**

Input — Employees:

| employee_id | employee_name | manager_id |
|---:|---|---:|
| 1 | Boss | 1 |
| 3 | Alice | 3 |
| 2 | Bob | 1 |
| 4 | Daniel | 2 |
| 7 | Luis | 4 |
| 8 | Jhon | 3 |
| 9 | Angela | 8 |
| 77 | Robert | 1 |

Output:

| employee_id |
|---:|
| 2 |
| 4 |
| 7 |
| 77 |

**Example explanation:** Employees 2 and 77 report directly to the head. Employee 4 reports through 2, and employee 7 reports through 4 and 2. Employees 3, 8, and 9 do not belong to the head's reporting chain. The assignment output is sorted by employee_id: 2, 4, 7, 77.

## Schema

**Employees**

| Column Name | Type |
|---|---|
| employee_id | int |
| employee_name | varchar |
| manager_id | int |

- `employee_id` contains unique values.
- Each row gives an employee's name and their direct manager's ID.

## My solution — SQLite

### Solution 1 — Nonrecursive CTE

The problem limits the reporting chain to three manager links. We can write one ordinary CTE for each level.

```sql
WITH direct_reports AS (
    SELECT employee_id
    FROM Employees
    WHERE manager_id = 1
      AND employee_id <> 1
),
second_level AS (
    SELECT E.employee_id
    FROM Employees AS E
    INNER JOIN direct_reports AS D
        ON E.manager_id = D.employee_id
),
third_level AS (
    SELECT E.employee_id
    FROM Employees AS E
    INNER JOIN second_level AS S
        ON E.manager_id = S.employee_id
),
all_reports AS (
    SELECT employee_id FROM direct_reports
    UNION
    SELECT employee_id FROM second_level
    UNION
    SELECT employee_id FROM third_level
)
SELECT employee_id
FROM all_reports
ORDER BY employee_id;
```

#### Step-by-step explanation with one example

**1. Find direct reports of Boss.** `direct_reports` keeps rows whose manager_id is 1. The sample also gives Boss manager_id = 1, so employee_id <> 1 excludes Boss himself.

| Level | employee_id | employee_name | Reports to |
|---:|---:|---|---|
| 1 | 2 | Bob | Boss (1) |
| 1 | 77 | Robert | Boss (1) |

**2. Find reports of those employees.** `second_level` joins Employees to direct_reports on employee.manager_id = direct_report.employee_id. Daniel reports to Bob; nobody reports to Robert in the sample.

| Level | employee_id | employee_name | Reports to |
|---:|---:|---|---|
| 2 | 4 | Daniel | Bob (2) |

**3. Find one more level.** `third_level` uses the same join against second_level. Luis reports to Daniel.

| Level | employee_id | employee_name | Reports to |
|---:|---:|---|---|
| 3 | 7 | Luis | Daniel (4) |

The assignment guarantees at most three manager links to the head, so these three levels cover every qualifying employee. Alice (3) points to herself and is not reached from Boss; Jhon (8) and Angela (9) remain outside Boss's chain.

**4. Stack and sort the level results.** `all_reports` combines the three employee ID sets with UNION. The final ORDER BY produces:

| employee_id | Chain to Boss |
|---:|---|
| 2 | 2 → 1 |
| 4 | 4 → 2 → 1 |
| 7 | 7 → 4 → 2 → 1 |
| 77 | 77 → 1 |

The query returns only employee_id, in ascending order.

### Solution 2 — Recursive CTE

```sql
WITH RECURSIVE team(employee_id, employee_name, manager_id, depth) AS (
    SELECT employee_id, employee_name, manager_id, 1
    FROM Employees
    WHERE manager_id = 1
      AND employee_id <> 1

    UNION ALL

    SELECT e.employee_id, e.employee_name, e.manager_id, t.depth + 1
    FROM Employees AS e
    JOIN team AS t
        ON e.manager_id = t.employee_id
    WHERE t.depth < 3
)
SELECT employee_id
FROM team
ORDER BY employee_id;
```

#### Step-by-step explanation with one example

**1. Read the input and required output.** One result row is the ID of an employee whose manager chain leads to Boss (`employee_id = 1`). The question asks for `employee_id` only. The final `ORDER BY employee_id` satisfies the assignment requirement to sort the IDs in ascending order.

```sql
SELECT employee_id, employee_name, manager_id
FROM Employees
ORDER BY employee_id;
```

| employee_id | employee_name | manager_id |
|---:|---|---:|
| 1 | Boss | 1 |
| 2 | Bob | 1 |
| 3 | Alice | 3 |
| 4 | Daniel | 2 |
| 7 | Luis | 4 |
| 8 | Jhon | 3 |
| 9 | Angela | 8 |
| 77 | Robert | 1 |

The `manager_id` column points from an employee to their direct manager. Boss and Alice each point to themselves in this sample, so we must avoid starting a recursive chain with either self-reference.

**2. Start with direct reports of Boss.** The anchor reads rows whose `manager_id` is 1. Boss also has `manager_id = 1` in this sample, so `employee_id <> 1` removes Boss. Direct reports begin at `depth = 1`.

```sql
SELECT employee_id, employee_name, manager_id, 1 AS depth
FROM Employees
WHERE manager_id = 1
  AND employee_id <> 1;
```

| employee_id | employee_name | manager_id | depth |
|---:|---|---:|---:|
| 2 | Bob | 1 | 1 |
| 77 | Robert | 1 | 1 |

These two rows are the starting `team`. Boss is absent, so his self-reference cannot keep generating Boss.

**3. Find the next reporting level.** For each current `team` row, the recursive join finds an employee whose `manager_id` equals that team member's `employee_id`.

```sql
SELECT e.employee_id, e.employee_name, e.manager_id, t.depth + 1
FROM Employees AS e
JOIN team AS t
    ON e.manager_id = t.employee_id
WHERE t.depth < 3;
```

Follow the same sample rows through the recursive rounds:

| Current `team` row | Matching direct report | New row |
|---|---|---|
| Bob (2), depth 1 | Daniel (4), whose manager is 2 | Daniel (4), depth 2 |
| Robert (77), depth 1 | None | No new row |
| Daniel (4), depth 2 | Luis (7), whose manager is 4 | Luis (7), depth 3 |
| Luis (7), depth 3 | Not expanded: `3 < 3` is false | No new row |

`UNION ALL` keeps both the anchor and the rows found in later rounds. The complete `team` for this example is:

| employee_id | employee_name | manager_id | depth |
|---:|---|---:|---:|
| 2 | Bob | 1 | 1 |
| 77 | Robert | 1 | 1 |
| 4 | Daniel | 2 | 2 |
| 7 | Luis | 4 | 3 |

Alice (3), Jhon (8), and Angela (9) form a separate reporting chain, so the join never reaches them from Bob or Robert.

**4. Stop before generating a fourth level.** `WHERE t.depth < 3` tests the current row before producing `t.depth + 1`. It allows depth 1 to produce depth 2, and depth 2 to produce depth 3. Luis remains in the CTE at depth 3, but he cannot generate a depth 4 row. The question guarantees the indirect relationship does not exceed three managers, so this check makes that bound explicit. In the supplied sample the chain would also end naturally after Luis.

**5. Return the requested column.** The outer query reads the completed `team` and sorts its employee IDs.

```sql
SELECT employee_id
FROM team
ORDER BY employee_id;
```

| employee_id |
|---:|
| 2 |
| 4 |
| 7 |
| 77 |

Manual check: Bob and Robert report directly to Boss (`2 → 1`, `77 → 1`); Daniel reports through Bob (`4 → 2 → 1`); Luis reports through Daniel and Bob (`7 → 4 → 2 → 1`). Boss is the head, and Alice's chain does not reach Boss.

## My solution — SQL Server

```sql

    WHERE manager_id = 1

    FROM Employees AS E
    INNER JOIN direct_reports AS D
        ON E.manager_id = D.employee_id

    SELECT E.employee_id
    FROM Employees AS E
    INNER JOIN second_level AS S

    SELECT employee_id FROM direct_reports
    UNION
    SELECT employee_id FROM second_level
    UNION
    SELECT employee_id FROM third_level

```

## Official solution

The supplied classroom notes give this solution:

```sql
WITH RECURSIVE CTE AS (
    SELECT employee_id, 1 AS level
    FROM Employees
    WHERE manager_id = 1
      AND employee_id != 1

    UNION ALL

    SELECT e.employee_id, c.level + 1
    FROM CTE AS c
    JOIN Employees AS e
        ON c.employee_id = e.manager_id
    WHERE c.level < 3
)
SELECT employee_id
FROM CTE
ORDER BY employee_id ASC;
```

### What this tests

Recursive CTEs for a manager hierarchy, starting at a chosen employee, excluding a self-reference, and limiting the depth.

### The approach

Start with direct reports of employee 1 at level 1. Repeatedly join each current report to their direct reports until level 3. Select the reached employee IDs.

### Why this way

The anchor avoids the head's self-reference, and each recursive round advances one reporting level. `level < 3` prevents generating a fourth level.

### Common mistakes

- Starting with Boss despite `manager_id = employee_id = 1`, which repeatedly generates Boss.
- Filtering Boss only in the outer query, which does not stop the recursion.
- Using a recursive depth condition that drops level 3 or generates level 4.
