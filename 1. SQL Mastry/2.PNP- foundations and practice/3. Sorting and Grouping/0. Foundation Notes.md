# Sorting and Grouping - Quick Revision Notes

**Main idea:** `ORDER BY` changes row order; `GROUP BY` changes the number and meaning of rows. First state what one output row should represent.

The small Orders table below is invented for revision. It is not a practice-question answer.

## 1. Start with the same rows

| OrderID | CustomerID | Status | Amount |
|---:|---:|---|---:|
| 101 | 1 | Delivered | 80 |
| 102 | 1 | Delivered | 20 |
| 103 | 2 | Delivered | 30 |
| 104 | 2 | Cancelled | NULL |
| 105 | NULL | Delivered | 5 |

One input row is one order. A missing `Amount` is unknown, not zero. A missing `CustomerID` still belongs to a row.

## 2. ORDER BY changes display order only

~~~sql
SELECT OrderID, CustomerID, Amount
FROM Orders
ORDER BY Amount DESC, OrderID ASC;
~~~

`Amount DESC` puts larger known amounts first. `OrderID ASC` resolves ties. The query still returns five rows; it does not calculate a total or remove duplicates. NULL placement can differ between SQL engines, so use an explicit NULL ordering rule when the question requires one.

## 3. DISTINCT removes duplicate selected values

~~~sql
SELECT DISTINCT CustomerID
FROM Orders;
~~~

The result contains three values: `1`, `2`, and `NULL` (order unspecified). The duplicate customer IDs disappear, but none of the five source rows is deleted. If you select `CustomerID, Status` together, DISTINCT compares the **pair**; customer 2 then has two different pairs.

## 4. GROUP BY changes the output grain

~~~sql
SELECT
    CustomerID,
    COUNT(*) AS order_rows,
    COUNT(Amount) AS known_amounts,
    SUM(Amount) AS total_amount
FROM Orders
GROUP BY CustomerID
ORDER BY CustomerID;
~~~

| CustomerID | order_rows | known_amounts | total_amount |
|---:|---:|---:|---:|
| NULL | 1 | 1 | 5 |
| 1 | 2 | 2 | 100 |
| 2 | 2 | 1 | 30 |

Now one output row represents **one CustomerID group**. SQL groups the missing CustomerID rows together. `COUNT(*)` counts every row; `COUNT(Amount)` skips the missing amount. Customer 2 has two orders but only one known amount, so the sum is 30.

## 5. WHERE filters rows; HAVING filters finished groups

~~~sql
SELECT CustomerID, SUM(Amount) AS delivered_total
FROM Orders
WHERE Status = 'Delivered'
GROUP BY CustomerID
HAVING SUM(Amount) >= 50;
~~~

The `WHERE` condition first removes order 104. The remaining rows are grouped by customer. Their totals are 100 for customer 1, 30 for customer 2, and 5 for the missing CustomerID group. `HAVING` keeps only customer 1 because 100 is at least 50.

| CustomerID | delivered_total |
|---:|---:|
| 1 | 100 |

Put a source-row condition in `WHERE`. Put a condition on a grouped result in `HAVING`.

## 6. Count distinct values inside each group

~~~sql
SELECT CustomerID,
       COUNT(DISTINCT Status) AS different_statuses
FROM Orders
GROUP BY CustomerID
ORDER BY CustomerID;
~~~

| CustomerID | different_statuses |
|---:|---:|
| NULL | 1 |
| 1 | 1 |
| 2 | 2 |

Customer 1 has two orders but only one distinct status; customer 2 has Delivered and Cancelled. `COUNT(DISTINCT column)` ignores NULL values of that column. Choose `COUNT(*)`, `COUNT(column)`, or `COUNT(DISTINCT column)` according to what the question calls a count.

## Quick check

1. Does one output row represent a source row or a group?
2. Do you need to preserve duplicates, remove duplicate selected values, or count them?
3. Is the condition about input rows (`WHERE`) or completed groups (`HAVING`)?
4. Does the requested order need a tie-breaker or explicit NULL placement?
5. Did you include every grouping column needed to define one result row?
