# PNP Q003. Customers in metro cities

![SOLVED](<../../_badges/solved.svg>) ![EASY](<../../_badges/easy.svg>) · Solved (recorded): 2026-10-27

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 3, pp. 14–15. **Difficulty:** Easy.

**Business scenario.** Marketing is launching same-day delivery in five metros: Bengaluru, Mumbai, Delhi, Hyderabad and Chennai. They need the customers in those cities for the launch campaign. City was typed in by hand at sign-up, so some values carry stray spaces or odd capitalisation.

**Task.** Return customers whose city is one of the five metros, matching regardless of case and surrounding spaces. Show the city with the spaces removed. Sort by city, then CustomerID .

**Dataset clarification.** The supplied data also calls Bengaluru `Bangalore`, Mumbai `Bombay`, and Delhi `New Delhi`. Treat those spellings as the same five metro areas.

**Expected output (as supplied):**

```text
CustomerID
FirstName
LastName
City : the city with leading and trailing spaces removed
State
```

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

```sql
SELECT
    CustomerID,
    FirstName,
    LastName,
    TRIM(City) AS City,
    State
FROM Customers
WHERE UPPER(TRIM(City)) IN (
    'BENGALURU', 'MUMBAI', 'DELHI', 'HYDERABAD', 'CHENNAI',
    'BANGALORE', 'BOMBAY', 'NEW DELHI'
)
ORDER BY LOWER(TRIM(City)), CustomerID;
```

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 3. The supplied solution uses PostgreSQL syntax:

```sql
SELECT c.CustomerID,
       c.FirstName,
       c.LastName,
       TRIM(c.City) AS City,
       c.State
FROM Customers AS c
WHERE LOWER(TRIM(c.City)) IN ('bengaluru', 'bangalore', 'mumbai', 'bombay',
                                'delhi', 'new delhi', 'hyderabad', 'chennai')
ORDER BY TRIM(c.City), c.CustomerID;
```

**What this tests.** Filtering a finite set of values after cleaning spaces and letter case, while keeping the requested output columns.

**The approach.** Normalize `City` for matching, include the dataset's alternate names for three metros, display the trimmed city, and sort the result.

**Why this way.** `TRIM` catches stray spaces; `LOWER` in the source and `UPPER` in your answer are equivalent for these names when the `IN` values use the matching case. The source sorts by `TRIM(City)`; your `LOWER(TRIM(City))` sorts mixed-case spellings together, so row order can differ under case-sensitive collations.

**Common mistakes.** Filtering only the five primary spellings misses `Bangalore`, `Bombay`, and `New Delhi` in the supplied data. `TRIM` alone does not handle odd capitalization; displaying the untrimmed column would leave stray spaces in the result.
