# PNP Q002. Ten highest-priced products

![SOLVED](<../../_badges/solved.svg>) ![EASY](<../../_badges/easy.svg>) · Solved (recorded): 2026-10-26

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 2, pp. 12–13. **Difficulty:** Easy.

**Primary topic:** ORDER BY with LIMIT. **Also covers:** NULLS LAST, FETCH FIRST ... WITH TIES.

**Business scenario.** The merchandising team fills a "Premium picks" carousel on the home page. It has exactly ten slots and shows the ten products with the highest current Sale_Price . The job runs every night, and the carousel must not reshuffle when nothing has changed, so a tie for the last slot needs a fixed rule.

**Task.** Return the ten products with the highest Sale_Price , highest first. A product with no price must never take a slot. If products tie on price at the cut-off, the lower ProductID wins.

**Expected output (as supplied):**

```text
ProductID
Product
Brand
Sale_Price
```

**Tables required:** Products.

**SQL concepts named in the source:** filtering NULLs with IS NOT NULL, ORDER BY ... DESC, where NULLs sort (NULLS LAST), LIMIT, deterministic tie- breaking, FETCH FIRST ... WITH TIES.

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

```sql
SELECT ProductID,
       Product,
       Brand,
       Sale_Price
FROM Products
WHERE Sale_Price IS NOT NULL
ORDER BY Sale_Price DESC, ProductID ASC
LIMIT 10;
```

## My solution — SQL Server

SQL Server uses `TOP (10)` in place of SQLite's `LIMIT 10`; the filter and sort rules stay the same.

```sql
SELECT TOP (10)
       ProductID,
       Product,
       Brand,
       Sale_Price
FROM Products
WHERE Sale_Price IS NOT NULL
ORDER BY Sale_Price DESC, ProductID ASC;
```

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 2. The source query is:

```sql
SELECT p.ProductID,
       p.Product,
       p.Brand,
       p.Sale_Price
FROM Products AS p
WHERE p.Sale_Price IS NOT NULL
ORDER BY p.Sale_Price DESC,
         p.ProductID
LIMIT 10;
```

**What this tests.** Filter missing values, order by more than one column, and return a fixed top ten.

**The approach.** Exclude `NULL` prices, sort prices from highest to lowest, use `ProductID` as the tie breaker, and take ten rows. The source's unqualified `p.ProductID` sort is ascending by default.

**Why this way.** The second sort key makes the cutoff stable, so the same products win if prices do not change.

**Common mistakes.** `Sale_Price > 0` wrongly excludes zero-priced products; sorting only by price leaves ties unstable; taking ten rows before sorting does not identify the highest-priced products. `WITH TIES` could return more than ten rows, which conflicts with exactly ten slots.
