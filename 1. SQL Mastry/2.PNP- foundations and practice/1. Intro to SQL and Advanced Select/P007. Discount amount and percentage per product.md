# PNP Q007. Discount amount and percentage per product

![SOLVED](<../../_badges/solved.svg>) · Solved (recorded): 2026-10-27 ![EASY](<../../_badges/easy.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 7, pp. 19–20. **Difficulty:** Easy.

**Primary topic:** Arithmetic expressions. **Also covers:** NULLIF to avoid division by zero, ROUND, NULLS LAST.

**Business scenario.** The pricing team is checking how deep discounts run across the catalogue. Market_Price is the MRP printed on the pack and Sale_Price is what the store charges today. A missing or zero Market_Price means the MRP was never captured, so that product has no measurable discount.

**Task.** For every product, return the discount in rupees and as a percentage of Market_Price , rounded to two decimals. Products with a missing or zero Market_Price get NULL for both. Sort by discount percentage, highest first, with NULLs at the end.

**Expected output (as supplied):**

```text
ProductID
Product
Market_Price
Sale_Price
discount_amount : Market_Price - Sale_Price
discount_pct : discount as a percentage of Market_Price , 2 decimals
```

**Tables required:** Products.

**SQL concepts named in the source:** column arithmetic, NULLIF, safe division, ROUND, NULLS LAST.

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

```sql
WITH cte AS (
    SELECT
        ProductID,
        Product,
        Market_Price,
        Sale_Price,
        CASE
            WHEN Market_Price = 0 THEN NULL
            ELSE Market_Price - Sale_Price
        END AS discount_amount
    FROM Products
)
SELECT
    ProductID,
    Product,
    Market_Price,
    Sale_Price,
    discount_amount,
    ROUND(discount_amount * 100.0 / Market_Price, 2) AS discount_pct
FROM cte
ORDER BY discount_pct DESC;
```

### Step-by-step explanation with one example

**Starting data.** Use the three illustrative `Products` rows from the question. Each product must remain in the output, even when its market price is zero.

| ProductID | Product | Market_Price | Sale_Price |
|---:|---|---:|---:|
| 1 | Mug | 100 | 80 |
| 2 | Sticker | 0 | 0 |
| 3 | Lamp | 200 | 150 |

**1. Calculate the rupee discount in the CTE.** For a valid market price, subtract `Sale_Price` from `Market_Price`. The `CASE` returns `NULL` when `Market_Price = 0`. If `Market_Price` is already `NULL`, the subtraction also gives `NULL`.

```sql
WITH cte AS (
    SELECT
        ProductID,
        Product,
        Market_Price,
        Sale_Price,
        CASE
            WHEN Market_Price = 0 THEN NULL
            ELSE Market_Price - Sale_Price
        END AS discount_amount
    FROM Products
)
SELECT ProductID, Product, Market_Price, Sale_Price, discount_amount
FROM cte
ORDER BY ProductID;
```

| ProductID | Product | Market_Price | Sale_Price | discount_amount |
|---:|---|---:|---:|---:|
| 1 | Mug | 100 | 80 | 20 |
| 2 | Sticker | 0 | 0 | NULL |
| 3 | Lamp | 200 | 150 | 50 |

The CTE keeps all three rows. Its `discount_amount` name is now available to the outer query; an alias cannot be reused in another expression in the same `SELECT` list that creates it.

**2. Calculate the percentage in the outer query.** Divide the rupee discount by the market price and multiply by 100. The `100.0` makes this decimal arithmetic, so a fraction is not lost to integer division. `ROUND(..., 2)` rounds the result to two decimal places.

```sql
WITH cte AS (
    SELECT
        ProductID,
        Product,
        Market_Price,
        Sale_Price,
        CASE
            WHEN Market_Price = 0 THEN NULL
            ELSE Market_Price - Sale_Price
        END AS discount_amount
    FROM Products
)
SELECT
    ProductID,
    discount_amount,
    Market_Price,
    ROUND(discount_amount * 100.0 / Market_Price, 2) AS discount_pct
FROM cte
ORDER BY ProductID;
```

| ProductID | Calculation | discount_pct |
|---:|---|---:|
| 1 | 20 × 100.0 ÷ 100 | 20.00 |
| 2 | NULL × 100.0 ÷ 0 | NULL |
| 3 | 50 × 100.0 ÷ 200 | 25.00 |

SQLite returns `NULL` for Sticker's percentage. The source's `NULLIF(Market_Price, 0)` is another way to make the divisor safe. SQLite may display a whole-number result as `20.0` rather than `20.00`; it is still rounded to two decimal places as a numeric value.

**3. Return all products in the required order.** `ORDER BY discount_pct DESC` puts 25% before 20%. In SQLite, descending order places the `NULL` percentage last. There is no `WHERE` clause, so Sticker stays in the result with both discounts `NULL`.

```sql
WITH cte AS (
    SELECT
        ProductID,
        Product,
        Market_Price,
        Sale_Price,
        CASE
            WHEN Market_Price = 0 THEN NULL
            ELSE Market_Price - Sale_Price
        END AS discount_amount
    FROM Products
)
SELECT
    ProductID,
    Product,
    Market_Price,
    Sale_Price,
    discount_amount,
    ROUND(discount_amount * 100.0 / Market_Price, 2) AS discount_pct
FROM cte
ORDER BY discount_pct DESC;
```

| ProductID | Product | Market_Price | Sale_Price | discount_amount | discount_pct |
|---:|---|---:|---:|---:|---:|
| 3 | Lamp | 200 | 150 | 50 | 25.00 |
| 1 | Mug | 100 | 80 | 20 | 20.00 |
| 2 | Sticker | 0 | 0 | NULL | NULL |

**Manual check.** Lamp's discount is `200 - 150 = 50` and `50 / 200 × 100 = 25%`. Mug's is `100 - 80 = 20` and `20 / 100 × 100 = 20%`. Sticker's zero market price makes both discounts `NULL`, and it remains last. These are illustrative results, not a claim of execution on the full supplied dataset.

## My solution — SQL Server

SQL Server uses the same CTE. `NULLIF(Market_Price, 0)` makes the outer division safe when the market price is zero; the SQLite version relies on SQLite's `NULL` division behavior. Descending sort also places `NULL` values last in SQL Server.

```sql
WITH cte AS (
    SELECT
        ProductID,
        Product,
        Market_Price,
        Sale_Price,
        CASE
            WHEN Market_Price = 0 THEN NULL
            ELSE Market_Price - Sale_Price
        END AS discount_amount
    FROM Products
)
SELECT
    ProductID,
    Product,
    Market_Price,
    Sale_Price,
    discount_amount,
    ROUND(discount_amount * 100.0 / NULLIF(Market_Price, 0), 2) AS discount_pct
FROM cte
ORDER BY discount_pct DESC;
```

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 7. This source query uses PostgreSQL syntax.

```sql
SELECT p.ProductID,
       p.Product,
       p.Market_Price,
       p.Sale_Price,
       NULLIF(p.Market_Price, 0) - p.Sale_Price                                      AS discount_amount,
       ROUND(100.0 * (p.Market_Price - p.Sale_Price) / NULLIF(p.Market_Price, 0), 2) AS discount_pct
FROM Products AS p
ORDER BY discount_pct DESC NULLS LAST,
         p.ProductID;
```

**What this tests.** Arithmetic expressions, safe division, numeric rounding, and sorting unknown percentages last.

**The approach.** `NULLIF(Market_Price, 0)` turns a zero divisor into `NULL`. It also makes the rupee discount `NULL` when the market price is zero. `ROUND` calculates the percentage to two decimal places.

**Why this way.** The source avoids division by zero inside the percentage expression. Its `NULLS LAST` makes the requested placement explicit in PostgreSQL; `ProductID` provides a deterministic order for tied percentages.

**Common mistakes.** Returning zero instead of `NULL` for an invalid market price, dividing by zero, using only integer arithmetic before rounding, or sorting before handling `NULL` values can produce the wrong result. Your CTE approach preserves the same output while making `discount_amount` reusable in the outer query.
