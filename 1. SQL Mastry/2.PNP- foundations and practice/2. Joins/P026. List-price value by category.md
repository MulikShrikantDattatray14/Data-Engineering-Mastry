# PNP Q026. List-price value by category

![SOLVED](<../../_badges/solved.svg>) · Solved (recorded): 2026-10-28 ![MEDIUM](<../../_badges/medium.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 26, pp. 44–45. **Difficulty:** Medium.

**Business scenario.** The category management team splits next quarter's promotion budget across categories. For each category they want three numbers: how many orders included it, how many units moved, and what those units are worth at list price. Finance will tie the units column back to the order lines, so no line may go missing, even when its product or category reference is broken.

**Task.** For every category, return the number of distinct orders that contained at least one of its products, the units sold, and the list-price value ( Quantity * Sale_Price ). Lines whose product points to a CategoryID with no Category row go under Unmapped . Lines whose ProductID is not in Products go under Unknown product . Sort by list-price value, highest first.

**Expected output (as supplied):**

```text
category_name : CategoryName , Unmapped or Unknown product
orders : distinct orders containing at least one line in the category
units_sold : sum of Quantity
list_price_value : sum of Quantity * Sale_Price
```

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

This solution follows both requirements in the task wording: keep every Category row and account for every OrderDetails row, including broken references.

```sql
WITH labeled_rows AS (
    SELECT
        C.CategoryID AS category_id,
        OD.OrderDetailID AS order_detail_id,
        OD.OrderID,
        OD.Quantity,
        P.Sale_Price,
        CASE
            WHEN C.CategoryID IS NOT NULL THEN C.CategoryName
            WHEN P.ProductID IS NULL THEN 'Unknown product'
            ELSE 'Unmapped'
        END AS category_name
    FROM OrderDetails AS OD
    LEFT JOIN Products AS P
        ON OD.ProductID = P.ProductID
    FULL OUTER JOIN Category AS C
        ON P.CategoryID = C.CategoryID
)
SELECT
    category_name,
    COUNT(DISTINCT OrderID) AS orders,
    COALESCE(SUM(Quantity), 0) AS units_sold,
    CASE
        WHEN COUNT(order_detail_id) = 0 THEN 0
        ELSE SUM(Quantity * Sale_Price)
    END AS list_price_value
FROM labeled_rows
GROUP BY category_id, category_name
ORDER BY list_price_value DESC NULLS LAST, category_name;
```

### Step-by-step walkthrough using the example above

**1. Decide what one output row represents.** Each Category has a row, even without sales. Order lines with a missing Category go under `Unmapped`. Order lines with a missing Product go under `Unknown product`. The three measures count distinct orders, sum units, and sum each line's `Quantity * Sale_Price`. The price is the current list price, not the amount paid for the order.

**2. Preserve the required input rows.** `OrderDetails LEFT JOIN Products` keeps every line and retrieves its product's category and list price when available. `FULL OUTER JOIN Category` also keeps unsold Category rows. Products connects the line to its Category.

The joined result for this one example is shown below. “Product found?” is an explanation column indicating whether `P.ProductID` matched; it is not selected by the final query.

| DetailID | OrderID | ProductID | Quantity | Sale_Price | C.CategoryID | C.CategoryName | Product found? |
|---:|---:|---:|---:|---:|---:|---|---|
| 1 | 100 | 10 | 2 | 10 | 1 | Drinks | Yes |
| 2 | 100 | 11 | 1 | 8 | 1 | Drinks | Yes |
| 3 | 100 | 20 | 1 | 5 | 2 | Snacks | Yes |
| 4 | 101 | 30 | 3 | 7 | NULL | NULL | Yes |
| 5 | 102 | 999 | 4 | NULL | NULL | NULL | No |
| NULL | NULL | NULL | NULL | NULL | 3 | Stationery | No |

**3. Assign the label.** The `CASE` first uses an existing Category row's name, so the unsold Stationery row remains Stationery. With no Category match, a missing Product becomes `Unknown product`; a present Product becomes `Unmapped`.

| order_detail_id | category_id | category_name |
|---:|---:|---|
| 1 | 1 | Drinks |
| 2 | 1 | Drinks |
| 3 | 2 | Snacks |
| 4 | NULL | Unmapped |
| 5 | NULL | Unknown product |
| NULL | 3 | Stationery |

**4. Count orders and units within each group.** `COUNT(DISTINCT OrderID)` counts order `100` only once under Drinks despite its two Drinks lines. The same order also counts once under Snacks. `COALESCE(SUM(Quantity), 0)` displays zero units for Stationery, whose joined quantity is `NULL`.

| category_name | OrderIDs in group | orders | Quantities | units_sold |
|---|---|---:|---|---:|
| Drinks | 100, 100 | 1 | 2 + 1 | 3 |
| Snacks | 100 | 1 | 1 | 1 |
| Unmapped | 101 | 1 | 3 | 3 |
| Unknown product | 102 | 1 | 4 | 4 |
| Stationery | NULL | 0 | NULL | 0 |

**5. Calculate list-price value.** Multiply quantity and price on each line, then sum within its group. `COUNT(order_detail_id) = 0` identifies a Category with no actual order line and assigns it value `0`. Unknown product has an order line but no known price, so its value stays `NULL`.

| category_name | Line calculations | list_price_value |
|---|---|---:|
| Drinks | 2 × 10 + 1 × 8 | 28 |
| Snacks | 1 × 5 | 5 |
| Unmapped | 3 × 7 | 21 |
| Unknown product | 4 × NULL | NULL |
| Stationery | No order lines | 0 |

**6. Group and sort.** Grouping by `category_id` and `category_name` keeps different real Categories distinct even if they share a name. The labels separate `Unmapped` from `Unknown product` although both have `category_id = NULL`. `ORDER BY` puts the highest known value first and the unknown value last, producing the expected output above.

**Check.** The reported units sum to `11`: `3 + 1 + 3 + 4 + 0`. The five input order lines also sum to `11`: `2 + 1 + 1 + 3 + 4`. This confirms that no order line was dropped. The query and output were verified with an in-memory SQLite 3.51.2 run. `FULL OUTER JOIN` requires [SQLite 3.39.0 or newer](https://www.sqlite.org/releaselog/3_39_0.html).

## My solution — SQL Server

SQL Server supports the same joins and aggregates. The last query block makes the `NULL` sort placement explicit using a second CTE:

```sql
WITH labeled_rows AS (
    SELECT
        C.CategoryID AS category_id,
        OD.OrderDetailID AS order_detail_id,
        OD.OrderID,
        OD.Quantity,
        P.Sale_Price,
        CASE
            WHEN C.CategoryID IS NOT NULL THEN C.CategoryName
            WHEN P.ProductID IS NULL THEN 'Unknown product'
            ELSE 'Unmapped'
        END AS category_name
    FROM OrderDetails AS OD
    LEFT JOIN Products AS P
        ON OD.ProductID = P.ProductID
    FULL OUTER JOIN Category AS C
        ON P.CategoryID = C.CategoryID
),
aggregated AS (
    SELECT
        category_id,
        category_name,
        COUNT(DISTINCT OrderID) AS orders,
        COALESCE(SUM(Quantity), 0) AS units_sold,
        CASE
            WHEN COUNT(order_detail_id) = 0 THEN 0
            ELSE SUM(Quantity * Sale_Price)
        END AS list_price_value
    FROM labeled_rows
    GROUP BY category_id, category_name
)
SELECT
    category_name,
    orders,
    units_sold,
    list_price_value
FROM aggregated
ORDER BY
    CASE WHEN list_price_value IS NULL THEN 1 ELSE 0 END,
    list_price_value DESC,
    category_name;
```

## Official solution

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 26, pp. 44–45. The source uses PostgreSQL syntax.

```sql
SELECT CASE
    WHEN p.ProductID IS NULL THEN 'Unknown product'
    WHEN cat.CategoryID IS NULL THEN 'Unmapped'
    ELSE cat.CategoryName
END AS category_name,
COUNT(DISTINCT od.OrderID) AS orders,
SUM(od.Quantity) AS units_sold,
SUM(od.Quantity * p.Sale_Price) AS list_price_value
FROM OrderDetails AS od
LEFT JOIN Products AS p ON p.ProductID = od.ProductID
LEFT JOIN Category AS cat ON cat.CategoryID = p.CategoryID
GROUP BY category_name
ORDER BY list_price_value DESC NULLS LAST, category_name;
```

**What this tests.** Joining a three-table chain without dropping order lines, counting distinct orders within each category, and calculating line-based list-price value.

**The source approach.** It starts from OrderDetails and uses two left joins. This preserves every order line and produces `Unmapped` and `Unknown product`. Missing product prices make the unknown-product list-price value `NULL`.

**Difference from our solution.** The task says “for every category.” We interpreted that to include a Category row with no sales. The published answer starts from OrderDetails, so it omits Stationery in the example above. Our `FULL OUTER JOIN` adds such rows and gives them zero orders, units, and value. We group by Category ID as well as label so same-named Categories remain separate.

**Common mistakes.** Counting order lines instead of distinct orders; dropping unmatched lines with an inner join; treating an unknown price as zero; or counting the full paid order amount as category list-price value.
