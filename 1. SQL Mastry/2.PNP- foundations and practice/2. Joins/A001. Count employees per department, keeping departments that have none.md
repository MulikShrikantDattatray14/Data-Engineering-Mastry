## My solution — SQLite

Your final query:

```sql
SELECT
    d.dept_id,
    d.dept_name,
    COUNT(e.emp_id) AS employee_count
FROM departments AS d
LEFT JOIN employees AS e
    ON d.dept_id = e.dept_id
GROUP BY d.dept_id, d.dept_name;
```

### Step-by-step explanation with one example

**Starting data.** Use the same illustrative rows from the question throughout:

`departments`:

| dept_id | dept_name |
|---:|---|
| 1 | Sales |
| 2 | Support |

`employees`:

| emp_id | dept_id |
|---:|---:|
| 11 | 1 |
| 12 | 1 |

**1. Keep every department.** Each result row must represent one department, including Support, which has no employee. Begin with `departments` as the left table.

```sql
SELECT d.dept_id, d.dept_name
FROM departments AS d
ORDER BY d.dept_id;
```

| dept_id | dept_name |
|---:|---|
| 1 | Sales |
| 2 | Support |

**2. Attach employees without removing empty departments.** The `LEFT JOIN` produces one row for each matching employee. When none matches, the department stays and the employee columns are `NULL`.

```sql
SELECT
    d.dept_id,
    d.dept_name,
    e.emp_id,
    e.dept_id AS employee_dept_id
FROM departments AS d
LEFT JOIN employees AS e
    ON d.dept_id = e.dept_id
ORDER BY d.dept_id, e.emp_id;
```

| dept_id | dept_name | emp_id | employee_dept_id |
|---:|---|---:|---:|
| 1 | Sales | 11 | 1 |
| 1 | Sales | 12 | 1 |
| 2 | Support | NULL | NULL |

**3. Count employees within each department.** Group by both selected department columns. `COUNT(e.emp_id)` counts the two non-`NULL` employee IDs for Sales and skips Support's `NULL` ID, giving zero. `COUNT(*)` would count Support's retained join row as one, so it would be wrong for the empty department.

```sql
SELECT
    d.dept_id,
    d.dept_name,
    COUNT(e.emp_id) AS employee_count
FROM departments AS d
LEFT JOIN employees AS e
    ON d.dept_id = e.dept_id
GROUP BY d.dept_id, d.dept_name;
```

| dept_id | dept_name | employee_count |
|---:|---|---:|
| 1 | Sales | 2 |
| 2 | Support | 0 |

**Manual check.** There are two sample employees in Sales and none in Support; both departments remain in the result. ## Official solution

**Source:** [Advanced SQL 100 Query Questions, Vol. 1](<../Source Materials/Advanced_SQL_100_Query_Questions_Vol1 (2).pdf>), question 1, PDF p. 2. The source uses MySQL 8 syntax.

```sql
SELECT d.dept_name, COUNT(e.emp_id) AS emp_cnt
FROM departments d
LEFT JOIN employees e ON e.dept_id = d.dept_id
GROUP BY d.dept_id, d.dept_name;
```

**What this tests.** Keeping departments with no employees while calculating an employee count.

**The approach.** Start from `departments`, left join matching `employees`, group by department, and count employee IDs.

**Why this way.** The left join preserves an empty department. Its unmatched employee ID is `NULL`, so `COUNT(e.emp_id)` returns zero for that department.

**Output note.** The source selects `dept_name` and names the count `emp_cnt`. Your query also selects `dept_id` and uses `employee_count`. The task does not prescribe output columns or aliases, so your projection still answers it.

**Common mistake.** `COUNT(*)` returns one for an empty department because the left join creates a retained row with `NULL` employee columns.
