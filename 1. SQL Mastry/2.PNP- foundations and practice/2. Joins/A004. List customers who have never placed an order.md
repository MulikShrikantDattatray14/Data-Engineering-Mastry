## My solution — SQLite

Your final subquery approach, with `NULL` order customer IDs excluded from `NOT IN`:

```sql
SELECT cust_id, cust_name
FROM customers
WHERE cust_id NOT IN (
    SELECT cust_id
    FROM orders
    WHERE cust_id IS NOT NULL
);
```

## Official solution

**Source:** [Advanced SQL 100 Query Questions, Vol. 1](<../Source Materials/Advanced_SQL_100_Query_Questions_Vol1 (2).pdf>), question 4, PDF p. 3. The source uses MySQL 8 syntax.

```sql
SELECT c.cust_id, c.cust_name
FROM customers c
LEFT JOIN orders o ON o.cust_id = c.cust_id
WHERE o.order_id IS NULL;
```

**What this tests.** Identifying customers with no matching order.

**The approach.** Keep every customer in a left join and select those whose joined order ID is `NULL`.

**Why this way.** A customer without orders remains in a left join with `NULL` order columns. The official query checks `o.order_id`, which is present for a real matched order.

**Your alternative.** Your `NOT IN` subquery gives the same result for non-`NULL` customer IDs and explicitly removes `NULL` values from the subquery to avoid the `NOT IN` null trap.

**Common mistakes.** Using an inner join, which drops customers with no order; or using `NOT IN` against a subquery that may return `NULL` without filtering it.
