# PNP Q017. Orders with payment type and shipper

![SOLVED](<../../_badges/solved.svg>) · Solved (recorded): 2026-10-27 ![EASY](<../../_badges/easy.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 17, pp. 32–33. **Difficulty:** Easy.

**Business scenario.** Every morning the operations desk reviews the most recent week of orders: how each was paid and which courier took it. An order with a missing or unrecognised payment or shipper code is exactly what they need to chase, so it must appear on the list, not vanish from it.

**Task.** For orders placed in the last 7 days covered by the data, return the payment type and shipper name. Show Unknown where the code is NULL or matches nothing. Sort newest first, then by OrderID descending.

**Expected output (as supplied):**

```text
OrderID
OrderDate
payment_type : PaymentType , or Unknown
shipper_name : shipper CompanyName , or Unknown
```

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

Your final query keeps all orders through two `LEFT JOIN`s, labels missing matches, and uses the latest order date in the data as its seven-day anchor.

```sql
SELECT
    O.OrderID,
    O.OrderDate,
    CASE
        WHEN P.PaymentType IS NULL THEN 'Unknown'
        ELSE P.PaymentType
    END AS payment_type,
    CASE
        WHEN S.CompanyName IS NULL THEN 'Unknown'
        ELSE S.CompanyName
    END AS shipper_name
FROM Orders AS O
LEFT JOIN Payments AS P
    ON O.PaymentID = P.PaymentID
LEFT JOIN Shippers AS S
    ON O.ShipperID = S.ShipperID
WHERE DATE(O.OrderDate) BETWEEN
      DATE((SELECT MAX(DATE(OrderDate)) FROM Orders), '-6 days')
      AND
      (SELECT MAX(DATE(OrderDate)) FROM Orders)
ORDER BY O.OrderDate DESC, O.OrderID DESC;
```

**Starting data.** Use the same illustrative rows from the question:

`Payments`:

| PaymentID | PaymentType |
|---:|---|
| 1 | UPI |

`Shippers`:

| ShipperID | CompanyName |
|---:|---|
| 1 | FastShip |

`Orders`:

| OrderID | OrderDate | PaymentID | ShipperID |
|---:|---|---:|---:|
| 1 | 2025-12-24 | 1 | 1 |
| 2 | 2025-12-25 | 1 | 1 |

**1. Find the seven calendar dates.** The latest date in `Orders` is 2025-12-31. That is day one, so subtract six days to get 2025-12-25 as the inclusive first day.

```sql
SELECT
    MAX(DATE(OrderDate)) AS latest_date,
    DATE(MAX(DATE(OrderDate)), '-6 days') AS first_date
FROM Orders;
```

| latest_date | first_date |
|---|---|
| 2025-12-31 | 2025-12-25 |

**2. Attach payment and shipper details without losing orders.** Start from `Orders` and join each lookup table with `LEFT JOIN`. A code that is `NULL` or has no matching lookup row leaves the order in place and gives `NULL` for the lookup value.

```sql
SELECT
    O.OrderID,
    O.OrderDate,
    O.PaymentID,
    O.ShipperID,
    P.PaymentType,
    S.CompanyName
FROM Orders AS O
LEFT JOIN Payments AS P
    ON O.PaymentID = P.PaymentID
LEFT JOIN Shippers AS S
    ON O.ShipperID = S.ShipperID
ORDER BY O.OrderID;
```

| OrderID | OrderDate | PaymentID | ShipperID | PaymentType | CompanyName |
|---:|---|---:|---:|---|---|
| 1 | 2025-12-24 | 1 | 1 | UPI | FastShip |
| 2 | 2025-12-25 | 1 | 1 | UPI | FastShip |
| 3 | 2025-12-31 | NULL | NULL | NULL | NULL |

All three orders remain at this stage. The last row shows why an inner join would be wrong for this report.

**3. Show `Unknown` for unavailable lookup values.** Each `CASE` changes a `NULL` lookup value to the requested label. The ID columns are still used in the join conditions but need not appear in the output.

```sql
SELECT
    O.OrderID,
    O.OrderDate,
    CASE
        WHEN P.PaymentType IS NULL THEN 'Unknown'
        ELSE P.PaymentType
    END AS payment_type,
    CASE
        WHEN S.CompanyName IS NULL THEN 'Unknown'
        ELSE S.CompanyName
    END AS shipper_name
FROM Orders AS O
LEFT JOIN Payments AS P
    ON O.PaymentID = P.PaymentID
LEFT JOIN Shippers AS S
    ON O.ShipperID = S.ShipperID
ORDER BY O.OrderID;
```

| OrderID | OrderDate | payment_type | shipper_name |
|---:|---|---|---|
| 1 | 2025-12-24 | UPI | FastShip |
| 2 | 2025-12-25 | UPI | FastShip |
| 3 | 2025-12-31 | Unknown | Unknown |

**4. Keep the last seven days and sort newest first.** `BETWEEN` includes both endpoints. For this example, it keeps 2025-12-25 through 2025-12-31. The final `ORDER BY` uses descending date and descending ID for date ties.

```sql
SELECT O.OrderID, O.OrderDate
FROM Orders AS O
WHERE DATE(O.OrderDate) BETWEEN
      DATE((SELECT MAX(DATE(OrderDate)) FROM Orders), '-6 days')
      AND
      (SELECT MAX(DATE(OrderDate)) FROM Orders)
ORDER BY O.OrderDate DESC, O.OrderID DESC;
```

| OrderID | OrderDate |
|---:|---|
| 3 | 2025-12-31 |
| 2 | 2025-12-25 |

Order 1 drops out because 2025-12-24 is before the window. Combining this filter and sort with Step 3 gives the complete query saved above:

| OrderID | OrderDate | payment_type | shipper_name |
|---:|---|---|---|
| 3 | 2025-12-31 | Unknown | Unknown |
| 2 | 2025-12-25 | UPI | FastShip |

## My solution — SQL Server

SQL Server uses `CAST(... AS date)` for SQLite's `DATE(...)` conversion and `DATEADD` for the six-day subtraction. The joins, `CASE` expressions, inclusive window, and sorting follow your SQLite query.

```sql
SELECT
    O.OrderID,
    O.OrderDate,
    CASE
        WHEN P.PaymentType IS NULL THEN 'Unknown'
        ELSE P.PaymentType
    END AS payment_type,
    CASE
        WHEN S.CompanyName IS NULL THEN 'Unknown'
        ELSE S.CompanyName
    END AS shipper_name
FROM Orders AS O
LEFT JOIN Payments AS P
    ON O.PaymentID = P.PaymentID
LEFT JOIN Shippers AS S
    ON O.ShipperID = S.ShipperID
WHERE CAST(O.OrderDate AS date) BETWEEN
      DATEADD(day, -6, (SELECT MAX(CAST(OrderDate AS date)) FROM Orders))
      AND
      (SELECT MAX(CAST(OrderDate AS date)) FROM Orders)
ORDER BY O.OrderDate DESC, O.OrderID DESC;
```

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 17. The supplied query uses PostgreSQL syntax.

```sql
SELECT o.OrderID,
       o.OrderDate,
       COALESCE(pay.PaymentType, 'Unknown') AS payment_type,
       COALESCE(sh.CompanyName, 'Unknown')  AS shipper_name
FROM Orders AS o
LEFT JOIN Payments AS pay ON pay.PaymentID = o.PaymentID
LEFT JOIN Shippers AS sh ON sh.ShipperID = o.ShipperID
WHERE o.OrderDate >= (
    SELECT MAX(latest.OrderDate)::date - 6
    FROM Orders AS latest
)
ORDER BY o.OrderDate DESC, o.OrderID DESC;
```

**What this tests.** Chained left joins, labels for unmatched lookup rows, and a seven-day window anchored to the data.

**The approach.** Keep each order, attach payment and shipper details when available, label missing values, then retain dates from six days before the latest order date.

**Why this way.** Left joins preserve orders with `NULL` or unrecognized codes. The source's `COALESCE` has the same result as your `CASE` expressions here. Anchoring the window to `MAX(OrderDate)` makes it independent of today's date.

**Common mistakes.** Inner joins that drop orders with missing codes; using today's date instead of the latest data date; subtracting seven days while also including the latest day; and sorting dates ascending.
