# PNP Q019. Units sold per product

![SOLVED](<../../_badges/solved.svg>) · Solved (recorded): 2026-10-27 ![EASY](<../../_badges/easy.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 19, pp. 34–35. **Difficulty:** Easy.

**Business scenario.** Merchandising decides which products get the end-of-aisle display in the app. They look at three numbers per product: units sold, the number of order lines, and the number of distinct orders. A product bought in bulk by a few customers and one bought one at a time by many need different promotions. Cancellations and returns are not recorded here, so every order line counts as sold.

**Task.** For each product that appears in OrderDetails , return units sold, order lines and distinct orders. Sort by units sold, highest first, then ProductID .

**Expected output (as supplied):**

```text
ProductID
Product
units_sold : sum of Quantity
order_lines : rows in OrderDetails for the product
orders : distinct OrderID s containing the product
```

## My solution — SQLite

Your final query follows the prompt's literal instruction to include each `ProductID` appearing in `OrderDetails`:

```sql
SELECT
    OD.ProductID,
    P.Product,
    SUM(OD.Quantity) AS units_sold,
    COUNT(OD.ProductID) AS order_lines,
    COUNT(DISTINCT OD.OrderID) AS orders
FROM OrderDetails AS OD
LEFT JOIN Products AS P
    ON OD.ProductID = P.ProductID
GROUP BY OD.ProductID, P.Product
ORDER BY units_sold DESC, OD.ProductID ASC;
```

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 19. The supplied query uses PostgreSQL syntax.

```sql
SELECT p.ProductID,
       p.Product,
       SUM(od.Quantity)           AS units_sold,
       COUNT(*)                   AS order_lines,
       COUNT(DISTINCT od.OrderID) AS orders
FROM OrderDetails AS od
JOIN Products AS p ON p.ProductID = od.ProductID
GROUP BY p.ProductID, p.Product
ORDER BY units_sold DESC NULLS LAST, p.ProductID;
```

**What this tests.** Counting units, order lines, and distinct orders at the product level.

**The approach.** Match order lines to product rows, group by product, sum quantities, count detail rows, and count distinct order IDs.

**Why this way.** `COUNT(DISTINCT od.OrderID)` does not count the same order twice when it has multiple lines for one product. `NULLS LAST` puts products with no computable quantity total after numeric totals in PostgreSQL.

**Source discrepancy.** The official `JOIN` is an inner join, so it excludes four `ProductID` values found in the supplied `OrderDetails` data that have no matching `Products` row. Your `LEFT JOIN` retains those IDs with `Product = NULL`, matching the prompt's literal “each product that appears in OrderDetails.” The prompt does not state how unmatched IDs should be treated.

**Common mistakes.** Using `COUNT(OrderID)` for the distinct-order measure; counting product rows instead of detail rows; or overlooking the different outputs produced by the two join choices on unmatched product IDs.
