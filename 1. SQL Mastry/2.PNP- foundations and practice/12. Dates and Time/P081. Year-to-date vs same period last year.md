# PNP Q081. Year-to-date vs same period last year

![NOT SOLVED YET](<../../_badges/not-solved-yet.svg>) ![HARD](<../../_badges/hard.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 81, pp. 153–155. **Difficulty:** Hard.

**Primary topic:** Anchored date ranges with conditional aggregation. **Also covers:** Multiple CTEs, Interval arithmetic and 29 February, FILTER for two periods in one pass, Growth percentage.

**Business scenario.** The finance team sends the board a one-line trading update: orders and order value so far this year, against the same stretch of days last year. Comparing a partial current year with the whole of last year makes every update before December look like a decline. So "same period last year" means from 1 January of the prior year to the same calendar day as the latest order date, one year earlier.

**Task.** Using the last order date in the data as the end of the current year-to-date (YTD) period, return one row with the YTD start and end, the matching prior-year start and end, orders and order value in each period, and the growth in order value as a percentage. When the YTD end is 29 February, the prior period must end on 28 February. Count every order in Orders as placed; cancellations are not modelled.

**Expected output (as supplied):**

```text
ytd_start : 1 January of the anchor year
ytd_end : the last order date in the data
prior_ytd_start , prior_ytd_end : the same dates one year earlier
ytd_orders , ytd_value : order count and SUM(Total_Order_Amount) in the current period
prior_ytd_orders , prior_ytd_value : the same for the prior period
value_growth_pct : percentage change in order value
```

**Tables required:** Orders.

**SQL concepts named in the source:** anchoring to MAX(OrderDate) , DATE_TRUNC('year', ...) , INTERVAL '1 year' arithmetic and leap days, half-open date ranges, conditional aggregation with FILTER , growth percentage with NULLIF .

The source is a text-based PDF; no separate question image was supplied.

*Illustrative example chosen to show the 29 February rule. The latest order date is 2024-02-29.*

Input — `Orders`:

| OrderID | OrderDate | Total_Order_Amount |
|---:|---|---:|
| 1 | 2023-01-10 | 100 |
| 2 | 2023-03-01 | 200 |
| 3 | 2024-01-10 | 150 |
| 4 | 2024-02-29 | 150 |

Expected output:

| ytd_start | ytd_end | prior_ytd_start | prior_ytd_end | ytd_orders | ytd_value | prior_ytd_orders | prior_ytd_value | value_growth_pct |
|---|---|---|---|---:|---:|---:|---:|---:|
| 2024-01-01 | 2024-02-29 | 2023-01-01 | 2023-02-28 | 2 | 300 | 1 | 100 | 200.00 |

The 2023-03-01 order is outside the prior-year comparison period.
