# Advance String Functions, Regex and Clauses - Quick Revision Notes

**Main idea:** clean text before comparing it, and check which pattern syntax your SQL engine supports. These invented examples teach the operations; they are not solutions to PNP practice questions.

## 1. Start with messy text

| row_id | city |
|---:|---|
| 1 | `' Mumbai '` |
| 2 | `'mumbai'` |
| 3 | `'Delhi'` |
| 4 | `NULL` |

Quotes show where the sample text begins and ends; the quotes are not stored in `city`.

## 2. TRIM and case conversion change the comparison value

~~~sql
SELECT row_id,
       TRIM(city) AS clean_city,
       LOWER(TRIM(city)) AS compare_city
FROM CityLabels
ORDER BY row_id;
~~~

| row_id | clean_city | compare_city |
|---:|---|---|
| 1 | Mumbai | mumbai |
| 2 | mumbai | mumbai |
| 3 | Delhi | delhi |
| 4 | NULL | NULL |

`TRIM` removes surrounding spaces. `LOWER` or `UPPER` puts text into one case for comparison. A `NULL` remains `NULL`. Cleaning values in the output is separate from deciding which rows pass a `WHERE` clause.

## 3. LIKE patterns: percent and underscore

With the example strings `Tea`, `Team`, and `Top`:

| Pattern | Meaning | Example matches |
|---|---|---|
| `'Te%'` | Starts with Te; `%` means zero or more characters | Tea, Team |
| `'Te_'` | Starts with Te and has exactly one more character | Tea |
| `'%op'` | Ends with op | Top |

The wildcard `%` belongs to `LIKE`. The wildcard `_` matches exactly one character. A literal dot in a `LIKE` pattern is just a dot; square-bracket character classes are **not** SQLite `LIKE` syntax. Pattern matching a `NULL` value does not return true.

## 4. SQLite GLOB uses different wildcards

SQLite `GLOB` uses `*` for zero or more characters, `?` for one character, and brackets for a character choice. It is case-sensitive.

| SQLite expression | Example meaning |
|---|---|
| `city GLOB 'M*'` | Begins with uppercase M |
| `city GLOB '?op'` | Three characters ending in op |
| `city GLOB '[MD]*'` | Begins with M or D |

A `GLOB` pattern and a `LIKE` pattern cannot be swapped by changing only the operator: their wildcards differ. `LIKE 'M%'` and `GLOB 'M*'` use different syntax.

## 5. SQL Server pattern reminder

SQL Server `LIKE` uses `%` and `_` too. Its `LIKE` also supports bracket character classes such as `'[AEIOU]%'`. SQLite `LIKE` treats those brackets as ordinary characters; SQLite `GLOB` uses brackets for a character class instead. Case behavior for `LIKE` depends on the engine and collation. If a case-independent comparison is required, normalize both sides with `LOWER` or `UPPER` and test the target dialect.

Regex functions and operators vary across SQL engines. State the engine before writing a regex pattern, especially when transferring a solution between SQLite and SQL Server.

## 6. Keep logical conditions visible

Use `AND` when two requirements must both hold, and `OR` when either can hold. Parenthesize mixed conditions so the intended grouping is visible:

~~~sql
WHERE (city IS NULL OR TRIM(city) = '')
  AND row_id > 0
~~~

This example identifies missing or blank city text for positive row IDs. `city = NULL` is not a valid test for missing data; use `IS NULL`.

## Quick check

1. Have surrounding spaces and case variants been handled consistently?
2. Does the chosen operator use `%`, `*`, or another wildcard?
3. Is a dot or bracket character literal in this SQL dialect?
4. Could the input be `NULL` or an empty string?
5. Are `AND` and `OR` grouped as the question intends?
