# PNP Q004. Customer emails that cannot be delivered

![SOLVED](<../../_badges/solved.svg>) ![EASY](<../../_badges/easy.svg>) · Solved (recorded): 2026-10-27

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 4, pp. 15–16. **Difficulty:** Easy.

**Primary topic:** LIKE pattern matching. **Also covers:** NOT LIKE, CASE to label the problem.

**Business scenario.** The marketing operations team is about to send a re-engagement campaign. Every hard bounce hurts the sender reputation, so they want to catch addresses that cannot work before the send. A valid address here has no spaces and the shape something@something.something .

**Task.** Return every customer whose Email is missing, contains a space, or does not match the shape _@_._ (at least one character, an @, at least one character, a dot, at least one character). Label the problem. Sort by CustomerID .

**Expected output (as supplied):**

```text
CustomerID , FirstName , LastName
Email : as stored
issue : Missing , Contains a space or Not in name@domain.tld form
```

**Tables required:** Customers.

**SQL concepts named in the source:** LIKE wildcards ( % any run of characters, _ exactly one), NOT LIKE, combining conditions with OR, NULL behaviour of LIKE.

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

```sql
SELECT
    CustomerID,
    FirstName,
    LastName,
    Email,
    CASE
        WHEN Email IS NULL OR TRIM(Email) = '' THEN 'Missing'
        WHEN Email LIKE '% %' THEN 'Contains a space'
        WHEN Email NOT LIKE '%_@_%._%' THEN 'Not in name@domain.tld form'
    END AS issue
FROM Customers
WHERE (
    CASE
        WHEN Email IS NULL OR TRIM(Email) = '' THEN 'Missing'
        WHEN Email LIKE '% %' THEN 'Contains a space'
        WHEN Email NOT LIKE '%_@_%._%' THEN 'Not in name@domain.tld form'
    END
) IS NOT NULL
ORDER BY CustomerID;
```

### Step-by-step explanation with one example

**Starting data.** We use the illustrative `Customers` rows from the question. The fourth email is valid, so it should not appear in the result.

| CustomerID | FirstName | LastName | Email |
|---:|---|---|---|
| 1 | Asha | Rao | NULL |
| 2 | Ben | Das | `ben das@example.com` |
| 3 | Cia | Sen | `cia.example.com` |
| 4 | Dev | Roy | `dev@example.com` |

**1. Assign an issue to each email.** The `CASE` checks conditions in order and returns the label for the first match. `Email IS NULL OR TRIM(Email) = ''` catches a missing address, including an empty string or only spaces. The next check catches any literal space. The pattern `%_@_%._%` requires at least one character before `@`, between `@` and the dot, and after the dot. If none of the checks matches, `CASE` has no `ELSE` and returns SQL `NULL`.

```sql
SELECT
    CustomerID,
    Email,
    CASE
        WHEN Email IS NULL OR TRIM(Email) = '' THEN 'Missing'
        WHEN Email LIKE '% %' THEN 'Contains a space'
        WHEN Email NOT LIKE '%_@_%._%' THEN 'Not in name@domain.tld form'
    END AS issue
FROM Customers
ORDER BY CustomerID;
```

| CustomerID | Email | issue |
|---:|---|---|
| 1 | NULL | Missing |
| 2 | `ben das@example.com` | Contains a space |
| 3 | `cia.example.com` | Not in name@domain.tld form |
| 4 | `dev@example.com` | NULL |

Customer 1 is labeled `Missing`. Customer 2 contains a space, so that label is chosen. Customer 3 has no `@` and fails the shape check. Customer 4 passes the checks; its `issue` is SQL `NULL`, not the text `'NULL'`.

**2. Remove rows without an issue.** The `WHERE` repeats the same `CASE` and keeps only rows where its result is not `NULL`. This drops customer 4 while retaining customers 1, 2, and 3. The full query also selects the requested name columns and sorts by `CustomerID`.

```sql
WHERE (
    CASE
        WHEN Email IS NULL OR TRIM(Email) = '' THEN 'Missing'
        WHEN Email LIKE '% %' THEN 'Contains a space'
        WHEN Email NOT LIKE '%_@_%._%' THEN 'Not in name@domain.tld form'
    END
) IS NOT NULL
```

| CustomerID | FirstName | LastName | Email | issue |
|---:|---|---|---|---|
| 1 | Asha | Rao | NULL | Missing |
| 2 | Ben | Das | `ben das@example.com` | Contains a space |
| 3 | Cia | Sen | `cia.example.com` | Not in name@domain.tld form |

**Manual check.** The three invalid addresses are included and sorted 1, 2, 3. The valid address is excluded. This exact cleaned query was executed in SQLite on the illustrative rows and produced the table above. The shape pattern is the simple check required by this question; it is not a full email validator.

### Alternative solution using a CTE

The `email_issues` CTE assigns one `issue` value to every customer, matching the four-row intermediate table in step 1 above. The outer query keeps rows whose `issue` is not SQL `NULL`, so the valid email is removed. This writes the `CASE` only once and produces the same three-row result.

```sql
WITH email_issues AS (
    SELECT
        CustomerID,
        FirstName,
        LastName,
        Email,
        CASE
            WHEN Email IS NULL OR TRIM(Email) = '' THEN 'Missing'
            WHEN Email LIKE '% %' THEN 'Contains a space'
            WHEN Email NOT LIKE '%_@_%._%' THEN 'Not in name@domain.tld form'
        END AS issue
    FROM Customers
)
SELECT CustomerID, FirstName, LastName, Email, issue
FROM email_issues
WHERE issue IS NOT NULL
ORDER BY CustomerID;
```

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 4.

```sql
SELECT c.CustomerID,
       c.FirstName,
       c.LastName,
       c.Email,
       CASE WHEN c.Email IS NULL OR TRIM(c.Email) = '' THEN 'Missing'
            WHEN c.Email LIKE '% %'                    THEN 'Contains a space'
            ELSE 'Not in name@domain.tld form'
       END AS issue
FROM Customers AS c
WHERE c.Email IS NULL
   OR TRIM(c.Email) = ''
   OR c.Email LIKE '% %'
   OR c.Email NOT LIKE '%_@_%._%'
ORDER BY c.CustomerID;
```

**What this tests.** Combining `NULL`, blank-string, literal-space, and simple `LIKE` pattern checks, then labeling the matching rows.

**The approach.** The answer key filters with four `OR` conditions and uses `CASE` to label each retained row. Your solution uses the same checks but repeats `CASE` in `WHERE` to exclude rows whose label would be `NULL`.

**Why this way.** Checking missing values first makes whitespace-only email addresses `Missing`. `CASE` chooses one label per row, and the final `ORDER BY` gives a stable customer order.

**Common mistakes.** `Email = NULL` cannot detect missing addresses; use `IS NULL`. A quoted `'NULL'` is text, not SQL `NULL`. Without a `WHERE` filter, valid emails appear with a null issue. Keep the shape pattern as `%_@_%._%` in executable SQL, without Markdown escape characters.
