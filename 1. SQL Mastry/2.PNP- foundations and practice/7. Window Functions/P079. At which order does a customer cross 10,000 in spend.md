# PNP Q079. At which order does a customer cross 10,000 in spend?

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 79, pp. 148–150. **Difficulty:** Hard.

**Primary topic:** Running SUM per customer with an explicit ROWS frame. **Also covers:** First crossing with DISTINCT ON, Named WINDOW clause, Date difference from first order, NULL amounts.

**Business scenario.** The CRM team is designing a "Gold" tier that unlocks once a customer's lifetime order value reaches 10,000. Before they promise anything, they want to know how quickly customers get there: on which order number the threshold is crossed, on what date, and how many days after the first order. If most customers cross within a few months, the tier is a retention tool; if it takes years, it is a loyalty reward for a handful.

**Task.** For each customer whose cumulative Total_Order_Amount reaches at least 10,000, return the first order at which the running total reaches 10,000: its position in the customer's order sequence, its date, the days since the customer's first order, and the running total at that point. Customers who never reach 10,000 are left out. Sort by days to cross, fastest first.

**Expected output (as supplied):**

```text
CustomerID
crossing_order_number : position of the crossing order (1 = first order)
crossing_order_date : OrderDate of that order
days_from_first_order : days between the first order and the crossing order
spend_at_crossing : running total including the crossing order
```

**Tables required:** Orders.

**SQL concepts named in the source:** running SUM with an explicit ROWS frame, ROWS vs the default RANGE frame on tied dates, named WINDOW , picking the first qualifying row per group, date difference, NULL amounts in a running total.

The source is a text-based PDF; no separate question image was supplied.
