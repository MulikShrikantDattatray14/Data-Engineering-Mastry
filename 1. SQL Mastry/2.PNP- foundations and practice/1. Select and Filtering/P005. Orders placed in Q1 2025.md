# PNP Q005. Orders placed in Q1 2025

![SOLVED](<../../_badges/solved.svg>) ![EASY](<../../_badges/easy.svg>) · Solved (recorded): 2026-10-27

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 5, pp. 16–17. **Difficulty:** Easy.

**Primary topic:** Date range filtering. **Also covers:** Half-open ranges vs BETWEEN, DATE literals.

**Business scenario.** Finance is closing January to March 2025 and needs the orders placed in that quarter to tie against the payment gateway report. Cancellations and refunds are not recorded in this dataset, so every row in Orders counts as a placed order.

**Task.** Return every order with an OrderDate from 1 January 2025 to 31 March 2025 inclusive. Sort by OrderDate , then OrderID .

**Expected output (as supplied):**

```text
OrderID
CustomerID
OrderDate
Total_Order_Amount
```

**Tables required:** Orders.

**SQL concepts named in the source:** date range filters, half-open ranges, BETWEEN, ISO DATE literals.

## My solution — SQLite

```sql
SELECT
    OrderID,
    CustomerID,
    OrderDate,
    Total_Order_Amount
FROM Orders
WHERE OrderDate >= '2025-01-01'
  AND OrderDate < '2025-04-01'
ORDER BY (OrderDate), OrderID;
```

### Step-by-step explanation with one example

**Starting data.** These are the illustrative `Orders` rows from the question. One row is one placed order.

| OrderID | CustomerID | OrderDate | Total_Order_Amount |
|---:|---:|---|---:|
| 1 | 10 | 2024-12-31 | 50 |
| 2 | 11 | 2025-01-01 | 100 |
| 3 | 12 | 2025-03-31 | 200 |
| 4 | 13 | 2025-04-01 | 300 |

**1. Keep orders from the start of the quarter.** `OrderDate >= '2025-01-01'` includes the first day of 2025. Order 1 is dated 2024-12-31, so it is removed. Orders 2, 3, and 4 pass this first condition.

```sql
SELECT OrderID, CustomerID, OrderDate, Total_Order_Amount
FROM Orders
WHERE OrderDate >= '2025-01-01'
ORDER BY OrderDate, OrderID;
```

| OrderID | CustomerID | OrderDate | Total_Order_Amount |
|---:|---:|---|---:|
| 2 | 11 | 2025-01-01 | 100 |
| 3 | 12 | 2025-03-31 | 200 |
| 4 | 13 | 2025-04-01 | 300 |

**2. Stop just before the next quarter.** `OrderDate < '2025-04-01'` includes all of March 31 but excludes April 1. Combined with step 1, it removes order 4 and keeps orders 2 and 3.

```sql
WHERE OrderDate >= '2025-01-01'
  AND OrderDate < '2025-04-01'
```

| OrderID | CustomerID | OrderDate | Total_Order_Amount |
|---:|---:|---|---:|
| 2 | 11 | 2025-01-01 | 100 |
| 3 | 12 | 2025-03-31 | 200 |

This is a **half-open range**: the beginning is included and the beginning of April is excluded. It also handles a value such as `2025-03-31 15:00:00` because that time is still before April 1. An upper bound of `<= '2025-03-31'` could exclude that value if the column stores times.

**3. Return the required columns in order.** `ORDER BY (OrderDate), OrderID` sorts by the full order date, then uses `OrderID` when dates match. The parentheses around `OrderDate` do not change the sort. In the sample, January 1 comes before March 31.

**Manual check.** The sample output is orders 2 and 3, with both quarter boundary dates included. The cleaned query was executed in SQLite on these four rows and returned exactly that result. A separate boundary check also included `2025-03-31 15:00:00` and excluded `2025-04-01 00:00:00`.

## My solution — SQL Server

The same date range and sort work in SQL Server. The unnecessary parentheses around `OrderDate` are omitted here without changing your logic.

```sql
SELECT
    OrderID,
    CustomerID,
    OrderDate,
    Total_Order_Amount

```

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 5. The source uses PostgreSQL `DATE` literals.

```sql
SELECT o.OrderID,
       o.CustomerID,
       o.OrderDate,
       o.Total_Order_Amount
FROM Orders AS o
WHERE o.OrderDate >= DATE '2025-01-01'
  AND o.OrderDate <  DATE '2025-04-01'
ORDER BY o.OrderDate, o.OrderID;
```

**What this tests.** Filtering a calendar quarter with correct inclusive and exclusive boundaries, then sorting the requested order rows.

**The approach.** Keep dates on or after January 1 and before April 1. Select the four required columns and sort by `OrderDate`, then `OrderID`.

**Why this way.** An exclusive April 1 boundary includes every time on March 31 when `OrderDate` stores a timestamp. The answer key's `DATE '...'` syntax expresses typed date literals in its source dialect; your quoted ISO dates suit SQLite and SQL Server.

**Common mistakes.** `OrderDate <= '2025-03-31'` can miss March 31 orders with times. `ORDER BY DATE(OrderDate)` loses the time part and can give the wrong order within a day. April 1 orders must be excluded.
