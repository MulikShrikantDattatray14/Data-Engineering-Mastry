# PNP Q095. Debug a revenue-by-category query that gives wrong numbers

![NOT SOLVED YET](<../../_badges/not-solved-yet.svg>) ![UNRATED](<../../_badges/unrated.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 95, pp. 193–196. **Difficulty:** Expert.

**Primary topic:** Debugging an incorrect query. **Also covers:** One-to-many fan-out, WHERE clause on a LEFT JOIN, Anchored calendar-year filter, FULL JOIN to keep unmatched rows.

**Business scenario.** The category management team reviews every category once a year, including the ones that sold nothing, because a zero is a decision too. An analyst wrote the query that feeds the review. Finance says the category numbers add up to far more than the company sold, and the category manager for a newly added category cannot find it in the report. You have been asked to find out why and ship a corrected version.

**Task.** The analyst's query is reproduced in Step 3. It runs without error. Find every fault, show how a row-count or total check exposes each one, and write the corrected report: for the latest calendar year in the data, one row per category with the number of orders that contained it and its list-price value. Categories with no sales must appear with zeros, and sales of products with no matching category must appear as Unmapped . Sort from the lowest value up, so the review opens with the categories that need a decision.

**Expected output (as supplied):**

```text
CategoryName : category name, or Unmapped
orders : distinct orders in the latest year with at least one line in the category
list_price_value : SUM(Quantity * Sale_Price) over those lines
```

**Tables required:** Orders , OrderDetails , Products , Category.

**SQL concepts named in the source:** grain and fan-out, how a WHERE filter on the right-hand table of a LEFT JOIN turns it into an inner join, anchored half-open year boundaries, FULL JOIN for unmatched rows on both sides, reconciliation checks.

**Starting query supplied for this debugging task:**

```sql
SELECT cat.CategoryName,

COUNT(o.OrderID)           AS orders,

SUM(o.Total_Order_Amount) AS revenue

FROM Category AS cat

LEFT JOIN Products      AS p ON p.CategoryID = cat.CategoryID

LEFT JOIN OrderDetails AS od ON od.ProductID = p.ProductID

LEFT JOIN Orders        AS o ON o.OrderID = od.OrderID

WHERE o.OrderDate >= (SELECT MAX(OrderDate) FROM Orders) - INTERVAL '1 year'

GROUP BY cat.CategoryName

ORDER BY revenue DESC;
```
