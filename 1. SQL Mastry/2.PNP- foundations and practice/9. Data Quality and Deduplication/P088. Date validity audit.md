# PNP Q088. Date validity audit

![NOT SOLVED YET](<../../_badges/not-solved-yet.svg>) ![UNRATED](<../../_badges/unrated.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 88, pp. 171–174. **Difficulty:** Expert.

**Primary topic:** Invalid date detection. **Also covers:** Rule table with CROSS JOIN LATERAL (VALUES ...), UNION ALL across tables, Anchored date logic, LEFT JOIN.

**Business scenario.** The logistics team's delivery-time dashboard shows a handful of negative delivery times and a few orders that seem to take forever. The data quality lead wants two things from one rule set: a daily scorecard with a count per rule, zeros included, and an exception list the support team can work through, one row per broken rule per record. Error rows will be excluded from delivery KPIs until fixed; warnings stay in but get reviewed.

**Task.** Check every order and every customer against the date rules below. Return one row per rule: its number, name and severity, how many records were checked, how many break it, the violation rate, and up to five example IDs. A rule with no violations must still appear, with 0. The row-level exception list goes in Step 10. Rules (all day differences in whole days): # Rule Severity Condition 1 Order date missing error OrderDate is NULL 2 Shipped before ordered error ShipDate < OrderDate 3 Delivered before shipped error DeliveryDate < ShipDate 4 Delivered before ordered error DeliveryDate < OrderDate 5 Delivered with no ship date error DeliveryDate present, ShipDate NULL 6 Ordered before customer sign-up warning OrderDate < DateEntered 7 Delivered after the 7-day promise warning DeliveryDate - OrderDate > 7 8 Not shipped 14+ days after order warning no ship or delivery date, and the latest order date in the data is 14+ days after OrderDate 9 Customer sign-up date missing warning DateEntered is NULL

**Expected output (as supplied):**

```text
rule_id , rule , severity : from the table above
records_checked : orders for rules 1-8, customers for rule 9
violations : records that break the rule (0 when none)
violation_pct : violations as a percentage of records checked, 2 decimals
example_ids : up to five OrderID s (or CustomerID s for rule 9) that break it, lowest first; NULL when there are none
```

**Tables required:** Orders , Customers.

**SQL concepts named in the source:** expressing rules as data with LATERAL VALUES, three-valued logic in comparisons, UNION ALL with aligned columns and typed NULLs, anchoring "today" to the data, LEFT JOIN to keep orders with no customer.

The source is a text-based PDF; no separate question image was supplied.
