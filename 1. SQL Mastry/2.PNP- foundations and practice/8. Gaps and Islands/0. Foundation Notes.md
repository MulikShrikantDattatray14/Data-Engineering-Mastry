# Gaps and Islands - Quick Revision Notes

**An island is a run of consecutive values; a gap is what is missing between runs.** Before writing SQL, define what “next” means: next integer, next calendar day, next month, or next business day.

## 1. Prepare one row per step

Use generic `MachineRuns` data. Machine A has a duplicate record on April 2; that is still only one active day.

| machine | run_day |
|---|---|
| A | 2025-04-01 |
| A | 2025-04-02 |
| A | 2025-04-02 |
| A | 2025-04-04 |
| A | 2025-04-05 |
| B | 2025-04-02 |

First remove duplicate machine/day pairs. Otherwise `ROW_NUMBER` advances twice on April 2 and incorrectly breaks a consecutive run.

```sql
WITH distinct_days AS (
    SELECT DISTINCT machine, run_day
    FROM MachineRuns
)
SELECT machine, run_day
FROM distinct_days
ORDER BY machine, run_day;
```

| machine | run_day |
|---|---|
| A | 2025-04-01 |
| A | 2025-04-02 |
| A | 2025-04-04 |
| A | 2025-04-05 |
| B | 2025-04-02 |

## 2. Why value minus row number makes islands

Number the distinct days **inside each machine**. Then shift each day back by its row number.

| machine | run_day | rn | `DATE(run_day, '-' || rn || ' days')` |
|---|---|---:|---|
| A | 2025-04-01 | 1 | 2025-03-31 |
| A | 2025-04-02 | 2 | 2025-03-31 |
| A | 2025-04-04 | 3 | 2025-04-01 |
| A | 2025-04-05 | 4 | 2025-04-01 |
| B | 2025-04-02 | 1 | 2025-04-01 |

April 1 → April 2 advances both date and row number by one day, so their difference stays fixed at March 31. At the jump to April 4, the date advances two days but row number only one, so the key changes. Group by **machine and key**: A and B must remain separate even when their shifted dates match.

```sql
WITH distinct_days AS (
    SELECT DISTINCT machine, run_day
    FROM MachineRuns
),
numbered AS (
    SELECT machine, run_day,
           ROW_NUMBER() OVER (
               PARTITION BY machine ORDER BY run_day
           ) AS rn
    FROM distinct_days
),
islands AS (
    SELECT machine, run_day,
           DATE(run_day, '-' || rn || ' days') AS group_key
    FROM numbered
)
SELECT machine,
       MIN(run_day) AS start_day,
       MAX(run_day) AS end_day,
       COUNT(*) AS days_in_run
FROM islands
GROUP BY machine, group_key
ORDER BY machine, start_day;
```

| machine | start_day | end_day | days_in_run |
|---|---|---|---:|
| A | 2025-04-01 | 2025-04-02 | 2 |
| A | 2025-04-04 | 2025-04-05 | 2 |
| B | 2025-04-02 | 2025-04-02 | 1 |

For distinct consecutive integers, the simpler key is `value - ROW_NUMBER()`. For monthly runs, first reduce to one row per month and use a month index such as `year * 12 + month` before subtracting the row number.

## 3. Find missing ranges with LEAD

For observed IDs `1, 2, 5, 6, 9`, the next observed value tells us what is missing after each row.

| id | next_id | missing between them |
|---:|---:|---|
| 1 | 2 | none |
| 2 | 5 | 3–4 |
| 5 | 6 | none |
| 6 | 9 | 7–8 |
| 9 | NULL | no next observed ID |

```sql
WITH ordered_ids AS (
    SELECT id,
           LEAD(id) OVER (ORDER BY id) AS next_id
    FROM ObservedIds
)
SELECT id + 1 AS gap_start,
       next_id - 1 AS gap_end
FROM ordered_ids
WHERE next_id > id + 1
ORDER BY gap_start;
```

The output is `(3, 4)` and `(7, 8)`. The last observed ID has no next row, so it does not imply an ending gap unless an upper boundary is supplied. Date gaps use the same idea with previous-day and next-day date arithmetic.

## 4. Boundary method and common mistakes

Another pattern marks an island start when `LAG(value)` is NULL or the current value is not the expected successor. A running `SUM(is_start) OVER (ORDER BY ...)` then assigns a group number. This is useful when the rule includes a **change of status** as well as a missing date, or when the next step is a business calendar rather than a simple +1.

Check these before finalizing:

- Define the exact unit of consecutiveness. Calendar days and rows are different when dates are missing.
- Remove duplicate keys before `ROW_NUMBER` or `LAG` if repeated records should count as one step.
- Partition by the entity: a run belonging to A must never merge with B.
- Sort on the actual sequence key, not an unrelated ID.
- Decide whether the result needs islands, missing gaps, the longest run, or every row inside a run. The final grouping/filter depends on that output.
- SQLite uses `DATE(d, '-1 day')` and string concatenation `||`. Translate date arithmetic for MySQL, PostgreSQL or SQL Server.

**Source coverage:** the advanced volume presents consecutive IDs, days and months; the interview bank uses the same island idea for consecutive active months.
