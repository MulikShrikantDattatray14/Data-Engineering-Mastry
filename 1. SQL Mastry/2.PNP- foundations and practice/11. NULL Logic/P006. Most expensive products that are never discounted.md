# PNP Q006. Most expensive products that are never discounted

![SOLVED](<../../_badges/solved.svg>) · Solved (recorded): 2026-10-27 ![EASY](<../../_badges/easy.svg>)

## Question and image

**Source:** [100 SQL Interview Questions](<../Source Materials/Updated_100_SQL_Interview_Questions.pdf>), question 6, pp. 17–19. **Difficulty:** Easy.

**Primary topic:** NULL handling (IS NULL, NULLIF, COALESCE). **Also covers:** CAST to text for display, ORDER BY with LIMIT.

**Business scenario.** The promotions team is planning a festive sale and wants to start with high-value products that currently sell at the printed price, with no discount at all. They want a short list of the ten most expensive such products, with a discount column that reads "Full price" instead of a number, so the sheet is easy to scan.

**Task.** Compute each product's discount amount as Market_Price - Sale_Price , but store "no discount" as NULL rather than 0. Return the ten most expensive products whose discount is NULL, with a discount_display column that shows the text Full price for them. A product with a missing Sale_Price or Market_Price has an unknown discount, not a full price, and must never take a slot. Sort by Sale_Price descending, then ProductID .

**Expected output (as supplied):**

```text
ProductID , Product , Brand
Sale_Price , Market_Price
discount_display : the discount as text, or Full price when there is none
```

**Tables required:** Products.

**SQL concepts named in the source:** creating NULL on purpose with NULLIF, testing with IS NULL, why = NULL never matches, COALESCE with a type cast, ORDER BY with LIMIT.

The source is a text-based PDF; no separate question image was supplied.

## My solution — SQLite

```sql
SELECT
    ProductID,
    Product,
    Brand,
    Sale_Price,
    Market_Price,
    'Full price' AS discount_display
FROM Products
WHERE Market_Price - Sale_Price = 0
ORDER BY Sale_Price DESC, ProductID ASC
LIMIT 10;
```

### Step-by-step explanation with one example

**Starting data.** Use the same four illustrative `Products` rows from the question. The prices are enough to decide which products have no discount.

| ProductID | Product | Brand | Sale_Price | Market_Price |
|---:|---|---|---:|---:|
| 1 | Mug | Home | 100 | 100 |
| 2 | Lamp | Home | 150 | 150 |
| 3 | Mystery | Home | NULL | 100 |
| 4 | Bottle | Home | 90 | 100 |

**1. Compare the printed and selling prices.** Subtract `Sale_Price` from `Market_Price` for each product. A zero difference means that the product sells at its printed price.

```sql
SELECT
    ProductID,
    Market_Price,
    Sale_Price,
    Market_Price - Sale_Price AS discount_amount
FROM Products
ORDER BY ProductID;
```

| ProductID | Market_Price | Sale_Price | discount_amount |
|---:|---:|---:|---:|
| 1 | 100 | 100 | 0 |
| 2 | 150 | 150 | 0 |
| 3 | 100 | NULL | NULL |
| 4 | 100 | 90 | 10 |

Product 3's discount is unknown: arithmetic with a missing price gives `NULL`. It must not be called a full-price product.

**2. Keep only a zero difference.** The `WHERE` condition retains products 1 and 2. Product 4 has a discount of 10. Product 3 is also excluded because `NULL = 0` is unknown, and `WHERE` keeps only true conditions.

```sql
SELECT ProductID, Product, Sale_Price, Market_Price
FROM Products
WHERE Market_Price - Sale_Price = 0
ORDER BY ProductID;
```

| ProductID | Product | Sale_Price | Market_Price |
|---:|---|---:|---:|
| 1 | Mug | 100 | 100 |
| 2 | Lamp | 150 | 150 |

Your query tests zero directly. The source's `NULLIF(Market_Price - Sale_Price, 0)` represents that same zero as `NULL`, then separately excludes products with a missing price. Both approaches select the same products here.

**3. Show the requested label.** After the filter, every remaining product has no discount, so the constant `'Full price'` is correct for every `discount_display` value.

```sql
SELECT
    ProductID,
    Product,
    Brand,
    Sale_Price,
    Market_Price,
    'Full price' AS discount_display
FROM Products
WHERE Market_Price - Sale_Price = 0
ORDER BY ProductID;
```

| ProductID | Product | Brand | Sale_Price | Market_Price | discount_display |
|---:|---|---|---:|---:|---|
| 1 | Mug | Home | 100 | 100 | Full price |
| 2 | Lamp | Home | 150 | 150 | Full price |

**4. Sort and take ten.** `Sale_Price DESC` puts the most expensive first. `ProductID ASC` decides the order if prices tie. `LIMIT 10` takes at most ten qualifying products; this small example has only two.

```sql
SELECT
    ProductID,
    Product,
    Brand,
    Sale_Price,
    Market_Price,
    'Full price' AS discount_display
FROM Products
WHERE Market_Price - Sale_Price = 0
ORDER BY Sale_Price DESC, ProductID ASC
LIMIT 10;
```

| ProductID | Product | Brand | Sale_Price | Market_Price | discount_display |
|---:|---|---|---:|---:|---|
| 2 | Lamp | Home | 150 | 150 | Full price |
| 1 | Mug | Home | 100 | 100 | Full price |

**Manual check.** Products 3 and 4 do not qualify. The two full-price products are ordered 150 before 100. The ten-row limit leaves both rows in this example. These are illustrative results, not a claim of execution on the complete dataset.

## My solution — SQL Server

SQL Server uses `TOP (10)` in the `SELECT` clause instead of SQLite's `LIMIT 10`. The filter, label, and tie-breaker stay the same.

```sql
SELECT TOP (10)
    ProductID,
    Product,
    Brand,
    Sale_Price,
    Market_Price,
    'Full price' AS discount_display
FROM Products
WHERE Market_Price - Sale_Price = 0
ORDER BY Sale_Price DESC, ProductID ASC;
```

## Official solution

**Source:** [provided SQL answer key](<../Source Materials/PrepNPlaced_SQL_100_v2/sql/all_100_solutions.sql>), question 6. This source query uses PostgreSQL syntax.

```sql
SELECT p.ProductID,
       p.Product,
       p.Brand,
       p.Sale_Price,
       p.Market_Price,
       COALESCE(NULLIF(p.Market_Price - p.Sale_Price, 0)::text, 'Full price') AS discount_display
FROM Products AS p
WHERE p.Sale_Price IS NOT NULL
  AND p.Market_Price IS NOT NULL
  AND NULLIF(p.Market_Price - p.Sale_Price, 0) IS NULL
ORDER BY p.Sale_Price DESC, p.ProductID
LIMIT 10;
```

**What this tests.** Distinguish a zero discount from an unknown discount caused by a missing price; then sort and limit deterministically.

**The approach.** `NULLIF(difference, 0)` turns a zero discount into `NULL`. The explicit price checks remove rows where `NULL` came from a missing input. `COALESCE` displays `Full price` for the remaining rows.

**Why this way.** It demonstrates nullable discount logic explicitly. PostgreSQL's `::text` cast allows the numeric discount expression and text fallback to be used together. Your direct zero-difference filter reaches the same final result without materializing the nullable expression.

**Common mistakes.** Testing `= NULL` instead of `IS NULL`, treating a missing price as no discount, or limiting before sorting can produce the wrong result. The `ProductID` tie-breaker makes the top ten deterministic.
