# 9. SQL The Problem (The Report)

## Question and image

Given `Students(ID, Name, Marks)` and the mark ranges in `Grades`, report `Name`, `Grade`, and `Marks` for every student. The matching grade is the row whose `Min_Mark` and `Max_Mark` include the student's marks.

For grades **8–10**, show the student's name and sort students with the same grade alphabetically by name. For grades **1–7**, display `NULL` instead of the student's name and sort students with the same grade by marks ascending. Sort all rows by grade descending. This is the wording of HackerRank's [The Report](https://www.hackerrank.com/challenges/the-report/problem) challenge.

**Example 1**

Input — `Students`:

| ID | Name | Marks |
|---:|---|---:|
| 1 | Julia | 88 |
| 2 | Samantha | 68 |
| 3 | Maria | 99 |
| 4 | Scarlet | 78 |
| 5 | Ashley | 63 |
| 6 | Jane | 81 |

Input — `Grades` uses the ranges listed in **Schema** below.

Expected displayed output:

| Name | Grade | Marks |
|---|---:|---:|
| Maria | 10 | 99 |
| Jane | 9 | 81 |
| Julia | 9 | 88 |
| Scarlet | 8 | 78 |
| NULL | 7 | 63 |
| NULL | 7 | 68 |

The two grade-7 students appear with hidden names and are ordered by marks, 63 before 68.

## Schema

`Students`:

| Column Name | Type |
|---|---|
| ID | Integer |
| Name | String |
| Marks | Integer |

`Grades`:

| Grade | Min_Mark | Max_Mark |
|---:|---:|---:|
| 1 | 0 | 9 |
| 2 | 10 | 19 |
| 3 | 20 | 29 |
| 4 | 30 | 39 |
| 5 | 40 | 49 |
| 6 | 50 | 59 |
| 7 | 60 | 69 |
| 8 | 70 | 79 |
| 9 | 80 | 89 |
| 10 | 90 | 100 |

The range endpoints are inclusive. The ranges shown do not overlap.

## My solution — SQLite

```sql
SELECT
    CASE
        WHEN Grades.Grade < 8 THEN 'NULL'
        ELSE Students.Name
    END AS Name,
    Grades.Grade,
    Students.Marks
FROM Students
JOIN Grades
    ON Students.Marks >= Grades.Min_Mark
   AND Students.Marks <= Grades.Max_Mark
ORDER BY
    Grades.Grade DESC,
    CASE
        WHEN Grades.Grade >= 8 THEN Students.Name
    END ASC,
    CASE
        WHEN Grades.Grade < 8 THEN Students.Marks
    END ASC;
```

### Step-by-step explanation with one example

**Starting data.** The six `Students` rows have marks 88, 68, 99, 78, 63, and 81. The relevant grade ranges are 60–69 → grade 7, 70–79 → grade 8, 80–89 → grade 9, and 90–100 → grade 10.

**1. Find each student's grade by matching a range.** The join matches a student when their marks are at least `Min_Mark` and at most `Max_Mark`. Both boundaries are included.

```sql
SELECT Students.ID, Students.Name, Students.Marks, Grades.Grade
FROM Students
JOIN Grades
    ON Students.Marks >= Grades.Min_Mark
   AND Students.Marks <= Grades.Max_Mark
ORDER BY Students.ID;
```

| ID | Name | Marks | Grade |
|---:|---|---:|---:|
| 1 | Julia | 88 | 9 |
| 2 | Samantha | 68 | 7 |
| 3 | Maria | 99 | 10 |
| 4 | Scarlet | 78 | 8 |
| 5 | Ashley | 63 | 7 |
| 6 | Jane | 81 | 9 |

For example, Julia's 88 falls in grade 9's 80–89 range. Samantha's 68 and Ashley's 63 both fall in grade 7's 60–69 range.

**2. Hide names below grade 8.** The `CASE` expression displays the text `'NULL'` for grades 1–7; grades 8–10 keep their student names. To see this transformation before sorting by grade:

```sql
SELECT Students.ID,
       CASE WHEN Grades.Grade < 8 THEN 'NULL'
            ELSE Students.Name END AS Name,
       Grades.Grade,
       Students.Marks
FROM Students
JOIN Grades
    ON Students.Marks >= Grades.Min_Mark
   AND Students.Marks <= Grades.Max_Mark
ORDER BY Students.ID;
```

| ID | displayed Name | Grade | Marks |
|---:|---|---:|---:|
| 1 | Julia | 9 | 88 |
| 2 | NULL | 7 | 68 |
| 3 | Maria | 10 | 99 |
| 4 | Scarlet | 8 | 78 |
| 5 | NULL | 7 | 63 |
| 6 | Jane | 9 | 81 |

Here `'NULL'` is a four-letter string, whereas unquoted SQL `NULL` is a missing value. The source challenge says to [print `NULL` as the name](https://www.hackerrank.com/challenges/the-report/problem); the displayed example alone does not show whether a platform distinguishes the underlying value types.

**3. Apply the two tie-breaking rules.** `Grades.Grade DESC` places grade 10 before 9, 8, and 7. Within grade 9, the second sort expression returns the actual names, so **Jane** precedes **Julia** alphabetically. Within grade 7, that name expression returns `NULL` for both rows, and the third expression sorts by marks, so **63** precedes **68**.

The final query returns:

| Name | Grade | Marks |
|---|---:|---:|
| Maria | 10 | 99 |
| Jane | 9 | 81 |
| Julia | 9 | 88 |
| Scarlet | 8 | 78 |
| NULL | 7 | 63 |
| NULL | 7 | 68 |

The range match is a join condition, while the two `CASE` expressions inside `ORDER BY` decide how students with the **same grade** are ordered. The grade ranges shown do not overlap, so every sample student matches one grade.

## My solution — SQL Server

The same query works in SQL Server:

```sql
SELECT
    CASE
        WHEN Grades.Grade < 8 THEN 'NULL'
        ELSE Students.Name
    END AS Name,
    Grades.Grade,
    Students.Marks
FROM Students
JOIN Grades
    ON Students.Marks >= Grades.Min_Mark
   AND Students.Marks <= Grades.Max_Mark
ORDER BY
    Grades.Grade DESC,
    CASE WHEN Grades.Grade >= 8 THEN Students.Name END ASC,
    CASE WHEN Grades.Grade < 8 THEN Students.Marks END ASC;
```
