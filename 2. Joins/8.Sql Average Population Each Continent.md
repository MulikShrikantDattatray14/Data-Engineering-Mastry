# 8. SQL Average Population Each Continent

## Question and image

Using `CITY` and `COUNTRY`, return each continent name (`COUNTRY.CONTINENT`) and the average population of its cities (`CITY.POPULATION`), **rounded down to the nearest integer**. Match `CITY.COUNTRYCODE` to `COUNTRY.CODE`. No output order is specified.

**Example 1**

Input — `CITY`:

| ID | NAME | COUNTRYCODE | DISTRICT | POPULATION |
|---:|---|---|---|---:|
| 1 | Nairobi | KEN | Nairobi | 4500000 |
| 2 | Cairo | EGY | Cairo | 9500000 |
| 3 | Mumbai | IND | Maharashtra | 20000000 |
| 4 | Delhi | IND | Delhi | 19000000 |

Input — `COUNTRY` (columns used in this example):

| CODE | NAME | CONTINENT | REGION |
|---|---|---|---|
| KEN | Kenya | Africa | Eastern Africa |
| EGY | Egypt | Africa | Northern Africa |
| IND | India | Asia | Southern Asia |

Expected output:

| CONTINENT | AVERAGE_POPULATION |
|---|---:|
| Africa | 7000000 |
| Asia | 19500000 |

Africa averages Nairobi and Cairo: `(4500000 + 9500000) / 2 = 7000000`. Asia averages Mumbai and Delhi: `(20000000 + 19000000) / 2 = 19500000`.

## My solution — SQLite

```sql
SELECT COUNTRY.CONTINENT,
       CAST(AVG(CITY.POPULATION) AS INTEGER) AS AVERAGE_POPULATION
FROM COUNTRY
JOIN CITY
    ON CITY.COUNTRYCODE = COUNTRY.CODE
GROUP BY COUNTRY.CONTINENT;
```

### Step-by-step explanation with one example

**Starting data.** `CITY` has the four city populations. `COUNTRY` supplies the continent for each city's country code.

| city | COUNTRYCODE | POPULATION |
|---|---|---:|
| Nairobi | KEN | 4500000 |
| Cairo | EGY | 9500000 |
| Mumbai | IND | 20000000 |
| Delhi | IND | 19000000 |

| COUNTRY.CODE | CONTINENT |
|---|---|
| KEN | Africa |
| EGY | Africa |
| IND | Asia |

**1. Attach a continent to each city.** The `ON` condition matches `CITY.COUNTRYCODE` to `COUNTRY.CODE` (`KEN` to Kenya, `EGY` to Egypt, and `IND` to India).

```sql
SELECT COUNTRY.CONTINENT,
       CITY.NAME AS city_name,
       CITY.POPULATION AS city_population
FROM COUNTRY
JOIN CITY
    ON CITY.COUNTRYCODE = COUNTRY.CODE
ORDER BY COUNTRY.CONTINENT, CITY.ID;
```

| CONTINENT | city_name | city_population |
|---|---|---:|
| Africa | Nairobi | 4500000 |
| Africa | Cairo | 9500000 |
| Asia | Mumbai | 20000000 |
| Asia | Delhi | 19000000 |

The join keeps **city rows**. India appears twice because it has two cities in `CITY`; each city should count once in the average. `COUNTRY.POPULATION` is a different column and is not used.

**2. Group the city rows by continent and average their populations.** `GROUP BY COUNTRY.CONTINENT` makes one group for Africa and one for Asia. `AVG(CITY.POPULATION)` uses the city values in each group.

```sql
SELECT COUNTRY.CONTINENT,
       COUNT(*) AS city_count,
       AVG(CITY.POPULATION) AS average_before_rounding
FROM COUNTRY
JOIN CITY
    ON CITY.COUNTRYCODE = COUNTRY.CODE
GROUP BY COUNTRY.CONTINENT;
```

| CONTINENT | city_count | average_before_rounding |
|---|---:|---:|
| Africa | 2 | 7000000 |
| Asia | 2 | 19500000 |

Africa: `(4500000 + 9500000) / 2 = 7000000`. Asia: `(20000000 + 19000000) / 2 = 19500000`.

**3. Round down and return the requested columns.** The sample averages are already whole numbers. `CAST(... AS INTEGER)` removes any fractional part; for a nonnegative population average such as `7000000.5`, it gives `7000000`. That is the requested rounded-down value for population data.

```sql
SELECT COUNTRY.CONTINENT,
       CAST(AVG(CITY.POPULATION) AS INTEGER) AS AVERAGE_POPULATION
FROM COUNTRY
JOIN CITY
    ON CITY.COUNTRYCODE = COUNTRY.CODE
GROUP BY COUNTRY.CONTINENT;
```

| CONTINENT | AVERAGE_POPULATION |
|---|---:|
| Africa | 7000000 |
| Asia | 19500000 |

The result has one row per continent that has matching city rows. No output order was requested. `CAST` truncates toward zero; it equals mathematical `FLOOR` for nonnegative populations, though the two differ on negative values.
