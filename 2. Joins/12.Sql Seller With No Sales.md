# 12. SQL Seller With No Sales

## Question and image

Report the names of all sellers who did not make any sales in 2020. Include sellers with no orders at all and sellers whose orders were only in other years. Return the result ordered by `seller_name` ascending.

**Example 1**

Input — `Customer`:

| customer_id | customer_name |
|---:|---|
| 101 | Alice |
| 102 | Bob |
| 103 | Charlie |

Input — `Orders`:

| order_id | sale_date | order_cost | customer_id | seller_id |
|---:|---|---:|---:|---:|
| 1 | 2020-03-01 | 1500 | 101 | 1 |
| 2 | 2020-05-25 | 2400 | 102 | 2 |
| 3 | 2019-05-25 | 800 | 101 | 3 |
| 4 | 2020-09-13 | 1000 | 103 | 2 |
| 5 | 2019-02-11 | 700 | 101 | 2 |

Input — `Seller`:

| seller_id | seller_name |
|---:|---|
| 1 | Daniel |
| 2 | Elizabeth |
| 3 | Frank |

Output:

| seller_name |
|---|
| Frank |

Frank has a sale in 2019 but none in 2020. Daniel and Elizabeth each have at least one sale in 2020.

## My solution — SQLite

```sql
SELECT s.seller_name
FROM Seller AS s
WHERE s.seller_id NOT IN (
    SELECT o.seller_id
    FROM Orders AS o
    WHERE o.sale_date >= '2020-01-01'
      AND o.sale_date < '2021-01-01'
      AND o.seller_id IS NOT NULL
)
ORDER BY s.seller_name ASC;
```

### Step-by-step explanation with one example

**Starting data.** The `Seller` table has three sellers. `Orders` records transactions across 2019 and 2020:

| seller_id | seller_name |
|---:|---|
| 1 | Daniel |
| 2 | Elizabeth |
| 3 | Frank |

| order_id | sale_date | seller_id |
|---:|---|---:|
| 1 | 2020-03-01 | 1 |
| 2 | 2020-05-25 | 2 |
| 3 | 2019-05-25 | 3 |
| 4 | 2020-09-13 | 2 |
| 5 | 2019-02-11 | 2 |

The output needs seller names, but `seller_id` is the unique key used to decide whether each seller made a sale. `Customer` is not needed: the sale date and seller ID are both in `Orders`.

**1. Find the IDs of sellers with a sale in 2020.** Include dates from January 1, 2020 up to, but not including, January 1, 2021. Exclude NULL seller IDs so `NOT IN` can compare against a list without NULLs.

```sql
SELECT o.order_id, o.sale_date, o.seller_id
FROM Orders AS o
WHERE o.sale_date >= '2020-01-01'
  AND o.sale_date < '2021-01-01'
  AND o.seller_id IS NOT NULL
ORDER BY o.order_id;
```

| order_id | sale_date | seller_id |
|---:|---|---:|
| 1 | 2020-03-01 | 1 |
| 2 | 2020-05-25 | 2 |
| 4 | 2020-09-13 | 2 |

The subquery in the final solution selects only `seller_id`, so its result is `1, 2, 2`. Repeated ID `2` does not change the membership test: seller 2 still belongs to the set of sellers with a 2020 sale.

**2. Check every seller against those IDs.** `NOT IN` keeps a seller only when their `seller_id` is absent from the subquery. The comparison is on IDs because different sellers may share a name.

```sql
SELECT
    s.seller_id,
    s.seller_name,
    CASE
        WHEN s.seller_id NOT IN (
            SELECT o.seller_id
            FROM Orders AS o
            WHERE o.sale_date >= '2020-01-01'
              AND o.sale_date < '2021-01-01'
              AND o.seller_id IS NOT NULL
        ) THEN 'keep'
        ELSE 'exclude'
    END AS decision
FROM Seller AS s
ORDER BY s.seller_id;
```

| seller_id | seller_name | decision |
|---:|---|---|
| 1 | Daniel | exclude |
| 2 | Elizabeth | exclude |
| 3 | Frank | keep |

Frank's 2019 order does not disqualify him. A seller with no orders at all would also be kept, because their ID would not appear in the 2020 subquery.

**3. Return names in alphabetical order.** The complete query above selects `s.seller_name` for the kept sellers and applies `ORDER BY s.seller_name ASC`:

| seller_name |
|---|
| Frank |

Manually checking the sample, seller IDs `1` and `2` have 2020 orders, while seller ID `3` does not. That leaves Frank alone in the result.
