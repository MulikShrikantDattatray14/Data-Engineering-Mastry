# 1. SQL Combine Two Tables

## Question and image

Report the first name, last name, city, and state of **each person** in Person. If a person's address is absent from Address, report NULL for city and state.

Return the result in any order.

**Example 1**

Input — Person:

| personId | lastName | firstName |
|---:|---|---|
| 1 | Wang | Allen |
| 2 | Alice | Bob |

Input — Address:

| addressId | personId | city | state |
|---:|---:|---|---|
| 1 | 2 | New York City | New York |
| 2 | 3 | Leetcode | California |

Expected output:

| firstName | lastName | city | state |
|---|---|---|---|
| Allen | Wang | NULL | NULL |
| Bob | Alice | New York City | New York |

Person 1 has no address row. Address 1 belongs to person 2. The address for personId 3 has no matching person in the example.

## Schema

Person:

| Column Name | Type |
|---|---|
| personId | int |
| lastName | varchar |
| firstName | varchar |

personId is the primary key. Each row gives one person's ID and name.

Address:

| Column Name | Type |
|---|---|
| addressId | int |
| personId | int |
| city | varchar |
| state | varchar |

addressId is the primary key. Each row gives an address for a personId.

## My solution — SQLite

```sql
SELECT Person.firstName, Person.lastName, Address.city, Address.state
FROM Person
LEFT JOIN Address
    ON Person.personId = Address.personId;
```

### Step-by-step explanation with one example

**Starting data.** `Person` contains Allen and Bob. `Address` has an address for Bob (`personId = 2`) and another address whose `personId = 3` does not appear in `Person`.

| Person.personId | firstName | lastName |
|---:|---|---|
| 1 | Allen | Wang |
| 2 | Bob | Alice |

| Address.addressId | Address.personId | city | state |
|---:|---:|---|---|
| 1 | 2 | New York City | New York |
| 2 | 3 | Leetcode | California |

**1. Keep every person.** The task asks for each person, including someone without an address. Put `Person` before `LEFT JOIN`, so every row from `Person` survives.

**2. Match addresses by person ID.** `ON Person.personId = Address.personId` compares the IDs describing the same person. Bob's ID 2 matches address 1. Allen's ID 1 has no match. Address 2 has person ID 3, which matches neither person in this example.

Inspect the joined rows before choosing final columns:

```sql
SELECT
    Person.personId,
    Person.firstName,
    Person.lastName,
    Address.addressId,
    Address.city,
    Address.state
FROM Person
LEFT JOIN Address
    ON Person.personId = Address.personId;
```

| personId | firstName | lastName | addressId | city | state |
|---:|---|---|---:|---|---|
| 1 | Allen | Wang | NULL | NULL | NULL |
| 2 | Bob | Alice | 1 | New York City | New York |

For Allen, SQLite supplies `NULL` for all `Address` columns because no address matched. The unmatched address for person 3 does not create a result row because `Address` is on the right.

**3. Select only the requested columns.** Remove the IDs used to inspect the join:

```sql
SELECT Person.firstName, Person.lastName, Address.city, Address.state
FROM Person
LEFT JOIN Address
    ON Person.personId = Address.personId;
```

| firstName | lastName | city | state |
|---|---|---|---|
| Allen | Wang | NULL | NULL |
| Bob | Alice | New York City | New York |

The sample has one address for Bob, so each person produces one row. If a person has several matching address rows, a join produces one row for each match; the prompt gives no rule for choosing just one. No `ORDER BY` is required.

## Official solution

The lecture material supplies this equivalent query:

```sql
SELECT p.firstName, p.lastName, a.city, a.state
FROM Person AS p
LEFT JOIN Address AS a
    ON p.personId = a.personId;
```

### What this tests

Choosing a `LEFT JOIN` when rows from one table must remain even without a match.

### The approach

Start from `Person`, match `Address` on `personId`, and return the requested name and address columns.

### Why this way

The `LEFT JOIN` preserves Allen's row and fills missing address columns with `NULL`.

### Common mistakes

An `INNER JOIN` would drop Allen. Matching `Person.personId` to `Address.addressId` would use the wrong relationship.
