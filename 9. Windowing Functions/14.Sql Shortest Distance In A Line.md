## My solution — SQLite

```sql
WITH next_points AS (
    SELECT
        x,
        LEAD(x) OVER (ORDER BY x ASC) AS next_x
    FROM Point
)
SELECT MIN(next_x - x) AS shortest
FROM next_points
WHERE next_x IS NOT NULL;
```

### Step-by-step explanation with one example

**1. Define the result and inspect the points.** The result is one row with one column, `shortest`: the smallest distance between any two points. The sample positions are:

```sql
SELECT x
FROM Point
ORDER BY x ASC;
```

| x |
|---:|
| -1 |
| 0 |
| 2 |

`x` is unique because it is the primary key. Sorting gives the points from left to right on the number line.

**2. Attach the next point to each row.** `LEAD(x) OVER (ORDER BY x ASC)` reads the next larger position in sorted order, while keeping one row per point. The `next_points` CTE stores this intermediate result.

```sql
SELECT
    x,
    LEAD(x) OVER (ORDER BY x ASC) AS next_x
FROM Point
ORDER BY x ASC;
```

| x | next_x |
|---:|---:|
| -1 | 0 |
| 0 | 2 |
| 2 | NULL |

For `x = -1`, the next point is `0`. For `x = 0`, the next point is `2`. The last point has no next row, so `next_x` is `NULL`. The `ORDER BY` inside `OVER` determines what "next" means; the outer `ORDER BY` displays this table in that same order.

**3. Calculate the adjacent gaps.** Because the points are sorted ascending, `next_x - x` is a nonnegative distance. Subtracting in the reverse order would produce negative numbers and make `MIN` choose the most negative value rather than the shortest distance.

```sql
WITH next_points AS (
    SELECT
        x,
        LEAD(x) OVER (ORDER BY x ASC) AS next_x
    FROM Point
)
SELECT x, next_x, next_x - x AS gap
FROM next_points
ORDER BY x ASC;
```

| x | next_x | gap |
|---:|---:|---:|
| -1 | 0 | 1 |
| 0 | 2 | 2 |
| 2 | NULL | NULL |

The first adjacent distance is `0 - (-1) = 1`. The second is `2 - 0 = 2`. The last gap is `NULL` because no second point exists to make a pair.

Only adjacent sorted points need comparison: a distance between nonadjacent points equals the sum of one or more adjacent gaps, so it cannot be smaller than every gap it includes. In this sample, the nonadjacent distance from `-1` to `2` is `3 = 1 + 2`.

**4. Ignore the missing next point and take the minimum.** The outer `WHERE` removes the final row with `next_x IS NULL`. `MIN` then combines the two valid gap rows into one answer row. `MIN` would also ignore the `NULL` automatically, but the filter makes the eligible pairs explicit.

```sql
WITH next_points AS (
    SELECT
        x,
        LEAD(x) OVER (ORDER BY x ASC) AS next_x
    FROM Point
)
SELECT MIN(next_x - x) AS shortest
FROM next_points
WHERE next_x IS NOT NULL;
```

| shortest |
|---:|
| 1 |

**5. Check the example.** The valid gaps are `1` and `2`, so their minimum is `1`. That matches the supplied output and the distance between points `-1` and `0`. The CTE is needed because the window result `next_x` must be calculated before the outer query can filter and aggregate it.
