# 6. SQL Daily Leads And Partners

## Question and image

**6. Sql Daily Leads And Partners**

Table: DailySales

| Column Name | Type |
|---|---|
| date_id | date |
| make_name | varchar |
| lead_id | int |
| partner_id | int |

There is no primary key (column with unique values) for this table. It may contain duplicates.

This table contains the date and the name of the product sold and the IDs of the lead and partner it was sold to.

The name consists of only lowercase English letters.

For each `date_id` and `make_name`, find the number of distinct `lead_id`'s and distinct `partner_id`'s.

Return the result table in ascending order of `date_id` .

**Example 1:**

Input:

DailySales table:

| date_id | make_name | lead_id | partner_id |
|---|---|---|---|
| 2020-12-8 | toyota | 0 | 1 |
| 2020-12-8 | toyota | 1 | 0 |
| 2020-12-8 | toyota | 1 | 2 |
| 2020-12-7 | toyota | 0 | 2 |
| 2020-12-7 | toyota | 0 | 1 |
| 2020-12-8 | honda | 1 | 2 |
| 2020-12-8 | honda | 2 | 1 |
| 2020-12-7 | honda | 0 | 1 |
| 2020-12-7 | honda | 1 | 2 |
| 2020-12-7 | honda | 2 | 1 |

Output:

| date_id | make_name | unique_leads | unique_partners |
|---|---|---|---|
| 2020-12-7 | honda | 3 | 2 |
| 2020-12-7 | toyota | 1 | 2 |
| 2020-12-8 | honda | 2 | 2 |
| 2020-12-8 | toyota | 2 | 3 |

*Explanation:*

For 2020-12-8, toyota gets leads = [0, 1] and partners = [0, 1, 2] while honda gets leads = [1, 2] and partners = [1, 2].

## Schema

**DailySales**  
date_id, make_name, lead_id, partner_id

- `date_id` — date
- `make_name` — varchar
- `lead_id` — integer
- `partner_id` — integer
- The table has no primary key and may contain duplicate rows.
- `make_name` contains only lowercase English letters.

## My solution — SQLite

```sql
SELECT
    date_id,
    make_name,
    COUNT(DISTINCT lead_id) AS unique_leads,
    COUNT(DISTINCT partner_id) AS unique_partners
FROM DailySales
GROUP BY date_id, make_name
ORDER BY date_id ASC;
```

### Key learnings

- The phrase “For each `date_id` and `make_name`” identifies the grouping columns, so the query groups by `date_id, make_name`.
- `lead_id` and `partner_id` are the values being counted inside each date-and-make group.
- `COUNT(DISTINCT ...)` prevents repeated lead or partner IDs from being counted more than once. This is necessary because `DailySales` may contain duplicate rows.
- Grouping by `lead_id` or `partner_id` would split the data into individual ID combinations instead of calculating one summary for each date and make.

### Step-by-step explanation with one example

We need one row for each date_id and make_name pair, with two separate distinct counts. Use the supplied DailySales rows throughout; their displayed date strings are retained exactly.

**Starting data**

`DailySales`:

| date_id | make_name | lead_id | partner_id |
| --- | --- | --- | --- |
| 2020-12-8 | toyota | 0 | 1 |
| 2020-12-8 | toyota | 1 | 0 |
| 2020-12-8 | toyota | 1 | 2 |
| 2020-12-7 | toyota | 0 | 2 |
| 2020-12-7 | toyota | 0 | 1 |
| 2020-12-8 | honda | 1 | 2 |
| 2020-12-8 | honda | 2 | 1 |
| 2020-12-7 | honda | 0 | 1 |
| 2020-12-7 | honda | 1 | 2 |
| 2020-12-7 | honda | 2 | 1 |

**1. See the date-and-make groups**

Both date_id and make_name define a result row. Counting the raw rows first helps distinguish sales rows from unique leads and partners.

```sql
SELECT date_id, make_name, COUNT(*) AS sales_rows
FROM DailySales
GROUP BY date_id, make_name
ORDER BY date_id, make_name;
```

Result:

| date_id | make_name | sales_rows |
| --- | --- | --- |
| 2020-12-7 | honda | 3 |
| 2020-12-7 | toyota | 2 |
| 2020-12-8 | honda | 2 |
| 2020-12-8 | toyota | 3 |

There are four date-and-make groups. Three Toyota rows on December 8 do not imply three different leads.

**2. Count leads and partners independently**

COUNT(DISTINCT lead_id) and COUNT(DISTINCT partner_id) each remove repetition within the same date-and-make group. Neither ID belongs in GROUP BY because we want one summary per date and make.

```sql
SELECT date_id, make_name,
       COUNT(DISTINCT lead_id) AS unique_leads,
       COUNT(DISTINCT partner_id) AS unique_partners
FROM DailySales
GROUP BY date_id, make_name
ORDER BY date_id, make_name;
```

Result:

| date_id | make_name | unique_leads | unique_partners |
| --- | --- | --- | --- |
| 2020-12-7 | honda | 3 | 2 |
| 2020-12-7 | toyota | 1 | 2 |
| 2020-12-8 | honda | 2 | 2 |
| 2020-12-8 | toyota | 2 | 3 |

For Toyota on December 8, leads are {0, 1}, while partners are {0, 1, 2}; the two counts are 2 and 3, not necessarily equal.

**3. Assemble the final query**

The saved final query orders by date_id as requested. The extra make_name ordering in the diagnostic queries above only makes the walkthrough easy to compare; ties within a date have no required order.

```sql
SELECT
    date_id,
    make_name,
    COUNT(DISTINCT lead_id) AS unique_leads,
    COUNT(DISTINCT partner_id) AS unique_partners
FROM DailySales
GROUP BY date_id, make_name
ORDER BY date_id ASC;
```

Final result for this example:

| date_id | make_name | unique_leads | unique_partners |
| --- | --- | --- | --- |
| 2020-12-7 | honda | 3 | 2 |
| 2020-12-7 | toyota | 1 | 2 |
| 2020-12-8 | honda | 2 | 2 |
| 2020-12-8 | toyota | 2 | 3 |

**Check the result:** Manual check: December 7 Honda has leads {0, 1, 2} and partners {1, 2}; December 7 Toyota has leads {0} and partners {1, 2}; December 8 Honda has {1, 2} in both columns; December 8 Toyota has two leads and three partners.

## My solution — SQL Server

```sql
SELECT
    date_id,
    make_name,
    COUNT(DISTINCT lead_id) AS unique_leads,
    COUNT(DISTINCT partner_id) AS unique_partners
FROM DailySales
GROUP BY date_id, make_name
ORDER BY date_id ASC;
```

The same query works in SQLite and SQL Server.
> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).

## Official solution

**Lecture solution supplied in the GROUP BY/HAVING notes:**

```sql
SELECT date_id, make_name,
       COUNT(DISTINCT lead_id) AS unique_leads,
       COUNT(DISTINCT partner_id) AS unique_partners
FROM DailySales
GROUP BY date_id, make_name;
```

### What this tests

Grouping by a two-column key and counting two different sets of unique IDs.

### The approach

Form one group per `(date_id, make_name)` pair, then count distinct leads and distinct partners independently within that group.

### Why this way

The source can contain duplicate rows and repeated IDs. `DISTINCT` prevents either count from increasing for a repeated ID.

### Common mistakes

- Grouping by date alone combines different makes.
- `COUNT(*)` counts sales rows, not unique leads or partners.
