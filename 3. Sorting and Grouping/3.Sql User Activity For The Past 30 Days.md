# 3. SQL User Activity for the Past 30 Days

## Question and image

**3. Sql User Activity For The Past 30 Days**

Table: Activity

| Column Name | Type |
|---|---|
| user_id | int |
| session_id | int |
| activity_date | date |
| activity_type | enum |

This table may have duplicate rows.

The `activity_type` column is an ENUM (category) of type (`'open_session'`, `'end_session'`, `'scroll_down'`, `'send_message'`).

The table shows the user activities for a social media website.

Note that each session belongs to exactly one user.

Write a solution to find the daily active user count for a period of 30 days ending `2019-07-27` inclusively. A user was active on someday if they made at least one activity on that day.

Return the result table ordered by day.

**Example 1:**

Input:

| 1 | 1 | 2019-07-20 | open_session |

| 4 | 3 | 2019-06-25 | open_session |
| 4 | 3 | 2019-06-25 | end_session |

Output:

| day | active_users |
|---|---|
| 2019-07-20 | 2 |

## Schema

**Activity**

- `user_id` — integer
- `session_id` — integer

- `activity_type` — enum containing `open_session`, `end_session`, `scroll_down`, or `send_message`

## My solution — SQLite

```sql
SELECT
    activity_date AS day,
    COUNT(DISTINCT user_id) AS active_users
FROM Activity
WHERE activity_date BETWEEN '2019-06-28' AND '2019-07-27'
GROUP BY activity_date
ORDER BY day ASC;
```

The date range starts on `2019-06-28` because a 30-day period ending on `2019-07-27`, with both dates included, begins 29 days before the end date.

`GROUP BY activity_date` creates one result group per active day. `COUNT(DISTINCT user_id)` counts each user only once within that day, even when the user performed several activities. For example, opening a session, scrolling, and ending the session are three activity rows but represent only one active user.

The date condition uses `WHERE` because it filters activity rows before they are grouped. Days with no activity are naturally absent because the table contains no rows to form those groups.

### Step-by-step explanation with one example

We need one row per active day in the inclusive 30-day window ending 2019-07-27. The count is people, not activity events. Carry the supplied Activity rows through the same date window and grouping.

**Starting data**

`Activity`:

| user_id | session_id | activity_date | activity_type |
| --- | --- | --- | --- |
| 1 | 1 | 2019-07-20 | open_session |
| 1 | 1 | 2019-07-20 | scroll_down |
| 1 | 1 | 2019-07-20 | end_session |
| 2 | 4 | 2019-07-20 | open_session |
| 2 | 4 | 2019-07-21 | send_message |
| 2 | 4 | 2019-07-21 | end_session |
| 3 | 2 | 2019-07-21 | open_session |
| 3 | 2 | 2019-07-21 | send_message |
| 3 | 2 | 2019-07-21 | end_session |
| 4 | 3 | 2019-06-25 | open_session |
| 4 | 3 | 2019-06-25 | end_session |

**1. Keep activities in the required 30 days**

An inclusive 30-day interval starts 29 days before its end: 2019-06-28 through 2019-07-27. Filter the original activity rows before counting.

```sql
SELECT user_id, session_id, activity_date, activity_type
FROM Activity
WHERE activity_date BETWEEN '2019-06-28' AND '2019-07-27'
ORDER BY activity_date, user_id, activity_type;
```

Result:

| user_id | session_id | activity_date | activity_type |
| --- | --- | --- | --- |
| 1 | 1 | 2019-07-20 | end_session |
| 1 | 1 | 2019-07-20 | open_session |
| 1 | 1 | 2019-07-20 | scroll_down |
| 2 | 4 | 2019-07-20 | open_session |
| 2 | 4 | 2019-07-21 | end_session |
| 2 | 4 | 2019-07-21 | send_message |
| 3 | 2 | 2019-07-21 | end_session |
| 3 | 2 | 2019-07-21 | open_session |
| 3 | 2 | 2019-07-21 | send_message |

Both rows for user 4 on June 25 disappear. The remaining rows are on July 20 and July 21.

**2. Inspect the distinct users on each day**

A person who opens, scrolls, and closes a session on the same day counts once. This diagnostic query displays the date-user pairs that COUNT(DISTINCT user_id) will count.

```sql
SELECT DISTINCT activity_date, user_id
FROM Activity
WHERE activity_date BETWEEN '2019-06-28' AND '2019-07-27'
ORDER BY activity_date, user_id;
```

Result:

| activity_date | user_id |
| --- | --- |
| 2019-07-20 | 1 |
| 2019-07-20 | 2 |
| 2019-07-21 | 2 |
| 2019-07-21 | 3 |

July 20 has users 1 and 2; July 21 has users 2 and 3. User 2 can count on both dates because each date is a separate group.

**3. Assemble the final query**

Group the filtered rows by date, count distinct users inside each date, rename activity_date to day, and sort by day.

```sql
SELECT
    activity_date AS day,
    COUNT(DISTINCT user_id) AS active_users
FROM Activity
WHERE activity_date BETWEEN '2019-06-28' AND '2019-07-27'
GROUP BY activity_date
ORDER BY day ASC;
```

Final result for this example:

| day | active_users |
| --- | --- |
| 2019-07-20 | 2 |
| 2019-07-21 | 2 |

**Check the result:** Manual check: July 20 has {1, 2} and July 21 has {2, 3}, so both counts are 2. Dates with no activity have no group and are omitted, as requested.

> **Shared SQL processing note:** `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → row limiting`. SQLite uses `LIMIT/OFFSET`; SQL Server uses `TOP` or `OFFSET/FETCH`. `WHERE` filters rows before grouping, while `HAVING` filters groups after aggregation. See [SQL Logical Query Processing Order](../0.%20SQL%20basics/SQL%20Logical%20Query%20Processing%20Order.md).
## Official solution

Lecture solution supplied in the GROUP BY/HAVING material:

```sql
SELECT activity_date AS day,
       COUNT(DISTINCT user_id) AS active_users
FROM Activity
WHERE activity_date BETWEEN '2019-06-28' AND '2019-07-27'
GROUP BY activity_date;
```

### What this tests

Filtering a date range and counting distinct users per day.

### The approach

Keep activities in the inclusive 30-day period, group by `activity_date`, then count each user once per date.

### Why this way

Several activities by one user on a day still represent one active user. A date with no activity produces no group and no result row.

### Common mistakes

`COUNT(*)` counts actions or duplicate rows, not users. Grouping by `user_id` would create a user-level result instead of a daily count. Check both endpoints of the 30-day period.
